# 미션 01 — 대표가 승인한 DNS 실패 후 분리 업무 실제 실행
작성일: 2026-11-11 KST
저장소: smartaiboom/ai-company-os

## 대표의 새 명시적 승인 — 이 미션에만 적용
대표는 2026-11-11 KST 대화에서 다음과 같이 명시적으로 승인했다.

> 미션 01의 새 분리 업무 실행을 승인해. 기존 DNS 실패 1회는 보존하고 Gemini 3.5 Flash-Lite 신규 최대 9회(기존 실패 포함 총 10회), YouTube 검색 최대 4회, 영상 정보 조회 최대 4회를 허용해. 프로젝트 gen-lang-client-0938732315의 무료 서비스만 사용하고 자동 재시도, 유료 전환, 대체 모델은 금지해. 기존에 동의한 목표·공개 조사 자료·AI 직원 결과의 Google 무료 API 전송과 서비스 개선·인적 검토 가능성에도 동의해. 같은 컷룸의 대표 기획 승인 대기까지만 진행해.

본 지시서에 기록된 승인은 **과거 실패한 업무의 재실행 동의가 아니라, 기존 실패 이력을 보존한 새 분리 업무 한 건에 대한 승인**이다. 실제 대표 승인 클릭, TTS/WAV, MP4/렌더, 게시/업로드는 허용하지 않는다.

## 전제와 목표
대표 원문 목표: "요즘 인기있는 게임에 대한 흥미있는 쇼츠 영상을 만들어봐. 기본적으로 인기있는 쇼츠는 몇초인지도 확인해보고."

- 컷룸: `company-aba553f29cfb454c8c05bad4abb49969`.
- 실패 업무: `qualityprovider-504d90900918450f98dd62b6f7704f1b`, `stopped/free_request_failed`. 기존 Gemini DNS 실패 1회를 소모 상태로 보존. 기존 서명/세션/active_operation 원본은 수정·삭제하지 않는다.
- 최신 `reports/VIDEO_MISSION_01_SAFE_RESUME_PREPARATION_RESULT_20261111.md`에서 새 분리 업무 `create-resume --confirm-new-execution` 기능 구현과 격리 오프라인 테스트 22개 통과가 보고됐다. 이를 재개발하거나 전체 테스트를 반복하지 말 것.
- Gemini와 YouTube API 키 모두 `Default Gemini Project`에 있으며 사용자 제공 프로젝트 ID는 `gen-lang-client-0938732315`. 사용자는 결제 미연결을 확인했다. 공급자 독립 검증으로 가장하지 않는다.
- 사용자 측 DNS IPv4/IPv6 조회 성공, `curl -4 -I https://generativelanguage.googleapis.com` 에서 HTTP/2 404 수신. 이는 HTTPS 연결이 가능하다는 근거일 뿐 실제 모델 접근/청구 성공 보장은 아니다.

## 승인된 외부 요청 상한과 조건
- 새 분리 업무의 Gemini 텍스트 모델 고정: `gemini-3.5-flash-lite`. 신규 최대 **9회(실패·타임아웃 포함)**; 과거 실패 1회와 합계 최대 10회. 새 실패 시 남은 횟수를 자동 재발송하는 데 쓰지 않는다.
- YouTube Data API `search.list` 최대 4회, `videos.list` 최대 4회. 실제 첫 조사 직원이 질의·후보를 스스로 정한다.
- 무료 서비스만 허용, 유료 결제 연결·유료 fallback·다른 모델·자동 재시도·무단 추가 API 요청 모두 금지.
- 무료 Google API로 전송되는 범위: 대표 목표, 한국어 세로형 Shorts 형식, 직원이 조회한 공개 동영상 메타데이터, 해당 미션 AI 직원의 선행 결과·검토/수정 피드백. 기존 회사 자료/개인정보/키/보류 후보를 전송하지 않는다.
- Google 무료 데이터의 서비스 개선/인적 검토 가능성에 대한 명시 동의가 있다. 원래 서명 동의 가드를 우회하지 않는다.

## Codex 실행 절차
1. `git status`를 확인하고 로컬 변경·미추적 데이터/로그/원장 보존 후 최신 GitHub를 안전하게 fast-forward한다. `AGENTS.md`, 이번 문서와 `reports/VIDEO_MISSION_01_SAFE_RESUME_PREPARATION_RESULT_20261111.md`를 읽는다. 이미 끝낸 키·쿼터·Billing 점검, 전체 재설계 및 반복 회귀 테스트를 수행하지 않는다.
2. 현재 실제 컷룸 연결과 기존 실패 원장을 **읽기 전용**으로 확인한다. 새 분리 업무가 아직 없다면 기존 CLI `create-resume --confirm-new-execution`를 **딱 한 번** 사용한다. 이미 생성된 분리 업무가 있으면 중복 생성하지 말고 상태를 검증한 뒤 이어간다. 기존 실패 업무에 `run`을 실행하지 않는다.
3. 기존 문서의 `video_mission_one prepare`를 활용해 `--account-project gen-lang-client-0938732315`, `--youtube-project gen-lang-client-0938732315`를 지정하고, 잔여량 숫자는 꾸며 넣지 말고 `unknown` 계약을 사용한다. `--quota-note`에는 사용자 확인의 근거 수준과 기존 DNS 실패 1회 소모를 정확히 기재한다. 실제 환경값 `GEMINI35_MODEL`, `GEMINI35_ENDPOINT`, `GEMINI35_AUTONOMOUS_FREE_ENABLED`는 기존 문서에 명시된 정확한 무료 모델·엔드포인트 값으로 **그 실행 프로세스에 한해** 설정한다. 비밀키 값은 출력·기록하지 않는다.
4. `prepare`가 돌려준 실제 제안 JSON/해시에서 `mission_resume` 과거 실패 참조, **새 9회/YouTube 4+4**, 무료/모델/데이터 정책/실제 입력 및 프로젝트 ID를 검토한다. 기존 명시적 승인과 일치할 때만 기존 `approve`로 **새 서명**을 저장한다. 만료되거나 계약 불일치 시 호출하지 않는다.
5. 새 업무에서 `run`을 최대 **한 번** 실행한다. 첫 전송 실패 또는 불명 네트워크 오류면 송신 전 소모 원장을 유지하고 즉시 중단. 같은 실행 재시도/대체 모델/원장 초기화 금지. 429·인증·모델 제한·요금 위험 등 오류도 동일 처리한다.
6. 성공하면 실제 직원에게 게임명·쇼츠 길이·조회수를 미리 답으로 제공하지 않는다. 조사 직원의 자율 YouTube 조회 → 관리자 주제·길이 판단 → 대본 직원의 전체 한국어 대본·스토리보드 → 내부 검토·수정 및 인수 → 컷룸 `awaiting_plan_approval`까지 진행한다. 확인되지 않은 Shorts 분류·저작권·실제 영상 소스는 미확인 표시.
7. 대표가 승인하거나 반려하는 단계는 실행하지 않는다. 추가 영상·음성/업로드·공개 게시도 금지한다.

## 결과 보고 — 성공·실패·차단 모두 필수
반드시 새 보고서 `reports/VIDEO_MISSION_01_APPROVED_DNS_RESUME_RESULT_20261111.md`를 작성해 안전하게 GitHub에 커밋·push한다. 이미 있으면 덮어쓰지 말고 충돌을 보고한다.
- 새 업무/옛 실패 업무 ID, 기존 실패 1회 보존, 각 승인·제안 해시의 참조, 적용 모델·프로젝트
- 실제 Gemini/YouTube 요청 횟수와 실패/불명 횟수(각 상한과 합산), 첫 HTTP 응답 또는 연결 오류(비밀값 제외), 과금에 대해 실제 관측 가능한 사실
- 새 업무와 컷룸 상태, 실제 게임·길이 선정 근거 및 기획안/한국어 대본 위치(생성된 경우) 또는 **단일 구체적 차단 사유**
- 자동 재시도/fallback 0, 기존 사용 데이터/음성·영상·키/시도 원장 보존 및 사용자 다음 행동 한 단계
- 코드 수정이 없다면 반복 회귀 테스트를 수행하지 않는다. 결과 보고서 외 무관한 파일을 커밋하지 않는다.
