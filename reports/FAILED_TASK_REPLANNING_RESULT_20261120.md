## 구현과 승인 경계

- `core/task_replanning.py`는 목표·단계·서명된 실패 참조·사용량·보존 관측·현재 도구·계약·권리와 예산 제한을 담는 공통 관리자 계약을 제공한다. 관리자는 재조사, 다른 방법, 보류, 대표 질문 중 하나를 선택하고 이유·다음 행동·성공 기준을 작성한다. 재조사만 허용 목록 안에서 도구를 제안한다. 대표의 재조사 선호는 서명된 입력이며, 관리자 응답은 실제 요청이 끝난 뒤 별도로 기록한다.
- `companies/video/research_replanning.py`는 기존 정책·원장·관측 해시로부터 새 업무 ID를 생성한다. 먼저 관리자 재계획 요청 1회를 검토하고 승인한다. 관리자 재계획이 재조사를 선택하면 그 서명 결과로부터 독립 조사 범위를 만들고 별도로 검토·승인한다. 다른 방법, 보류, 대표 질문은 다음 검토를 위해 표시한다. 두 승인 모두 현재 키, 무료 전용·$0 조건, 24시간 만료, 요청 또는 입력 해시에 결합된다. 첫 직원 요청은 서명된 범위에 본문 해시를 고정하고 후속 요청은 전송 전에 각각 원장에 본문 해시를 예약한다.
- 추가 상한은 관리자 재계획 1회, 신규 조사 직원 최대 4회, 독립 관리자 검토 1회로 **Gemini 합계 최대 6회**다. Tavily는 관리자가 도구 범위에 포함할 때 기본 검색 최대 1크레딧이며, 다운로드 0회·비용 $0이다. 직원이 도구 사용과 종료를 선택하며 검색을 강제하지 않는다. 기존 예약은 누적 사용량에만 포함된다.
- `research_workflow.py`는 최신 근거 참조 계약, 기존 서명·프로젝트 잠금·예약과 독립 관리자 검토를 재사용한다. 자료 부족이나 보류는 기획·제작 인수에서 차단된다. 사용 가능한 결과도 조사 참고용으로만 연결하며 편집·다운로드·게시에는 기존 권한이 필요하다. `studio_server.py`와 `studio/studio.js`는 두 실패와 누적량, 담당 관리자 응답 대기, 신규 승인·실행 대기, 보류·중단·철회를 한국어로 표시한다.
- 두 이전 승인과 예약은 실행에 재사용하지 않는다. 이력이나 도구 계약·키가 바뀌거나 승인이 만료·철회되면 중단한다. 각 단계는 한 번만 시작할 수 있으며 공급자 실패나 결과 미확정 이후에는 자동 재호출 없이 중단한다.

## 검증과 운영 보존

- 외부 연결과 이름 조회를 차단한 관련 Python 35건과 Node 컷룸 시나리오를 통과했다. `tests/test_research_replanning.py`에서 두 실패 연결, 관리자 네 가지 선택, 승인·예약 분리, 전문 자료만 사용한 원문 연결과 독립 검토, 자료 부족 보류, 변경된 범위·키·만료·철회·중복·동시 실행, HTTP 503 및 관리자·직원 타임아웃 중단을 확인했다. 비영상 재고 fixture에서 공통 계약을 사용했다. `tests/test_cutroom_next_action.cjs`에서 누적과 추가 한도, 대기와 중단 화면을 확인했다.
- 기존 운영 파일 198개의 작업 전후 SHA-256이 동일했다. 비밀키와 잠금 파일은 비교 목록에서 제외했다. 승인·원장, 대본 v2, WAV 4개, MP4 1개, 대표 평가, 제작사와 Commons 기록을 보존했다. 새 운영 승인 파일 및 추가 백업을 만들지 않았다.
