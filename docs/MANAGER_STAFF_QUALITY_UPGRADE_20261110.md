## 오늘의 목표
사용자가 어제 실제 Google Flow 영상 3개 + MeloTTS 한국어 음성 + 자막을 합쳐 60초/9:16로 완성한 기술 시안을 **10점 만점에 2~3점**으로 평가했다. 시험용 한 사이클은 돌아갔으나 게시 품질이 아니다.

오늘은 화면/UI나 영상 클립 생성 도구를 더 붙이는 날이 아니다. **AI 관리자가 낮은 품질의 원인을 판단하고, AI 직원이 구체적으로 개선할 수 있는 실무 역량**을 갖추게 하자. 다음에 실제 영상을 만들면서 자연어 피드백으로 성장하는 운영 단계로 넘어갈 합격 조건은 `docs/OPERATIONS_READINESS_GATE.md`를 따른다.

중요: '경험 축적'은 추론 모델 가중치 재학습이 아니라, 구조화된 검증 기록을 저장하고 적절한 다음 프로젝트에서 근거와 함께 재사용하는 것이다. 모델에게 코드를 이용한 단순 룰검사/모의 답변을 시켜 놓고 실제 AI 자율 판단이라고 주장하지 않는다.

## 실무 품질 기준 — 총 10점 (객관+주관 혼합)
평가 지표는 아래를 일관되게 사용. 실제로 볼 수 없는 결과에 대해 감각 품질 점수를 임의 산정하지 않는다.
- 대본/기획: 0~3점. 초반 3초 관심 유도(0~1), 목표 시청자에 맞는 한 가지 분명한 메시지(0~1), 사실 정확성과 구체적 유용성(0~1)
- 영상/편집: 0~3점. 화면과 대본 의미적 일치(0~1), 소스 다양성·과도한 반복 회피(0~1), 9:16 시각 구성·자막과 가독성(0~1)
- 음성/자막: 0~2점. 이해 가능한 발음·어조·속도(0~1), 자막-발화 동기와 읽기 편의성(0~1)
- 전체 완성도: 0~2점. 처음~끝 이야기 흐름과 밀도(0~1), 목표 시청자에게 유익하고 게시 수준이라 느껴지는지(0~1)
- 증거 부족시 해당 항목은 `unassessed`, 근거 출처 명시. 미평가를 자동 합격/0점으로 환산하지 않는다. 위험한 허위점수보다 미평가를 우선.
- 사용자 현재 평가는 2~3/10이라는 **주관적 기준선**, 모델/자동 평가 2~3점인 것으로 조작하지 않는다.
- 초기 운영 전환 목표 제안: 사용자 평가 7/10 이상을 지속적으로 지향. 그러나 지표 자체를 맞추는 편법보다 실제 시청 품질 개선을 우선.

## AI 관리자 강화 (공통 core)
- 입력: 목표, 사용자 답변/제약, 도메인 회사의 capabilities, 이전 관련 피드백, 비용·호출 권한.
- 산출: 구체적 제작 전략(대상/핵심 메시지/흐름/장면별 이야기와 소스 필요량/대본 방향/목소리 요구조건), 업무 분해와 담당·의존성·완료 기준, 사용자 질문 필요 여부와 이유, 승인 차단 요소.
- AI 직원 결과를 **적절한 평가 주체/기준**에 따라 검토. 결함마다 근거, 심각도, 담당자, 재작업 요청, 기대 개선 지표를 명시. 개선 후 전/후 비교; 실패하면 횟수/비용 한도 내 재수정 또는 정직하게 `needs_user_review` 표기.
- 별도 새 고정 키워드 규칙으로 사용자 답변을 강제하는 대체 AI 관리자 금지. 실제 AI/provider 연동 가능한 스키마·프롬프트/계약을 설계하되 지금 새 유료 또는 외부 실제 AI 호출은 사용자 승인 전 금지.

## AI 직원 강화 (영상 회사)
- 기획/대본 직원: '1분에 10개 설명' 같은 과밀 목표면 사용자 가치에 따라 우선순위 및 구성 조정; 도입 후크(0~3초), 핵심 사례, 이해 가능한 시연/증거, 짧은 마무리. 필요 시 관리자에게 목표 재확인 요청. 한국어 자연어·확인되지 않은 정보 구분.
- 영상 기획/편집 직원: 한 종류의 5~8초 클립을 20초 반복하여 화면을 채운 기존 문제를 인식. 60초 장면별 촬영/생성 샷 목록과 소요 길이, 내레이션-장면 대응, 교차편집·실제 시연 필요 여부, 안전한 소스 부족 대기를 제안. **외부 실제 클립을 생성한 척하지 않음**.
- 음성 직원: 현재 MeloTTS 한계를 기록. 발음하기 쉬운 자연어 대본, 이름/영어 표현 보정, 목표 시청자에 따른 목소리·속도·톤 기준 제안. 자연스러움 품질은 사용자 청취 또는 승인된 실제 평가가 없으면 미평가로 남김. 별도 새 TTS/유료 API 도입·모델 다운로드는 이번 작업 금지.
- QA 직원: 실제 기술적 미디어 검사와 콘텐츠 평가를 분리; 근거 없는 게시 합격 금지. 작업 생성-평가-수정의 품질 루프를 한 번 시연.

## 자연어 피드백과 경험 사용
사용자 예시: `대본이 밋밋하다`, `화면이 계속 반복된다`, `음성이 기계 같다`, `30~40대 주부용이면 친근한 말투가 좋겠다`.
- project/target segment/issue/positive preference/proposed correction/evidence/source/version/confidence/verified-or-hypothesis를 저장, 수정·철회 가능.
- 다음 유사 시청자 대상에서는 적절한 경험 ID를 검색·적용한 근거를 남김. 다른 대상에는 무분별한 일반화 금지.
- 저장만 하고 실제 다음 대본·샷플랜·음성 지시서 변경이 없으면 미통과.
- '자동으로 개선되었다'는 주장은 전후 비교의 근거가 있을 때만.

## 개발 실행 범위 — 한 묶음
1. 기존 코드와 어제의 구현 상태를 재사용하는 설계를 간단하게 먼저 기록. 부적절한 대규모 폴더 이동/전면 재작성 금지.
2. `core/`에 재사용 가능한 관리자 판단·직원 handoff·QA 판정·수정 사이클·피드백 경험 컨텍스트를 최소한으로 확장. **공통 업무 흐름은 core**, 쇼츠의 후크·영상 다양성·자막·발음 등 규칙은 `companies/video/`.
3. 실제 모델에 전달할 명확한 역할별 지시와 출력 계약을 준비해 미래에 허가받은 모델 연결 시 사용 가능하게 한다. 추론/도구 결과·모의/룰 기반 출력을 메타데이터로 분리. 사용 허가 없이 새 모델 호출하거나 호출 차단 장치를 우회하지 않는다.
4. 소스가 부족하면 `external_clip_pending` 상태로 멈추고 사용자 수동 생성/업로드 필요만 알림. 실제 완성품 없이 완료 처리 금지.
5. 사용자 중간 승인 남발은 금지하지만 권리·비용·실제 외부 전송 승인 게이트는 유지.
6. 기능 묶음 개발 후 **마지막에 통합 테스트 한 번**: 초보자 60초 영상 목표 → 관리자 계획 → 관련 직원 결과 인계 → 밋밋한 도입부/반복 클립 결함 탐지 → 관리자 재작업 → 개선 전후 대본·샷 계획 비교 → 자연어 피드백 저장 → 유사 목표 재사용 / 다른 시청자군 비적용 → 예산·권리·중복실행 안전 확인. 실제 네트워크 호출 없이 mock/fixture 검증은 그 사실을 결과에 분명히 기록.
7. 스코어 합격을 조작하는 테스트, fixture 소스의 '실제 AI 영상' 허위 표시, 실제 AI 판단 없는 '자율 회사 달성' 선언 금지. 못 하는 항목은 미구현/미평가로 보고.
