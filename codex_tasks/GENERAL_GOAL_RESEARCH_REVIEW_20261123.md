## 사용자 승인 범위

## 구현 절차
1. 안전 동기화 전 로컬 미커밋 상태와 운영/시범 프로젝트·승인/외부요청 원장·평가를 확인하고 보존. GitHub main을 확인 후 안전하게 동기화한다. 기존 프로젝트의 goal/audience/language/platform/duration/notes 및 mission job, planning job, provider action 가용성에서 실행이 안 되는 실질 원인을 재현. 원래 미완료 조사·기획 업무를 보존하고 중복 작업을 만들지 않는다.
2. **현재 기능 재사용 우선**으로 기존 자유 목표 실행 경로(budget/general mission/planning)가 가능한지 확인한다. 가능하면 작은 UI/상태 연결 수정만 하고 우회할 수 있는 기존 API를 재사용한다. 불가능하면 공통 조사·기획 job의 범용 지원을 필요한 최소 범위로 추가. GAME_GOAL 이름을 자유 목표로 치환하는 문자열 패치 금지. 과거 고정 GAME_GOAL 프로젝트 및 정상 승인된 과거 report/ledger 처리 유지.
3. 자유 목표 텍스트와 추가 요구(최근 모바일 게임 쇼츠 실제 관찰, 조회수와 관측 날짜·원문 출처, 길이 분포, 주제 3개, 매력 포인트, 자료 이용 가능성과 권리 상태)를 실제 AI 직원이 읽고 작업 계획/독립 자료 수집/관리자 검토 후 **대표용 조사·기획 보고서**에 반영. 자료가 없으면 가설/미확인/조사실패를 명시하고 조회수·날짜·링크를 만들어내지 않음. '인기' 주장에는 관측 자료가 반드시 있어야 하고 근거 부족이면 보류 또는 추가 자료 필요로 보고.
4. **기획 보고와 대본을 분리**한다. 이번 프로젝트는 조사 보고와 주제/길이 제안만 표시하며 실제 AI가 대본/음성/영상 제작을 하지 않는다. 승인·수정·반려 동작이 새 report와 연결되는지 검증. 사용자 수정지시에는 기존 버전과 피드백을 전달하고 새 버전 저장; 이전 기록은 읽기 전용 보존. 필요하다면 이번 단계 전용 보고서 상태를 구현하되 과도한 범용 재설계·새 자율형 엔진 개발 금지.
5. 컷룸에 다음 행동이 없으면 활성 상태/차단 사유를 정확히 표시하고 실제 실행이 가능하면 '실제 조사 시작' 행동을 노출. 비용/공급자·모델·전송 데이터·호출 한도 확인/동의 경로는 기존 규칙을 지킨다. 기존 project 예산/동의가 새 자유 목표를 허용하지 않는다면 승인 범위를 새로 확인. 설정/키/무료 등급 미확인시 실행 전 막고 이유 표시. **승인 없이 실제 Gemini/Tavily/YouTube/외부 API 호출 0회**, 실패/미확정 자동 재시도 0회. 기존 503 원장은 변경하지 않는다.
6. 오프라인 모의 HTTP/provider로만 재현/검증: 새 자유 목표에서 보고서 초안 생성·승인 대기, 수정을 주면 이전 의견 보존한 새 보고서, 과거 고정 GAME_GOAL 미션 영향 없음, 중복 생성 방지, 대표 승인 전 downstream 대본/제작 차단, 출처 미확인 보고와 실제 AI 보고 구분, 상태가 명확한 UI. 실제 AI 호출 성공은 **실제 호출과 유효 응답이 있었을 때만** 주장하며 모의 응답을 실제 보고로 표시하지 않는다.
7. 서버 실행 상태를 추측하지 않고 현재 프로젝트의 화면 위치와 사용자가 다음에 눌러야 할 정확한 버튼, 승인 조건 및 정지 조건을 결과에 남긴다. 실제 외부 실행은 대표에게 다시 승인받기 전까지 진행하지 않는다.
8. 기존 운영 로컬 아티팩트/평가/시도·승인·비밀키 보존 확인; 수정된 기능 관련 테스트만 실행. 보고서 reports/GENERAL_GOAL_RESEARCH_REVIEW_RESULT_20261123.md에 [수정 전 차단 원인/수정 경로/테스트 종류·결과/실AI 호출 여부/사용자 버튼 동선/남은 승인 필요사항]을 기록. 관련 코드 및 결과만 commit/push main, 원격 SHA 검증. 불가하면 정확한 장애와 최소 대안 보고하고 강행하지 않는다.

## 품질 완료 기준
새로 만든 **현재 모바일 게임** 프로젝트를 그대로 사용, UI에서 대표가 1회 명확한 실행을 승인할 수 있는 상태, AI에게 원 목표가 실제로 전달됨, 연구·기획 보고서가 화면에 나오고 대표 수정·재작성·승인 가능하며 기록 보존됨. 실제 외부 호출은 별도 명시 승인 전까지 수행하지 않으므로 개발 완료와 실제 AI 콘텐츠 품질 검증은 분리. 불필요한 대본 작성·영상 제작 없음.
