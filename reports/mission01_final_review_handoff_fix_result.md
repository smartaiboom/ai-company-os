# 미션 01 최종 기준 집계 및 무호출 대표 제출 복구

## 실제 원인

2026-11-18 16:25:58 KST의 스토리보드 관리자 검토는 Gemini **1회**, HTTP 200, 역할 결과 `validated`였다. 응답 해시와 검토 대상 스토리보드 해시를 저장된 결과와 대조했다. 대본과 시스템 스토리보드는 모두 `accepted_by_ai_manager`였고 미확정 호출은 없었다. 작업은 편집 검토 이후 `finalize`에서 `invalid_checks`로 중단됐다.

기존 최종 제출은 대본 검토의 5개 기준만 복사했다. 계획에는 7개가 있었고, 스토리보드 검토는 7개 모두 수락했다. 따라서 대본 검토에 배정되지 않았던 장면 구성과 출처 참조가 최종 목록에서 누락됐다. 편집 검토의 수락 기록은 그대로다.

## 변경

- 업무별 최신 버전 및 해당 수락 리뷰를 확인하고, 계획 순서대로 각 기준을 한 번씩 포함한다. 공동 기준 5개는 대본과 스토리보드 양쪽의 `met`가 필요하다. 장면 구성과 출처 참조 2개는 스토리보드의 수락 검토를 사용한다. 배정·버전·검토가 맞지 않거나 누락 또는 미충족이 있으면 제출을 차단한다.
- 최종 기준 목록과 업무별 버전 참조는 시스템이 계산한다. 최종 기준의 출처는 `system_aggregation`이며, 각 기준에 해당하는 업무·버전을 표시한다. 모델의 원본 근거와 출처는 업무별 검토 이력에 보존하고 Markdown에서도 구분해 표시한다.
- 복구는 확인된 최종 집계 오류만 대상으로 한다. 기존 서명 동의의 유효 기간, 원장과 검토 대상·응답 해시, 대본과 시스템 스토리보드의 계보를 재검증한다. 대표의 명시적 제출 동작으로만 로컬 v2를 만든다. 중단된 작업 파일·원장·동의·대표 결정은 덮어쓰지 않으며, v2에는 로컬 복구와 기존 중단 이력을 연결한다.

## 대표 다음 조작

컷룸을 새로고침한 뒤 기존 프로젝트에서 **최종 기준 집계 · 대표 제출 → 기존 검토로 대표 제출 복구 → 대표 승인 대기로 제출**을 선택한다. 이 동작은 외부 전송과 새 동의 생성 없이 v2를 **기획 승인 대기**로 제출한다. 기획 승인 자체는 별도다.

현재 동의의 만료 시각은 **2026-11-18 17:25:47 KST**다. 만료되면 버튼으로 제출할 수 없다. 만료를 우회하거나 기존 호출을 자동 실행하는 경로는 추가하지 않았다.

## 검증

- 핵심 통합 및 컷룸 테스트 **102개 통과, 실패·오류 0개**였다. 누락·중복·미충족·최신 버전 불일치 차단과 공동·편집 전용 기준이 있는 모의 정상 제출을 확인했다. JavaScript 문법 검사와 `git diff --check`도 통과했다.
- 운영 파일은 읽기 전용으로 사용했다. 임시 복제본에서 실제 서명을 읽기 전용 HMAC 계산으로 검증하고, 컷룸 HTTP 경로에서 최종 기준 7개·업무별 버전 참조·기존 승인 계보가 포함된 v2를 생성했다. v1과 대표 결정이 그대로였으며, 운영 및 복제본의 기존 작업·동의 파일은 수정되지 않았다.
- 복제본의 프로젝트 상세와 v2 Markdown을 확인했다. 토큰 없는 요청은 HTTP 403, 잘못된 상태 해시·만료된 동의·중복 제출은 HTTP 409였다. 만료 검증은 복제본에서만 시간을 바꿔 검사했다.
- 진행 중 호출이 없음을 확인하고 운영 컷룸을 기존 환경과 작업 루트로 재시작했다. 실제 localhost의 GET 조회에서 복구 가능 상태와 최신 JavaScript를 확인했다. 운영 프로젝트는 기존 중단 상태를 유지했고 재시작 전후 JSON이 일치했다. 운영 제출 버튼 클릭은 검증하지 않았다.
- 누적 Gemini **20회**, YouTube **4회** 기록을 보존했다. 이번 작업의 실제 Gemini·YouTube 요청, 운영 대표 결정 및 운영 동의 생성은 **0회**였다.
