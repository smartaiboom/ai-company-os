# Gemini 재차 중단 진단과 요청 계약 수정

## 운영 증거

2026-11-23 16:15:24 KST, 일반 모바일 게임 조사 v5의 후속 범위에서 직원 보고서 작성 `research-10` 요청을 예약했습니다. 16:15:25 KST에 응답을 여는 단계에서 Gemini HTTP **400 `INVALID_ARGUMENT`**를 받았습니다. Gemini는 예약 1회·완료 0회, Tavily는 0회입니다. 모델의 성공 응답 수신 표시와 토큰 사용량은 없습니다. 공급자 오류 원문과 거절 필드는 미보존이며, 모델 출력·청구 여부는 미확인입니다. 원본 v5의 15:59:14 KST 요청도 같은 HTTP 및 공급자 상태였으나 두 건의 세부 사유가 같은지는 미확인입니다.

후속 범위는 원본의 성공한 직원 판단을 다시 호출하지 않았습니다. 앞선 보고서의 보존 출처 7개와 원본 실행의 YouTube 표본 5개가 새 직원 보고서 입력에 포함됐습니다. 후속 범위에서 YouTube 검색 8회·상세 조회 7회가 모두 완료됐고 영상 메타데이터 22개가 추가됐습니다. 검색 한 건은 정상적으로 표본이 없었습니다. 최종 입력은 관측 묶음 10개와 출처 ID 34개였고 관리자 검토는 시작되지 않았습니다. 기존 범위의 Gemini 2회·YouTube GET 16회 상한과 예약 차감은 유지됩니다.

## 전송 구조 비교

세 파일의 바이트를 현재 REST 직렬화와 대조하고 예약 페이로드 해시와 일치함을 확인했습니다. 공통 요청은 `gemini-3.5-flash-lite`의 `v1beta/models/{model}:generateContent`에 대한 POST입니다. 송신 어댑터에서 JSON 본문과 `Content-Type: application/json`, `x-goog-api-key` 헤더 배치를 확인했습니다. 과거 실제 헤더 값은 미보존입니다. 세 본문은 동일한 1,569바이트 시스템 지시, `responseMimeType: application/json`, `responseJsonSchema`, `maxOutputTokens: 4096`, 온도 0.2를 사용했습니다. 조사 도구는 본문 텍스트로 제시하며 REST 함수 호출 도구를 보내지 않습니다. ## 수정 및 검증

- 일반 조사의 Gemini 전송 스키마를 단순화했습니다. 조사 선택 분기를 합치고 출처 ID 목록과 도구 옵션은 입력에 유지했습니다. 직원과 관리자 응답의 출처 일치, 허용 옵션, 조기 종료, 건수와 게임별 검증은 기존 로컬 검증기가 계속 적용합니다. 저장 요청을 오프라인에서 같은 입력으로 재구성해 원본 실패 본문은 29,719 → 22,309바이트, 후속 실패 본문은 39,638 → 38,686바이트로 줄어드는 것을 확인했습니다.
- 이후 HTTP 오류에는 제한된 본문 길이 또는 잘림 표시, 허용된 상태·필드 그룹과 알려진 스키마 복잡도 문구 감지 여부만 남깁니다. 공급자 원문이나 원래 필드 경로는 저장하지 않습니다. 새 전송 계약은 새 요청의 서명에 반영됩니다. 기존 실패 예약의 재전송 또는 자동 재개는 없습니다.
- Python 44개와 컷룸 Node 검증이 통과했습니다. 모의 400과 200, REST 헤더와 본문, 34개 출처에서 허용·미등록 ID 판정, 오류 상세 비노출을 확인했습니다. 로컬 운영 파일 822개의 작업 전후 SHA-256이 일치했습니다. 실제 Gemini·YouTube·Tavily 호출은 0회였으며 운영 v5 후속 범위는 여전히 중단 상태입니다. 실제 공급자가 새 요청 구조를 수용하는지는 검증되지 않았습니다.
