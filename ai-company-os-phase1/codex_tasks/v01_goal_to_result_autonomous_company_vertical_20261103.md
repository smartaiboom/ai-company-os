# AI Company OS v0.1 — 목표 입력부터 최종 산출물까지, 사용자 중간 결재 없는 AI 회사 자율 운영 수직 완성

## 0. 절대 먼저 읽을 기준 — 변경 금지
최우선으로 **`AI_COMPANY_OS_CORE_PRINCIPLES.md`**와 **`AGENTS.md`** 전체, `codex_tasks/README_KOREAN_LANGUAGE_RULE.md`를 읽고 그대로 따른다.

이번 사용자 요청: “그래 알겠어 항상 저 문서를 수시로 참조해! codex에게 명령 방식 바꾼것도 기억하지? 전체적으로 맡기기로 한거? 다음 진행해줘.”

**업무 목표와 완료 기준만 부여한다. Codex가 코드 전체를 분석하고 필요한 설계·개발·오프라인 검증·수정·보고를 스스로 주도하라.** 파일 하나·버그 하나마다 지시서를 쪼개거나 사용자에게 개발 판단을 재질문하지 말 것. 이 위임은 **개발 자율성**이지 실제 AI 공급자 호출 권한/운영 안전 동의의 위임은 아니다.

### 제품의 단 하나의 핵심 목표
**사용자가 프로젝트 목표를 한 번 입력하면 AI 관리자와 AI 직원이 실제로 계획·업무 배분·품질 기준 제정·실행·결과 전달·검토·수정·최종 통합까지 수행해 사용자에게 완성된 결과물을 제출한다.** 계획 승인, 결과 승인, 관리자 proceed 승인, 품질 기준 승인, 수정 승인 같은 *업무 내용의 사용자 중간 결재*는 정상 운영 과정에 존재하면 안 된다. AI 관리자가 자율적으로 결정해야 한다. Codex 자신이 업무 판단이나 품질 기준을 실제 대신 정해도 안 된다. 이것은 영상 특화 시스템이 아니라 어떤 업무 목표에도 적용할 범용 AI 가상 회사다.

## 1. 이번 작업의 결과물(반드시 실제 구현)
**기존 프로그램을 보존하면서, 기존 수동 승인 방식과 별도로 안전한 'AI 회사 자율 운영 모드'의 최소 기능 수직 경로를 코드로 구현**하고, 가상 프로젝트+가짜 AI 관리자·직원 공급자로 목표 입력부터 최종 결과 생성까지 end-to-end 실행해 동작을 입증한다.

Codex가 자율적으로 선택해야 할 개선 방향 예시(방법은 자유, 기준은 엄격):
- `app.py`, `manager_decision.py`, `manager_plan.py`, `execution_engine.py`, `semantic_review.py`, `ai_safety.py`, `ai_provider_adapter.py`, 기존 진행/승인/저장/원장 구조를 **전체 흐름 관점에서** 분석.
- 수동 승인 로직을 무작정 삭제·전체 교체하는 대신, **명시적 모드 opt-in** 또는 안전하게 분리된 도메인 프로세스로 **내부 'AI 관리자'의 작업 판단·검토가 수동 승인을 대신하도록** 설계한다. 모델 판단을 근거 없이 approved로 날조하지 말고, **내부 모델의 실제 역할별 제안/평가 + 시스템의 검증 가능한 안전 검사를 구분한 감사 기록**을 남긴다.
- **AI 관리자가 목표/도메인에 맞춘 계획과 평가 기준을 만들도록** 한다. 개발용 mock 테스트는 가짜 모델 출력을 fixture로 제공할 수 있지만, 실제 제품 로직에 Codex가 품질 기준·사업 판단·동영상 분량 등을 상수로 넣으면 실패다.
- AI 직원이 업무 결과를 만들고, 서로 선행 산출물과 검토 의견을 전달하며, 관리자가 품질 평가/수정·재검토, 후속 업무 진행, 최종 결과 통합을 스스로 지휘하게 연결한다. 품질 문제가 있으면 내부적으로 수정 지시→직원 수정→재검토를 수행하되 **호출/수정 횟수 상한·시도 영속 기록·종료 조건**으로 무한 루프 차단.
- 필요 시 '업무 자체가 목표/리소스와 모순', '도구/근거 부족' 상태에서는 관리자에게 재계획 또는 불확실성 명시를 허용. **기본적으로 사용자의 업무 내용 결정을 요구하면 목표 실패**로 간주. 진짜 외부 데이터 제공·예산/과금 증액·권한 승인 등이 필요할 때만 사용자를 호출한다.
- 화면/상태 보고가 실제 자동 흐름을 보여주도록 사용자의 반복 승인 버튼 대신 진행 현황·결과·근거·중지 사유를 보여준다. 새 엔드포인트를 만든다면 **실사용 전송을 묵시적으로 켜는 버튼은 절대 안 됨**. UI 추가는 핵심 실행 흐름이 완성된 다음 최소 범위로.
- 최종 결과를 단순 '테스트 통과' 메시지가 아니라 **직원 결과·관리자 평가·수정 이력·최종 산출물이 저장되고 사용자에게 볼 수 있는 형태**로 입증. 가상 성공과 실제 AI 성공을 구분.

## 2. 반드시 보존할 안전 경계
이번 작업은 **실제 AI API 호출 0회** 및 **실사용 프로젝트 실행·승인·데이터 변경 0회**. Codex가 바뀐 구조를 실제 API에 연결해 자동 호출하도록 활성화하는 것은 이번 승인 범위 밖이다.

현재 실사용 프로젝트 `cb44b605b498`: 2026-11-03 최신 보고 기준 **9/20회**, 앞 9건 완료/실패·예약 0, TASK-001/002 완료·사용자 승인, TASK-003/004 대기, 마지막 관리자 `ask_user` 제안에 사용자 답변이 `answered`로 저장됨. 이 프로젝트는 **읽기 전용 현황 확인만 허용**, JSON을 절대 변경하지 말 것. 이전 데이터/백업/guard/사용자 동의/원장 모두 불변. 타 프로젝트 `c85d9853906a`의 미확정 예약 절대 변경·해제하지 말 것.

현행 **실사용** 보호 `openrouter/free`, 고정 HTTPS URL, API 키 비노출, 사전 데이터 전송 동의, 실제 호출별 현재 요구되는 별도 승인, 프로젝트별 기본 20회 예산, 요청 전 예약 영속 저장, 2회/시작 제한, 실패/timeout도 사용량 차감, 자동 재시도 없음, 불확실 예약 차단, 금전적 비용/권한 변경 동의 등을 임의 제거·우회 금지. **제품 목표의 '중간 업무 승인 없음'과 '실제 호출 사전 동의·비용·중복 전송 방지'는 별개의 정책**이다. 자율 운영 모드는 이번에는 **mock-only로 실행/종단간 검증**. 실사용 모드에서 실제 업무 호출이 필요하면 미래에 사용자 사전 설정한 프로젝트당 전체 외부 전송/호출·비용 한도 안에서 자동 실행하는 별도 승인 설계를 제안할 수 있으나 **이번에 자동 실사용 활성화/비밀 설정·공급자 허용 목록 완화는 절대 금지**.

코드에 영상 1분, TASK-003, TASK-004, 10가지 팁 등을 일반 로직으로 하드코딩 금지. 기존 원본 API와 이전 테스트 최대한 보존. KST(UTC+9). 기존 미추적 파일, data/backups, git 제외 실사용 데이터 삭제·수정 금지. git reset/clean/force push 금지. 새 백업 중복 생성 금지.

## 3. Codex 자율 개발 과정 (중간 허가 불필요한 영역)
A. 현행 정상 수동 흐름과 보호 경계를 도식화/기능별 소유권 분석. **사용자 중간 승인 다섯 종류(계획/관리자 판단/직원 결과/품질 기준/수정)를 이번 mock 자율 모드에서 실제 AI 관리자·직원 흐름으로 치환하는 설계**를 택한다. 사소한 UI/테스트에 매몰되지 말고 end-to-end 실무 결과가 먼저다.

B. **모의 모델이면서도 모델 결정과 직원 결과의 출처를 분리한 가짜 provider**를 사용해, 업무 관리자의 역할 판단이 어디서 나왔는지 구별. 테스트는 모델의 임의 프로포절/평가를 통과시켜, Codex가 결과를 하드코딩하지 않았음을 보여야 한다. 사용자 승인 필드에 가짜 '사용자'를 기입하는 방식으로 자동화 **금지**. 새 명시적인 `ai_manager_decision` 감사와 모델 결정 기록으로 운영 승인/사용자 승인 역할 구분. 내부 자동 결정이 기존 live `require_proceed`/사용자 결재를 우회하게끔 기존 live 코드만 약화시키지 말 것.

C. 종단간 시나리오를 실제 수행:
- 임의 목표 A: 계획→프로젝트별 기준→두 명 이상 다른 AI 직원에게 작업 배정→직원 선행 결과 전달→관리자 검토→품질 통과→최종 보고/결과 파일. **사용자 중간 업무 승인 호출 0**.
- 다른 도메인 목표 B: 중간 직원 결과 품질 미달→AI 관리자 수정 지시→직원 재작성→재검토→후속 실행→최종 제출. **사용자 승인 0**.
- 오류/모호한 사실/사용 가능 예산 소진/안전 경계 위반/반복 실패→근거 보존 후 안전 정지·보고, 무한 호출·무한 반복 없음. 사용자의 실제 추가 비용 동의가 필요하면 그때 운영상 승인을 요청한다.
- 두 목표의 계획/품질 기준이 각각 모델 입력에 따라 달라지고 서로 고정되지 않음을 확인.
- 저장 후 새 프로세스에서 재조회, 중지 후 재개 시 중복 작업/전송·승인 위조 방지.

D. 관련 기존 회귀 테스트를 집중 실행. 실패 원인을 Codex가 분석하고 개발 범위 내에서 고치고 재시험하며, 불필요하게 테스트를 수백 개 추가할 필요는 없음. 테스트 스텁이나 승인 기록만 조작해서 성공 표시하면 실패. 실제 HTTP 통합 테스트의 로컬 소켓 제한은 별도 보고, 거짓 통과 금지.

E. 최종적으로 안전한 수동→자율 전환을 위해 **지금은 무엇이 mock-only인지, 실제 모델로 안전하게 연결하려면 어떤 외부 호출 사전승인/원장/모드 격리가 남았는지** 구체적으로 문서화. 기존 실사용 `cb44...`은 이번에 자율 모드로 변경/마이그레이션하지 않는다.

## 4. Codex 작업 범위 결정권
필요한 관련 코드 파일·테스트·문서 수정을 **Codex 스스로 결정하고 이어서 진행**한다. 지시서대로만 최소 한 파일 수정하는 것이 목표가 아니다. 다만 불필요한 대규모 전면 재구축/기존 검증 삭제는 금지. 기술적으로 한 번에 전부 못 하면 **가장 중요한 mock 자율 end-to-end 실행 경로를 실제로 완성**, 미완성 라이브 연결은 정직하게 남겨라. 작은 하위 명령마다 사용자에게 물어보지 말라. 개발 선택에는 Codex가 책임지고, 예산/데이터 삭제/외부 서비스 실제 호출에는 멈춘다.
