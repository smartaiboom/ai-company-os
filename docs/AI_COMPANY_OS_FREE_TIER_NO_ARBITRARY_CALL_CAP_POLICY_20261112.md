사용자는 이전에 합의한 '미션 01 Gemini 10→20, YouTube 각 4→8' 방식을 재검토하고 명확히 정정했다.
"임의로 한도를 정해놓은 게 무슨 의미가 있는 거야? 유료 전환만 승인받도록 하면 무료 안에서는 마음껏 테스트해야 하는 거 아니야? 상한 꽉 차면 테스트 진행 안 할 거야? 어차피 할 거잖아? 쓸데없이 호출 안 하고 반복 호출 안 하면서 무료 안에서 충분히 테스트해야 하는 거 아니야?"

**본 지시서는 `docs/VIDEO_MISSION_01_DOUBLE_CALL_BUDGET_20261112.md`의 임의 상한 20/8/8 확대 정책을 대체한다.** 이미 발생한 과거 한도·동의·실패·서명/원장 기록은 삭제하거나 소급 변경하지 않는다.

## 목표
무료로 사용 가능한 범위 내에서 실제 AI 작업·테스트를 불필요하게 중단시키는 '내부 임의 호출 상한'을 **새 승인·실행 경로에서 제거**한다. 실질적 안전 경계는 다음과 같다.
1. **공급자가 실제로 허용하는 무료 모델/프로젝트/API/할당량·속도 제한**만 활용한다. 공급자의 공개 정책/계정 설정에서 무료·결제 연결 여부가 확인 불가하면 과금되지 않는다고 단정하거나 임의로 공급자 한도를 추정하지 않는다. 무료 서비스만 사용하는 기존 사용자 진술·계정/모델 고정/결제 미연결 전제를 계속 검증하며 불확실한 유료 경로는 차단한다.
2. **유료 전환·유료 모델/서비스·결제 계정 연결·유료 사용을 야기할 수 있는 설정 변경은 명시적 대표 사전 승인 필요.** 무료 사용 예산 10/20/4/8 같은 숫자에 따른 추가 대표 승인은 요구하지 않는다. 모델, 공급자, 외부 전송 목적/데이터 범위가 변경되면 기존 데이터 동의 정책을 준수한다. 유료 전환 여부는 단순 호출 카운터로 판단하지 않는다.
3. 사용량은 정확히 기록한다: 공급자·계정/모델/API 작업·시도·성공/실패·시간·공급자 quota 오류/429·불명 전송 및 가용한 토큰·요청 사용량. 단순 계측은 실행 권한을 새로 부여하는 것이 아니다. 실제 공급자 quota가 확인되지 않으면 unknown. 공급자 quota 소진·429/무료 제한 발견 시 즉시 차단하고 정책을 준수; 제한 우회, 계정 순환, 유료 fallback 금지.
4. **반복 호출 낭비 방지**: 검증된 조사/관리자 선정/직원 중간결과 재사용, API 요청 전 지역 단위 유효성/형식 검사와 오프라인 테스트 우선, 동일 작업 자동 재시도·무한 루프·오류 원문 없는 무작정 재호출 금지. 모델 응답 검증 실패 시 오류를 기록해 진단하고 필요 시 코드 수정 후 *새 목적이 구체적인 다음 요청*을 수행하도록 설계한다. 완료된 업무를 처음부터 재수행하지 않는다. 실패/타임아웃/결과 불명 요청은 보존하고 불명 상태의 자동 재전송은 금지.
5. 내부 예산 원장/승인 UI는 이미 개발한 기능이므로 삭제하지 않는다. **선택적 프로젝트별 예산/사용량 관측·대표가 실제로 지정한 제약·유료 승인 보호** 역할로 유지한다. 신규 기본 실행에서는 임의 호출 수의 소진이 진행 차단 조건이 되지 않게 해야 한다. 단, 사용자나 조직이 별도로 **명시한** 제한은 계속 엄격히 지킨다.
6. 기존 4개 stopped 업무·과거 실제 Gemini 7회, YouTube search 2회/videos 2회·기존 동의·서명·실패 원장은 원본 불변. 새 방식은 **향후 별도로 승인·검증된 독립 작업**에만 적용하고, 기존 서명된 10/4/4·20/8/8 숫자를 직접 바꾸지 않는다. 이전 실패 업무를 억지로 run하거나 과거 승인 가드를 우회하지 않는다.
7. 미션 01의 목적은 YouTube로 실제 관측한 자료와 관리자 선정(롤토체스 소재, 25초)을 재사용해 AI 대본→AI 관리자 검토→스토리보드→검토→**동일 컷룸 대표 승인 대기**까지 도달하는 것이다. 이 목적을 예산 관리 리팩터링 때문에 더 지연시키지 않는다. 예산 정책 적용에 필요한 최소 변경만 하고, 실전 진입 준비와 오프라인 종단 테스트까지 한 번의 작업으로 묶는다.
