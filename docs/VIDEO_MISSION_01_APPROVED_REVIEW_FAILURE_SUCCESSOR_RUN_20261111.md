## 실행 목표와 최소 작업 절차
1. 안전하게 최신 main을 fast-forward, `git status`와 로컬 원장을 확인한다. 키·데이터·미추적 파일은 보존한다. 이미 끝난 DNS/결제/쿼터 감사나 전체 코드/테스트 재수행 금지.
2. **과거 조사 자료 재사용 가능성을 최우선 판단**한다. 두 번째 업무 원장에 보존된 AI 직원의 validated 조사 결과, 실제 YouTube 메타데이터 10건, 영수증 SHA·증거 ID·생성시간·30일 보존 정책·원본 작업 연결을 확인한다. 미검증 관리자 feedback/selection은 재사용하지 않는다. 원본, 출처, 무결성, 기간과 동일 목표 연결을 검증할 수 있으면 그 validated 조사 결과만 다음 분리 업무에서 재사용하도록 최소 변경한다. 검증 불가면 재사용 불가로 명시하고, 남은 YouTube 2+2 내에서 직원이 **새로운 조사 질의를 스스로 생성하는** 정상 경로를 택한다. 기존 공개 정보나 후보를 Codex가 임의로 주입·편집하지 않는다.
3. 현재 보존/서명/시도 가드를 유지하면서 **두 번째 실패 업무 다음의 분리 후속 업무**를 생성하는 안전 경로가 존재하는지 확인한다. 기존 `stage_mission_resume`/공통 엔진을 최대한 재사용하되 **첫 DNS 실패 전용 가드를 완화하거나 속여 통과하지 말 것**. 이 오류 유형의 새 successor 경로가 없다면 기존 사용 이력과 상한을 증명 가능한 방식으로 연결하는 **최소 범위 추가 구현** 및 관련 오프라인 테스트만 수행한다. 어떤 경우에도 구 2개 stopped 업무 및 consent/attempt/active_operation을 변경하지 않는다. 기존 작업과 구 결과가 새 작업으로 연결되었다고 허위 표시하지 말 것.
4. 새 업무 grant/제안은 독립적이어야 한다. 체인에 두 과거 업무·시도 참조, Gemini 누적 4회·새 최대 6회/총 10회, YouTube 각 누적2·새 최대2/총4회, 무료 프로젝트, 명시적 새 research/review 구조 계약의 해시, 적절한 검토 입력을 담고 새 승인 서명을 요구한다. 검토/해시 확인 없는 승인 생성 금지. 과거 서명·제안 재사용 금지. 업무당 제한만 아니라 전체 미션 체인의 누적 상한을 실행 직전 강제해야 한다.
5. **중요한 실행 조건**: 실제 통합된 새 업무 경로와 호출 상한을 오프라인 fixture(합성임을 명시)로 한 번 검증한 경우에만 이번에 승인된 실제 API 실행을 진행한다. 실패 이력 변조, 무결성/예산/동의 안전조건 위반, 이미 성공된 대표 승인 상태, 데이터 출처 부정확, 구현 불가능이 있으면 실제 호출 없이 중단하고 정확한 단일 차단 사유를 보고한다. 개발 성공을 실제 모델 성공으로 주장하지 않는다.
6. 조건 충족 시 `prepare → 실제 제안/해시 검토 → 새 approve → run 1회`를 현재 검증된 CLI 경로로 진행한다. Gemini 고정 모델·엔드포인트·활성화 설정은 실행 프로세스에만 사용한다. 잔여 공급자 할당량 미확인은 `unknown`으로 정직하게 기록한다. **외부 테스트 호출 0회, 자동 재시도 0회, 실패하거나 불명한 요청은 소모**, 다음 자동 분리 업무 생성/재시도 금지.
7. 실제 AI가 자율적으로 게임 트렌드/길이를 분석하고 선정 근거·영상 분류/권리 불확실성을 표시한 후 실제 한국어 전체 대본·스토리보드를 작성하고 내부 검토를 거쳐 컷룸 `awaiting_plan_approval`까지만 올린다. 검증된 조사 캐시를 사용한 경우 원본 출처를 분리 명시하고, 신규 관측이 아닌 데이터를 '새로 조회했다'고 표시하지 않는다. mock fixture는 절대 실제 결과로 제출하지 않는다. 대표 승인, 음성/TTS/MP4, 업로드·게시 금지.
