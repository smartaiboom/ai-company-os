# 다음 작업: AI 직원 업무 검토 승인 게이트

**상태:** 준비됨. 이 파일은 작업 지시이며, 사용자의 별도 실행 요청 전에는 개발을 시작하지 않는다.

## 목표

선행 업무의 결과를 검토자가 승인하기 전에는 그 결과를 필요로 하는 후속 업무가 실행되지 않게 한다. 수정 요청, 수정 실행, 재검토, 재승인 흐름을 실제 상태와 저장 결과에 반영한다.

## 시작 전에 확인할 것

- `AGENTS.md`, 이 폴더의 `README.md`와 `task_history.md`를 읽는다.
- `reports/employee_workflow_connection_audit.md`, `reports/explicit_workflow_links_report.md`, `reports/quality_review_flow_20261029.md`를 읽는다.
- `app.py`의 `/task/execute`, `/task/update`, `mark_downstream_for_review`, 계획 승인 및 UI 렌더링을 확인한다.
- `manager_plan.py`, `execution_engine.py`, `tests/test_explicit_workflow_links.py`, `tests/test_quality_review_flow.py`, `tests/test_task_execution_persistence.py`와 현재 데이터 구조를 확인한다.
- 최근 작업 이력과 `git status`를 확인한다. 기존 사용자 변경은 보존하고 실제 프로젝트 데이터를 테스트에 쓰지 않는다.

## 요구 동작

1. **실행 상태와 검토 상태 분리:** 기존 작업 `status` 의미를 바꾸지 않는다. 별도 검토 상태를 두고 최소한 `검토 대기`, `승인됨`, `수정 요청`을 구분한다. 검토가 필요 없는 독립 업무는 `검토 불필요`로 표현할 수 있다.
2. **승인 전 후속 실행 차단:** `input_task_ids`로 연결된 선행 결과가 비어 있지 않고 완료 상태여도, 검토 상태가 승인되지 않았거나 재검토 표시가 있으면 후속 실행을 막는다. 실행 엔진을 호출하기 전에 차단하고, 어떤 선행 업무의 검토가 필요한지 쉬운 한국어 오류로 안내한다.
3. **승인 조건:** 결과가 존재하고 작업 실행이 성공한 경우에만 검토를 승인할 수 있다. 승인 시 검토자/시각 등 기존 기록 형식에 맞는 이력을 남긴다. 승인된 결과가 변경되거나 다시 실행되면 승인을 취소하고 다시 검토 대기로 돌린다.
4. **수정 요청:** 검토자는 구체적인 수정 의견을 입력해 수정 요청을 남길 수 있다. 빈 의견은 거부한다. 원래 업무 결과는 수정 실행이 성공하기 전까지 보존하고, 후속 업무는 계속 차단한다.
5. **수정 및 재검토:** 수정 요청을 받은 업무를 다시 실행할 때 검토 의견을 입력 자료로 전달한다. 성공한 새 결과는 다시 검토 대기 상태가 된다. 재검토 승인 후에만 연결된 후속 업무 실행을 허용한다. 실패·빈 결과면 기존 결과와 차단 상태를 보존한다.
6. **연결된 후속 업무만 게이트 적용:** 명시적 `input_task_ids`와 기존 데이터 호환 경로를 따르며, 독립 업무의 기존 실행 동작과 화면 처리를 불필요하게 바꾸지 않는다. 선행 결과가 변경되면 그 결과에 의존하는 기존 승인과 후속 완료 결과를 무효화하거나 재검토 대상으로 표시한다.
7. **기존 데이터 호환:** 저장된 프로젝트 JSON을 일괄 수정하지 않는다. 검토 상태가 없는 예전 업무는 안전하게 검토 대기로 취급해 승인 전 후속 실행을 허용하지 않는다. 화면에서 상태를 설명하고 검토할 수 있는 경로를 제공한다.
8. 기존의 `openrouter/free` 제한, 실패 결과 보존, 중복 제출 방지 모달, 화면 위치 복원, 업무 결과 전달 방식을 유지한다. 전체 AI 응답·프롬프트·비밀값을 로그에 기록하지 않는다.

## 필수 테스트 조건

- 연결된 선행 결과가 검토 대기일 때 후속 실행이 차단되고 실행 엔진은 호출되지 않는다.
- 승인된 선행 결과는 ID와 결과 본문이 연결된 후속 업무에 전달되고 실행이 허용된다.
- 수정 요청에 의견이 저장되며 후속 실행은 차단된다. 수정 의견이 재실행 입력에 포함되는지 확인한다.
- 수정 실행이 실패하거나 빈 결과를 반환하면 이전 결과가 보존되고 검토 승인이 나지 않는다.
- 수정 실행 성공 후 검토 상태가 다시 대기가 되고, 재승인 뒤 후속 업무가 실행된다.
- 승인 뒤 선행 결과가 변경되면 연결된 후속 결과의 승인이 무효화되고 재검토가 요구된다.
- 독립 업무, 실패한 선행 업무, 빈/누락된 결과, 재검토 필요 업무, 구형 데이터(검토 상태 없음)를 검증한다.
- 관련 계획 승인, 명시적 작업 ID 전달, 품질 검토, 결과 저장, UI 회귀 테스트를 실행한다. 모든 테스트는 임시 데이터와 모의 엔진을 사용하고 실제 AI API를 호출하지 않는다.
