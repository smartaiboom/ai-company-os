# 컷룸 보고서 직접 검토 연동 — 복사·붙여넣기 제거 (2026-11-23)

## 목표
대표가 더 이상 v1~v4처럼 길어진 컷룸 보고서를 ChatGPT에 복사해서 붙이지 않도록 한다. AI Company OS의 최신 보고서/대표 결정/증거를 ChatGPT가 GitHub에서 직접 읽을 수 있는 **안전한 검토용 산출물**로 만들고, 이후 '결과 나왔어'만으로 최신 결과를 검토한다. 이후 별도 단계에서 모바일 게임 세 종 이상 비교 기획을 품질 개선한다. 이번에는 **보고서 전달 경로부터 완성**한다.

## 기존 배경
- 저장소 smartaiboom/ai-company-os 의 main은 공개 저장소임. 운영 로컬 data/, approvals/consent, ledgers, .env, 토큰 등은 공개 금지.
- 실제 모바일 게임 쇼츠 조사 프로젝트: company-062d79eeabeb4e5baab3d60ec462db5f.
- 현재 컷룸에 보고서 v4 생성. 2026-11-23 15:34 KST YouTube 공개 데이터 관측 5건(전부 마인크래프트 영상), 조회수·길이·영상 링크, 관리자 'hold', 대표 검토 대기. 실무 목표인 '서로 다른 모바일 게임 3개 후보 비교'는 아직 미달. 승인 잔여량 Gemini 10/YouTube GET 16 등은 운영 원장에 있으며 이번 개발에 소모하지 말 것.
- ChatGPT는 GitHub의 public markdown/json을 직접 읽을 수 있지만 사용자 PC localhost:8004와 로컬 data/는 직접 접근할 수 없음. 따라서 사용자에게 반복 보고서 붙여넣기/캡처 요구하지 말 것.

## 구현
1. AGENTS.md와 general_research_report.versions()/research_workflow.status()/studio_server 실제 데이터 경로를 점검. 가장 작은 기능으로 **latest report review export** 생성. 원본을 변조하지 말고 읽기 전용 파생 구조(JSON 또는 Markdown 한 파일)로 생성. 내용: 프로젝트의 비식별 표시명·분야, 보고서 버전·KST 시각·검토 상태·대표 결정 유무, 직원 조사 요약, 관리자 판단·이유, 후보 비교표, 출처(공개 URL·제목·공개 메트릭·관측시각·게시시각·한계), 부족 근거/불확실, 도구 호출 예약/완료 집계(비밀/credential 제외), 직전 보고서 대비 변경 사항. 현재 v4 최신 건부터 충분히 검토 가능해야 함. 너무 긴 과거 v1~v3 원문 반복 삽입 금지; 이전 버전은 버전·결정·핵심 변경 요약만. '실제 영상 열람', 'Shorts 확인', '저작권 승인' 등 미확인 사실 주장 금지.
2. **안전 필터는 allowlist 방식**: 자유형 원래 목표, 대표 피드백 전문, 직원의 원문 외부 응답, API 요청 URL/headers, keys/tokens, 사용자 정보, 로컬 path, 서명/해시가 비밀일 가능성 있는 값, 동의 상세, 내부 사정과 비용 원장은 통째로 공개 금지. 유튜브 공개 URL·제목·공개 메트릭 및 검토용 짧은 설명만 허용. 출처 발췌도 민감성 검사를 위해 기본 제외하고 필요 시 공개 자료 최소 발췌만. 사용자 프로젝트가 임의 자유형 목표이므로 일괄 자동 공개는 위험하다.
3. **공개 저장소 자동 푸시는 기본 OFF**. 컷룸과 로컬의 review export 생성은 자동화하되, 처음에는 사용자가 공개 가능하다고 확인한 단일 프로젝트/버전만 안전 검토 후 Codex가 한 번 GitHub main의 정해진 검토용 파일 (예: reports/review_exports/mobile_game_latest.md)로 commit/push. 이후에도 사용자가 별도로 허용하지 않은 모든 새 보고서를 인터넷에 자동 공개하지 않는다. 가능하다면 현재 프로젝트만 명시 승인한 게시 정책으로 이후의 같은 범위 자동 게시가 가능한지 조사하되 개인정보/토큰 자동 필터 보증이 불가능하면 수동 게시로 유지. 로컬 git 인증 정보를 서버 응답으로 노출하지 않는다. ChatGPT가 GitHub에서 이 exact file을 직접 읽고 확인하게 할 것. 사용자에게 원문 붙여넣기 요청 금지.
4. 보고서 생성 이후 로컬 최신 export 파일 자동 갱신 및 컷룸에 '검토용 요약 생성됨' / 'GitHub에 공유됨 여부' / '공개되지 않은 로컬 파일' 구분 표시. 전송 실패를 실제 게시 성공으로 표시하지 않는다. 게시할 때는 하나의 고정 파일 교체가 원칙이며 보고서가 많아질수록 파일이 누적 생성되지 않음. GitHub remote main의 SHA를 확인. 공개 게시 확인이 사용자 동의를 필요로 하는 경우 UI에서 실제 무엇을 공개하는지 미리보기 가능하게 하되 기존 승인·외부 API 조사 승인과 혼동하지 않는다.
5. 안전성과 간편함을 모두 우선. GitHub API 토큰을 컷룸 JS/브라우저로 전달하거나 .env를 전송·Git에 기록 금지. 가능하면 기존 Codex CLI의 git 자격증명을 활용하는 승인된 1회 동기화, 또는 기존 연결된 GitHub 도구를 통해 안전 snapshot 전달. 사용자가 매번 개발명령을 복사해 실행해야 한다면 그 한계를 보고할 것. '완전 자동'으로 표현하려면 별도 자동 게시 경로가 실제 통합 검증돼야 함.
6. 오프라인 테스트: 현재 v4 기록 복사본에서 export, v1~v4 구분, 게임 후보/유튜브 5개 근거/관리자 보류 표기, KST, 비밀키·서명·사용자 피드백/원목표·로컬 경로 등 비노출, duplicate export no uncontrolled files, 새로운 보고서에서도 고정 latest 파일 덮어쓰기 안전, 기존 records/consents/data/아티팩트 불변, localhost의 실제 검토 UI, 상태 변경 시 게시 성공 오인 금지. 실제 외부 Gemini/YouTube/Tavily 호출 0. 동의 없는 GitHub 공개 게시 0.
7. 결과 reports/CUTROOM_REVIEW_EXPORT_RESULT_20261123.md에 실제 구현 범위, 보안·공개 범위, 로컬 export 실제 유무, GitHub 게시 실증 여부, 사용자가 다음에 해야 할 단 하나의 행동, GitHub에서 assistant가 실제 보고서를 확인할 경로를 적어라. 코드/테스트/보고서만 main에 commit/push, 원격 SHA 확인.
8. 기존 v4는 승인하지 말고 보존. Gemini/YouTube 남은 예산 소비하지 말고 **다음 기능 단계**에서 '모바일 게임 3종 실제 비교'를 실시하도록 후속 미완료에 기록. 기존 5개 마인크래프트 영상 관측은 재사용하되 다양한 게임 표본 없으면 영상 기획 승인 불가. 개발 위주로만 계속 돌지 말고 사용자 콘텐츠 품질 목표 유지.

## 완료 판정
대표는 컷룸 v4를 복사하지 않고, 승인된 안전 검토용 최신 파일을 GitHub에 게시한 뒤 ChatGPT에 '결과 나왔어'라고만 말해 최신 보고서를 직접 검토받을 수 있음. 만약 직접 게시 연결이 불가능하면 확인 가능한 제한을 분명히 설명하고 **한 번의 Codex 명령으로 안전 공유하는 방법**까지 구현. 자동 생성과 자동 공개 게시를 혼동하지 말 것.
