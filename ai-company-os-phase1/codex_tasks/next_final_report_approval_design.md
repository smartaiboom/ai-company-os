# 다음 작업: 최종 산출물 확정 절차 분석 및 최소 설계

## 목표
AI Company OS의 전체 목표는 사용자가 목표를 주면 AI 직원이 조사→기획→개발→검토·수정→최종 결과까지 협력하는 것이다. 현재 mock 자동 진행과 승인된 선행 결과 전달까지 구현되어 있으나, 마지막 업무 결과는 검토 승인 게이트가 적용되지 않을 수 있고 HTML 보고서는 확정 여부를 나타내지 않는다. 이번에는 **구조를 먼저 확인하고 최종 결과 확정의 안전한 최소 설계를 작성**한다. 운영 코드 변경을 우선하지 않는다.

## 사전 확인
- AGENTS.md, codex_tasks/README.md, codex_tasks/task_history.md, reports/ai_company_os_current_state_audit_20261102.md, reports/mock_workflow_orchestration_20261102.md, reports/mock_workflow_http_browser_validation_20261102.md를 읽는다.
- app.py의 최종 업무 판단, task_has_successful_result, task_review_controls, /task/review, project_report, save_project, 수정 시 후속 검토 표시 및 관련 테스트를 확인한다.
- git status, 브랜치, origin/main, diff를 확인한다. 기존 사용자 변경/미추적 파일/JSON/백업을 보존한다. reset, clean, force push 금지. 시각은 KST.

## 분석과 설계 항목
1. 최종 업무의 결과가 어떤 조건에서 검토 불필요로 분류되는지 코드 근거를 명확히 파악한다.
2. '업무 완료', '검토 승인 대기', '최종 보고서 확정'을 어떻게 구분할지와 화면 문구·상태 판정 기준을 제안한다.
3. 최종 결과에 수정 요청→재실행→재검토→최종 승인 흐름을 적용할 최소 수정 범위를 파일/함수 단위로 설계한다.
4. 확정된 결과를 추적 가능한 파일(예: 프로젝트별 Markdown/JSON 스냅샷)로 보관할 때 필요한 버전, 확정 일시 KST, 승인 상태, 업무 ID, 선행 결과 참조 및 데이터 보존 정책을 제안한다. 기존 JSON 호환성을 유지한다.
5. 이미 승인된 최종 결과의 선행 업무가 바뀔 경우 확정이 무효화되거나 재검토로 넘어가는 정확한 기준을 설계한다.
6. 소켓/실데이터 없이 가능한 임시 저장 경로 mock 테스트 시나리오를 작성하고 완료 기준을 명시한다.
7. 구현을 하나의 작은 후속 작업으로 분리하고 위험·영향·미확인 사항을 기록한다.

## 안전 범위
- 이번 작업은 **분석·설계만** 한다. 운영 코드·테스트·기존 데이터/백업 수정 금지, 실제 AI API 호출 금지, 외부 의존성 설치 금지.
- 관련 파일 읽기와 필요하다면 프로젝트 데이터가 아닌 독립 테스트만 실행한다. 실행하지 않은 검증을 완료했다고 주장하지 않는다.
- 기존 무료 모델 제한 및 mock 자동 진행 안전 장치를 유지하는 설계를 권고한다.
