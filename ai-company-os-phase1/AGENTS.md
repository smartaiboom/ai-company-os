# AI Company OS 개발 공통 규칙

## 작업 시작 전

- 기존 프로젝트 구조, 관련 코드와 테스트, 적용 중인 지침을 먼저 확인한다.
- 기존 동작과 파일 형식을 유지하고, 요청 범위에 필요한 최소한만 변경한다.
- 사용자가 지정한 수정 범위와 금지 조건을 우선한다. 별도 허가 없이 업무 데이터나 기존 파일을 삭제하거나 복구하지 않는다.

## AI API와 비용 안전

- 실제 AI API 요청은 OpenRouter의 `openrouter/free` 모델만 사용한다.
- `AI_ENGINE=openai_compatible`인 실제 요청 경로에서는 요청을 보내기 전에 `AI_MODEL`이 정확히 `openrouter/free`인지 확인한다. 값이 없거나 다르면 명확한 오류로 중단한다.
- 유료 모델로 전환하거나 fallback을 추가하지 않는다. 결제 기능, 유료 호출 경로 또는 비용 발생을 허용하는 우회 경로를 구현하지 않는다.
- 사용자가 API 호출을 요청하지 않았으면 호출하지 않는다. 요청이 있더라도 비밀 키와 인증 정보는 화면, 로그, 테스트 출력, 보고서에 기록하지 않는다.

## 구현과 검증

- 구현 후 변경한 동작과 관련된 기존 테스트를 실행하고 결과를 확인한다. 필요한 테스트가 없으면 요청 범위 안에서 모의 테스트를 추가한다.
- 실행한 테스트 명령과 실제 통과·실패 결과를 기록한다. 실행하지 않은 테스트를 통과했다고 표현하지 않는다.
- 사용자 요청이 테스트 실행, API 호출, 파일 쓰기 등을 금지하면 그 제한을 우선하며, 제한 때문에 확인하지 못한 사항을 명시한다.

## 작업 보고서

- 각 작업 결과는 프로젝트 루트의 `reports/` 아래에 설명적인 파일명으로 저장하고, 저장 후 다시 읽어 내용과 파일 생성을 검증한다.
- 보고서에는 변경 파일, 테스트 명령과 결과, 오류 또는 미해결 사항, 실제 API 호출 여부를 기록한다. API를 호출했다면 모델 ID와 호출 여부만 필요한 범위에서 기록하고, 비밀 정보와 키 값은 절대 포함하지 않는다.
- 사용자가 보고서 생성을 금지했거나 해당 경로에 접근할 수 없다면 파일을 만들거나 확인했다고 주장하지 않는다. 제한 또는 접근 오류를 알리고, 가능한 경우 보고서 내용을 대화에 제공해 저장할 수 있는 경로를 안내한다.

## 승인 요청 안내 언어

- Codex의 작업 설명과 승인 요청 전 안내는 한국어를 기본으로 작성한다.
- 승인 전에 실행할 명령, 변경할 파일, 작업 목적과 예상 위험을 쉬운 한국어로 설명한다.
- 사용자가 내용을 이해하기 어려운 영어 명령만 단독으로 제시하지 않는다. 명령이 필요하면 한국어 설명과 함께 제시한다.
- 이 지침은 Codex가 작성하는 안내에 적용하며, 실제 Codex 앱의 시스템 승인 창 언어까지 변경할 수 있다고 보장하지 않는다.

## Git과 데이터

- 일반적인 개발·테스트 작업은 사용자에게 매번 확인을 요청하지 않고 진행한다. 테스트 전용 로컬 loopback 서버 시작·접속, 변경 범위 확인, 의도한 파일만 스테이징, 커밋·푸시, 안전한 main 통합, 최종 읽기 전용 검증도 별도 확인 없이 수행한다.
- 관련 테스트가 통과하면 Git 상태와 diff를 확인하고 해당 작업에 필요한 파일만 스테이징·커밋·푸시한다. 현재 main에서 안전하게 진행할 수 있으면 main에 반영하고, 그렇지 않으면 전용 브랜치에서 검증한 뒤 안전한 방식으로 main에 통합한다. 원격 상태를 확인하고 force push는 하지 않는다.
- 자동 진행을 멈추고 사용자에게 확인할 예외는 유료 서비스 사용 또는 비용 발생 가능성, 결제·과금 설정 변경, 기존 업무 데이터의 삭제·초기화, 해결되지 않은 충돌, 해결되지 않은 테스트 실패다. 실패나 충돌이 남아 있으면 커밋·푸시·main 통합을 하지 않는다.
- 기존 프로젝트 데이터와 업무 기록을 보존하고, 요청 범위에 필요한 경우에만 의도한 데이터를 변경한다. 삭제·초기화는 사용자의 명시적 요청 없이는 하지 않는다.
