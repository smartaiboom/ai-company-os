## 사용자 피드백 — 왜 다음 개발이 필요한가
사용자가 2026-11-09 실제 Google Flow 3클립 영상과 2026-11-10 로컬 설명 그래픽 영상을 **둘 다 직접 시청**한 결과:
1. 체감 품질 향상이 크지 않음. 정보 전달은 되지만 **이미지/움직임이 부족해 지루함**.
2. MeloTTS 음성이 최근 자연스러운 AI 음성 서비스와 비교해 **어색함**.
3. 대본은 일반적인 AI 입문 설명보다 **실제 최신 관심사·트렌드에 맞는 흥미로운 주제**로 제작해야 정확히 품질 평가 가능.
이 피드백을 실제 사용자 판단으로 저장하고 향후 관련 영상에 재사용하되, 초반 '2~3/10' 대비 사용자 점수가 올랐다고 주장 금지. 지난 60초 쇼츠들을 덮어쓰거나 재렌더하지 말 것.

### 관리자 역할: 소재 비교 후 자율 선택
- 사용자 대상은 한국어 쇼츠를 보는 일반 초보자/직장인 중 **실제 영상 제작에서 하나로 합리적으로 선택**. 사용자에게 사소한 스타일·한 장면마다 승인 요구 금지.
- 근거 있는 후보 최소3개를 비교: 관심 유발, 실제 활용 가능성, 60초에 시각적 시연 가능 여부, 사실 검증 난도, 이미지/영상 확보 난도, 비용/권리, 교육적 가치. 선정 근거와 제외 사유를 `topic_decision.md`로 기록.
- 정보형 '어떻게 하세요'만 반복하는 지루한 콘텐츠 피하고, 처음3초에 확인 가능한 결과 대비/놀라운 차이/구체적 문제 해결을 제시. 클릭베이트, 허위 조회수/특정 모델 능력·가격 허위 시연 금지.
- 공개 정보의 정확성/최신성은 날짜/근거를 대본 각 사실 주장과 연결. AI로 답변을 만들어 실제 앱에서 테스트한 것처럼 표시 금지.

## 시각적 품질 P0 — 카드만 보여주는 영상 중단
- **대본과 장면을 동시에 설계**한다. 60초 9:16에서 실제 사물·사람·업무 장면/화면녹화/데모·사진·시각적 비교가 역할을 가지도록 한다. 텍스트 카드는 설명 보조용, 지속시간/반복 상한을 명시하고 화면 대부분을 카드로 채우는 새 시안 금지.
- 사용 가능한 자산 우선: 이미 저장된 Google Flow 3개(사용권 미확인으로 게시불가·임시 품질용), 사용자가 직접 만든 이미지·영상 중 로컬에 실제 있는 자료, 공개 허용 라이선스가 확인된 자료, 프로그램으로 직접 생성한 예시 캡처/애니메이션. 부족하면 필요한 B-roll을 장면별로 `asset_requests.md`에 프롬프트/화면 역할/초·규격/수량/사용권 확인 항목까지 기록. **새 Google Flow 동영상이 존재하지 않는데 있다고 가정하지 말 것.** 이미지로 인물/실제 장소를 위조하거나 상표/로고를 오인시키지 말 것.
- 기존 3개 짧은 Flow 클립의 20초 반복 금지. 시각적 다양성/전환의 유용성, 길이 대비 의미 전달을 검사. 기존 정적 텍스트 카드10개와 외부 Flow 클립 반복 시안을 넘어서는 실질적 시청 경험을 목표로 한다.
- 자동화 시스템으로 재사용할 시각 자산 계획/파일 영수증/저작권 정보/화면-대본 연계를 `companies/video/`에 최소 추가 구현. '이미지 소스 없음' 상태를 자동 승인하지 말 것.

## 자연스러운 한국어 TTS P0 — 먼저 2개 음성을 비교할 수 있는 샘플
- 기존 MeloTTS는 문제를 직접 청취한 사용자가 어색하다고 평가함. **근거 없이 속도만 바꿔 새 음성 품질이 해결됐다고 보고 금지.**
- 실제 대체 후보 조사: Qwen3-TTS 공식 https://github.com/QwenLM/Qwen3-TTS (한국어 10언어 지원, 지시 기반 발화/톤, 코드 Apache-2.0 표기), 다른 합법적 무료 로컬 후보. 공식 코드·가중치·음성 출력의 상업 이용권은 각각 확인. 모델이 '더 자연스럽다'는 품질은 실제 청취 평가가 있어야 함.
- Codespaces CPU/RAM/디스크 여유·Python 호환, 모델 가중치 크기/라이선스와 다운로드 비용/네트워크, 실행시간 예상치는 도구 자료로 검증. 이전 사용자 방향은 무료 우선, 기존 데이터 보존, 신규 모델 다운로드/외부 전송은 별도 승인 필요. **새 모델을 무단 대용량 다운로드/설치하거나 유료/외부 TTS API 호출하지 말 것.** 설치 필요 시 `tts_comparison_plan.md`에 단일 최우선 후보/환경·용량·권리·실행 명령과 사용자에게 필요한 결정 하나를 명시하고 그 상태에서 안전하게 보류.
- 이미 사용 가능한 별도 적법한 무료 한국어 음성이 있고 추가 다운로드/동의 없이 로컬 실행 가능하면 동일한 10~15초 대본으로 A/B 샘플을 별도 폴더에 생성(기존 WAV 덮어쓰기 금지)하고 발음·속도·강세·감정·권리/음성 결함을 평가표로 비교. 실제 사용자가 듣기 전 합격 주장 금지. 현재 대체 후보가 실행불가면 MeloTTS 다시 한 번 전체 60초 새로 합성해 성과처럼 보고하지 말 것.

## 이번 개발에서 실제로 수행할 것
1. `AGENTS.md`, 이전 영상 보고서 두 개, `reports/CURRENT_PROGRESS.md`, `core/`, `companies/video/` 기존 코드·시험, 실제 로컬 미디어·모델 상태를 분석한다. 현재 GitHub main과 작업 트리 상태를 점검하고 보존한다.
2. 사용자 피드백 원문을 선별적 경험 기록으로 받아 기존 `ExperienceJournal`/품질 계약과 연결한다. 특정 프로젝트/이 대상의 경험과 일반화 불가 의견을 구분. **기존 사용자 평가를 예시용 가짜 fixture로 바꾸어 설명하지 말 것**. 실사용 원장에 무단 쓰기는 금지, 이번 새 작업 폴더의 별도 안전 저장소에 기록한다.
3. 소재 후보3개 이상과 최신 근거를 비교 → 자체 품질 기준으로 한 주제 선택 → 대본 초안·관리자 비판·재작업·최종 대본 및 분 단위(초별) 미디어/음성 계획을 실제 파일로 남긴다. 누가 판단했는지 Codex vs deterministic code vs 실제 AI 모델 구분. 정확한 AI 추론 승인이 없으므로 **이번에는 실제 LLM API 호출0회**. 다만 시스템의 공통 관리자/직원 품질 계약이 다음 실제 모델 승인 시 재사용되도록 통합한다.
4. 실제 사용 가능한 시각 자료로 **새 이미지/동작 중심** 검토 시안을 가능하면 별도 60초 MP4로 렌더하고, 없다면 임의의 빈 카드로 60초를 채우지 않는다. 특정 필수 자산 부족·음성 미확보 시 완성 MP4 대신 샷플랜·콘택트시트·필요 자산 요청을 정확하게 내고 품질 게이트를 실패로 남긴다. 예전 영상을 새 영상으로 포장 금지.
5. TTS는 위 안전 조건을 지킨 상태에서 실제 A/B WAV 비교 가능하면 제작; 불가능하면 가장 유망한 후보 조사와 **사용자 승인 후 실행할 좁은 작업**을 명시. 현재 MeloTTS의 발화 평가는 이미 '어색함'이므로 단지 코덱 정상이라 합격 처리 금지.
6. 새 시안/검토 자료는 `data/video_quality_iteration/<새 KST 폴더>/`에 저장. `topic_decision.md`, `script_draft.md`, `manager_review.md`, `script.md`, `shot_plan.md`, `asset_requests.md`, `tts_comparison_plan.md`, `evaluation.md`, 새 MP4/WAV(실제 존재할 때만), 영수증, 소스 권리표를 저장. 사용자가 다운로드할 파일 경로 명시.
7. `reports/USER_FEEDBACK_QUALITY_UPGRADE_RESULT.md`에 **사용자 피드백별 조치/실제 바뀐 점/미달 점, 트렌드 확인 근거, 시각적 개선 실제 증거, TTS A/B 결과 또는 차단 이유, 마지막 실물 시안 위치, 사용자 시청 전 후 평가 없음, 제품 자율성의 실제 수준**을 기록. `reports/CURRENT_PROGRESS.md`도 갱신. 기존 2편과 새 시안을 비교하되 '새 영상이 더 좋다'는 주관 평가는 사용자에게.
8. 기능 묶음 최종 통합 검증은 한 번, 불필요한 전체 렌더/모델 반복 금지. 실제 MP4면 ffprobe/디코딩/60초/자막 싱크 확인. 코드/테스트/보고서를 GitHub main에 커밋·푸시, 원본 미디어/데이터/모델/원장/키/대형 로컬 파일은 올리지 않는다. 변경0/과금0/외부 전송0/게시0/보존 검증을 명시.
9. 계속 UI/웹 화면 금지. **한 번의 피드백으로 실제 결과물이 나아졌다는 증거**와 **유저가 확인할 수 있는 소리·영상**을 우선한다. 안전한 외부 미디어/모델 다운로드 필요로 보류했다면 똑같은 준비 명령을 반복하지 않도록 정확한 미결정 하나와 파일로 종료.
