- 준비는 독립 BudgetVideoStore의 기존 prepare_budget으로 실제 proposal을 만들되 provider grant나 예산 승인을 발급하지 않는다. 제안과 프로젝트 binding은 로컬에 보존한다. 새로고침과 동일 준비 요청은 같은 job/해시·원래 만료를 유지한다. 동시에 준비하면 프로젝트 잠금으로 중복 생성을 막는다. 데이터 동의 거절 시 미등록 상태로 남고 grant는 발급하지 않는다.
- 승인 버튼은 서버에 저장된 정확한 제안의 review_hash와 명시적 approve를 전달한다. 기존 `_check_contract`/approve로 만료·입력/정책·서명·키 바인딩을 검사한 뒤 grant를 발급하고 enable_budget의 기존 새 프로젝트 연결을 사용한다. 승인/거절 중복 제출은 거부한다. 중간 파일 저장 장애로 동일 proposal의 grant만 만들어진 경우 서명/본문과 빈 원장 일치를 확인한 뒤에만 연결을 마무리할 수 있게 했다. 기존/사용한 원장을 초기화하거나 이미 승인량이 있는 원장을 새 등록으로 재사용하지 않는다.
- `companies/video/budget_video_provider.py`: 이 opt-in 경로의 기존 signed provider 검증에 로컬 계정 ID/무료 확인 설정의 일치도 추가했다. 기존 grant 서명·철회·만료·고정 모델/엔드포인트·키·데이터 scope·컷룸 binding 가드는 유지한다. 기존 미션의 provider 경로는 변경하지 않았다.
- `companies/video/studio/studio.js`: 새 프로젝트에만 등록 준비 폼과 별도 데이터 동의 패널을 표시한다. 프로젝트/목표/모델/API/계정/무료 전용/전송 데이터 범위·입력/정책/유효기간/책임과 검토 해시를 읽고 승인·거절할 수 있다. 예산 승인 패널과 구분하며 등록만으로 실행하지 않는다. 승인 후 동의 상태·철회 버튼을 표시하고 기존 예산 요청/증액/명시적 계속 버튼을 재사용한다.

## 로컬 설정과 승인 분리

브라우저에 API 키나 서명 키 입력란을 만들지 않았다. 서버의 기존 GEMINI_API_KEY와 고정 GEMINI35_MODEL/GEMINI35_ENDPOINT 설정을 사용한다. 소유자가 키의 소속·결제 미연결/무료 조건을 로컬에서 확인하고 `BUDGET_GEMINI_ACCOUNT_PROJECT`에 그 공개 프로젝트 ID, `BUDGET_GEMINI_FREE_ACCOUNT_CONFIRMED=1`을 설정해야 준비할 수 있다. HTTP 입력 계정이 이 로컬 값과 다르거나 무료 확인이 없으면 차단한다. 실행 시에도 해당 설정·기존 활성화 플래그·grant 가드를 확인한다. 키 원문은 폼/HTTP 응답·보고서에 내보내지 않으며 저장된 proposal의 credential_binding도 조회 flow에서 숨긴다.

이는 로컬 소유자 확인 진술과 키 바인딩이며 공급자 콘솔의 독립 검증이 아니다. 실제 계정/결제/API를 조회해 입증했다고 주장하지 않는다. 미설정 상태에서는 안전한 로컬 준비 안내를 보여 주고 등록/실행을 막는다. 이번 작업에서 실제 서버 환경이나 .env를 변경하지 않았다.

**데이터 전송 동의와 예산 승인은 독립적**이다. 등록·공급자 서명 후에도 승인량 0이며 전송할 수 없다. 초기 관리자 견적은 승인으로 취급하지 않는다. 견적은 기존 manager 서비스 입력을 재사용하고, 부족 시 채택된 AI 작업계획의 잔여 필요량을 한 요청으로 제안한다. 별도 AI 견적 API를 추가하지 않았다. 예산 증액은 provider 동의 만료/철회나 새 모델·계정·데이터 정책을 우회하지 못한다. 철회는 기존 revoke를 호출해 이후 전송을 차단하며 연결/과거 소모 원장은 삭제하지 않는다.

## 오프라인 검증

`tests/test_budget_cutroom.py`의 초기화부터 등록 준비·공급자 승인까지 **실제 localhost HTTP**를 사용하도록 변경했다. 합성 임시 프로젝트/키·모의 native Gemini send만 사용하고 DNS·socket은 loopback 외 목적지를 차단한다. fixture는 실제 AI 산출물이 아니다.

`PYTHONPATH=core:companies/video python -B -m unittest tests.test_budget_cutroom tests.test_project_budget_ledger tests.test_studio_server`: **22개 통과, 5.464초**. localhost 소켓 권한 승인 아래 실행했으며 외부 네트워크 차단은 테스트 내부에 유지했다. `node --check companies/video/studio/studio.js`, `git diff --check` 통과. 설치된 브라우저 도구가 없어 헤드리스/시각 검증은 수행하지 않았고 새 도구를 설치하지 않았다.

확인한 동작: 새 프로젝트 HTTP 생성·opt-in 준비·정확한 해시의 독립 공급자 승인 → 초기 예산 0 → 관리자 견적 2회/대표 예산 승인 → 예약·소모 2회 → 추가 4회 요청 한 건 → 증액 후 같은 plan/직원 버전에서 4단계 계속. 토큰 누락, 위조/다른 프로젝트 hash, 미설정/권한 없는 계정·무료 아닌 설정, 키 변경, 제안 만료, grant 만료·서명 변조, 동의 거절/철회, 새로고침/중복 준비·승인, 동시 준비/실행, 기존 미션형 프로젝트 등록 금지와 기존 부족/실패·불명/소모 가드도 확인했다. 합성 대본의 기존 소스 대기 상태를 성공/대표 승인 대기로 바꾸지 않았다.
