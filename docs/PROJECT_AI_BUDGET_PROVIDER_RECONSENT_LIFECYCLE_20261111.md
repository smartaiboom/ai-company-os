이번 목표는 **기존 예산·동의·사용량·실패 이력을 보존하면서 공급자 동의가 만료/거절/철회된 경우 새 제안과 새 검토 해시·승인 이벤트로 이어갈 수 있는 한정된 절차**를 구현하고 오프라인 검증하는 것이다. 기존 동의 내용을 조용히 연장하거나 상태를 초기화하는 것이 아니다.

## 작업 범위
1. `companies/video/studio_server.py`, `companies/video/budget_video_provider.py`, `companies/video/studio/studio.js`, 기존 budget ledger 및 서명·grant 코드에서 필요한 부분만 확인. 이미 구현한 준비/승인/거절/철회/예산 추가 승인 기능 재사용. 새 전역 동의 시스템 재개발, UI 재설계 금지.
2. 기존 제안이 만료되거나 거절된 **미등록 새 프로젝트**는 명시적 사용자 요청으로 **새 제안 ID, 유효기간, review_hash**를 만들 수 있도록 한다. 과거 제안과 거절/만료 이력은 보존하고, 동일 입력의 단순 새로고침은 새 제안을 만들지 않는다. 기존 만료 제안을 유효한 것처럼 처리하거나 이전 해시를 새 승인으로 재사용하지 않는다.
3. 이미 예산 모드로 연결된 프로젝트에서 provider 동의가 만료/철회된 경우, 예산 원장 및 사용량·기존 공급자 attempt를 **그대로 유지한 채**, 동일 scope를 다시 검토·승인하는 별도 안전한 동의 갱신 절차를 제공한다. 동일 scope인지 프로젝트/모델/계정/무료 데이터 정책/목적/키 바인딩을 실제 검증할 것. scope 변경 시 별도 신규 동의 정책으로 분리하고 기존 scope 이벤트 덮어쓰기 금지.
4. 새 승인 전에는 반드시 실제 provider 실행 차단. 기존 consent 서명과 철회 이력을 재작성/삭제하지 않고 새 이벤트 또는 새 grant로 연결. 예산 승인·증액은 provider 동의를 대신하지 못하며, provider 동의 갱신은 예산 증액을 뜻하지 않는다. provider API 호출의 `verify_consent` 가드가 새 동의의 유효기간/철회/키 변경을 확인하도록 한다.
5. 이미 불명·예약된 시도는 동의 갱신으로 자동 재전송할 수 없으며, 정상 `budget_approval_required` 대기만 기존 안전 이어가기 정책 범위에서 가능하다. 실패한 실제 요청과 사용량은 보존한다. 자동 재시도/유료 전환 없음.
6. HTTP/컷룸 JS의 최소 진입점에서 정확한 구 승인 상태·새 제안 해시·검토 범위·확인 버튼을 표시. 동일 출처/workspace 토큰·해시·만료·중복·경쟁·권한 차단을 실제 원장 동작으로 검증한다. 비밀키·서명 키는 브라우저에 보여 주지 않는다.
7. 합성 임시 컷룸+mock provider+외부 네트워크 차단에서 준비 만료→새 제안→승인, 거절→새 제안→승인, 사용 중 동의 철회/만료→실행 차단→새 동의→기존 사용량 보존→남은 예산에서 정상 업무 계속, 스코프/키 변경·구 해시·중복/동시 제출·예산 미승인·불명 시도 재발송 거부를 표적 테스트한다. 실제 API 호출 **0회**, 실제 프로젝트 동의 갱신 **0건**.
8. 로컬 신뢰·인증 수준을 과장하지 말 것. 프로젝트별 계정 RBAC나 공급자 요금 독립 검증, 모든 도메인/provider 연동 및 미션 01 이관은 별개. 변경 범위가 과해지면 안전하게 완료 가능한 최소 기능만 구현하고 미완료를 명시한다.
