# AI Company OS 현재 상태 점검 지시서

## 목적
현재 AI Company OS의 전체 목표(사용자의 고수준 목표를 AI 직원들이 조사·기획·개발·검토·수정·최종 보고까지 협업 수행)에 비추어 실제 구현 상태와 다음 개발 우선순위를 파악한다. 이번 단계는 **읽기 전용 분석**이며 기능 개발을 하지 않는다.

## 시작 전
- 프로젝트 `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, 이전 보고서 및 관련 코드/테스트를 확인한다.
- `git status`, 브랜치, `origin/main`을 확인하고 기존 수정·미추적 파일을 모두 보존한다. `reset`, `clean`, 파일 삭제 금지.
- 한국 표준시(KST)를 기준으로 기록한다.

## 분석 항목
1. 목표 입력, 업무 계획/분배, AI 직원 실행, 선행 결과 전달, 검토 승인/수정, 재실행, 최종 보고 및 저장의 각 단계별 실제 구현 파일과 동작 여부.
2. 실제 AI 모델 연결 방식, `openrouter/free` 제한, 실제 호출 없이 확인 가능한 안전성.
3. 기존 자동 테스트의 검증 범위와 미검증 영역. 이전 보고서의 통과 기록과 이번에 실제 실행한 테스트를 구별한다.
4. AI 직원의 자율 협업을 막는 미구현 부분, 위험, 의존 관계, 다음 개발 작업의 우선순위.
5. 가장 작은 안전한 다음 개발 작업 1개와 명확한 완료 기준.

## 금지 사항
- 운영 코드, 테스트, 사용자 업무 데이터, 백업, 기존 보고서 수정 금지.
- 실제 AI API 호출, 유료 서비스 사용, 데이터 초기화 금지.
- 불필요한 의존성 설치 또는 구조 변경 금지.
- 테스트가 데이터에 영향을 줄 가능성이 있으면 실행하지 말고 이유를 보고한다.

## 결과 저장 및 공유 (필수)
- 분석 보고서를 `reports/ai_company_os_current_state_audit_20261102.md`에 **반드시 파일로 저장**한다. 기존 동일 경로 파일이 있으면 덮어쓰지 말고 내용을 확인하여 보존한다.
- 보고서에 근거 파일/함수, 구현/미구현 구분, 테스트 실행 여부 및 결과, 미해결 위험, 다음 작업 제안, 실제 API 호출 여부를 기록한다.
- 저장 후 파일을 다시 읽어 검증한다.
- 이번 분석 보고서 **하나만** 스테이징·커밋하여 `origin/main`에 안전하게 푸시한다. 원격 충돌, 실패한 테스트 또는 사용자 변경 혼재 시 푸시를 중단하고 이유를 알린다. 강제 푸시 금지.
- 완료 후 보고서 경로, 커밋 SHA, 푸시 여부만 간단히 알려준다. **결과를 대화에만 남기지 않는다.**
