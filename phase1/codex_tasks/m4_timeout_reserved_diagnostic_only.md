# M4 예약 상태·시간 초과 원인 진단 전용 (실제 API 호출 금지)

## 배경
최신 reports/v01_m4_real_free_ai_acceptance_20261102.md: 격리 프로젝트 c85d9853906a, 계획 호출 1/7회 예약, reserved 1건, completed/failed 0건. loopback 클라이언트 55초 TimeoutError, 서버 프로세스 종료. 모델 결과 없음. 동일 프로젝트 JSON이 /tmp/ai-company-os-m4/projects/c85d9853906a.json 및 Git 제외 data/m4_acceptance_preserved/projects/c85d9853906a.json에 보존됨. 이 둘은 동일 예산 기록의 복제본.

## 목적
실제 호출 없이 **왜 예약 상태가 남았는지**와 재개 전에 필요한 안전한 최소 조치를 판단한다. 중복 개발 금지. 기존 M1~M3·M4 코드 변경은 필수적인 결함이 명확할 때만 제안하고, 이번 단계에서는 원칙적으로 읽기 전용.

## 수행
1. git status --short, 기존 보고서, ai_safety.py의 요청/예약/timeout 처리, app.py의 요청 scope 및 서버 처리, 기존 테스트 실행 경로만 최소한으로 읽는다. 전체 리포지토리 탐색·전체 테스트·브라우저 설치 금지.
2. 보존된 프로젝트 메타데이터에서 예약 id·시각·상태·호출 종류·누적 예산을 확인하되 민감한 원문·API 키·업무 결과·사용자 데이터는 출력/커밋하지 않는다. 복제본을 별도 프로젝트로 취급하지 않는다. 경로가 없으면 없는 그대로 기록.
3. 45초 외부 요청 timeout과 55초 loopback 클라이언트 timeout이 어떤 경로로 충돌했는지 코드상 가능한 원인을 구분한다. 특히 HTTP 서버가 동기/단일 스레드인지, 저장 콜백/락 교착, HTTP 요청·응답 대기, 서버 종료 타이밍, network timeout이 어디에 적용되는지 **정적 분석과 안전한 로컬 모의 테스트만**으로 확인한다. 외부 네트워크 접속·OpenRouter 조회/재전송 금지.
4. 예약이 reserved로 남은 이유를 확정할 수 없으면 추정이라고 명시하고, 전송 완료 여부는 미확인으로 유지. 예약 초기화/failed로 강제 변경/새 프로젝트 생성/예산 리셋/실제 API 재호출 금지.
5. 결과를 reports/v01_m4_real_free_ai_acceptance_20261102.md에 짧은 '예약/타임아웃 진단' 섹션으로 추가: 확인한 사실, 원인 후보와 근거, 확정 불가능한 부분, 다음 1단계. 기존 보고 내용 유지.
6. 보고서만 선택적으로 커밋·푸시하고 원격 반영 확인. Git 제외 데이터/백업/미추적 파일 보존. git diff --check.

## 성공 기준
실제 API 요청 **0회 추가**, 안전 상태 보존, 다음 최소 조치가 명확함. Codex 토큰 절약. 보고서에서 v0.1 M4 완료를 주장하지 않는다.
