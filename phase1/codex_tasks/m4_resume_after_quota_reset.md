# M4 사용량 초기화 후 안전 이어하기 — 기존 상태 우선

## 목적
Codex 사용량 초기화 후 **중단된 M4만 이어서** 진행한다. M1~M3 재개발, 신규 아키텍처 설계, 이미 시도한 API 요청 재전송 금지. 기존 M4 지시서와 codex_tasks/m4_resume_approved_test_safely.md를 재사용한다.

## 우선순위: 이전 작업 보존·보고서 원격 반영
1. git status --short, branch, origin/main과의 차이, 로컬 reports/v01_m4_real_free_ai_acceptance_20261102.md, 기존 M4 테스트 프로젝트/real_ai.attempts·예약 상태를 **읽기 전용**으로 확인한다. 기존 미추적 파일(__pycache__, api_connection_audit.md, app_phase2_before_fix.py 등), JSON·스냅샷·백업 보존. reset/clean/force push 금지.
2. 이전 보고서가 로컬에만 있다면 결과를 읽고 **실제 API 시도 횟수·성공 여부·중단 이유를 먼저 확정**한다. 기존 기록에 reserved/failed/completed가 있으면 예산에서 소모된 것으로 취급하고, 재시도/예산 초기화/프로젝트 재생성으로 우회하지 않는다.
3. 기존 M4 보고서의 미반영 상태를 해결하여 reports/v01_m4_real_free_ai_acceptance_20261102.md를 GitHub에 안전하게 커밋·푸시한다(비밀·실제 결과 원문 제외). 기존 미추적 파일·테스트 데이터·API 키·응답 본문은 커밋하지 않는다.
4. 이후 **같은 M4 프로젝트에서** 승인된 테스트를 이어갈 수 있는지 판단한다. 프로젝트가 아예 생성되지 않았고 실제 호출 0회임을 확인한 경우에만 새 격리 테스트 프로젝트를 준비할 수 있다. 실제 모델은 openrouter/free, 승인된 목표는 '소규모 매장의 재고 확인 업무를 개선하는 도구 기획 및 실행 제안서 작성', 외부 전송 범위는 그 프로젝트의 목표·업무 입력·승인된 선행 결과·품질 기준·수정 의견만, 프로젝트 총 7회/시작·재개당 2회. 다른 목표/기존 프로젝트 데이터 전송 금지.
5. AI_REAL_REQUESTS_ENABLED=1 및 AI_ENGINE=openai_compatible 설정은 **격리된 테스트 프로세스에 한정**. 서버 활성화와 해당 프로젝트 목표 지문 동의·approved_at·enabled를 별도로 확인. 사용자 승인/업무 승인/품질 기준 승인을 자동으로 대신하지 않는다. Codex 환경에서 직접 확인 가능한 사용자 승인이나 안전한 활성화가 없으면 외부 호출을 하지 않고 이유를 보고한다. API 키 값·일부·길이 출력 금지.
6. 실제 API 호출은 사용자가 승인한 범위 내에서만, 요청 전 M2 공통 안전 검사/예산 예약을 거친다. 실패/타임아웃/예약 불명확 시 자동 재시도 없음. 유료 모델/우회 호스트/fallback 없음. 환경 오류로 실패하면 무한 재시도 금지.
7. 실제 연결이 진행된다면 기존 M4 지시서의 단계(계획→사용자 승인→직원 결과 전달→의미 검토→필요 시 사용자 승인 수정→재검토→최종 확정·JSON/Markdown)를 재사용하고 완료 범위와 한계를 기록한다. 승인되지 않은 단계를 성공으로 꾸미지 않는다.
8. 브라우저 환경이 없으면 대규모 설치하지 않고 loopback HTTP 대체 검증만 기록. 기존 테스트 전체를 반복 실행하지 말고 코드 수정이 있을 때만 관련 집중 테스트와 최종 회귀 1회 수행.
