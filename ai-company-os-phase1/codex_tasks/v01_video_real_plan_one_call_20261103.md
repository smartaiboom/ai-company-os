## 시작 전 최소 확인
1. `git pull --ff-only` 후 최신 `reports/v01_video_first_integrated_progress_20261102.md`, `reports/v01_m4_real_free_ai_acceptance_20261102.md`, 관련 기존 앱/안전 모듈과 `tests/support/m4_runner.py`의 필요한 구간만 확인한다. 전면 재설계·전체 코드 조사·반복 테스트 금지.
2. 기존 재고 테스트 프로젝트 `c85d9853906a`의 reserved 1/7은 미확정 상태로 그대로 보존한다. 해당 프로젝트의 원본·보존본·예약·판단 원장·예산·동의·백업을 수정/복사/리셋/재전송하지 않는다. 새 영상 프로젝트는 **사용자가 승인한 별개의 신규 목표**에만 사용한다.
3. 기존 영상 목표의 **실제** 프로젝트가 이미 생성되었거나 계획 요청이 예약/전송된 흔적이 있는지 확인한다. 중복 생성·중복 전송 위험이 있으면 **호출 0회로 중단**한다. 테스트 fixture의 가상 승인과 실제 승인 구별.
4. OpenRouter 인증키는 **존재 여부만** 확인하고 값·일부·길이 출력 금지. `AI_MODEL=openrouter/free`, 허용된 고정 OpenRouter HTTPS 엔드포인트, 무료 경로, 공통 request_scope/영속 예약/프로젝트 잠금/7회 전체 및 시작당 2회 상한을 실제 전송 직전까지 검사한다. 키/모델/호스트/동의/격리 조건 하나라도 미충족이면 **호출 0회로 중단**. 다른 모델·유료 경로·fallback·프록시·리다이렉트·자동 재시도 금지.

## 한 번의 실제 계획 생성
5. 기존 앱의 `/create`와 `/manager/plan` 경로를 사용한다. 실제 영상 프로젝트는 별도 **Git 제외 격리 데이터 디렉터리**에 만들고 원본 업무 데이터 및 영구 환경은 바꾸지 않는다. 프로젝트 목표 지문, 승인된 외부 전송 범위(영상 목표·이 프로젝트의 업무 입력/승인된 선행 결과/성공 기준/수정 의견), KST 동의 시각, enabled와 예산을 정확히 기록한다. 아직 존재하지 않는 업무 결과를 임의 생성해 전송하지 않는다.
6. 실제 요청에 한해서 격리 프로세스의 `AI_REAL_REQUESTS_ENABLED=1` 및 허용 엔진을 사용한다. 이전 daemon HTTP 테스트 실행기를 그대로 사용하지 않는다. 기존 `ObservedServer`의 요청 스레드 종료 관측과 안전 저장 경로를 활용한다. **전체 wall-clock 취소가 보장되지 않는 점**을 명확히 인식하고, 클라이언트 타임아웃을 제공자 실패나 작업 완료로 추정하지 않는다. 진행 중인 worker를 조용히 종료하지 말고 관측/종료가 불확실하면 프로세스와 reserved를 안전하게 보존하고 중단한다. 필요하면 실제 실행에 필요한 최소 runner 연결만 수정하고 모의 집중 테스트로 검증한다. 종료 보장 없는 무한 대기는 피하되, 임의 kill로 예약 상태를 조작하지 않는다.
7. 승인된 영상 프로젝트에서 **관리자 계획 생성 외부 요청 최대 1회만** 실행한다. 시작당 허용 2회는 최대치이지 이번 2회 실행 허가가 아니다. 실패, 빈 응답, 타임아웃, 429, 형식 오류, 예산 reserved 등 어떠한 경우에도 추가 실제 요청·재시도·대체 모델 호출 금지. 예약은 요청 전에 영속 저장하고 불확실하면 소비된 채로 유지한다.
8. 성공 시 생성된 가변 작업 수/역할/선행 관계/질문을 저장하고 `pending_approval` 상태에서 **즉시 중단**한다. 계획 승인, 성공 기준 승인, AI 직원 실행, 의미 검토, 수정, 최종 승인, MP4 제작/업로드를 **이번에 수행하지 않는다**. 사용자의 승인을 임의로 대행하지 않는다. 사용자에게 실제 계획 내용을 확인할 수 있는 안전한 방법(화면 또는 비밀 없는 요약)을 보고한다.

## 보고와 종료 조건
9. `reports/v01_video_real_plan_one_call_20261103.md`에 실제 요청 수(0 또는 1), 프로젝트 ID(민감하지 않은 내부 ID만), 누적 예산/예약/성공/실패/미확정 상태, 실제 제공자 응답 확보 여부, 계획 생성 여부, 작업·역할·선행 관계 요약, 승인 대기 상태, 미완료/다음 한 단계, KST를 정확히 작성한다. 요청이 중단됐으면 **왜 중단됐는지**와 추가 호출 없이 복구 가능한 조건을 기록한다. 인증키·토큰·원문 민감 데이터·개인 정보·외부 전송 전문을 Git에 올리지 않는다.
10. 기존 프로젝트/백업/미추적 파일/이전 산출물을 보존한다. 코드 변경은 실제 실행을 위해 필수적인 최소 수정만, 테스트는 변경한 부분의 집중 테스트만. 보고서와 필요한 코드/테스트만 선택적 `git add`, `git diff --check`, 커밋·푸시. 실사용 프로젝트 JSON/키/로그는 Git 제외. 브라우저 설치, 전체 테스트, 별도 진단 과제 증식 금지.

**완료 판정**: 실제 무료 AI 요청 최대 1회에서 유효한 관리자 계획을 확보하고 사용자 계획 승인 대기에 도달했으면 이번 작업 성공. 외부 결과 미확정/중단이면 이번 작업은 미완료로 정직하게 보고하고 추가 요청을 보내지 않는다. v0.1 전체 완료 또는 실제 영상 생성 완료라고 주장하지 않는다.
