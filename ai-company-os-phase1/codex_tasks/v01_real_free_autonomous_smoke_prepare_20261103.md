# AI Company OS — 첫 실제 무료 AI 자율 운영 테스트: 짧은 영상 완성 프로젝트 준비

## 사용자 최신 목표
사용자가 앞서 안내문 제작 실전 테스트를 제안받고 **“안내문보다는 간단한 영상제작을 테스트 해보고 싶은데?”**라고 목표를 변경했다. **이 파일의 이전 '업무 이메일 안내문' 목표는 폐기하고 수행하지 않는다.** 이 문서는 아직 Codex 실행 전 교체용 지시다. 기존 다른 업무/데이터는 보존.

처음부터 이어온 AI Company OS 핵심 목표는 **사용자가 목표 한 번 입력 → 실제 AI 관리자 계획/업무 분배·품질 기준·직원 실행/검토·수정/협업 → 최종 결과물 생성**이고, 업무별 사용자 결재는 없어야 한다. Codex는 AI 회사의 개발자이지 관리자/직원이 아니며, 작업 지시서는 **상위 목표**를 맡기는 방식이다.

## 새 테스트 목표 — 완성 영상이 결과물
**“ChatGPT 초보자를 위한 ‘좋은 질문을 하는 방법’ 한국어 20~30초 설명 영상을 제작하라. 이해하기 쉬운 화면 구성과 자막을 포함하고, 가능하면 한국어 음성도 넣어라. 최종적으로 재생 가능한 MP4 영상 파일과 간단한 제작 결과 보고서를 제출하라. 검증되지 않은 기능을 사실처럼 단정하지 마라.”**

- **핵심 성공 조건은 실제 재생 가능한 `.mp4` 파일**이다. 대본, 타임라인, 스토리보드, 이미지, 제작 지시서만 작성하고 '영상 완성'이라고 보고하는 것은 실패. AI 관리자와 직원이 스스로 영상 제작에 필요한 단계와 역할, 품질 기준을 정하고 협업해야 한다. 20~30초, 한국어, 초보자, MP4는 **프로젝트 목표의 요구조건**이지 엔진에 하드코딩할 규칙이 아니다.
- 외부 영상 생성 서비스(Kling 등), 유료 영상·이미지·음성 API, 계정 연결, 업로드/게시를 **이번 범위에서 사용하지 않는다**. 우선 로컬에서 가능한 무료 도구(예: ffmpeg, Python 표준 도구, 이미 설치돼 있는 안전한 로컬 라이브러리)로 자막·타이틀·간단한 도형/배경을 렌더링하여 MP4를 만들 수 있는지 확인한다. 외부 소스 다운로드 없이 로컬에서 생성한 배경·텍스트만으로 가능하다. 음성은 실제 로컬 TTS가 가능한 경우에만 포함; 불가능하면 무음/자막 영상으로 제공하고 음성을 포함했다고 속이지 않는다. 작업 환경에 ffmpeg/인코더가 없으면 임의로 성공 표시하지 말고, 재현 가능한 안전한 무료 대안이나 실제 필요한 전제조건을 정확히 보고한다.
- **AI 직원이 산출한 대본/타임라인/자막 등 AI 판단을 렌더러가 입력으로 받아서 영상이 만들어져야 한다**. Codex가 영상 내용을 정하고 단독으로 만들어서 AI 회사의 성공으로 포장하는 행위 금지. 로컬 MP4 렌더링은 AI 회사의 **실행 도구 능력**으로 명확하게 추상화하고, 관리자/직원의 생성 콘텐츠와 실행/검토 결과를 추적한다. AI가 실제 파일 생성 도구를 사용할 수 없으면 AI 기반 제작 파이프라인을 개발·테스트하여 첫 실사용 경로와 연결하되, mock 시연과 실제 AI 성공을 엄격히 구분한다.

## Codex에 위임하는 전체 개발 목표
**기존 범용 자율 회사 엔진이 문서뿐 아니라 실제 MP4 같은 실행 산출물을 만들어내도록, 로컬 영상 제작 도구 연결에 필요한 설계·개발·오프라인 검증을 Codex가 스스로 진행한 다음, 새 실제 무료 AI 프로젝트의 최초 운영 동의안을 준비한다.** 안전 범위 내 필요한 코드 분석/수정/테스트는 한 작업에서 모두 수행하고, 세부 오류 때마다 사용자에게 멈춰 질문하지 말 것.

### 1. 도구/환경 분석과 범용 실제 산출물 계약
- Codespaces/프로젝트에 FFmpeg, TTS, 이미지/자막 렌더링 도구가 설치돼 있는지 읽기 전용 확인. 설치가 필요하면 별도 외부 다운로드/유료 API를 무단 수행하지 말 것. 환경 확인 실패 시 그 상태를 정직하게 기록.
- 현재 `autonomous_company`는 텍스트 JSON/Markdown 중심이므로, 실제 영상 파일을 만들려면 **범용 산출물 실행 도구/아티팩트 단계**가 필요한지 분석. 이 변경을 영상 전용 전체 엔진으로 고정하지 말고, 향후 파일·이미지·코드 등 결과물 실행 도구를 연결할 수 있도록 작고 분리된 인터페이스 설계. 도구별 입력 검증, 호출 권한/로컬 파일 경로 제한, stdout/stderr 비밀정보 제어, KST, 산출물 SHA256, 실행 실패 시 정상 완료 차단 및 기록. 시스템에서 임의 AI 생성 셸 명령이나 파이썬 코드를 무제한 실행하도록 하지 말 것.
- MP4의 최소 충족 조건은 단순한 20~30초 1280x720 또는 1080x1920 등 일관된 비율, 한국어 자막/타이틀, 재생 가능·코덱/길이/프레임 확인, 자체 생성된 소재. TTS 불가시 음성 없음 명시. AI 관리자는 사용자 목표를 바탕으로 품질 판정을 한다. 영상 제작 실패나 영상 길이 미달을 관리자 '성공'이라고 속이지 말 것.
- 모델/직원 응답에는 영상 제작에 필요한 **일반화된 파일 생성 지시 데이터**만 담고, 렌더러는 검증된 허용 형식(JSON 장면/타임라인, 자막 문자열 등)만 받아 실행해야 한다. 사용자 목표에 없는 특정 규칙을 관리자 역할에 고정하지 말 것.

### 2. 새 프로젝트 생성 / 승인 준비까지만 실제 데이터에 적용
- 새 테스트 목표로 **전용 free-v2 저장소의 신규 프로젝트 한 건**만 만든다. 기존 영상 프로젝트 `cb44b605b498`나 다른 `c85d9853906a`, 기존 저장/백업/원장/비밀키를 절대로 변경하지 않는다. 이미 동일한 준비 작업이 수행됐으면 중복 생성 금지.
- `create`/운영 범위 `prepare`를 이용해 새 목표/ID/hash에 결합된 **최초 무료 운영 동의 제안만** 만든다. 승인되지 않은 전송 자료 유형에 기존 파일·코드·계정 정보가 포함되지 않도록. **로컬 렌더러 사용을 위해 필요한 도구 권한**은 모델에 대한 데이터 외부 전송 동의와 명확히 구별. 새 비밀키·서명 동의·실제 API 요청은 이번에 만들지 않는다.
- 운영 동의의 데이터 범위: 위 테스트 목표, AI가 새 프로젝트 안에서 생성한 계획/기준/대본/자막/장면 구성/직원 결과/검토·수정·통합 결과. 자체 로컬 생성 영상 파일을 OpenRouter로 업로드하지 않는다. OpenRouter 무료 `openrouter/free`, 비용 0, fallback/유료 미허용. 최초 동의 없이 실제 AI를 호출해서는 안 된다.

### 3. 오프라인 전 과정 검증
- **실제 AI 호출 0회, 유료 API/외부 전송 0회**. 가짜 공급자/가짜 HTTPS 응답으로 AI 관리자 계획→대본/화면 구성 직원→관리자 검토/수정 가능→로컬 렌더링→MP4 검사→최종 결과 통합까지 가능하면 실제 end-to-end로 검증. 이때 실제 AI가 작성했다고 주장하지 말 것. 로컬 ffmpeg가 없으면 성공을 허위 주장하지 말고 검증하지 못한 범위 명시.
- 기존 무료 자율 API 경로/운영 한도 없는 정상 실행·중복 방지/오류·원장·동의 취소·기존 프로젝트 회귀 유지.
- 로컬 영상 생성이 현재 모델 출력 인터페이스로 불가능하면 **실제 AI가 최초 호출 후에도 영상 파일을 만들 수 있도록 하는 필요한 연결**을 구현하고 검증하는 것이 우선. 외부 API를 호출해 해결하려 하지 말 것. 단 이번에 전체 변경이 어려우면 안전한 범위까지 실제 구현하고 미완료를 명확히 보고.

### 4. 이번 작업의 금지 범위
- **실제 OpenRouter API 호출, 실제 운영 동의 approve, `--owner-confirmed`, live run, 모델에게 외부 목표 전송, 타사 영상/음성 API 사용, 유료 비용 0원 초과** 금지. 개발 지시 위임/사용자의 '영상 테스트를 하자'는 실제 송신 동의로 오인 금지.
- 사용자 승인 없이 기존 프로젝트 데이터 수정·마이그레이션·백업 삭제·대량 백업·Git 강제 정리 금지. 기존 실사용 `cb44b605b498` 원장 9/20과 영상 TASK-003/004 대기 그대로 보존.
- 대시보드/화면 꾸미기 개발 금지. Git에는 키, 미승인 계약 원문, 실사용 데이터, 사용자 개인정보 포함 금지.
