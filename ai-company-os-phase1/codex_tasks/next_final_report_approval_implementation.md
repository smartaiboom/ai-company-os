# 다음 개발 작업: 최종 결과 승인 및 버전 보관 최소 구현

## 목적
AI Company OS의 목표 입력→AI 직원 협업→검토·수정→최종 보고 흐름에서 마지막 결과가 별도 사용자 승인 없이 완료로 오인되는 문제를 해결한다. 직전 설계 보고서 `reports/final_report_approval_design_20261102.md`를 기반으로 **현재 순서형 계획의 마지막 업무 하나에 대한 최종 승인 및 불변 JSON 스냅샷 보관**을 최소 수정으로 구현한다.

## 사전 확인 필수
- `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, `reports/final_report_approval_design_20261102.md`, `reports/mock_workflow_orchestration_20261102.md`, 관련 코드·테스트부터 읽는다.
- 브랜치, `origin/main`, `git status`, `git diff`, `git diff --cached` 확인. 기존 수정/미추적 파일, 프로젝트 JSON, 업무 결과, 백업 전부 보존. `reset`, `clean`, 강제 push, 일괄 스테이징 금지.
- 모든 데이터·로그·화면 시각은 KST. 실제 AI API 호출, 유료 모델 설정, 외부 의존성 설치 금지.

## 구현 범위
1. 기존 순서형 tasks 배열의 **마지막 업무 하나**를 최종 승인 대상으로 정한다. '최종 보고' 등의 업무명 문자열로 판별하지 않는다. 공통 승인 필요 판정을 도입해 기존 후속 업무 승인 게이트와 마지막 업무 승인 경계를 유지한다.
2. 마지막 업무 실행 성공 시 최종 승인 대기로 전환하고, 사용자 승인 또는 수정 요청 폼을 제공한다. 수정 요청→재실행→재승인에 기존 검사·수정 의견 전달·결과 보존 규칙을 재사용한다. 기존 수동 실행과 mock 자동 진행에서 마지막 결과 승인 대기에 정지해야 한다.
3. **검토 승인과 최종 확정은 서로 다른 상태**다. 승인 시 유효한 현재 성공 결과·선행 결과·재검토 상태를 검사한 뒤 프로젝트별 `data/artifacts/{project_id}/final_reports/v000001.json` 형태의 새 버전 불변 스냅샷을 저장한다. 스냅샷에는 당시 목표·실행 결과·승인·근거·KST 확정 일시 및 현재 상태 지문을 포함한다. 기밀 키/환경 변수/토큰은 포함하지 않는다.
4. 스냅샷의 쓰기 및 재독 실패 시 프로젝트를 확정으로 표시하지 않는다. 스냅샷 저장 후 프로젝트 저장이 실패해도 잘못된 확정 표시가 생기지 않도록 유효성 검증한다. 과거 스냅샷은 삭제/덮어쓰기 하지 않고, 재승인은 새 번호를 사용한다. 원자성/다중 프로세스 한계를 정직하게 기록한다.
5. 선행 결과·상태·승인, 목표/계획/마지막 업무의 결과 변경이나 재실행이 발생하면 현재 확정은 무효로 판정한다. 과거 스냅샷 파일은 그대로 보존한다. 단순 UI 표시 상태/무관한 이력 변경만으로는 무효화하지 않는다. GET 조회는 읽기 전용이어야 한다.
6. 프로젝트 상세 및 최종 보고 화면에 업무 실행 완료와 **최종 확정 여부를 구분**해 표시한다. 미승인 결과를 '최종 확정'으로 표시하지 않는다. 기존 JSON에 새 필드가 없어도 읽기 가능해야 하며 기존 데이터는 자동 변환하지 않는다.
7. 구현 전 기존 코드의 저장·승인 처리 흐름과 영향 범위를 확인한다. 범위가 과도하게 커지거나 데이터 손상 위험이 확인되면 무리하게 수정하지 말고 안전한 부분만 구현하거나 중단 이유를 보고한다. 기존 AI 엔진/모델 제한이나 무관한 구조는 수정하지 않는다.

## 완료 조건·테스트
- `TemporaryDirectory`로 프로젝트와 artifacts 경로를 격리하고 mock/네트워크 금지 환경에서 테스트한다.
- 마지막 업무 pending→수정 요청→재실행→승인, 유효 확정 v1 생성과 KST 기록, 중복 승인 거절, 변경 후 무효화 및 재승인 v2/과거 v1 보존, 누락/손상 파일 거짓 확정 방지, 실패한 파일 쓰기·프로젝트 저장, 구형 JSON 호환을 검증한다.
- 기존 승인 게이트, 결과 전달, 중복 실행 보호, mock 자동 진행, 무료 모델 제한 관련 테스트를 재실행한다. 격리되지 않은 실제 업무 데이터 경로의 smoke 테스트는 실행하지 않는다.
- `git diff --check`를 확인하고 테스트 실패 또는 충돌이 남아 있으면 커밋·푸시하지 않는다. 실제 AI API 호출은 절대 하지 않는다.

## 보고서 및 GitHub 전달 (필수)
- 반드시 `reports/final_report_approval_implementation_20261102.md`에 실제 구현 범위, 변경 파일, 실행한 테스트와 정확한 결과, 미구현 항목/위험, 실제 AI API 호출 여부를 저장하고 다시 읽어 확인한다. 기존 동일 경로 파일이 있다면 덮어쓰기 전에 내용 보존 여부를 확인한다.
- 관련 코드·테스트·보고서·필요한 작업 이력만 선택적으로 스테이징하여 `origin/main`에 안전하게 커밋·푸시한다. 업무 데이터, 과거 스냅샷, 백업, 기존 미추적 파일은 Git에 포함하지 않는다.
- 푸시 후 원격 커밋 및 보고서 존재를 확인하고 보고서 경로·SHA·푸시 결과를 간단히 알린다. **대화에만 결과를 남기지 않는다.**
