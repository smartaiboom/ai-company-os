## 2. 실행 전 선행 검사
1. `git pull --ff-only`로 최신 상태 반영, 파일·데이터/원장 충돌 없음 확인. 코드는 필요 최소한만 수정하고 기존 사용자 작업/백업을 보존한다.
2. 신규 store가 정확히 위 isolated free-v2 namespace, project_id 및 대기 상태인지를 확인. 최초 운영 grant가 없으면 **위 명시된 사용자 승인에 근거해 승인 절차 수행이 허가된다**. 승인 기록을 이미 만들었다면 중복 승인/반복 run을 하지 않는다.
3. 승인 파일과 실제 계약을 읽어 외부 전송 scope, 로컬 도구, 모델, 비용 0, 유효기간, 호출 상한 없음, 30분 벽시계, 내부 수정·불확실 예약 안전장치가 위 요청과 일치하는지 검사.
4. 환경변수·보호된 구성에서 AI_API_KEY **존재 여부만** 확인하고 절대로 원문·일부·유사값/인증 헤더를 콘솔·로그·보고서·Git에 남기지 않는다. `AI_ENGINE=openai_compatible`, `AI_MODEL=openrouter/free`, 고정 OpenRouter HTTPS endpoint, 실제 `AI_AUTONOMOUS_FREE_ENABLED=1` 등의 요구조건을 코드 기준으로 검사. 신규 자율 무료 경로에 필요한 정확한 flag만 승인된 실행 프로세스 범위에서 설정할 수 있으나, 안전 guard/사용자 권한/기존 다른 프로젝트 동의를 우회하거나 전역 .env·비밀키를 임의 재작성하지 않는다.
5. provider 요청의 가격 0 필터·`allow_fallbacks=false`와 공급자 실제 `usage.cost` 검증을 유지. **실제 공급자가 요청 계약에 맞지 않거나 응답 비용 0을 증명하지 못하면 즉시 정지**. 무료라는 광고만으로 비용 0 성공이라고 단정하지 말 것. 유료 가능성이 보이면 송신 전 차단. 다른 모델/계정으로 우회 금지.
6. local ffmpeg/ffprobe/Noto CJK/eSpeak NG 설치와 `local_artifacts` allowlist 경로 검증. 영상/오디오/기존 코드·파일 본문을 provider에 첨부하지 않는다. 새 프로젝트 내 최초 생성 텍스트/도구 receipt 메타데이터만 승인 범위로 전송.
7. 기존 영상 프로젝트 `cb44b605b498`, 미확정 예약이 있는 `c85d9853906a`, 기존 backup/data 및 이전 mock 증거 프로젝트는 **절대 변경·재실행하지 않는다**.

## 3. 한 번의 실제 승인과 실행
- 선행 검사를 통과하면 `autonomous_live_cli`의 **현재 코드가 요구하는 계약 검토 hash/프로젝트 초기 hash에 결합된 정상 `approve --owner-confirmed` 절차**를 실행한다. 이것은 사용자의 2026-11-04 대화 중 명시된 최초 동의에 근거한다. user instruction/statement를 조작해 유효하지 않은 계약을 승인하면 안 된다.
- 승인 후 최신 승인 상태 해시를 조회해, 한 번의 `run PROJECT_ID --state-hash APPROVED_STATE_HASH`로 실제 관리자→실제 직원→검토·수정→로컬 렌더→MP4 검증→최종 보고를 수행한다. **중간 업무 품질 승인·재개 사용자 결재 요구 금지**.
- 동일 프로젝트에 대해 첫 실행 후 자동 재실행·중복 송신·실패 시 임의 재시도 금지. 429/402/5xx/timeout/비용 정보 불명확/무효 모델 JSON/정책 충돌/리밋·만료·품질 정체/미확정 상태는 기존 보호 절차대로 정지하고 실제 사유를 보고한다. 안전한 clean checkpoint continue가 필요한 경우에도 코드가 이미 완결됐음이 증명되고 동일 operation이 재전송되지 않는 범위에서만 신중히 평가할 것; 포괄적 재시도 권한은 없다.
- AI 관리자에게 실제 관찰 불가능한 영상 품질을 '봤다'고 주장하게 하지 말 것. 렌더러의 기술적 MP4 검사와 관리자 텍스트/메타데이터 품질 판단, **사용자가 실제 영상의 미적/음성 품질을 낮게 평가할 수 있음**을 명확히 구분한다. 첫 24초 mock 영상은 글자와 eSpeak 한국어 음성만으로 매우 처참하다는 사용자의 실제 평가가 있었다. 이번 테스트는 실사용 자율 협업/MP4 생성 경로 실증이며, 고품질 유튜브 결과물 보장을 뜻하지 않는다.
- 성공이면 실제 OpenRouter 회신과 연결된 대본·장면 구성·검토·수정·최종 MP4 SHA/길이/검사 결과·final.json/md·원장 기록을 확인한다. **MP4 없이 최종 성공 금지**. 결과가 조건 미달일 때는 정지/실패로 기록.

## 4. 결과 확인을 쉽게 만들기
- 실사용 최종 MP4가 만들어진 경우 **원본 파일은 보존**하고, Codespaces 탐색기에서 간단히 내려받도록 신규 프로젝트의 `preview/` 등 **동일한 로컬 저장소 안에 복사본 `video.mp4`**을 생성하거나 실제 path를 매우 짧은 복사 명령으로 제공한다. 다른 사용자 프로젝트 파일을 읽거나 변경하지 않고, Git에는 MP4/오디오/실사용 API 출력/사용자 데이터/계약/키를 넣지 않는다.
- `ffprobe`와 디코딩 검증으로 파일 존재/길이/해상도/코덱/오디오/한국어 자막 표시 여부를 확인하고, 실제 체감 품질을 검증하지 못했으면 솔직히 표시한다.
