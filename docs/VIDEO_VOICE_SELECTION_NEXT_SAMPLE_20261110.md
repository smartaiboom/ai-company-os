## 즉시 실행 지시
**AGENTS.md를 준수하고 이번 턴에 실제 코드 구현·테스트·실행 결과·GitHub main push까지 완료. 문서만 읽고 종료 금지.**

사용자가 질문한 핵심: "Gemini 음성을 채택하면 모든 영상이 같은 음성이냐?" → 답은 **아니오**. 이번 Gemini 3.8 Flash TTS/Puck B는 **직장인·한국어 AI 사용법 영상의 실제 A/B 청취 7/10 기준선이자 우선 후보**일 뿐, 모든 영상·채널에 보편적으로 고정하는 정책이 아니다. 사용자 승인 "다음 진행해줘"에 따라 관리자/음성 직원의 *영상 목적에 맞는 목소리 선택*을 기존 시스템에 실용적으로 연결하고, 이전 8초를 넘어서는 한 개의 더 나은 실음성 테스트를 준비한다.

## 개발할 기능: 자동 선택의 근거는 있지만 재생성 권한은 없다
1. **video-specific voice selection contract**를 기존 `voice_quality.py` / `video_production_company.py` 등에 **최소 확장**:
   - 관리자는 영상의 채널/시리즈 식별자, 타깃/언어, 주제·장르, 분위기(친근한 설명/뉴스/차분한 정보/유쾌한 쇼츠 등), 브랜드 일관성, 실제 검증된 목소리 evidence 및 제약을 음성 직원에 넘김.
   - 음성 직원은 provider/model/voice/style/선정 이유, 청취 평가 연결, 근거 부족 시 `unassessed`/별도 탐색 필요, 결정 주체·버전을 구조화해 반환.
   - **같은 시리즈·기존 대표 보이스가 있으면 일관성 우선**, 타깃/톤이 바뀌거나 적합하지 않을 때 후보 재평가. 실제 7점 evidence가 일치하는 **한국어 직장인 AI 초보자** 범위에 한해서 Gemini3.8/Puck 우선, 다른 타깃은 근거 없이 Puck 복제 금지. "장르별 남성/여성 목소리" 고정 규칙, 실제 써보지 않은 목소리를 검증된 추천으로 만들지 말 것.
   - "우선 추천"과 "외부 생성 허가/상업 게시 허가"는 엄격 분리, 권한 false 기본. 채널 기본 음성은 사용자가 지정하거나 충분한 증거가 있을 때만 부여. 기존 7점 하나로 전 채널 대표 목소리를 자동 확정하지 않는다.
   - 채널·시리즈·영상별 예외와 그 이유·선호 변화는 기존 ExperienceJournal/상태 계약 재사용. 새 거대 공통 엔진·새 모델 권한/서명 시스템 만들지 말 것.
2. **실행 검증**: 적어도 동일 직장인 AI 팁 영상 두 편은 Puck 우선 추천, 시리즈에 승인된 다른 기본 음성이 있으면 그 설정이 우선되는지, 다른 장르/대상은 미검증 보이스를 억지로 권하지 않는지, 명시된 변경 이유/검토가 없는 예외 차단, 실제 평가 7점과 목표8점을 혼동하거나 실 API 권한을 묵시적으로 추가하는 시도 거절. 기존 관리자→writer→voice→editor→QA에 실제 인수결과 SHA/톤·타깃 선택이 반영되는지 **오프라인 코드 실행**; Codex-authored/mock 분명히 표시.
3. **다음 음성 체감 개선을 위한 한 개 샘플**: 사용자에게 이미 공개된 가상 회의 대본 후보(137자)를 사용하되, 20초 예상 길이는 **추정치**이므로 20초 내로 읽힌다고 임의 확정하지 말 것. 8초 시험보다 긴 **실제 발화 15~35초** 허용 범위에서 장면 타이밍은 음성 실측 후 맞추고, 원문이 길어 토큰/로컬 제한을 넘으면 **정확 입력 재검토 후 새 승인 필요**라 표시. 내레이션 내용을 음성 친화적으로 다듬어 3초 후크, 의미상 쉼, 숫자 구별을 명확히 하고, 다음 비교에서 B기준 7점 대비 '목소리/억양·듣기편함·속도/쉼·후크 전달력'을 따로 사용자에게 평가받을 수 있는 rubric과 before/after 전달자료 준비. 다듬은 대본은 codex-authored, 실제 Gemini 실모델 아님.
4. **이번 단계는 유료·무료 포함 실 API 호출/다운로드/결제/키 조회/새 TTS 음성 생성0회**. 이전 대화의 60자 특정 payload 실행 승인/attempt는 1/1 소모했고 새 137자 대본이나 수정본으로 확장할 수 없음. 이번 "다음 진행해줘"는 음성 직무 전략 개선 지시이며 개인/회사 내용을 새로 외부 전송하라는 구체 동의로 오인하지 않는다. 다음 실물 한 번에 필요한 정확 새 전송문, 모델·보이스·스타일·대략 비용 정책($0 Free Tier만), 실패 포함1회·자동 retry0·데이터 개선 정책·새 출력경로를 보고서에 명시. 60자 전용 하드코딩을 최소 범위에서 일반화할 필요가 있으면 승인·이력·비용 경계를 유지하고 **모의 테스트까지만**; 그 변경 자체가 필수 아니면 추가 구현하지 않음.
5. 기존 파일/비밀/작업결과 보존, KST; 원 데이터 변경·기존 사본 덮어쓰기 금지. 적은 수의 관련 테스트를 한 묶음 수행하고 false positives/미진한 부분 기록. GitHub에는 코드·테스트·텍스트 보고서만 push, 로컬 오디오/비밀/사용자 파일 제외.
