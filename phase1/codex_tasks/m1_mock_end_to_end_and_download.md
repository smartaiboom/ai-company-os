# AI Company OS v0.1 — M1 통합 작업: mock 완주 + 최종 Markdown 다운로드

## 이번 작업의 목표
`reports/ai_company_os_v01_completion_roadmap_20261102.md`의 **M1 전체를 하나의 구현·검증·보고 작업으로 완료**한다. 목표 입력→계획 승인→직원별 mock 업무 실행과 선행 결과 전달→사용자 승인→명시적 mock 품질 형식 검사→수정 1회와 재평가→추가 승인→최종 결과 확정→읽기 쉬운 Markdown 다운로드가 단일 격리 시나리오에서 이어져야 한다. 독립적인 설계/HTTP/브라우저 후속 작업으로 불필요하게 쪼개지 않는다.

## 필수 사전 점검
- `AGENTS.md`, `codex_tasks/README.md`, 작업 이력, v0.1 로드맵, 최신 품질 수정 1회·최종 확정·mock 워크플로·HTTP 검증 보고서, 관련 운영 코드와 테스트를 읽는다.
- 브랜치/origin/main, git status/diff/staged diff를 확인하고 기존 사용자 변경·미추적 파일·프로젝트 JSON·스냅샷·백업을 보존한다. reset/clean/force push/무차별 git add 금지. 시간 표기는 KST.
- 오직 mock과 임시 프로젝트·artifacts를 사용한다. 실제 AI API/외부 제공자 요청·유료 모델·결제 변경 금지.

## 하나의 통합 구현 범위
1. 기존 업무 실행, 사용자 승인, 보조 품질 평가, 수정 1회, 최종 확정 경로를 재사용한다. 현재 mock 출력이 형식 품질 검사를 통과하기 어렵다면 테스트만을 위해 명시적 mock fixture를 사용하며, 일반 mock 엔진이 의미를 이해하고 지능적으로 수정한다고 주장하지 않는다.
2. 정확한 대상 ID와 성공 이력을 유지한 채 수정 의견이 동일 담당 역할에 전달되고, 수정/재평가가 각 1회 상한을 넘지 않으며, 재개 시 승인 경계를 건너뛰지 않게 한다.
3. 유효 확정 스냅샷 `data/artifacts/{project_id}/final_reports/vNNNNNN.json`의 내용을 사람이 읽을 수 있는 **Markdown 확정본**으로 제공한다. 다운로드는 검증된 프로젝트 ID와 확정 버전으로만 접근하며 경로 조작·미확정/무효·손상 스냅샷을 거절한다. 민감한 키/비밀/환경 변수·불필요한 내부 경로는 포함하지 않는다. GET은 기존 프로젝트 JSON/보관 파일을 수정하지 않는다. JSON 내 목표·업무 ID·결과·확정 버전 및 KST 시각과 Markdown 내용이 일치해야 한다.
4. 사용자 웹 화면에 확정본 다운로드 링크와 확정/미확정 안내를 명확히 제공한다. 기존 화면·처리 모달·버튼/오류 안내를 깨뜨리지 않는다.
5. 기존 품질 수정 1회 경로의 실제 loopback HTTP, 검토와 재개, 최종 확정·다운로드를 하나의 통합 HTTP 시나리오로 검증한다. 필요한 경우 관련 실패/중복 409/저장 오류/스냅샷 무효화 회귀를 같은 테스트 묶음에 포함한다.
6. Codespaces에 Playwright/Chromium이 있으면 실제 브라우저 클릭·모달·검토·다운로드를 테스트한다. 없다면 무료 설치 가능성/환경 위험을 확인하고 무리한 패키지·OS 변경은 피한다. HTTP/HTML 검증으로 대체하며 브라우저 미검증을 보고하고 M4 인수 조건으로 남긴다. 브라우저 때문에 M1 전체를 무조건 실패로 처리하지는 않되 웹 실증 미완료를 숨기지 않는다.
7. 핵심 동작에 오류가 발견되면 M1 범위의 최소 수정만 수행하며 운영 시스템의 전체 구조와 AI 엔진/무료 모델 제한은 변경하지 않는다. M2/M3/M4 기능을 지금 구현하지 않는다.

## 완료 기준 및 검증
- TemporaryDirectory로 projects/artifacts를 격리하고 AI 네트워크 요청 함수를 호출 시 실패하는 mock으로 막는다.
- 한 프로젝트의 단일 통합 시나리오에서 시작→핸드오프→검토 수정 1회→재평가→최종 v1 보관→Markdown 다운로드·내용 비교가 성공한다.
- 사용자 승인 우회/미확정 다운로드/경로 탈출/결과 변조/다중 요청/실패/빈 결과/저장 오류/과거 스냅샷 보존을 필요한 집중 테스트로 확인한다.
- 기존 전체 unittest와 관련 HTTP를 실행하며 필요한 브라우저 결과는 별도 표기한다. `tests/test_smoke.py`처럼 실데이터 경로를 격리하지 못한 테스트는 실행하지 않는다.
- `git diff --check` 확인. 실제 API 호출 금지. 실패/충돌/데이터 위험이 남으면 push 중단.
