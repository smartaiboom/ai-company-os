# TASK-003 빈 결과 및 상태 불일치 수정 보고서

작업일: 2026-10-29

## 원인 조사

`data/projects/7d7c8275c935.json`의 `AI 초보자를 위한 자동화 제품` 프로젝트에서 `TASK-003`은 상태가 `진행 중`이고 결과 필드가 없었다. 업무 결과 본문은 보고서에 복사하거나 수정하지 않았다. 저장된 작업 이력에는 TASK-003의 실패 이벤트가 여러 건 있으며, 최근 두 건은 `finish_reason=length`에 대응하는 “응답이 중간에 끊겼습니다” 오류였다. 실제 task 요청/응답 원문이나 별도 실행 로그는 저장소에서 찾지 못했다.

코드와 이력을 연결한 실행 순서는 다음과 같다:

1. `/task/execute` 라우트가 선행 작업 상태를 검사하고 현재 작업 상태를 메모리에서 `진행 중`으로 둔다 (`app.py`).
2. 실행기는 `openrouter/free` 보호 검사를 거친 후 요청을 보낸다. 응답의 `choices[0].message.content`를 읽고 `finish_reason == "length"`이면 기존 진단 로그를 기록한 뒤 예외를 던진다 (`execution_engine.py`). 요청 한도는 `max_tokens=4096`이다.
3. 예외가 발생하면 실행기는 결과 문자열을 반환하지 않으므로 새 결과를 할당하지 않는다.
4. 기존 라우트의 예외 처리기가 `task_execution_failed` 이력을 기록하면서 상태를 다시 `진행 중`으로 저장했다. 그 결과 작업은 실제로 실패했는데도 상태가 진행 중으로 남았다. 이번에 읽은 저장 프로젝트 기록과 일치하는 원인이다.

`finish_reason=length`가 확인되지만, 기존 이력에 토큰 사용량이 없어 4096 토큰 한도 도달인지 제공자/모델의 다른 출력·문맥 한도인지는 구분할 수 없다. 실제 AI API는 호출하지 않았다.

## 수정 내용

- `/task/execute`가 실행기에서 예외를 받으면 상태를 `실행 실패`로 저장하고 기존 실패 이력과 오류 응답을 유지한다. 성공한 작업은 이전과 같이 `완료`로 저장한다.
- 실행기가 문자열이 아닌 값, 빈 문자열 또는 공백만 반환해도 결과를 할당하기 전에 실패 처리한다. 따라서 빈 결과가 완료 상태로 저장되지 않는다.
- 기존 결과가 있는 작업을 다시 실행하다 실패하면 이전 결과는 덮어쓰거나 삭제하지 않는다. 상태는 실패로 남는다.
- 실패한 선행 작업은 기존 선행 완료 검사에서 미완료로 취급되어 후속 업무 실행을 막는다. 후속 입력 후보에도 완료 상태인 작업만 포함한다.
- 작업 상태 선택 목록과 프로젝트/최종 보고서의 집계에 `실행 실패`를 표시한다. 처리 중 UI의 오류 응답에도 실행 실패 상태를 표시해 현재 작업 행의 상태 선택과 맞춘다.
- `execution_engine.py`의 `openrouter/free` 사전 검증, 모델 제한, 4096 토큰 한도 및 응답 중단 검사는 완화하거나 변경하지 않았다. 유료 모델/fallback은 추가하지 않았다.
