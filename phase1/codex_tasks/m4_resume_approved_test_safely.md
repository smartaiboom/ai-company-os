# M4 안전 재개 — 승인된 실제 무료 AI 테스트만 수행

## 배경
이 작업은 새 M4 개발이 아니다. 기존 codex_tasks/m4_user_approved_real_free_ai_acceptance.md와 M1~M3 구현을 재사용한다. 이전 M4 실행은 AI_REAL_REQUESTS_ENABLED 스위치가 꺼져 중단했고 실제 요청/테스트 프로젝트 생성은 0회였다. 사용자 승인 범위는 ChatGPT 대화에서 확정된 목표 '소규모 매장의 재고 확인 업무를 개선하는 도구 기획 및 실행 제안서 작성', OpenRouter openrouter/free, 최대 7회, 전송 범위는 해당 새 테스트 프로젝트의 목표·업무 입력·승인된 선행 결과·성공 기준·수정 의견에 한한다. 이 문서만으로 사용자의 새 권한을 추정하거나 안전 장치를 우회하지 않는다.

## 최소 작업
1. 기존 M4 지시서, ai_safety.py의 check_project_permission, 앱의 환경 설정/프로젝트 동의 초기화 및 실제 호출 경로, 이전 M4 로컬 보고서가 있으면 필요한 부분만 확인. Git 상태를 먼저 보고 기존 미추적 파일·업무 데이터·백업 보존. 전체 재설계/기능 재구현 금지.
2. AI_REAL_REQUESTS_ENABLED=1과 AI_ENGINE=openai_compatible는 **격리된 테스트 서버 프로세스에만** 일시 적용하고, 전역 shell 설정/영구 .env/운영 서비스 설정을 변경하지 않는다. 이미 존재하는 API 키를 재사용하되 값/길이/일부 문자열도 출력하지 않는다. 프로젝트별 enabled·consent는 승인된 새 테스트 프로젝트에만 목표 지문·전송 범위·KST 승인 시각을 명시적으로 설정. 기존 프로젝트는 변경하지 않는다.
3. Codex 실행 환경에서 사용자의 실제 외부 전송 승인이 직접 확인되지 않거나 승인 범위가 불분명하다면 실제 호출을 수행하지 말고 사전 점검 결과와 필요한 1개 조치만 보고한다. 환경 제한이나 인증 문제를 우회하지 않는다. API 키나 서버 활성화 여부를 핑계로 더 넓은 권한을 부여하지 않는다.
4. 실제 전송 전 프로젝트 동의, 정확한 모델/호스트, 영속 7회 예산, 요청당 2회, 전송 데이터가 허용 범위인지 검사한다. 준비되면 M4 원래 지시서의 계획 1회→사용자 승인 경계→직원·검토·수정·최종 보고의 제한된 흐름을 재개한다. 사용자 승인 단계는 자동 승인하지 않는다. 실패·타임아웃 시 자동 재시도/유료 fallback 금지.
5. Codex 사용량 절약: 최소 파일 확인, 새 코드/테스트는 필수 버그가 발견된 경우만, 테스트 전체 반복 실행 금지. 브라우저가 없다면 대규모 설치하지 않는다. 기존 보고서에 결과만 갱신하거나 보고서 파일이 없으면 신규 작성한다.
6. reports/v01_m4_real_free_ai_acceptance_20261102.md에 실제 API 시도 수·중단 원인·프로젝트 동의/승인 상태·실제 완료 범위·테스트 결과·v0.1 판정·다음 1단계를 비밀/업무 결과 원문 없이 기록한다. 이전 보고서가 로컬에만 있다면 내용을 보존하여 갱신. 원격에 없는 경우 안전한 새 보고서로 추가.
7. GitHub에 **관련 보고서/필요한 코드만** 선택적으로 커밋·푸시. 기존 미추적 파일, API 응답/키, 프로젝트 JSON/스냅샷/백업은 커밋 금지. git diff --check. push 후 원격 보고서 확인.

## 완료 판단
실제 AI API 호출 여부를 명확히 보고한다. 사용자 승인·환경이 갖춰지지 않았다면 안전하게 중단한 상태를 완료라고 주장하지 않는다. 이 작업은 기존 M4 재개이며 새 설계·중복 구현을 요구하지 않는다.
