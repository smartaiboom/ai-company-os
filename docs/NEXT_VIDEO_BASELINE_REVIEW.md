## 현행 엔진의 알려진 한계 (속이지 말 것)
- companies/video/production_video.py의 validate()는 width*9 == height*16을 요구해 **16:9 가로형만 지원**. 사용자가 명시한 9:16 쇼츠와 불일치. 9:16인 척하거나 단순 회전/늘리기로 합격 처리 금지.
- audio_mode는 none 또는 espeak_reference만 허용. espeak_reference는 자연스러운 한국어 내레이션이 아닌 로봇식 참고 음성. 자연스러운 TTS가 제작됐다고 주장 금지.
- 일반 VideoProductionCompany의 실제 AI 실행은 별도 생성·동의·무료 비용/원장 계약이 필요. 현재 1회 질문 인수 초안을 바로 실행/핸드오프하거나 권한을 우회하지 말 것.
- 결과 품질을 독립 평가할 AI 호출도 승인되지 않음. 모의 관리자/직원이나 Codex 자체가 작성한 콘셉트는 'AI Company OS 실제 AI 직원 결과'로 표시하지 말 것.

## 이번 작업 (실행 가능한 범위 최대로, 추가 API 호출 0)
1. 현재 실제 질문/답변/확정 명세를 원장 손상 없이 읽어 입력으로 사용. 코어의 기존 VideoProductionStore 및 mock/offline 경로와 기존 production_video.render() 가능 범위를 빠르게 확인.
2. 현재 두 답변을 가지고 **기준선 산출물**을 작성: 목표를 반영한 60초 내외 장면별 구성표, 실제 한국어 대본, 내레이션 스크립트, 자막/화면 구성, 각 장면 길이, 결과물 평가표. 영상 플랫폼/대본 포함 여부 외의 세부 연출은 '추정'으로 구분. 출력은 가능한 한 실제로 사용/평가 가능한 파일로 저장.
3. 네트워크/클라우드/새 AI 모델 호출 없이 기존 로컬 영상 렌더러로 **실제 재생 가능한 미리보기 영상**을 생성할 수 있다면 생성. 기존 도구 제약으로 16:9만 가능하다면 이를 분명히 표시한 기술 시안으로만 만들고, 9:16 요구 충족이라고 주장하지 않는다. TTS는 robotic reference를 명시하거나 영상 없는 내레이션 텍스트로 대체한다. ffmpeg·폰트 등 환경 문제가 있으면 숨기지 말고 실패 이유 보고. 기존 핵심 코드의 영상 규격을 이번 테스트에서 무리하게 재개발하지 않는다.
4. 실제 결과를 확인하기 위해 출력 파일 경로(특히 mp4 및 대본/장면표), 미디어 메타데이터(화면비, 해상도, 실제 길이, 오디오 트랙 유무)를 ffprobe로 확인하고, 가능하면 프레임/재생 여부를 확인. 가정과 실제 명세 불일치 항목을 비교하여 'AI 관리자에게 다음에 어떤 질문/선택지를 추가해야 하는지' 실제 근거로 정리. 실제 시청·청취하지 않았는데 품질을 보증하거나 봤다고 쓰지 않는다.
5. **질문 생성 프롬프트/기능은 이번 단계에서 수정하지 않는다.** 산출물을 사용자에게 보여주고 피드백을 받은 후 함께 보완한다. 제품 AI와 Codex가 작성한 내용 출처를 구분. 과거 데이터 삭제, 재호출, 영상 회사 외부 실행 금지.
