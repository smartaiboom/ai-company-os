# AI Company OS — 무료 API 자동 연속 실행 완성: 인위적 2회/20회 제한 제거, 운영 안전 유지

## 최상위 원칙 및 사용자 결정
**작업 시작·개발 도중·종료 전에** `AI_COMPANY_OS_CORE_PRINCIPLES.md`의 새 **4-1항**, `AGENTS.md`, `codex_tasks/README_KOREAN_LANGUAGE_RULE.md`를 반드시 읽어라. 직전 결과 보고서 `reports/v01_autonomous_live_provider_integration_20261103.md`도 확인하라.

최신 사용자 결정: **“아직 API는 무료인 관계로 굳이 제한을 할 필요는 없어. 나중에 유료로 전환했을 때 제한을 해야지.”**

제품 목표는 사용자 목표 1회 → AI 관리자 계획·기준·업무 지시·검토·수정 → AI 직원 실행/선행 결과 전달 → 최종 결과물이다. 개발은 Codex에게 전체적으로 맡긴다. 사용자 업무 중간 승인/재개 요구가 없도록 **무료 모델에서 2회/시작, 20회/프로젝트의 인위적 ‘비용성 호출 상한’을 없애고**, 부정확한 자동화나 무한 폭주 없이 **한 번의 최초 운영 동의 뒤 자율적으로 완주**하는 기능까지 개발하라. 다른 모델/유료 전환은 이번 범위가 아니다. 대시보드는 2단계로 미룬다.

### 중요: ‘무료 무제한’이라는 오해 금지
무료 모델에도 공급자 속도 제한, 무료 쿼터, 장애, 계정 상태, 서비스 조건이 존재할 수 있다. 제공자의 제한/무료 여부를 우회하지 말고 준수한다. **무제한 재시도·무제한 수정 루프·중복 전송·과금 가능성은 금지**. 앱 자체의 2회/20회 인위적 상한과 **실제 공급자 조건/보안·품질을 위한 중단 조건**을 구분해 설계. 공급자 제한에 도달했으면 원인과 진행 상태를 보존하며 안전하게 일시 중단한다.

## 상위 개발 목표
**이미 완성한 `autonomous_live` 엔진과 `autonomous_live_cli`를 중심으로, 사용자 최초 데이터 전송/무료 모델 운영 동의 한 번 이후 무료 AI 관리자·직원들이 추가 사용자 실행/업무 승인 없이 정당하게 필요한 호출을 이어가 최종 산출물을 제출하는 ‘실제 AI 연결 가능’ 한 사이클을 완성하고, 실제 송신 0회로 fake HTTPS 종단간 검증하라.**

Codex가 전체 코드를 분석하고 설계·구현·오프라인 테스트·회귀·보고·커밋을 한 작업에서 자율 수행. 작은 수정마다 사용자에게 묻지 말 것. 기존 수동 live 프로젝트와 mock 엔진을 변경/삭제하거나 실사용 예산을 고치지 말 것.

### 기능 요건
1. **무료 자율 모드와 유료 모델 경계 분리:** 새 `autonomous_live`의 free-only 허용 계약에서 과거 `limits.max_calls=1..20`, `per_start=1..2`가 정상 자동 작업을 멈추는 문제를 해결하라. 새 무료 프로젝트는 비용 0, provider=openrouter, model=openrouter/free, 고정 HTTPS, 명시적 scopes/goal/context 및 유효기간/취소/서명된 운영 승인만 요구하며, 기본 인위적 총 호출 수는 두지 않는다. `max_calls` 같은 정책은 필요시 사용자 선택적 기술적 상한으로 지원할 수 있지만 무단 강제하지 않는다. **기존 저장 계약·서명된 승인과 과거 한도는 그대로 집행**하고 조용히 확장/재서명하거나 마이그레이션하지 않는다. Paid mode를 추가/활성화하지 않는다. 미래 유료 모드는 명시 비용 한도·별도 동의로만.
2. **‘자동 끝까지’와 중복/폭주 방지:** 최초 무료 운영 동의 후 새로운 안전한 단일 run/continue 모드가 관리자 계획→업무별 실행→검토/수정→최종 보고까지 **사용자 중간 start/resume 버튼 없이** 진행. 내부 체크포인트·원자 저장·KST 원장·계약 검증 유지. 정상 완료는 delivered, 충돌/모호한 attempt/모델 무효/취소/만료/보안 위반/공급자 quota/과금 위험이면 정지 또는 명확한 pause. 동일한 응답/작업 중복 송신 금지. 자동 재개는 이전에 완료 확정된 체크포인트에서만. timeout/불명확 전송 여부 후 **자동 재시도 금지**. 실패와 오류를 성공으로 허위 기록하지 말 것.
3. **반복·실패 안전성:** 업무당/전체 수정 횟수 제한, 한 단계 정체 탐지, 동일 결과 반복 및 논리적 무한 루프 감지, 사용자 동의 취소·비용 0 조건 재검사, 제공자 자체 rate limit·quota 차단과 안전한 스로틀링을 구현하라. 이 보호는 무료 AI 사용을 돈처럼 20번에 끊는 상한이 아니라 **실제 안전·업무 품질 제어**다. 지나치게 높은 반복 횟수/작업 생성으로 자원 사용이 폭주하지 않도록 관리. 실제 공급자 quota를 우회하거나 여러 계정을 돌리지 않는다. 제공자가 유료 전환을 요구하면 실행 중단.
4. **첫 운영 동의 보호:** 새 프로젝트 목표/동의 대상 정보 범위/무료 전용·비용 0/모델/엔드포인트/실행 기한/수정·종료 규칙을 명시해 사용자가 한 번 허용하도록 계약을 검증·감사. 실제 동의 없이 절대로 실송신하지 않는다. ‘호출 수 상한 없는 무료 모델’이라는 사실도 동의안에 분명히 보여야 한다. `prepare`는 제안 생성뿐이고 `approve`는 명시적 별도 owner-confirmed/최신 상태/hash 확인. 이 Codex 작업이 사용자 대신 실사용 동의 만드는 것은 금지.
5. **기존 공통 안전 모듈 검토:** `ai_safety.request_json`, `project_budget` 등의 2회/20회 강제가 실제 live request 내부에서도 일어나는지 코드로 파악하라. 새 무료 자율 경로를 안전하게 별도로 모델링하고 기존 수동 경로의 무단 우회/보호 해제/false consent 작성은 금지. 원장이 한 군데에서 영속 예약되며 전송 전 저장되고 attempt는 모두 기록·계수되어야 한다. 다른 프로젝트의 20회 동의나 기존 정책에 영향 없어야 한다.
6. **최소 실행 경로:** CLI/API로 goal/create→prepare/approve→**run once**→최종 JSON/Markdown 확인이 가능하도록 하라. 설령 프로세스가 사고로 끊겨도 안전한 재시작 방식은 유지하되 2회마다 사람의 resume 요구 금지. 명시 취소/진행 상태 조회는 제공하되 대시보드/프런트엔드 제작은 하지 않는다.
7. **AI 역할과 판단 출처:** 기존 계획·검토·수정·finalize 결과는 관리자/직원 AI 응답에만 기반해야 한다. Codex나 if문이 특정 영상/도서관/창고 작업 또는 품질 기준을 하드코딩/대리 승인 금지. 실제 AI의 제약(JSON/finish_reason/unknown/툴 검증 불가)은 분명히.
8. **향후 유료 안전 확장:** 지금 유료 모델을 켜지 않되 추후 도입 시 사용자 별도 명시 동의·비용 예산/실제 비용 추적·예산 초과 중단을 적용할 위치와 무료/유료 분기 경계를 문서화하라.

## 시험 / 완료 기준
- **외부 AI·DNS·HTTP 요청 0회**. 가짜 HTTPS transport / 가짜 키 / 가상 프로젝트 / 테스트용 최초 운영 동의만 사용. AI_REAL_REQUESTS_ENABLED=1로 외부 실제 송신 활성화 금지. 실제 OpenRouter 호출은 이후 사용자가 명시적 최초 운영 동의를 승인한 뒤 별도 단계에서만.
- 무료 자율 fake-HTTPS 목표 2개(하나는 관리자가 수정 지시)를 **각각 단 한 번의 실행 명령**으로 끝까지 돌려 final.json/final.md 저장, 사용자 중간 업무 승인/재개 요청 0회. **관리자/직원 합계 2회 초과, 20회 초과 사례**도 인위적 상한에 걸리지 않는다는 것을 테스트(가짜 응답/의미 없는 무한 반복은 금지). 적어도 하나의 테스트는 **정당한 20회 초과** 정상 업무 DAG로 만들어 반복 폭주가 아닌 상황임을 입증.
- 계약 검증/최초 동의 없음/범위 위반/모델 전환/무료 아닌 청구/신원·목표 변조/취소·만료/공급자 쿼터/불확실 예약/중복 송신/timeout/품질 반복 정체/수정 상한에 대한 차단 및 정지 상태 테스트.
- 기존 mock 자율 경로, 기존 수동 live 안전 계약/2회/20회/미확정 예약 차단, 전체 예산 정책을 **변경 없이 회귀 통과**해야 한다.
- 기존 진짜 프로젝트 `cb44b605b498`(마지막 9/20, TASK-003/004 대기), 다른 `c85d9853906a` unresolved attempt, 백업/미추적 파일/사용자 동의 **읽기 외 접근 및 변경 금지**. 검사 목적 SHA 대조 허용, 원문이나 키 출력 금지. 프로젝트별 저장 정책은 새 격리 namespace에서만 변경.
- KST 사용, 금전 비용 0, 유료 모델·fallback 없음, 데이터/백업 삭제 없음, `git diff --check` + 집중/회귀 테스트 통과. 테스트 성공을 실제 AI 성공으로 표시하지 말 것.

## 보고서와 변경 반영
`reports/v01_free_autonomous_full_cycle_without_artificial_call_caps_20261103.md` 생성. 다음을 한국어로 기록:
1. 변경 전 인위적 2회/20회 제한이 어느 계층에서 작동했는지와 어떻게 안전하게 분리했는지.
2. **단 한 번의 run으로 fake HTTPS 직원/관리자가 끝까지 협업해 최종 파일 저장한 증거**, 20회 초과 정상 테스트, 사용자 중간 업무 결재/재개 0회.
3. 기존 동의·실사용 9/20·원장/미확정 예약/기존 데이터 보호·실제 AI 호출 0회 확인.
4. 공급자 쿼터/품질/비용 0/무한 루프/중복 전송 등 **계속 필요한 안전차단**, 유료 전환 시 필요한 예산·승인 안전.
5. 테스트 명령/수/실패·수정/미완료, 변경 파일, 실사용 전 남은 정당한 운영 동의 또는 구현 장애물. 상위 원칙 세 시점 참조 기록.
6. 다음 한 번의 실사용 무료 운영 동의에서 사용자에게 정확히 보여줄 내용 — 한도 없는 무료 시도와 공급자 조건, 취소·기간, 데이터 범위. 이 문서나 Codex 작업만으로 그 동의를 이미 얻었다고 하지 않는다.
7. 결과 코드/테스트/보고서만 선택 커밋·푸시, 원격 검증. 키·실사용 동의/응답/JSON 원문·guard/비밀정보 Git 제외.

**합격 기준:** 현재 mock-only 1사이클 성공을 넘어, 새 무료 자율 live 경로가 **인위적 호출 상한에 중간 중단되지 않고 목표부터 최종 결과까지 안전하게 진행 가능한 구현**으로 발전하고, 실제 송신 없이 fake HTTPS로 완주 및 핵심 보호를 검증한다. 대시보드는 나중에 한다.
