# AI Company OS — 최상위 목표 및 개발 불변 원칙

문서 상태: 프로젝트 개발 기준 (사용자가 대화에서 반복 명시한 목표를 정리)
기준일: 2026-11-03 KST
우선순위: 이후 작업 지시서·보고서·예시 구현·AI 모델 응답보다 이 문서의 **제품 목표**를 우선한다. 다만 법률·안전·서비스 보안 정책과 명시적 비용/외부 전송 동의를 무효화하는 뜻은 아니다. 기술 설계 변경 시 기존 데이터와 안전 경계를 보존한다.

## 1. AI Company OS가 존재하는 이유

**사용자는 최종 목표를 한 번 입력한다. AI 관리자가 계획하고 AI 직원이 실제 작업을 수행하며 서로 결과를 전달한다. 관리자가 검토·수정·재배분해 최종 결과물을 완성하고 사용자에게 전달한다.**

사용자가 매 업무마다 승인하거나, 품질 기준을 직접 작성하거나, AI 직원 결과를 확인하거나, 관리자 대신 다음 업무를 선택해야 한다면 목표 미달이다. **업무 내용에 대한 반복적인 사용자 중간 승인 없이 최종 결과가 나오는 자율 협업**이 핵심이다.

가상 회사는 단순 채팅·할 일 목록·테스트 데모·사전 작성된 결과물을 이어 붙이는 것이 아니다. AI 관리자와 각 AI 직원이 실제 모델의 판단/생성 능력으로 일하고 업무 결과가 서로 전달되어야 한다.

## 2. 역할과 책임

### 사용자
- 목표와 필요시 필수 제약/초기 운영 권한을 한 번 제시한다.
- 특별히 사전 승인하지 않은 유료 비용·외부 데이터 전송 범위 확대 등 예외적인 운영 권한을 요청받을 수 있다. 이것은 **업무 내용에 대한 중간 결재**가 아니다.
- 최종 결과물과 보고서를 받으며, 원하면 최종 피드백을 준다.

### AI 관리자 (가상 회사 내부 역할)
- 목표 이해, 계획·조직·담당자 배분, 프로젝트별 성공 및 품질 기준 제안/설정, 우선순위, 후속 업무 결정.
- 직원 업무 결과 검토, 오류·근거 부족·품질 문제 확인, 수정 지시·재검토·업무 재배분.
- 업무 의존 관계, 예산·운영 제약 내 반복·정지·재개 판단, 최종 산출물 통합 및 보고.
- 관리자의 실제 판단을 Codex나 고정 if문, 사용자가 반복해서 대신해서는 안 된다.

### AI 직원 (가상 회사 내부 역할)
- 맡은 업무를 실제 AI로 수행하고 산출물·근거·불확실성을 보고한다.
- 선행 직원 결과를 입력받고 후속 직원에게 필요한 내용을 전달한다.
- 관리자 지시에 따라 검토·수정·재실행한다.
- 도구나 근거를 실제로 확인하지 않았으면 사실 검증/실행 완료를 허위 주장하지 않는다.

### Codex (개발 도구; 가상 회사 직원이나 관리자가 아님)
- AI Company OS의 코드·테스트·운영 흐름을 구현·검증한다.
- 구체적인 프로젝트의 업무 판단, 결과 평가, 품질 기준 선정 또는 진행 결정의 **실제 주체가 되어서는 안 된다**.
- 개발을 위한 mock fixture/예시 기준을 작성할 수는 있으나 이를 실제 AI 관리자 판단이나 사용자 승인으로 오인·적용하지 않는다.

## 3. 목표 동작과 완료 기준

**정상 경로**:
목표 입력 → AI 관리자 계획/성공 기준/업무 분배 → AI 직원 A 실제 실행 → 관리자 검토 → 필요시 직원 수정·재검토 → 직원 B에 선행 결과 전달 → 추가 업무/품질 검토 → 관리자 최종 검토/산출물 통합 → 사용자에게 완성된 결과물 보고.

- 범용 시스템이어야 한다: 영상 제작, 시장 조사, 소프트웨어 개발, 사업 기획 등 목표에 따라 AI 관리자가 업무 구조와 기준을 구성한다. 특정 영상의 초 수·팁 수·단계 ID를 실행 로직에 하드코딩 금지.
- 사람이 중간 승인하지 않아도 **사전에 부여된 운영 한도 안에서** 자율 진행하는 것이 정상 경로다.
- 관리자·직원은 충분한 정보가 있으면 자율 판단하고, 내부 품질 문제면 AI끼리 해결한다. 사용자에게 '대본 유지할까요', '어떤 품질 기준을 승인할까요', '다음 업무로 갈까요' 같은 업무상 결정을 반복 요청하는 것은 설계 결함이다.
- 최종 결과물이 실제로 생성되고 이전 업무 결과·수정 내역·불확실성이 추적되는 것을 입증해야 완료다. 테스트 통과 수 자체가 제품 완성 기준이 아니다.
- 일반적인 AI 실패·무효 응답은 기록을 보존하고, 사전 허용된 호출/복구 정책 내에서 안전하게 회복하도록 설계한다. 불확실한 중복 전송과 과금은 금지하며 자동 재시도는 반드시 별도 한도·중복 방지·정책 검증이 선행되어야 한다.

## 3-1. 사용자가 한눈에 볼 수 있는 운영 현황판 (핵심 제품 요구사항)

**AI는 중간 결재 없이 자율적으로 일하지만, 사용자는 AI 회사에서 무엇이 진행되는지 언제든 한눈에 볼 수 있어야 한다.** 자동화는 블랙박스가 되어서는 안 된다. 이 기능은 부가 기능이 아닌 목표 입력→자율 협업→최종 산출물과 동급의 필수 완료 조건이다.

- 프로젝트별 **목표·전체 진행 단계·현재 상태(대기/진행/검토/수정/완료/안전 정지)**와 최근 상태 변화, 남은 업무·최종 산출물 접근을 한 화면에 보여준다.
- AI 관리자 및 각 AI 직원별 **담당 역할, 현재 수행 업무, 입력받은 선행 결과, 진행/완료 시각(KST), 산출물, 검토 결과, 수정 요청 및 처리 이력**을 확인할 수 있어야 한다.
- 선행 업무 결과가 다음 직원에게 **누구에게서 누구로, 어떤 버전으로 전달됐는지** 추적 가능해야 한다. 완료·진행률·검토 통과 여부는 저장된 실제 이벤트/증거에 근거해야 하며 임의의 퍼센트나 가짜 실시간성을 보여주지 않는다.
- 사용자는 전체 현황 요약에서 업무별 상세 내용과 관리자 판단·검토/수정 근거·불확실성/오류 내역까지 필요한 만큼 펼쳐 확인한다. 기본 화면은 비개발자도 이해 가능한 한국어와 명료한 상태를 사용한다.
- **조회는 승인 행위가 아니다.** 상태 열람·진행 관찰·결과물 열람에 매 단계 승인 버튼을 요구하지 않는다. 운영 한도 내에서는 사용자 관찰 여부와 무관하게 AI 회사가 자율 진행한다.
- 진행 상태는 저장된 KST 이벤트를 기준으로 갱신되며, 장시간 작업·일시 중단·재개·예산/외부 권한 때문에 정지한 사유를 정확히 구별한다. UI 연결이 끊겨도 작업 이력과 결과를 보존하고 재조회할 수 있어야 한다.
- 실제 모델/비밀키/민감 원문은 무단 노출하지 않으면서 호출 횟수·남은 사용 한도·실제 운영 상태를 확인할 수 있게 한다.
- **완료 기준**: 모의 종단간 실행과 향후 실사용 실행 모두에서 사용자가 현황판만 보고 “누가 무엇을 하고 있고, 왜 수정 중이며, 다음 작업과 최종 결과는 무엇인지” 이해할 수 있어야 한다. 단순 내부 로그나 읽기 어려운 JSON만 남겨서는 부족하다.

## 4. 사용자 중간 승인과 운영 안전장치를 구분

### 제거·축소해야 하는 잘못된 기본 경로
- 관리자 계획을 사람이 매번 승인해야 다음 단계로 진행
- 직원 결과를 사람이 업무마다 승인해야 후속 직원 실행
- 품질 기준을 사람이 매번 작성/확정
- AI 관리자 판단을 사람이 매번 수락
- AI 품질 수정과 재검토를 사람이 매번 결재
- 최종 결과물을 만드는 데 중간 사용자 결정을 연속 요구

위 규칙은 현재 코드에 남아 있을 수 있다. **현재 구현이 존재한다고 이를 목표 동작으로 간주하지 않는다.** 기존 구현을 한꺼번에 삭제하거나 실제 권한을 임의 우회하지 말고, 별도 안전한 설계/마이그레이션/테스트로 역할에 맞춰 개선한다.

### 계속 지켜야 하는 진짜 운영 경계
- AI 공급자에게 보내는 자료 범위와 데이터 전송 동의, API 키 비밀 관리
- 사전 허용 모델·호출 횟수·예산/비용 상한, 유료 과금·외부 시스템 부작용
- 예산 초과·비승인 모델 변경·민감정보 전송 확대 등 승인 범위 밖 행동에 대한 사용자 승인
- 영속 원장 선예약·중복 호출 방지·불확실한 예약/timeout 보존, 감사 기록
- 실사용 파일·다른 프로젝트·백업 보존, KST(UTC+9)
- 법률/보안/안전 정책 및 실제 시스템 변경에 필요한 권한

**업무 검토를 사람이 하는 것과, 시스템의 외부 비용/권한을 통제하는 것은 별개다.** 사용자가 초기 운영 범위를 한 번 승인했더라도 그 범위 밖 요청은 새 승인이 필요할 수 있다. 이 문서만으로 기존의 건별 호출 동의가 자동 확장·폐지되거나 실사용 호출이 새로 허가되는 것은 아니다.

## 5. 개발 방식 — Codex의 자율 개발과 AI 회사의 자율 운영을 혼동하지 않는다

- Codex에는 상위 개발 목표, 현재 구조, 완료 기준, 불변 조건을 준다. 하위 코드 수정/오프라인 테스트는 Codex가 분석·자율 수행할 수 있다.
- AI 회사 내부 업무상의 판단은 **실제 AI 관리자와 AI 직원**의 역할이며 Codex가 대신 결정하거나 영상 예시를 코드로 고정하지 않는다.
- 기존 코드를 전체적으로 파악하고 최소한의 통합 수정으로 종단간 성공 경로를 완성한다. 부분 오류마다 프로젝트 목표를 잃고 방대한 진단·테스트 작업을 반복하지 않는다.
- 실제 API 호출, 요금, 외부 전송, 기존 프로젝트 데이터 변경은 현재 유효한 허용 범위·승인 정책을 따라야 한다.
- 테스트는 성공 경로와 핵심 안전 차단 사례에 집중한다. 허위 mock 성공을 실제 AI 실행 성공으로 표현하지 않는다.

## 6. 현재 상태와 전환에 관한 주의

2026-11-03 시점의 Phase 1은 업무별 사용자 승인, 품질 기준 승인, 실제 호출별 별도 승인 등 수동 보호 경계를 많이 포함한다. 이는 **최종 제품이 아니라 현재 구현·이행 단계**다. Codex의 테스트를 통과했더라도 목표의 자율 회사가 완성됐다는 뜻이 아니다.

우선할 작업은 현재 기능을 버리는 것이 아니라 **업무 판단의 소유권을 AI 관리자에게 되돌리고, 사전 허용된 운영 범위 안에서는 사용자의 중간 결재 없이 최종 산출물까지 이어지는 흐름을 구현**하는 것이다. 실제 사용자 프로젝트 데이터는 보존하며 마이그레이션·안전 검증 후 적용한다.

## 7. 모든 후속 Codex 작업의 사전 점검

작업 전 다음을 스스로 확인한다.
- 이 변경이 사용자의 중간 업무 승인 횟수를 늘리는가 줄이는가?
- 업무 판단을 AI 관리자/직원이 하는가, Codex/고정 규칙/사용자가 대신하는가?
- 이번 결과로 목표 입력부터 최종 산출물까지 실제 거리가 줄어드는가?
- 범용적인가, 아니면 영상 사례에만 맞춘 하드코딩인가?
- 기존 프로젝트·백업·운영 안전 한도·KST를 보존하는가?
- 단지 테스트 수치가 아니라 실제 결과 전달·검토·수정·최종 보고가 가능한가?

위 질문에 역행하는 개발 지시라면 구현 전에 충돌을 명시하고 상위 목표에 맞춰 설계를 바로잡는다.
