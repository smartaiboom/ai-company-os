# v0.1 M4 실제 무료 AI 인수 테스트 — 안전 사전 점검 중단

작성: 2026-11-02 KST. 작업 기준: `6f19c7f1fda5fc2b1213fc73ad8dff846b97bb5b` (`main`과 `origin/main` 일치).

**실제 AI 연결 테스트를 시작하기 전 안전하게 중단했다. 실제 API 호출 0회.** 사용자는 목표 ‘소규모 매장의 재고 확인 업무를 개선하는 도구 기획 및 실행 제안서 작성’, OpenRouter `openrouter/free`, 프로젝트 전체 최대 7회, 승인된 테스트 프로젝트 자료 전송에 동의했고 유료 모델 전환·자동 재시도를 금지했다.

사전 점검에서 `AI_API_KEY` 환경 변수는 존재했지만, 실제 키 값은 조회·출력하지 않았다. `AI_MODEL`, `AI_ENGINE`, `AI_API_BASE_URL` 변수도 설정되어 있었다. 다만 M2 안전 경계의 필수 서버 스위치 `AI_REAL_REQUESTS_ENABLED=1`은 설정되지 않았다. 앱의 공통 요청 경로는 이 값이 없으면 실제 요청을 명확히 거부한다. 이 안전 설정을 임의로 켜는 것은 사용자가 승인한 호출 횟수 동의와 별개의 서버 운영 설정이므로 변경하지 않았다. 키 존재만으로도 요청을 전송하지 않았다.

대상 `openrouter/free` 및 정확한 OpenRouter 주소 설정값은 노출하지 않는 방식으로 검사할 수 있었지만, 서버 스위치가 누락되어 종단 호출을 허용할 수 없는 상태라 실제 연결 요청은 보내지 않았다. 테스트 프로젝트도 만들지 않았고, 기존 업무 데이터는 읽거나 변경하지 않았다. 모델/호스트 자격 증명, 계정 무료 라우팅, 결과 품질, JSON/Markdown 다운로드, 브라우저 UI 및 회귀 테스트는 이 중단 때문에 검증하지 않았다. 실제 호출 실패·성공 수 모두 0이며 원인은 사전 안전 설정 누락이다.

다음 단계는 운영자가 격리 테스트 환경에서 승인된 범위에 한해 `AI_REAL_REQUESTS_ENABLED=1`을 설정하고, 이 환경에 `AI_MODEL=openrouter/free`, 허용된 OpenRouter 기본 주소, 유효한 API 키가 준비되었는지 확인하는 것이다. 이후 이 승인 범위 내 최대 7회, 요청당 최대 2회 제한과 테스트 프로젝트 동의를 적용해 재개할 수 있다. 유료 경로·fallback·자동 재시도는 허용되지 않는다.

검사한 파일 외 기존 미추적 항목은 보존했다. 실제 키·민감 결과 원문은 포함하지 않았다. 이 보고서는 안전 설정 확인과 API 연결을 검증하는 검증 코드가 없으므로 코드·테스트 변경이나 전체 회귀 테스트를 수행하지 않았다.


## 사용량 초기화 후 재개 점검 — 2026-11-02 KST

`codex_tasks/m4_resume_after_quota_reset.md`에 따라 기존 상태를 우선 확인했다. `git pull --ff-only`가 성공하여 `4117825`까지 갱신되었고, 점검 시 main과 origin/main 사이 로컬 추가 커밋은 없었다. 기존 미추적 파일·업무 JSON·백업은 보존했다.

### 이전/이번 호출 및 예산

- 이전 보고서 기준 실제 API 시도 0회, 성공 0회, 실패 0회, 테스트 프로젝트 생성 0회.
- 이번 실제 API 시도 0회, 성공 0회, 실패 0회. 예산 예약이나 동의 설정을 새로 만들지 않았다.
- `data/projects` JSON의 목표를 읽기 전용으로 대조했으며 승인 목표와 정확히 일치하는 프로젝트는 발견되지 않았다. `/tmp` 최상위에도 M4 이름의 격리 경로는 없었다. 존재하지 않는 프로젝트의 예산을 생성하거나 초기화하지 않았다. 이 확인은 다른 위치에 소실·보관된 기록까지 없음을 보장하지 않는다.
- `/tmp`의 M4 경로 최초 탐색에서는 무관한 daemon 디렉터리 접근 거부가 있었다. 권한을 우회하지 않았으며 후속 최상위 경로 확인과 프로젝트 메타데이터 점검으로 범위를 한정했다.

### 안전 경계와 승인 상태

`ai_safety.py`의 `check_project_permission` 및 실제 전송 경로를 확인했다. 프로젝트 enabled, 목표 지문, approved_at, 전송 범위 동의, 서버 활성화가 필요하며, 요청 전 영속 예약·프로젝트 총 7회·시작/재개당 2회·reserved 재전송 차단을 적용한다. 모델은 정확히 `openrouter/free`, 호스트는 고정 OpenRouter HTTPS 경로로 제한되고 리다이렉트는 차단된다.

환경 변수는 키 존재 여부와 조건 일치 여부만 검사했다. 키는 존재하고 모델/엔진 조건은 일치했으나 서버 활성화는 꺼져 있었다. 키 값·일부·길이 및 응답 본문은 조회·출력하지 않았다. 이번 지시서는 격리 프로세스 활성화를 허용하므로 서버 스위치 자체를 추가 승인 사유로 삼지는 않는다. 다만 현재 직접 확인 가능한 사용자 메시지는 작업 문서 실행 요청이며, 과거 외부 전송 승인은 문서 내 기록으로만 확인된다. 안전 재개 문서 3항과 이번 지시서 5항의 직접 확인 조건을 충족했다고 추정하지 않아 외부 전송과 프로젝트 생성 전에 중단했다. 프로젝트 동의 enabled/approved_at 및 계획·업무·품질 기준의 사용자 승인을 대신 설정하지 않았다.

### 완료 범위·검증·남은 조건

이번 변경 파일은 이 보고서 하나다. 코드 변경이 없어 지시서에 따라 집중/전체 회귀 테스트를 실행하지 않았다. 실제 계획 생성, 역할별 결과, 의미 검토·수정·재검토, 최종 사용자 승인, JSON/Markdown 다운로드 및 브라우저/loopback HTTP 인수는 수행하지 않았으며 성공으로 판정하지 않는다. v0.1 M4는 미완료다.

실행 결과: `git status --short`, `git branch --show-current`, `git log --oneline origin/main..HEAD`, `git pull --ff-only`, 보고서/관련 안전 코드 읽기, 비밀을 출력하지 않는 환경 조건·프로젝트 메타데이터 확인을 완료했다. 보고서 재읽기와 `git diff --check` 후 이 보고서만 커밋·푸시하고 원격 파일 일치 여부를 확인한다.

다음 1단계: 사용자가 현재 대화에서 위 재고 확인 목표에 한해 OpenRouter `openrouter/free`, 해당 격리 프로젝트 자료의 외부 전송, 총 7회·재개당 2회 한도 내 테스트 시작을 직접 승인한다. 승인 후에도 계획·업무 결과의 사용자 승인 경계에서는 멈추며 자동 승인하지 않는다.
