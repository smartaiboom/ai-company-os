## 이번 한 단계
이미 구현한 미션 01을 실제로 진행한다. 반복적인 키/쿼터/결제 감사나 새 보고서만 만드는 작업은 하지 않는다. 2026-11-11 최신 실행 보고서에서 **Gemini 3.5 Flash-Lite의 현 API 키 계정별 무료 접근을 사전에 확정할 증거가 없다는 이유만으로** 실행을 막았다. 이 점을 합리적으로 해결하고 가능한 경우 실제 관리자→조사 직원→대본→대표 검토 대기까지 수행한다.

대표의 확정 목표: "요즘 인기있는 게임에 대한 흥미있는 쇼츠 영상을 만들어봐. 기본적으로 인기있는 쇼츠는 몇초인지도 확인해보고."

## 승인 기록(재확인 요청 금지)
사용자는 2026-11-11 KST에 이번 미션의 다음 실제 외부 호출 범위를 명시적으로 승인했다.
- Gemini 텍스트 `gemini-3.5-flash-lite` 최대 10회 (실패/시간초과도 소비).
- YouTube Data API `search.list` 최대 4회, `videos.list` 최대 4회.
- 무료 서비스만. 유료 전환, 자동 재시도, fallback/다른 모델, 추가 외부 서비스, 음성·MP4·게시 금지.
- 목표·공개 YouTube 조사 자료·AI 직원 업무 결과의 Google 무료 API 전송, 서비스 개선/인적 검토 가능성을 이해하고 동의함.
- 기존 `prepare`→`approve`의 프로젝트별 동의 서명/제안 해시/사전 예약 및 시도 원장은 반드시 준수한다. 이 MD 승인 기록만으로 코드를 우회하여 `run`을 바로 호출하지 않는다.

## 실행 지침
1. GitHub 최신을 안전하게 가져오고 `AGENTS.md`를 읽는다. 현행 승인/상태 가드와 실제 프로바이더 요금 설정을 점검한다. 기존 키 존재·YouTube 할당량·사용자 보고의 결제 미등록 상태를 새 감사로 반복하지 않는다.
2. **실제 유료 청구가 발생하지 않는 기술적 조건**이 충분히 충족되는지 평가한다. 최소 조건: 현재 키 프로젝트에 Billing이 비활성이라는 믿을 만한 기존 증거와 Gemini 무료 호출 모드/정확한 모델·엔드포인트/쿼터 상한 및 추가 유료 도구 미사용. 사용자 보고 '결제 미등록'을 근거의 일부로 활용하되, Codex가 확인하지 못한 사실을 직접 검증한 것처럼 꾸미지 않는다. 확인이 부족하여 유료 노출 가능성을 배제할 수 없으면 API를 호출하지 말고 해당 **한 조건**만 보고한다.
3. 무료 전용 조건을 만족한다면 기존 `prepare`가 요구하는 확인값을 **검증 가능한 값으로만** 제공하고 제안 JSON/해시를 읽는다. 불확실한 잔여 쿼터를 임의 숫자로 입력하지 않는다. 동의 범위와 일치하면 `approve`를 사용해 정확한 서명 승인을 저장한다.
4. **별도 API 시험 호출을 만들지 않는다.** 첫 Gemini 요청부터 미션의 실제 업무 요청으로 보내고 승인 상한 10회 중 1회로 소모한다. 실제 공급자가 이 모델·요금제의 접근을 거절하면 반환된 오류를 증거로 기록하고 즉시 중단(자동 retry 0, 대체 모델 0). 모델의 실행 가능성을 미리 무한정 검증하려고 하지 않는다.
5. 사용 권한이 허용되면 기존 직원 웹 조사/관리자 판단/대본 작성/내부 검토 경로를 끝까지 연결한다. 조사 직원이 게임 후보·조회 영상·길이를 자율 조사. 허위 근거/임의 길이/쇼츠 분류 확정 금지. 기존 승인한 YouTube API 상한을 준수하고 사용한/실패한 요청을 소비로 기록한다.
6. 실제 모델 결과·직원별 출처/선정 근거/전체 한국어 대본/타임라인/버전·SHA만 컷룸 `awaiting_plan_approval`에 제출한다. 실패 시 실제 결과가 없는 승인 대기 카드 생성 금지. 실제 대표 승인/음성·영상·업로드는 금지.
7. **현재 구현의 승인 가드가 계정별 사전 증거를 반드시 요구해 진행할 수 없다면**, 이를 우회하거나 임의 사실을 넣지 말고 공급자 과금 노출 방지 조건을 유지하면서 필요한 최소 수정 가능성을 분석한다. 실제 수정이 필수이고 안전조건 충족이 확인되는 경우에만 최소 코드 수정·관련 테스트를 수행한다. 무료 안전성 검증이 불충분하면 소스/원장을 바꾸지 않고 그 차단 사유 하나를 보고한다.
