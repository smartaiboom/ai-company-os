# AI Company OS — 첫 실제 무료 AI 자율 운영 시험: 새 프로젝트/최초 운영 동의안 준비

## 목적
사용자가 요청: “그래 이제 AI 자율 운영 테스트를 해보자. 간단한 목표를 주고 ai가 결과까지 도출하는거야.”

이번 작업은 **첫 실사용 AI 자율 프로젝트를 안전하게 시작할 준비**다. **실제 AI 전송은 아래 계약에 대한 사용자의 별도 명시적 동의가 입력된 다음 단계에서만** 한다. Codex가 개발 작업 위임이나 일반적인 시험 요청을 비용/외부 전송에 대한 서명 동의로 간주하지 말 것. 특히 `approve --owner-confirmed`, `run`, 실사용 API 요청 활성화는 **이번 지시서에서 실행 금지**. 초기 실사용 프로젝트 생성과 제안 생성은 허용, 하지만 기존 수동 프로젝트·키·원장/guard는 불변.

## 필수 읽기
먼저 `AI_COMPANY_OS_CORE_PRINCIPLES.md`, `AGENTS.md` 전체, `reports/v01_free_autonomous_full_cycle_without_artificial_call_caps_20261103.md`, `autonomous_free.py`, `autonomous_live_cli.py`의 실제 최신 내용을 확인. 사용자 중간 업무 승인 0회, Codex는 개발자, AI 관리자/직원은 내부 역할, 무료 모델 비용성 호출 상한 없음, 대시보드는 나중, KST, 기존 데이터 보존.

## 테스트할 목표 (공개적이고 민감 정보 없음)
**“ChatGPT를 처음 쓰는 직장인을 위해, 실제 업무에 적용할 수 있는 이메일 초안 작성 팁을 설명하는 한국어 1페이지 안내문을 작성하라. 초보자도 따라 할 수 있는 예시 프롬프트 3개와 사용 시 주의사항을 포함하되, 확인하지 않은 기능·효과는 단정하지 말라.”**

이 문장은 실사용 목표 입력이다. 이 외에 사내 메일이나 업무 파일, 과거 사용자 프로젝트 결과, 개인 정보, 계정, 비밀키를 입력하거나 provider에 보내지 않는다. AI 관리자가 해당 목표의 업무 계획·품질 기준·직원별 역할을 독립적으로 결정하게 하고, Codex가 계획/기준을 하드코딩하지 말 것. 새로운 프로젝트가 기존 영상 프로젝트에 섞이면 안 된다.

## 해야 할 일
1. 기존 프로젝트의 저장소 및 환경, 충돌 가능성/CLI 동작을 읽기 전용으로 확인한다. 실제 AI API가 향후 실행 가능하도록 설정 상태를 **키/비밀 노출 없이** 확인하고, 미설정이면 차단 상태와 준비 방법만 보고한다. 특히 무료 전용 flag, 고정 URL/모델, 키 존재 여부/guard 차단 조건을 식별. AI_REAL_REQUESTS_ENABLED나 다른 guard를 **이번 작업에서 영구 수정하거나 활성화하지 않는다**. 실제 요청·네트워크 연결/모델 동작 탐색은 하지 않는다.
2. 기존 `data/` 및 상위 사용자 프로젝트, 다른 `c85d9853906a` 미확정 예약과 혼재되지 않은 **새 전용 free-v2 저장 경로**에 위 목표로 프로젝트를 **정확히 한 건** 생성한다. 이미 동일한 준비 작업으로 생성한 프로젝트가 있다면 반복 생성하지 않는다. 경로는 Git ignore되고 기존 저장소/guard와 분리되어야 하며 암호/개인정보를 포함하지 않는다. 생성된 project_id, 목표 SHA, 최신 초기 상태 hash를 기록한다. 필요하면 최초 테스트용 저장소용 서명 키 위치를 보안 경계 내에 분리한다. 지금은 prepare만 실행해 서명 키·승인 권한을 생성하지 않는 정상 경로 사용.
3. `autonomous_live_cli --store NEW_FREE_STORE prepare PROJECT_ID --proposal-out ...`로 실제 초기 **무료 운영 계약 제안만** 생성한다. 실제 목표·7개 scope·OpenRouter/free 정확한 모델·고정 HTTPS URL·가격 0/유료 전환 없음·기본 전체/실행당 인위적 호출 상한 없음·업무/수정 한도·실행 30분 벽시계·24시간 동의·공급자 무료 쿼터와 중복/불확실 예약 처리·취소 의미를 검토할 수 있도록 요약. **prepare와 프로젝트 생성이 네트워크 요청을 만들어선 안 된다.**
4. 시간이 경과해 expires_at가 실제 승인 시점에 지나면 그때 최신 proposal/hash를 다시 준비해야 한다. 현재의 제안이나 이 Codex 개발 지시서로 운영 동의가 성립했다고 하지 않는다.
5. 승인 후 실제 한 사이클을 달성하기 위해서 **실제 OpenRouter 반환 구조·strict JSON/usage.cost 필드가 전송 후 차단시킬 가능성**을 코드와 fake transport 테스트 관점에서 미리 점검하되 실제 API 테스트는 금지. 코드 변경이 필요한 명확한 버그가 있으면 Codex가 자율 수정·오프라인 검증·회귀 후 커밋. 단 제품 기능 무단 완화/비용성 fallback 금지. 새로운 작은 지시서 요청 없이 한 작업에서 처리.
6. 보고서 `reports/v01_real_free_autonomous_smoke_prepare_20261103.md` 작성. 작성한 실제 새 프로젝트 경로/ID, 원본 goal 요약, 프로젝트 최신 hash, proposal 경로/hash, 승인 계약의 정확한 필드, 키/환경 준비 여부를 설명하되 **API 키·서명 키·전체 사용자 데이터 원문을 출력/커밋하지 말 것**. 승인에 필요한 **딱 한 가지 사용자 선택**과 다음에 Codex가 실행할 정확한 명령 흐름 제공. 최초 운영동의 이전 실제 AI 호출 0건. 기존 `cb44b605b498` 9/20 불변과 다른 데이터·백업 보존 증거.
7. 테스트/준비 프로세스에서 실사용 요청 전송 가능성이 있으면 반드시 안전하게 중단. 프로젝트·제안 파일 외 기존 업무 자료는 수정하지 않는다. Git에는 코드 변경(있을 경우)과 작업 보고서만 선택적으로 커밋/푸시. 새 프로젝트 JSON/운영 승인 제안은 Git 제외하고 사용자 Codespaces 로컬에만 유지. `git diff --check`, 관련 테스트, 원격 확인.

## 이번 작업에 포함되지 않는 권한
- **실제 OpenRouter API 호출 0건**. `approve`에 `--owner-confirmed` 전달 금지. `run`/실제 직원 실행·실제 모델 전송/유료 비용/다른 모델 fallback 금지.
- 사용자 대신 '승인됨' 기록 생성 금지. 이번 사용자 발언은 실제 실험을 시작하자는 취지이지만 API로 **어떤 자료를 보낼지, 무료 조건/호출 범위, 유효기간**을 명시 확인하기 위한 준비 단계다.
- 이전 사용자 승인/원장 `cb44b605b498` 변경, 다른 `c85d9853906a` 미확정 예약 해결, 삭제·백업 초기화·강제 Git 정리 금지.

## 합격 기준
**새로운 민감정보 없는 목표에 대해 실제 실사용 free-v2 프로젝트 1건을 준비하고, 그 프로젝트에 정확히 결합된 무료 전송 운영 계약 제안까지 생성한 다음, 사용자의 명시적 운영 동의 전에서 멈춘다.** 데이터·키 보안과 기존 9/20 안전상태 보존. 사용자 승인 후에는 새 목표 프로젝트에서 실제 모델이 스스로 계획→직원 실행→검토→최종 문서를 만들게 한다. 이번 작업은 준비 완료이지 실송신 성공이 아니다.
