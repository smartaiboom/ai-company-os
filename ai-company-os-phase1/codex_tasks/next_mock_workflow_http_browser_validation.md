# 다음 작업: mock 자동 진행의 HTTP·브라우저 통합 검증

## 목적
AI Company OS의 mock 전용 업무 자동 진행 기능이 실제 사용자 웹 흐름에서 안전하게 작동하는지 확인한다. 기존 AI 직원 협업·승인 흐름을 보존하면서 **검증 우선**으로 진행한다. 운영 기능을 새로 확장하는 작업은 아니다.

## 사전 확인
- `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, `reports/mock_workflow_orchestration_20261102.md` 및 관련 운영 코드·테스트를 먼저 읽는다.
- 현재 브랜치, origin/main, git status/diff와 기존 미추적 파일을 확인한다. 기존 프로젝트 JSON·업무 결과·백업은 수정·삭제·초기화·무단 스테이징하지 않는다. reset, clean, force push 금지. 시각은 KST로 기록한다.
- 기존 Playwright/Chromium 검증 환경을 사용할 수 있는지 확인하되 설치 및 변경은 최소화한다.

## 검증 대상
1. 격리된 임시 프로젝트와 mock 실행기로 계획 승인 → 웹에서 자동 진행 시작 → 첫 검토 대기 정지 → 사용자 승인 → 웹에서 재개 → 다음 직원에게 승인된 선행 결과 전달을 HTTP/브라우저 경로에서 확인한다.
2. UI의 시작·재개 버튼, 중단 이유 안내, 모달/진행 표시, 409 동시 요청 안내와 저장 상태 일치를 확인한다.
3. 미승인 계획, 필수 선행 결과 누락, 실패/빈 결과, 수정 요청, 중복 자동 실행, 실행 횟수 상한을 가능 범위에서 검증한다.
4. mock 외 모드에서 /workflow/run 요청이 실제 AI 실행 전에 거절되고 프로젝트 데이터가 변경되지 않는지 검증한다.
5. 과거 브라우저 테스트 결과와 이번 실제 실행 결과를 분리 기록한다. 불가능한 검증은 미검증으로 정직하게 표기한다.

## 안전한 작업 범위
- 기존 기능은 우선 변경하지 않는다. 검증 중 명백한 오류를 발견하면 가장 작은 수정과 관련 테스트만 추가하고 보고서에 근거를 기록한다.
- 임시 저장 경로, 모의 실행기, loopback 서버만 사용한다. 실제 업무 데이터, 외부 네트워크 AI API, 유료 모델을 절대 호출하지 않는다.
- 브라우저 환경이 없다면 무리하게 OS를 변경하지 말고 격리된 HTTP 통합 테스트로 대체하고 한계를 기록한다.
- 관련 단위/HTTP/브라우저 테스트와 `git diff --check`를 실행한다. 저장소 실제 데이터 경로가 격리되지 않은 테스트는 실행하지 않는다.

## 산출물 및 GitHub 전달 (필수)
- 반드시 `reports/mock_workflow_http_browser_validation_20261102.md`를 파일로 작성한다. 기존 동일 파일이 있으면 읽고 보존하며 임의로 덮어쓰지 않는다.
- 검증 항목별 실제 실행 결과, 명령·통과 수, 변경 파일, 미확인 위험, 실제 AI API 호출 여부 및 데이터 격리 방법을 기록하고 재독한다.
- 의도된 변경 파일과 이번 보고서만 선택적으로 스테이징하고 테스트가 통과하며 충돌이 없으면 원격 origin/main에 안전하게 커밋·푸시한다. 충돌·미해결 테스트 실패가 있으면 푸시하지 않고 이유를 알린다.
- 결과를 Codex 대화에만 남기지 않는다. 완료 보고에는 **보고서 경로, 커밋 SHA, 푸시 여부**를 명확히 기록한다.
