# 대표 조사 검토에서 기획·대본과 제작 인계까지

2026-11-25 KST · 시작 기준 `d51d147`

## 구현

컷룸의 조사 보고서에서 대표가 후보를 선택하거나 자연어 기획 방향을 남기고 목표 길이를 정할 수 있다. 관리자 보류 보고서도 근거 한계를 확인하고 다음 기획으로 인계할 수 있다. 원본 보고서 버전·해시, 기존 판단, 선택 후보, 근거 ID, 미확인 조건과 명시적 목표 변경은 기존 프로젝트에 남는다. 조사 결과와 관리자 보류 기록은 유지된다.

기존 Gemini 품질 엔진이 관리자 배정, 작가 대본, 편집 직원 장면표, 관리자 내부 검토를 담당한다. 기획·대본의 무료 전송 서명과 대표의 업무 결정을 분리했다. 같은 승인 범위에서 수정 의견과 이전 산출물을 이어받아 새 버전을 만들며, 일치하는 최신 승인 해시만 제작 입력으로 사용한다. 전체 고정 호출 한도는 추가하지 않았다. 실제 제작 도구·권리·비용 승인은 기존 조건을 따른다.

포괄적인 조사 전용 게이트가 이미 준비된 레거시 미션의 멱등 진입도 막고 있었다. 해당 진입을 허용하고 조사 전용 프로젝트의 직접 미션 실행·보고 우회는 계속 차단한다. 대본 계약에 맞는 장면도 기존 세로 제작의 장면당 20초와 전체 120초 규격을 넘으면 제작에서 거절될 수 있었다. 신규 인계는 기존 세로 제작 규격 검사를 대표 제출 전에도 사용한다.

## 검증

| 단계 | 결과 |
| --- | --- |
| 오프라인 | 관련 Python 22건과 컷룸 Node 검증 통과. 기존 `general_report_only` 미션 인계 회귀를 다시 실행해 통과했다. 최신 보고서 해시 불일치, 사용자 선택 중복, 외부 전송 무승인을 차단했다. |
| 격리 컷룸 | localhost HTTP에서 가상 대표 후보 선택, 별도 무료 범위 서명, 관리자·작가·편집 역할별 모의 응답으로 기획 v1 제출, 대표 수정, 기획 v2 제출 및 승인을 확인했다. v1 원본은 그대로였고 승인된 v2의 수정 내레이션이 기존 제작 장면 규격에 연결됐다. 빈 영상이나 모의 파일을 실제 제작 결과로 제출하지 않았다. |
| 운영 컷룸 | 기존 운영 프로젝트 GET HTTP 200. 실제 v8 검토 대기와 v9 `provider_unavailable` 유지, 운영 파일 1,442개의 해시 일치를 확인했다. 운영 v8의 대표 결정을 작성하지 않았다. |
| 실제 AI | 격리 프로젝트의 실제 기획·대본 검증 범위에 대한 대표 명시 승인을 받았다. 기존 조사 전용 서명과 구분했다. 동일 모델·프로젝트의 HTTP 503 이후 정상 복구를 확인할 수 없어 실제 서명·예약·호출은 0건이다. 실패 자동 재전송은 없었다. |

## 남은 연결
