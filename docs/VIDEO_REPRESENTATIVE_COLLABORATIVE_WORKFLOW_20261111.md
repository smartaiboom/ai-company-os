# AI 영상제작 회사 — 대표 협업형 운영 흐름 확정 및 구현 우선순위
기준: 2026-11-11 KST

## 사용자가 확정한 제품 목표
사용자는 **AI 영상제작 회사의 대표**다. 사용자에게는 큰 제작 목표만 요구한다(예: 스포츠 뉴스 영상을 만들어 줘). AI 관리자는 조사·기획·대본 직원을 지휘해 실제 근거 있는 소재를 발굴하고, 어떤 영상·어떤 방식으로 만들지 기획안과 대본을 내부 검토·수정한 뒤 대표에게 보고한다. 대표가 반려하거나 피드백하면 관리자→담당 직원 재작업→내부 재검토→대표 재보고. **1차 대표 승인이 나야** 승인된 버전의 대본/기획안 기반으로 실제 영상·음성·자막·편집 제작이 시작된다. 완성 MP4를 대표에게 보고하고 피드백/수정/재보고를 반복해 **2차 대표 승인** 후 최종 완료한다. 대표가 개입하는 이 협업 방식은 의도된 제품 특징이지 완전자율 목표에서의 실패가 아니다. 나중에 축적한 실제 평가를 기반으로 신뢰성 높은 판단부터 자율화한다.

### 예시
스포츠 뉴스라는 큰 목표라면 AI 조사 직원이 최신의 확인 가능한 경기/뉴스 자료를 확인, 주제 후보 비교, 추천 이유·날짜·출처·시각자료 사용 권리를 보고한다. 손흥민 득점 등의 사건을 **확인되지 않은 실제 사실로 기재하지 않는다**. 영상·중계화면을 사용하려면 권리를 확인하고 불가능하면 자체 제작 그래픽/정당한 라이선스 소스 사용. AI 초보자 팁이나 그 외 장르도 가능해야 하므로 기존 '한국어 직장인 AI 초보자' 데모를 **모든 프로젝트에 강제하지 않는다**.

## 정확한 실행 단계/불변식
1. `goal_submitted`: 대표의 넓은 목표와 제작 제약 저장.
2. `research_planning`: AI 관리자 업무배정, 직원 조사/인기주제 후보·시점·출처·불확실성 표시, 내부 주제선정·대본 작성, 0–3초 후크/실제 시연 가능한 장면 및 권리·사실 확인, 내부 반려·수정. '모의 코덱스 작성' vs '실제 LLM 추론' 구분.
3. `awaiting_plan_approval`: 기획 요약/근거 URL/대표 추천/승인 대상 주제 및 대본 전체/버전/sha/업무 상태/남은 위험·소스·비용을 대표에게 표시. 대표 선택: `approve` 또는 `request_revision`. 승인되지 않은 버전을 제작 직원에게 보낼 수 없음.
4. `plan_revision`: 대표 피드백 원문과 버전 연결, 관리자와 직원에게 수정할 부분 배정, 새 버전/변경사항 보고, 다시 `awaiting_plan_approval`. 피드백 횟수/버전 기록 보존.
5. `production`: 승인된 버전·sha만 인수하여 음성/TTS, 소스/영상 편집, 자막 합성, QA, 실제 미디어 파일/ffprobe 검사. 제작에 필요한 **외부 API/비용/라이선스 범위는 승인된 별도 실행권한만** 사용; 대표의 기획안 승인만으로 유료 API·외부 게시 허가는 생기지 않음. 기존 음성 Gemini/Puck은 실제 21.52초/7점으로 사용자 수용되었으나 모델 일괄 강제는 금지.
6. `awaiting_video_approval`: 실제 재생 가능한 MP4/작업 산출물, 실제/미검증 QA, 비용/소스 근거, 제작에 사용한 승인 대본 버전/sha를 대표에게 보고. `approve` or `request_revision`.
7. `video_revision`: 대표 피드백 근거로 관련 직원 재작업 후 재보고. 기존 승인 대본 내용/기획 자체 변경이 필요하면 **1차 기획안 승인으로 되돌려** 새 버전 승인받아야 함. 다른 파일 덮어쓰지 않으며 비디오 버전별 보존.
8. `completed`: 최종 대표 승인과 매칭되는 실제 최종 파일 검증, 승인 증거/산출물 해시 및 경험 피드백 저장. 사용자 최종 승인 없이 완료·게시 합격으로 표시 금지. 게시 자체는 별도 지시/권한.

## 개발 우선순위: 이 순서를 유지하라
**A. 우선 업무 시스템 연결/완성**: 지금까지 만든 조사/주제선정/대본 검토·반려/음성/WAV/60초 MP4 제작 엔진/승인 엔진을 코드와 현존 테스트로 감사해서 사용 가능한 것을 재사용한다. 공통 `core/`와 전문 `companies/video/` 구조 유지. 상태머신과 산출물 인수/대표 승인 2회·재작업·완료를 **기존 구조의 최소 변경으로 통합**. 대표 UI 이전에도 기존 CLI/테스트 등으로 전 구간의 흐름·차단·승인반려·재진입을 확인할 수 있어야 한다. 실제 LLM/미디어 API 호출과 모의 콜백을 바꾸어 표현하지 않는다. 외부 모델 호출·결제·실제 미디어 재생성은 사용자로부터 별도로 승인된 범위를 초과하지 않는다. 무한 준비/중복 mock/새 승인지갑/일회성 문서 생성 대신 **동작하는 기본 통합 기능**을 우선.
**B. A의 오류 없는 기본 사이클이 확인되면 대표용 웹 UI 만들기**: 기존 웹 화면/라우트가 있으면 먼저 확인·재사용. 프로젝트 생성(큰 목표), AI 직원·관리자 작업 흐름과 이벤트 타임라인, 근거/리서치/주제후보·기획안·전체 대본 열람, 1차 승인 및 피드백/재보고, 제작 진행/파일·실행비용·실패 상태 표시, MP4 재생 및 2차 승인/피드백/완료. 사용자가 보고 판단하기 쉬운 **실제 상태를 표시하는 화면**, 보기만 좋은 가상 대시보드는 금지. 사용자 조작 승인 때 서버측 버전+SHA 검사, 이중 클릭/새로고침 중복 요청 방지.
**C. UI로 실제 업무가 보인 다음 AI 관리자·직원 품질 향상**: 실제 주제선정, 대본, 영상 퀄리티·도구 선택을 관찰하고 사용자 피드백/경험을 적용해 개선. 품질을 먼저 완벽하게 만들겠다고 A/B를 지연하지 말 것.
