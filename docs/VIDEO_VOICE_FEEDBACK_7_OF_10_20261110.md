# 영상제작 회사 2단계: 실제 음성 사용자평가 반영·제작 품질 향상
기준일 2026-11-10 KST

## 최상위 목적
사용자가 **실제로 청취한 2개 음성**을 평가: **Gemini 3.8 Flash TTS/Puck (B)가 MeloTTS (A)보다 훨씬 자연스럽다. B 자연스러움 7/10점.** 이 사실을 **실제 사용자 평가**로 영상제작 전문 AI 회사에 반영하고 음성 직원의 후속 제작·관리자 검토의 품질을 개선한다. 목표는 궁극적으로 유튜브에 올리고 싶은 수준의 자동 영상제작 회사다. 1단계 AI 회사 구조 재설계, 공통 코어 재구축, GUI는 제외.

## 절대 구분할 것
- 지난 실제 호출 보고서 `reports/GEMINI_TTS_ONE_SHOT_UNBLOCK_RESULT.md`: 실제 B_gemini.wav (8.04초, PCM16 mono 24kHz, SHA256 `7674f8d8449f5011aff56efd6c4f52ba7d878c43541df6d7043442a4ba831419`), A_reference_melo.wav (10.982초, SHA256 `a011f8bb6b83e5d3515171bcdf6fc9e9aa09d42844f8e14cfbb8955de18b25a5`), 동일 60자 대본 SHA `ec1e2906fd065530a2bbfc79bfab9d3769a9f72296897887f5b02d4efeeffa59`. 로컬 경로 `data/gemini_tts_single_free_trial_v1/operation/`.
- **사용자 직접 청취 확인:** B 선호, B 7/10. 이는 진짜 사용자 선호·점수의 verified evidence. **B가 언제나/모든 상황에서 최고라거나 게시품질 합격, 특정 품질 결함(억양/발음/속도)이 있다는 근거는 아님**. 그런 결함을 꾸며내지 말 것.
- 기존 `core/quality_feedback.py` ExperienceJournal, `companies/video/quality_workflow.py`, `companies/video/tts_job.py`, `companies/video/tts_execution.py`, `reports/CURRENT_PROGRESS.md` 재사용. 1회 Gemini 실 TTS 요청의 전송·영속 guard **이미 소모됨**. 이번 작업에서 외부 실 모델·TTS·영상 API 호출 **0회**, 비용 0, 새로운 키/가입·무료쿼터 조회 없음. 사용자가 B 평가를 전달한 것은 **추가 유료/무료 생성 API 호출을 승인한 것이 아님**. 새 실음성 A/B가 필요하면 별도의 정확한 다음 테스트를 한 번만 제안할 것.

## 이번 개발에서 반드시 실제 수행
1. **실제 사용자 피드백을 보존 가능한 구조로 저장**:
   - 원문: `실제 음성 A/B 청취 평가 결과: 더 나은 음성=Gemini TTS(B), 새 Gemini 음성 자연스러움=7/10점, 의견=B가 훨씬 자연스러워.`
   - 원본 오디오와 평가의 연결을 A·B SHA, 60자 대본 SHA, 모델/보이스, 시각 KST, 선호/점수, 근거 출처(user_structured)를 갖는 명확한 immutable evidence artifact로 저장. 원문 임의 수정 금지. 평가를 기존 ExperienceJournal에 저장할 때는 **실제 사용자 검증 출처 provenance=user_structured**로, domain video / target_segment 한국어 직장인 AI 초보자 범위에만 선택되도록 작성. 기존 저널과 해시/ID 보존; 가능하면 별도 user feedback 저널을 유지하고 기존 journal을 덮어쓰지 않는다. 동일 평가 두 번 저장 방지(idempotent by evaluation SHA).
   - 경험 기록의 `verification='verified'`는 **사용자의 실제 선호/점수 사실만**, 모든 Gemini 음성의 객관 품질 증명 또는 향후 영상의 게시합격 아님. 객관적인 다음 샘플 품질 향상은 hypothesis.
2. **음성 직원의 실제 작업 우선순위 갱신**:
   - 기본 추천 후보로 `Gemini Developer API / gemini-3.8-flash-tts / Puck` 사용, **추가 생성 권한과는 철저히 분리**. Melo는 A 대조군으로 보존하며 사용자가 분명하게 더 낮게 평가한 사실 반영. 자동으로 모든 다른 한국어 대상/프로젝트에 적용하지 말고 대상과 스코프 검증.
   - 대본 직원이 전달할 내레이션 전용 텍스트(출처/사실 확인 포함)와 음성 직원의 스타일·발음 가이드·쉼표·호흡·속도·강조 및 예상 발화길이, 실제 장면별 목표길이와 영상 직원·자막 직원 인수계약 정비. 단 실제로 지원하지 않는 TTS voice/style 파라미터를 전송하지 말 것. 한국어 숫자·영어·고유명사 발음을 점검할 수 있게 하되 검토를 합성 자체로 가장하지 말라.
   - 관리자의 '음성' 평가 기준을 **실제 사용자 청취 점수 7/10과 그 후속 개선 목표(예: 8점 이상, 단 새 음성 생성 후 사용자 청취 필요)**로 연결. 현재는 만족도 7/10이며 게시 여부 미결정, 신규 샘플 전후 우열/자연스러움 향상 수치 꾸며내기 금지.
   - 8초 샘플 성공이 60초 음성 전체의 안정성/리듬/구독자 매력까지 증명하지 못하므로, 다음 실제 실험은 60초 대본 중 자연스러운 15~25초 구간 또는 길이가 다른 2문단으로 구성된 **구체적 정확 문장 1건**을 추천. 무료 API/출력 한도/음성 생성 권리·데이터처리·비용 정책을 확인하고, 실제 실호출은 **다음 별도 동의 이후**.
3. **품질 실증 자료**: 기존 파일을 실제로 탐색·SHA 확인 가능하면 표준 WAV 기술 정보, 원문/결과 binding, 사용자 직접 선호·점수/미검증 항목을 기록. 관리자·음성직원·대본/영상직원의 연결 계약/데이터 전달이 정말 실행되는지 **오프라인 실행 가능한 최소 통합 테스트**로 증명한다. 기존에 구현한 흐름 재사용, 모의 직원 대답을 실제 LLM 판단이라 부르지 마라.
4. **다음 품질 테스트의 제작물 준비**: 기존 446자 가상회의 60초 대본 등을 그대로 무작정 TTS에 넣지 말고, *시청자 관심을 끄는 주제*와 자연스러운 한국어로 된 **실제 내레이션 후보/음성 디렉션/장면별 시간 배정**을 전문 직원이 바로 인수받을 수 있는 파일로 설계. 사용자가 7점이라고 평가한 것이 제안 대본/영상까지 개선됐다는 뜻이 아님. Codex가 직접 작성한 내용이라면 codex-authored로 명시. 비용/상업 사용/데이터 처리 정책/실 계정 잔여 쿼터는 검증 범위 내에서만 보고.
5. 파일 기반 결과: `reports/VIDEO_VOICE_USER_AB_FEEDBACK_RESULT.md`에 (i) 원문 7/10 B 우선, (ii) 기존 실물 A/B SHA/길이, (iii) feedback ID/저널/hash/범위/선택 검증, (iv) 회사 음성 직원·관리자 코드 실제 변경점, (v) 오프라인 테스트 증거, (vi) '다음에 실제로 생성하면 좋은 단 하나의 샘플'·모델/음성/전송텍스트/한도/비용/필요 동의, (vii) **실 API 요청0, 신규 WAV없음, 미검증 품질/권리 유지**를 명시. `reports/CURRENT_PROGRESS.md` 갱신. 피드백 관련 파일은 로컬 보호 경로/권한을 고려하고, 원문에 비밀이 없으면 깃에 코드·테스트·보고서만 올려도 됨.
6. `AGENTS.md`에 따라 기존 코드·프로젝트/사용자 자산/승인·시도·비용원장 불변, KST 사용, git reset --hard/clean 금지. 코드/테스트/보고서 main 커밋·푸시. 변경한 부분 중심 테스트를 한 번 묶어 실행하고 필요한 경우 회귀 검사. '결과 나왔어' 시 ChatGPT가 결과를 직접 읽을 수 있게 보고서 경로 명시.

## 가장 중요한 실패 회피
- 이번 턴에서 또 계정 Free Tier/키/Models.list 조회·새 인증 게이트 만들기 하지 않는다. 이전 1회 실 TTS 성공을 무효화하지 않는다.
- 원 사용자 평가를 근거 없이 'Gemini 9/10'이나 'CapCut 동급/게시 합격'으로 과장 금지.
- 코드가 실행 가능한 음성 직무 개선을 해야 하며 단순 문서 작성/JSON 포장만 했다면 그 한계를 솔직히 적을 것.
- 새로운 실제 Gemini 생성 1회 승인 없이 또 호출하지 않는다. 기존 허가와 guard/attempt는 1/1 소모 상태.
- 궁극적으로 manager→writer→voice→editor/QA 실제 에이전트가 설계·제작·평가하는 **영상제작 전문 회사**를 개선하는 중이라는 목표를 유지한다.
