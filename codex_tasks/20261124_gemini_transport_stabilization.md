## 2. 공통 요청 경로 분석 및 근거 있는 수정
- companies/video/research_workflow.py execute_research/step_worker/run_worker/accounted, autonomous_gemini35 및 실제 하위 전송 모듈, 일반 조사 보고서 계약, 관리자 계약, 공통 원장/서명/검증기를 추적한다. 파일 이름이나 위치는 실제 저장소를 기준으로 한다.
- 직원 보고와 관리자 검토 모두의 실제 직렬화된 REST 요청을 검사한다. provider wire schema와 엄격한 로컬 schema를 분리 유지하며, 중첩/분기/열거/필드 지원 여부 및 입력 중복, 토큰 설정, 모델별 지원 계약을 점검한다. 공급자 공식 명세와 비교 가능한 경우 확인하고 근거를 기록한다.
- 구조화 출력 단순화만으로 문제가 해결됐다고 가정하지 않는다. 증거가 지지하는 결함을 수정하고, 필요하면 최소한의 공급자 호환 출력 계약(단순 JSON 및 엄격한 로컬 검증 등)을 설계한다. 출처 ID 귀속, 3종 게임 근거, 보류 판단, 승인·예산·서명·전송 동일성 검증은 약화하지 않는다.
- 지원되지 않는 요청 형태는 실제 호출 전 검증 가능한 범위에서 차단한다. 실패 유형을 HTTP 요청 거절/인증/쿼터·청구/공급자 장애/전송 미확정/응답 파싱/로컬 검증으로 구분해 사용자에게 다음 행동을 표시한다. 원문 대신 비밀정보 제거된 제한된 진단만 저장한다.
- 현재 can_resume_report는 report_only 재진입을 제한하므로 무한 재시도 허용으로 바꾸지 않는다. 확인된 계약 결함의 실질적 수정과 새 서명·유효 승인·예산을 전제로만 안전한 후속 범위 준비 가능 여부를 설계한다. 근거 없으면 보류 및 독립 검토로 넘긴다.
- 기존 공통 모듈 재사용, 영상 분야별 규칙은 companies/video에 유지. 임의 모델 변경·공급자 전환·유료 전환 금지. 광범위 재설계는 필요성과 대안 기록 후 독립 검토.
