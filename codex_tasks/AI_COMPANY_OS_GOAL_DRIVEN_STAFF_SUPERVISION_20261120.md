## 구현
1. 공통 업무 목표·관리자 성공 기준·가용 도구/권한·업무 제한·실제 수행 증거·미충족 항목을 전달하는 계약을 설계하고 기존 공통 엔진의 관리자 검토 및 재작업 계약을 가능한 한 재사용한다. 목표/완료 조건은 모델의 의미 판단과 코드의 객관적 검증 가능한 사실을 구분한다. 형식 통과와 목표 달성 상태를 별도로 기록한다. 비영상 가상 업무에도 적용 가능해야 한다.
2. 직원에게 실제 관리자 목표/성공 기준과 현재 도구·예산·수집된 자료를 명시적으로 전달한다. 실질적인 실행이 필요한 조사에서 관측 없이 종료하려는 경우, 도구가 가용하고 승인/예산 안에서 합리적인 다음 행동이 있으면 조기 종료를 정상 완료로 취급하지 않는다. 모델에 구체적인 부족 항목과 선택 가능한 다음 행동을 전달한다. 특정 검색 도구/순서를 코드로 강제하지 않는다. 모든 도구가 불가하거나 실패하거나 적절하지 않을 때는 확인 가능한 이유와 부족한 자료/대안을 명시해 정직하게 보류할 수 있다. 실제 도구 실행 증거 없이 수행했다고 주장할 수 없게 하며 의미 검증 실패나 거짓 완료를 자동 보정하지 않는다. 검색 결과 0건과 미사용을 구분한다.
3. 관리자에게 목표 대비 결과, 실행 이력/도구 사용 여부, 증거 카탈로그, 미충족 항목, 잔여 승인 예산을 전달하고 완료/보완 지시/대안 제안/대표 질문/보류 중 실제 모델이 판단할 수 있게 한다. 모델은 보완 목표와 이유 및 확인 기준을 구체화한다. 관리자가 추가 업무를 지시하면 승인된 범위 내에서 직원에게 전달하고 결과를 다시 검토하는 유한 루프를 구현한다. 실제 관리자 검토는 예약된 별도 호출로 계산하며 직원이 관리자 결과를 대신 작성하지 않는다. 마지막 독립 검토에 필요한 몫을 보존한다. 예산 부족이면 다음 실행 제안만 만들고 대표 검토를 기다린다. 기존 hold를 성공으로 바꾸지 않고 관리자 의미 검토/독립 출처/원문/권리 기준을 유지한다.
4. 승인과 호출 범위를 동적으로 늘리지 않는다. 개선 루프의 최대 직원/관리자 호출 및 보완 횟수, 전체 합산 상한, 외부 도구 크레딧 및 전송 범위, 만료/키/계약/요청 해시를 기존 서명·원장에 결합하고 검토 화면에 제공한다. 기존 기본 무료 운영 한도와 사용자 승인 경계를 존중하며 추가 예산 필요 시 명시적 별도 제안으로 남긴다. 이미 소진된 범위, 이번 완료된 hold 범위 및 두 이전 실패 범위를 재실행하거나 초기화하지 않는다. 실패/미확정/429/503/타임아웃/변조/철회/만료에서 자동 재호출하지 않는다. 정상 응답의 업무 보완과 전송 실패 재시도를 구분한다. 반복 보완·무진전·도구 고갈 시 중단한다. 동일 도구 중복 호출은 필요성과 승인 범위가 확인되는 경우에만 허용한다.
5. 영상 적용: 실제 프레스 킷 및 편집 권한 확인 목표, 장면별 미충족 항목, 실제 사용 가능한 조사 도구/옵션, 관측 수집과 근거 참조 계약을 연결한다. 제공 가능한 도구가 목표를 달성하기에 부족하면 관리자가 대안 또는 도구 추가 제안을 할 수 있게 한다. 기존 승인된 공개 검색/제작사 경로 및 권리·보안 제한을 우회하지 않는다. 검색 단서와 원문 확인을 구분하고 카탈로그가 비어 있으면 기획/제작 인수 금지. 현재 진행된 hold 이후 별도의 안전한 신규 보완 업무 제안 경로를 설계·구현하되 기존 서명과 모든 누적 호출 보존, 명시적 추가 승인 전 0회 전송. 구현 불가 시 차단 사유 및 대안 보고. 기존 대본 v2, WAV 4개, MP4, 대표 평가·제작사/Commons 상태 유지.
6. 컷룸에서 응답 검증 성공/실제 업무 미완료, 관리자 보완 지시, 직원 실제 도구 수행(대기/실행/빈 결과/실패/미사용), 근거 수, 미충족 조건, 누적·추가·잔여 예산, 보완 루프 및 중단/대표 승인 필요 상태를 한국어로 구분한다. 현재 영수증과 실제 모델 판단을 혼동하지 않는다.
