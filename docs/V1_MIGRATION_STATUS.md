# AI Company OS v1.0 — 새 작업 영역과 안전한 이전 절차

작성: 2026-11-09 (KST). 이 문서는 **실제 수행한 복사와 앞으로 필요한 검증을 구분**한다.

## 현재 구성
- `src/`: 기존 Phase 1의 실제 Gemini 3.5 / AI 관리자·직원 협업 엔진을 구성하는 **16개의 기존 Python 모듈을 동일 Git blob SHA로 복사**. 코드를 재작성하거나 기능을 개선한 것이 아니다.
- `phase1/`: Git 추적 대상 과거 소스·테스트·기록의 완전 보관본.
- `ai-company-os-phase1/`: **2026-11-09 Git 추적 중복 파일 정리 완료**. Codespaces에는 예전 로컬 비추적 데이터가 남을 수 있으므로 삭제하지 않는다.
- `docs/`: 현재 v1.0 개발 방향과 이전/정리 기준.
- `tests/`: 독립 테스트 시작. 기존 테스트들이 간접적으로 `app.py` 등 구 코드를 가져오는 것으로 확인돼, 무분별하게 66개를 복사하지 않았다. 대신 `phase1`에 의존하지 않는 핵심 모의 회사 종단 간 테스트 4개와 필요한 fixture만 복사/작성했다. **신규 4개 테스트는 아직 Codespaces에서 실행 확인 전**이며 과거 150개 회귀 테스트를 대체하지 않는다.
- 루트 `AGENTS.md`: 새 개발 목표 및 데이터/보존·정리 규칙.

## 새 코드의 성격 및 실행주의
- 진입점 후보: `src/video_production_company.py`의 VideoProductionCompany, `src/autonomous_gemini35.py`의 Gemini35Company.
- 기본 import들이 같은 폴더의 모듈을 참조하므로 향후 실행 시 `PYTHONPATH=src`(또는 `src/`에서 실행) 필요. **현재 v1.0 실제 실행 테스트 전이며 정상 동작을 보증하지 않음**.
- `src/`는 일단 필요한 범위의 보수적인 복사본이다. `gemini_connection_once.py`, `groq_provider.py` 등 이름이 초기 실험처럼 보이는 파일도 다른 모듈의 코드 import 의존성을 확인했으므로 일단 유지.
- 실제 AI 호출, 기존 계정 동의, 과금, 운용 원장, 과거 프로젝트 재실행은 하지 않는다.

## v1.0 목표
사용자와 AI 관리자가 필요한 질문을 주고받아 목표를 명확히 함 → 전문 AI 직원 협업으로 실제 결과 제작 → 실제 산출물 품질 평가와 사용자 피드백 → 수정 결과 및 근거 저장 → **다음 작업에서 관련 경험 조회·적용을 증명**. 초기 사용자 참여는 허용, 장기적 자율 운영 방향 유지.

## 개발 중 파일 정리 규칙
1. 운영 루트에는 실제 소스·공용 설정·핵심 자동 테스트·현재 문서만 보존.
2. 일회성 실제 AI 연결 확인 스크립트, 한 번 사용한 진단 도구, 옛 개발 보고서/작업 지시서는 phase1에서 보관.
3. 활성 코드로 다른 모듈이 import하는 파일은 이름만 보고 제거하지 않는다.
4. 기능 교체 때마다 구 파일 참조 확인과 회귀 테스트 통과 후, 명확한 삭제 목록을 사용자에게 설명하고 정리한다.
5. Git 추적 외 `data/`, `backups/`, `artifacts/`, API 비밀·비추적 파일은 삭제·덮어쓰기·복사하지 않는다. 기존 원장 해시와 소진된 호출 권한·미확정 시도도 유지.
6. GPT(ChatGPT)는 GitHub 구조 확인·문서·이전 계획·안전한 Git 파일 정리를 우선 담당, Codex는 필요한 실제 코드 변경 및 로컬 실행·검증에 집중.

## 아직 미완료 — 안전상 남긴 항목

- 루트 `tests/` 신규 독립 테스트 실제 실행·필요한 수정, 과거 150개 중 안전·API·실제 영상 렌더 등 추가해야 할 핵심 회귀 범위 선별. 신규 테스트만 통과한다고 기존 모든 기능을 보증하지 않는다.
- root v1.0 진입점/CLI/UI, 목표 문답 및 경험 저장·검색·품질 개선 신규 기능.

## 다음 Codex 작업 (개발 시간을 아끼도록 최소화)
Codespaces에서 `git status --short`로 로컬 소스·비추적 data 보호 상태 확인 후 `git pull --ff-only`. 루트에서 `PYTHONPATH=src python -B -m unittest discover -s tests -p 'test_*.py' -v`로 **phase1을 Python 검색 경로에 넣지 않고** 새 독립 테스트 4개가 통과하는지 확인. 필요 시 테스트 코드만 최소 수정. 추가로 `PYTHONPATH=src python -B -c 'import video_production_company,autonomous_gemini35'` 등 독립 import 점검. 실제 외부 AI 호출 **0회**, 기존 데이터/원장/백업 쓰기 0회. 테스트 실패 시 내용 보고하고 코드 변경은 최소 범위. `git clean -fd`, `git reset --hard`, 프로젝트 replay 금지. 새 `src/`에 **진짜 사용자 실행 진입점/UI가 없는 상태**이므로 이번 테스트가 실서비스 독립 실행 완료를 의미하지 않는다고 명시.


## 2026-11-09 KST — v1 독립 오프라인 테스트 결과 확인

근거: `reports/v1_standalone_src_tests_verification_20261109.md` (GitHub Codex 검증 보고서).

- 원본 Phase 1 폴더, 기존 루트 app.py 및 기존 데이터가 없는 격리 환경에서 `src/` 16개 모듈 import 성공.
- 루트 `tests/` 신규 4개 회귀 테스트 독립 실행 통과. 실패·오류·건너뜀 0건.
- 실제 AI 호출 0회, 이전 프로젝트 재실행 0회, 일반 파일 750개 변경 없음.
- 수정 사항은 위 검증 보고서 신규 추가만이며, 구현 소스·테스트는 그대로였다.

### 정리 전에 남은 조건

1. **Codespaces의 현재 사용 경로와 gitignored `data/`, `backups/`, `artifacts/` 실제 위치를 확인**. GitHub에서는 비추적 자료의 독립 보관 여부를 검증할 수 없다.
2. 새 v1.0의 사용자 실행 진입점(CLI/UI)과 최소 실제 산출물 생성 루트를 정한다. 기존 `ai-company-os-phase1/`의 실행 명령/사용 데이터에 의존하는 사용자는 삭제 시 즉시 영향받는다.
3. 핵심 회귀 4개 외에 예산/동의/원장, 실제 도구 실행, 프로젝트 저장·복구 등을 v1 루트에서 보호하도록 단계적으로 핵심 테스트 선별·실행.
4. 과거 Git 추적 소스는 `phase1/` 보관본에서 완전히 열람 가능한 상태 유지. 구 `ai-company-os-phase1/` Git 추적 중복 폴더를 제거하기 직전에 사용자에게 범위와 영향을 설명하고 승인받을 것. 기존 실사용 데이터·비추적 파일 삭제 금지.

**현재 상태: 새 v1 src·tests가 구 경로에 대한 모의/모듈 의존성을 제거한 것은 검증됐지만, 기존 실행 폴더 삭제에 대한 충분한 조건은 아직 충족하지 못함.**


## 2026-11-09 KST — Git 추적 중복 폴더 정리 완료

- `phase1/`의 277개 Git 추적 파일과 기존 `ai-company-os-phase1/`의 277개 Git 추적 파일 사이에 누락/내용 SHA 차이 0건 확인.

- **이 작업에 추가 실행 테스트를 하지 않음** (파일 정리 전 기존 독립 테스트 4개 통과 근거 보존).

- 사용자용 v1 진입점과 실제 AI/품질/경험 축적 기능은 **다음 제품 개발 단계**다. 폴더 정리의 범위를 넘는 검증은 다음 통합 개발 시 묶어서 수행한다.
