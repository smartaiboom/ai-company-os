## 구현 및 검토 경계

- `core/web_research.py`는 실제 관측으로 근거 카탈로그를 구성한다. 발췌 하나마다 URL, 제목, 원출처, 호스트, 관측·출처 시점, 출처 종류, 전체 SHA-256과 선택용 ID를 결합한다. 검색 단서, 직접 확인 페이지, API 관측, 미디어 메타데이터를 구분한다. 수집 기록과 카탈로그 구축 시 해시를 검증한다.
- 기존 모델 출력은 원문 조각을 직접 작성했다. 새 단계 스키마는 현재 관측 ID만 문자열 열거로 노출한다. 프로그램이 선택된 ID를 저장된 발췌에 연결해 기존 인용 형태 `{source, quote}`로 전달한다. 존재하지 않는 ID, 중복, 변조된 관측, 모델이 직접 제출한 가짜 인용문을 거부한다. 확정·상충 판정에는 서로 다른 적격 원출처와 호스트가 필요하며 검색 단서와 미디어 메타데이터는 단독으로 그 요건을 충족하지 못한다.
- 관측이 없으면 출처 선택 개수는 0으로 제한한다. 남은 도구 중 추가 조사를 자율 선택하거나, 부족한 자료와 다음 확인 내용을 담은 미확인 보고를 제출할 수 있다. 주장과 실행 가능성은 공백으로 제출할 수 없다. 구조적으로 적격한 주장이 없으면 관리자 판단은 보류만 허용하고 기획·제작 인수에서 제외한다. 독립 관리자에게는 직원 해석과 원문을 함께 보내 관련성, 원출처 중복, 측정 범위와 권리 조건을 재검토하도록 한다. 참조 유효성만으로 주장의 사실 여부를 확정하지 않는다.
- `companies/video/research_workflow.py`는 기존 Gemini JSON 스키마, 공통 판단 오류 피드백, 서명, 독립 관리자 호출 몫을 재사용한다. 새 승인에 계약 버전을 결합한다. 기존 서명 결과·인용·인수 형식은 읽을 수 있다. `companies/video/studio/studio.js`는 직원 해석, 관측 발췌, 출처 유형, 관리자 보류를 구분해 보여 준다. 조사 권한과 편집·다운로드·게시 권한의 분리를 유지했다.
