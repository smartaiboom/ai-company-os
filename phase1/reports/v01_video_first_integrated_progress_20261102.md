## 동작한 기능과 증거

새 `tests/test_video_first_integrated_workflow.py`의 단일 통합 테스트가 실제 loopback HTTP에서 다음 흐름을 검증했다. 기존 앱·계획 생성기·실제 엔진의 요청 구성 및 의미 검토·확정본 코드를 사용하되, 제공자 transport는 모두 모의 응답으로 교체했다. 테스트 환경의 openai_compatible 설정은 모의 transport를 통해 실제 연결 경로를 검사하기 위한 것으로 실제 공급자 호출이 아니다. 공통 외부 opener는 강제로 차단했다.

관리자가 반환한 계획은 3개/4개 작업의 두 경우다. 3개는 초보자 대본 작가→품질 검토 담당→편집 연출 담당, 4개는 영상 구성 기획 담당을 앞에 추가한다. 코어에 영상 역할/작업 수를 넣지 않았고 응답 fixture에만 둔다. 실제 모델이 계획을 생성하거나 품질을 판단한 증거는 아니다.

- 계획 생성 후 pending_approval 및 업무 미생성, 승인 전 실행 거절을 확인했다. 계획 승인 뒤 반환된 가변 역할·선행 관계가 업무로 반영된다.
- 4개 작업의 경우 앞선 영상 구성 결과는 승인 전 대본 실행을 차단하고 승인 후 작가 요청에 전달된다. 모든 직원 요청의 영상 목표 유지 및 재고 목표 잔재 부재를 확인했다.
- 사용자 품질 기준은 ‘60초 대본에 화면 자막과 사실 확인 안내가 포함되어야 한다’로 모의 승인했다. 대상 결과 승인 전 의미 검토를 차단한다.
- 초기 대본은 자막 안내가 없어 모의 검토가 changes_needed를 반환한다. 실제 대상 내용의 자막 유무로 판정을 선택하며 단순 고정 pass가 아니다. 모델 판정 fixture이므로 실질적 내용 품질 보증은 아니다.
- 수정 판정만으로 기존 승인을 철회하거나 자동 수정하지 않는다. 별도 사용자 수정 승인 요청 후 같은 작가가 수정 1회 수행한다. 수정 의견이 직원 입력에 포함되며 대상 재승인 전 재검토는 차단된다.
- 수정 대본의 화면 자막 안내를 확인한 모의 재검토가 pass를 반환한다. 검토 결과 사용자 승인 전 최종 실행을 차단한다. 최종 편집 담당 입력에는 승인된 수정 대본과 model_claim 검토 결과가 전달된다.
- 최종 대본·장면 구성표·편집 지시서를 포함한 결과를 생성한다. 최종 사용자 승인 전 .md/.json 다운로드는 모두 409, 승인 후 모두 200 및 첨부 다운로드다. 내려받은 JSON은 보관 snapshot과 동일하고 Markdown은 그 JSON을 confirmed_markdown으로 변환한 내용과 정확히 같다. 모든 업무 결과 포함·다운로드 GET의 프로젝트 무변경도 확인했다.

모의 산출물 내용은 목적·조건을 구체화하는 질문 예시, 개인 정보 입력 금지/사실 확인 자막, 0~10초·10~45초·45~60초 장면표, 가독성·전환·소재 권리 확인 편집 지시다. 실제 낭독 60초 측정, 제품 설명 최신성, 저작권 검토는 미검증이다. 테스트는 사용자 승인을 HTTP 요청 fixture로 모사하며 실제 사용자의 계획/업무 승인을 대신하지 않는다. 산출물 JSON/Markdown은 테스트 임시 저장과 HTTP 응답에서 검증 후 정리되며 실사용 프로젝트 자료로 저장·커밋하지 않는다.

## 수정 및 집중 테스트

변경 파일은 신규 통합 테스트와 이 보고서 2개다. 운영 앱·안전 코드·M1~M3·기존 M4 보고서는 수정하지 않았다. 이번 모의 통합에서 운영 경로의 수정이 필요한 연결 결함은 발견하지 못했다. 기존 의미 검토는 대상 바로 다음의 ‘품질 검토 담당’ 역할과 별도 최종 업무를 요구하는 현재 제약을 유지했다. 임의 역할 이름/배치를 가진 모든 계획이 의미 검토 가능한 것으로 주장하지 않는다.

실행 명령: `python -B -m unittest tests.test_video_first_integrated_workflow` (승인된 로컬 loopback 실행).

초기 실행에서는 fixture PROJECT_ID 누락으로 두 하위 사례가 실패했고 직접 가져온 TestCase 때문에 기존 4개가 추가 수집됐다(총 5개 중 기존 4개 통과, 신규 두 하위 사례 오류). 모듈 참조로 수집을 제한하고 ID를 보완했다. 다음 실행은 최종 입력의 실제 줄바꿈을 JSON 이스케이프와 비교한 테스트 오류로 두 하위 사례가 실패했다. JSON 표현을 맞춰 수정한 최종 실행은 **테스트 1개 통과, 3개/4개 작업 하위 사례 모두 통과**다. 모의 전송 수는 각각 6회/7회이며 각 프로젝트의 7회 안전 예산 내에서 검사했다. 미해결 테스트 실패는 없다. 코드 변경이 없어 전체 회귀·브라우저 설치를 수행하지 않았다. `git diff --check` 및 보고서 재읽기를 수행한다.

## 다음 단 하나의 실제 무료 AI 실행 단계

다음 작업은 **새 영상 목표에 대한 직접 동의 후, 기존 앱으로 별도 격리 영상 프로젝트를 만들고 계획 생성 1회만 실행한 뒤 사용자 계획 승인에서 멈추는 한 번의 작업**이다. 과거 재고 프로젝트 동의나 이번 지시서로 이 동의를 대신하지 않는다.

필요한 직접 동의는 위 영상 목표와 해당 프로젝트의 목표·업무 입력·승인된 선행 결과·성공 기준·수정 의견 외부 전송, OpenRouter openrouter/free, 별도 프로젝트 총 최대 7회/시작·재개당 2회, 실패·시간 초과 예산 소모, 유료 전환·fallback·자동 재시도 금지를 포함해야 한다. 기존 재고 예약을 해결하기 위해 새 프로젝트를 만드는 것이 아니라 사용자가 별도로 요청한 영상 목표의 신규 프로젝트여야 한다. 기존 재고 프로젝트는 계속 차단·보존한다.

동의가 주어지면 아래 단일 절차를 후속 작업에서 실행한다.

1. 키는 존재 여부만, 모델/고정 OpenRouter HTTPS 주소는 일치 여부만 확인한다. 격리 프로세스에만 AI_REAL_REQUESTS_ENABLED=1 및 AI_ENGINE=openai_compatible를 적용하고 기존 데이터와 다른 전용 경로를 app.PROJECTS_DIR/ARTIFACTS_DIR로 사용한다. 원래 데이터 경로나 영구 환경은 변경하지 않는다.
2. 기존 앱 /create로 영상 프로젝트를 생성하고 목표 지문·전송 범위·KST 동의 시각·enabled·7회 예산을 그 프로젝트에만 기록한다. 테스트의 approved_project 가상 동의를 실제 동의로 사용하지 않는다. 기존 프로젝트/원장을 복사하거나 초기화하지 않는다.
3. 기존 ObservedServer를 사용해 요청 스레드를 추적하고 /manager/plan 요청에 기존 request_scope·프로젝트 락·요청 전 영속 예약·모델/호스트 검사를 적용한다. 테스트 transport 교체를 해제하는 것은 후속 직접 승인된 격리 실행에 한한다. 전체 wall-clock 취소는 보장되지 않으므로 클라이언트 시간 초과를 작업 완료로 취급하지 않는다. 종료 관측이 미완료면 작업 프로세스를 유지하고 완료 불명/예약 소모 상태로 보고하며 재시도하지 않는다. 이전 임시 daemon 실행 도구를 그대로 재실행하지 않는다.
4. 계획 1회 성공 시 pending_approval 상태와 반환된 질문·작업/역할·선행 관계를 사용자에게 제시하고 멈춘다. 품질 기준·계획·업무·수정·최종 승인은 실제 사용자 입력으로만 진행한다. 이후 작업 수가 예산이나 기존 의미 검토 제약과 맞지 않으면 임의 축소·자동 승인 대신 계획 검토 단계에서 조정한다. 실패·모호 상태에서는 호출을 더 보내지 않는다.

현재 차단 요인은 새 영상 목표의 직접 외부 전송 동의가 아직 없다는 점이다. 실제 공급자 라우팅/인증/응답 품질과 위 종료 도구의 실제 외부 동작은 이번 모의 결과만으로 보증할 수 없다. 별도 진단 과제를 계속 추가하지 않고 후속 한 번의 승인된 계획 실행에서 그 결과를 함께 기록한다.
