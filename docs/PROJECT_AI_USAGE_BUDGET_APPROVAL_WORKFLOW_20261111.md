# AI Company OS — 프로젝트별 호출 예산과 추가 승인 관리
작성일: 2026-11-11 KST
적용 대상: 공통 core 엔진 우선, 영상 회사는 첫 연동 대상

## 이번 사용자 결정
대표는 "상한을 정해놓으면 개발이나 테스트에 방해가 된다. 호출예산을 관리하고 예산이 필요할 때 승인을 받으면 좋겠다"고 결정했다. 기존의 일률적 10/4/4 고정값은 **모든 향후 프로젝트에 적용할 제품 정책이 아니다**. AI 관리자는 프로젝트에 필요한 예산을 계획하고, AI 직원들은 허가된 잔여 범위 안에서 자율 진행하며, 부족하면 진행 상황과 필요한 **추가 승인만** 대표에게 요청한다. 불필요한 신규 기획/재조사를 반복하지 않는다.

**본 결정은 예산 관리 기능의 구현 승인이지, 현재 미션에 대한 추가 외부 API 호출·기존 상한 증액·유료 결제 승인 자체는 아니다.** 기존 미션 01 누적 Gemini 6/10, YouTube search 2/4, videos 2/4와 세 stopped 업무, 무료/데이터 처리 동의·서명·attempt·active_operation을 소급 수정하지 않는다. 현재 실제 미션을 임의 재시작하지 않는다.

## 구현 원칙
1. `AGENTS.md`와 기존 `core/`의 provider 동의, 사용/시도 원장, 제한 검증, 분리 업무·재개 경로, `companies/video/video_mission_one.py` 등을 조사해 **이미 있는 기능 재사용**. 특정 미션에 맞춘 예산 하드코딩을 앞으로의 공통 기본 정책으로 복제하지 말 것. 이미 완료된 시스템 재개발·대규모 리팩터링/전체 회귀 반복 금지.
2. 공통 재사용 가능한 `project budget`과 `budget request` 개념: 프로젝트·모델/API 작업별 사용량 단위(예: Gemini 실제 요청 시도 수, YouTube search.list / videos.list 횟수), 승인 예산, 소모(실패·타임아웃·불명 포함), 잔여, 추가 요청량과 사유, 대표 승인/거절, 승인 이력. 비용은 공급자 실제 금액을 확인할 수 있을 때만 "실측"; 그 외 예상치/미확인 구분. 수량 단위(호출 수 vs YouTube quota units/토큰/원화 비용)는 서로 혼동하지 않는다.
3. 관리자가 작업 계획에 근거한 **필요 예산 견적을 자율 제안**할 수 있도록 하되, 견적은 승인된 할당량이 아니다. 기본 예산을 제품 전역의 임의 숫자로 강제하지 않는다. 사용자가 승인한 초기 한도 내에서는 **각 개별 호출에 재승인받지 않고** 실행하도록 하며, 계획 변경 또는 잔여 부족 시 추가 수량·이유·이미 완료한 일·비용/무료 영향·실패 가능성을 요약한 요청 한 건만 대표 검토 대기로 올린다. 중복 승인 요청 금지. 승인 전 남은 수량을 넘는 전송은 가드에서 차단한다.
4. 대표 승인 시 원래 승인/사용량/실패 이력을 덮거나 reset하지 않고 **추가 승인 이벤트**로 증액한다. 거절 시 안전하게 대기. 승인 예산의 차감은 외부 요청 **전** 예약해 영속화하고 상태 불명도 소모. 시스템 장애 후 동일 요청 자동 재전송 금지. 동시 실행/중복 전송·재개·만료·변조·원장 연결 검증.
5. 예산 추가 승인과 외부 데이터 전송 정책 동의를 구별한다. 동일 프로젝트·같은 무료 모델/API·같은 목적·동일 Google 무료 데이터 정책에서는 기존 유효 범위/동의 정보를 재사용할 수 있지만 **새로운 모델, 계정, 공급자, 데이터 범위, 유료 전환에는 별도 명시 동의 필요**. 유료 전환 및 카드/결제 연결을 자동 수행하지 않는다. 과거 동의의 원장·만료·범위 계약은 우회 금지.
6. 컷룸 UI에 예산 상태와 '추가 승인 요청'을 기존 대표 검토 동선과 정합성 있게 제시할 수 있는지 확인하고 가능한 범위에서 최소 연결한다. 이번 기능의 핵심은 엔진의 실제 승인/차감 차단이며 표시만 구현하지 않는다. 사용자 인터페이스는 특정 업종에 묶이지 않게, 영상 회사에는 어댑터 수준으로 연동한다.
7. **기존 미션 01의 하드코딩 10/4/4와 과거 signed grant/업무들은 변경하지 않는다.** 신규 예산 방식은 새 프로젝트/새 명시적 예산 승인을 받은 운영에 우선 적용하고, 미션 01으로 이관할 경우 별도 이관 검증 및 대표 승인 없이는 허용되지 않게 한다. 기획·대본 산출물과 실사용 예산을 fixture로 혼동하지 않는다.
8. 합성 오프라인 테스트에서 초기 제안→대표 승인→여러 직원 호출 예약/사용→예산 부족에 따른 일시 정지 및 추가 승인 요청→대표 승인 후 이력 보존형 계속 진행, 거절·중복/만료·동시 실행·불명 실패 소모·예산 초과 차단·유료 경로 차단을 검증한다. 테스트 네트워크 차단; 실제 API 호출 **0회**. 이미 존재하는 기능이면 불필요한 변경 없이 그 흐름을 증명하고 부족한 최소 코드만 추가한다.
9. 이번 작업 범위가 지나치게 커진다면 공통 budget ledger/approval 경계의 안전한 최소 기능을 우선 완성하고, UI나 기존 미션 이관은 '후속 미완료'로 명확히 표시한다. 빈 mock/UI만 만들고 예산 집행 안전성이 구현됐다고 표시하지 않는다.
