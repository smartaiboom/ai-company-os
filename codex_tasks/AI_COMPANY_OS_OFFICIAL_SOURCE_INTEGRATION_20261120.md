## 개발
1. 기존 core/research_https.py, core/web_research.py, core/staff_supervision.py, core/task_replanning.py, companies/video/publisher_discovery.py, production_sources.py, research_workflow.py, research_supervision.py 및 기존 보안/권리/운영 정책을 분석한다. 기존 공식 페이지 실행기 재사용을 우선한다. 공통 페이지 관측과 도메인별 접근/권리 검토를 분리한다. 현재 승인된 장면의 공식 제작사/배급사 도메인과 경로, 사용할 수 있는 기존 승인 범위를 확인한다.
2. 웹 검색 결과는 단서로 취급한다. 직원이 후보 공식 페이지를 선택해 승인된 공개 호스트·경로에 한해 원문 관측을 할 수 있게 기존 HTTPS/robots/공개 IP 고정 TLS/리다이렉트/응답크기/시간/콘텐츠 제한을 재사용한다. 임의 검색 결과 방문, 인증·유료벽 우회, private IP, 비밀정보 전송, 다운로드 및 게시를 허용하지 않는다. 허용 목록 밖은 추가 승인 제안 또는 보류. 접근 불가/빈 결과/정책상 차단과 미실행을 구분한다. 출처 URL, 발췌, 원출처, 관측 시각, 범위 및 해시를 기존 근거 카탈로그로 연결한다. 실제 원문 없이는 확인된 권리라고 판단하지 않는다.
3. 직원의 자율 도구 선택과 관리자 목표/완료 기준, 보완 지시 및 독립 검토를 하나의 흐름으로 연결한다. 공개 검색→원문 확인→전문 자료 조합은 가능한 선택이지 고정 순서가 아니다. 목록에 공식 페이지가 없거나 증거가 부족하면 정직한 보류/추가 권한 제안을 남긴다. 기존 독립 원출처, 근거 의미, 권리 검증 규칙을 유지한다. 관리자의 보완과 실제 직원 후속 수행을 검증하되 제한된 호출 수 때문에 목표 충족을 거짓 선언하지 않는다.
4. 기존 두 실패/재계획/보류 기록 및 최신 별도 감독 범위의 사용 상태를 읽기 전용 확인한다. 계약 변경 시 기존 승인 재사용 없이 새 버전의 안전한 제안으로 연결한다. 이미 사용된 승인/원장을 초기화하지 않는다. 실제 승인 제안에 목표, 정확한 공급자/모델/계정 조건, 전송 데이터 종류, 접속 허용 호스트·경로, 모든 호출/GET 상한, 만료, 총액 $0 정책, 원장과 기존 기록 연결을 포함한다. 기존 운영 정책으로 처리할 수 없는 확대는 차단한다.
5. 기존 컷룸 화면에서 실제 검색, 공식 원문 조회, 근거 수, 출처 유형, 목표 달성 여부 및 관리자 보완/보류가 구분되게 한다. 기존 전문 API, 권리 확인/편집/게시 승인 흐름과 기존 산출물을 보존한다.
