# 다음 개발 작업: AI 직원 결과에 대한 mock 품질 검토 저장·표시

## 목표
AI Company OS 가상회사 프로젝트에서 AI 직원의 결과를 다음 직원에게 전달하기 전에 검토할 수 있는 기반을 만든다. `reports/autonomous_quality_review_design_20261102.md`의 **가장 작은 1단계 구현**만 수행한다. 자동 수정 루프·사용자 승인 대체·실제 AI 호출은 아직 구현하지 않는다.

## 시작 전 확인
- `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, `reports/autonomous_quality_review_design_20261102.md`, 최종 보고서 승인·mock 자동 진행 보고서 및 관련 `app.py`, `execution_engine.py`, 테스트를 읽는다.
- 브랜치·origin/main·git status/diff, 현재 추적/미추적 파일과 기존 업무 결과·스냅샷·백업을 확인한다. 기존 사용자 변경을 보존하고 reset/clean/force push 금지. 시각 KST.
- 테스트는 임시 projects/artifacts 경로와 mock으로 격리한다. 실제 AI API 요청·유료 서비스·비밀 키 접근 금지. 필요 없는 종속성 설치·구조 변경 금지.

## 구현 사항
1. 정확한 한 업무 ID와 고정된 mock 품질 검토자 `mock-quality-reviewer-v1`, 공개 규칙 `required-sections-v1`를 사용해 단일 결과를 명시적 요청으로 평가한다. 임의 업무명이나 가까운 업무로 대상 추론 금지.
2. `quality_review.py` 같은 작은 순수 모듈에서 독립된 제목/Markdown 제목으로 표시된 `목표`, `결과`, `미확인 사항`의 존재를 판정한다. 품질 검사는 **형식 검사**이며 사실성 검증이라고 표시하지 않는다. 구조화된 `pass`, `changes_needed`, `inconclusive` 판정 및 검사 근거·한국어 피드백을 만든다. 잘못된 입력/규칙/판정과 오류는 통과시키지 않는다.
3. `app.py`의 프로젝트별 잠금 아래 mock 전용 명시적 `/quality/review` POST를 추가한다. 대상의 완료, 비공백 결과, 성공 이력, 재검토·입력 맥락을 확인하고 필요할 때만 평가한다. mock 이외 모드는 요청 전 거절한다. AI 엔진·외부 네트워크를 호출하지 않는다.
4. 검사 대상의 result revision/hash, 입력 맥락 및 정책을 식별하는 최소 메타데이터와 품질 평가/감사 이력을 프로젝트 JSON에 저장하고, 화면에 '모의 형식 검사' 판정·누락 항목·수정 의견을 표시한다. 구형 JSON 누락 필드는 읽기만으로 변형하지 않고 미검토 처리한다.
5. 결과/입력/정책이 바뀌면 이전 판정을 stale로 표시한다. 단순 조회 GET은 파일 수정 금지. 동일한 현재 평가의 중복 제출은 추가 평가/이력을 만들지 않는다.
6. 이번 단계의 품질 평가는 **보조 정보**이며 기존 `review_status`·사용자 수정 의견·승인 게이트·최종 확정 상태를 바꾸지 않는다. 결과 재실행, 후속 자동 실행, 자동 승인, 자동 수정은 절대로 수행하지 않는다. 이미 확정된 스냅샷 내용과 유효성을 평가만으로 무효화하지 않는다.
7. 기존 프로젝트 잠금으로 동일 프로젝트 동시 평가/승인/실행 충돌은 409로 방어하고 다른 프로젝트는 독립적으로 처리한다. 기존 `openrouter/free` 제한 유지.

## 테스트 / 완료 조건
- `TemporaryDirectory`와 mock/네트워크 금지로 아래를 검증한다: 제목 형식 통과 및 누락→수정 필요, 빈 결과·실패 상태·규칙 오류→판정 불가 또는 거절, 프롬프트형 지시 문구 무시, 중복 평가 멱등성, 입력 변경 후 stale, GET 무쓰기, 저장 오류 시 거짓 성공 금지, 동일 프로젝트 경쟁 409, 다른 프로젝트 동시 진행.
- 검토 결과만 저장해도 기존 승인/최종 확정 스냅샷·사용자 의견이 그대로 유지되는지 확인한다.
- 기존 자동 진행/품질 검토/최종 확정/비용 보호 회귀 테스트를 실행한다. 실제 데이터 경로의 격리가 보장되지 않으면 해당 테스트는 실행하지 않는다.
- `git diff --check` 확인. 미해결 테스트 실패·충돌이나 데이터 손상 위험 시 푸시 금지.

## 결과 전달
- 반드시 `reports/mock_quality_review_implementation_20261102.md`에 결과를 파일로 작성하고 다시 읽어 검증한다. 보고서에는 실제 구현 범위/변경 파일, 테스트 명령·결과, 데이터 격리, 미확인 위험, 실제 AI API 호출 여부를 기록한다. 동일 파일이 이미 존재하면 임의로 덮어쓰지 않는다.
- 관련 코드·테스트·보고서·필요한 작업 이력만 **선택적으로** 스테이징하여 안전하게 커밋·origin/main에 푸시하고 원격 SHA 및 보고서 존재 확인. 기존 미추적 파일·업무 데이터·스냅샷·백업은 스테이징/삭제하지 않는다.
- 결과를 Codex 대화에만 남기지 않는다. 완료 응답에 보고서 파일 경로와 커밋 SHA/푸시 여부를 간단히 알린다.
