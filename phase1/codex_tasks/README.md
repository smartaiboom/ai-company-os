# Codex 작업 지시 파일 사용법

## 파일 구성

- `next_step.md`: 다음 개발 작업의 범위와 완료 조건이다. 사용자가 해당 작업을 지시했을 때만 실행한다. 파일이 있다는 이유만으로 작업을 시작하지 않는다.
- `task_history.md`: 완료된 작업, 검증 결과, 보고서, 커밋과 다음 순서를 기록한다. 확인된 사실만 날짜순으로 덧붙인다.
- 각 작업은 먼저 저장소의 `AGENTS.md`와 관련 코드·테스트·최근 보고서를 확인하고, 지시 파일과 충돌하면 사용자의 최신 지시 및 `AGENTS.md`를 따른다.

## 공통 작업 원칙

1. 기존 코드, 프로젝트 데이터, 업무 결과, 백업을 먼저 살펴보고 보존한다. 요청 범위 밖의 파일을 덮어쓰거나 삭제·초기화하지 않는다.
2. 실제 AI API는 사용자가 명시적으로 요청한 경우에만 호출한다. 실제 호출이 허용된 경우에도 저장소 `AGENTS.md`의 `openrouter/free` 제한과 비밀 정보 보호 규칙을 지킨다. 유료 모델이나 비용이 드는 우회 경로를 추가하지 않는다.
3. 기능 수정은 요청에 필요한 최소 범위로 한다. 상태·결과·이력 저장은 실패 및 재시도 상황에서도 기존 결과를 잃지 않도록 검증한다.
4. 관련 테스트를 추가하거나 실행하고, 실행한 명령과 실제 결과를 보고서에 기록한다. 테스트가 실패하거나 충돌이 남으면 커밋·푸시하지 않는다.
5. `git diff --check`를 실행한다. 보고서는 `reports/`에 작성한 뒤 다시 읽어 생성 여부, 내용, 테스트 결과를 확인한다.
6. 검증이 통과하면 의도한 코드·테스트·보고서만 스테이징한다. 기존 사용자 변경이나 무관한 미추적 파일은 커밋에 넣지 않는다. 원격 상태를 확인하고 force push 없이 커밋·푸시한다.
7. 작업 설명과 승인 전 안내는 쉬운 한국어로 쓴다. 확인된 사실과 추정·미확인 사항을 구분한다.

## 작업 마무리

완료 후 `task_history.md`에 결과를 추가하고, 관련 보고서와 커밋을 연결한다. 다음 작업은 `next_step.md`를 갱신하되, 실제 실행은 사용자의 지시가 있을 때만 한다.
