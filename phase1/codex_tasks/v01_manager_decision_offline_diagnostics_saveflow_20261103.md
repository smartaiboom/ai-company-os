## 구현할 한 가지 흐름
1. **실패 단계 구분**: 현재 `app.py`의 `propose_real_manager_decision_once`가 `except Exception`에서 모든 오류를 동일한 `real_manager_stopped`로 기록하고 구체적 원인을 버린다. 네트워크/예약 저장, 제공자 응답 구조 및 finish_reason, JSON 파싱, strict 계약·binding, 호출 후 프로젝트/원장 지문, 제안 영속 저장을 **안전한 단계 코드**(예: transport, provider_response, decision_contract, project_binding, proposal_persist)로 구분하라. 실제 예외 메시지·raw response·prompt·키·사용자 원문은 Git/일반 로그/사용자 오류에 남기지 않는다. 단계와 **제한된 오류 유형/필드명**만 KST 감사 이력에 기록하되 비밀·응답 원문을 노출하지 말 것. 원래 실패를 재구성할 수 없다면 `historical_cause=unknown`으로 유지한다.
2. **저장 경로 안전성**: 응답 후 유효한 판단이 생성되면 기존 승인 계획/결과 지문과 원장 1회 증가를 확인하고 `provider=real_openrouter_free`, `status=pending_user_decision`, attempt ID·KST를 원자적으로 저장하며 `manager_decision_view`로 조회 가능해야 한다. 실패 감사 기록은 저장 중 다른 프로세스의 변경을 덮어쓰지 않도록 현재 프로젝트 잠금/원자 저장 규칙을 지켜라. 특히 `real_ai.stop_reason` 존재, 예약→completed 변화, `updated_at` 차이, 요청 전후 예산 변화 때문에 **유효한 응답을 거짓 stale로 거절하는지** 실제 코드 분기 분석 후 필요한 최소 수정. 보안을 느슨하게 하거나 binding을 모델 대신 조작하지 않는다. 응답이 잘못됐으면 수정해서 승인된 척하지 않는다.
3. **재시도 방지**: 기존 실제 프로젝트 `cb44b605b498`에는 이미 관리자 kind=manager_decision 1회와 guard가 존재한다. 이 기록·guard를 절대 초기화/삭제하지 말고, 같은 사용자 승인을 재사용하거나 호출을 재실행하지 않는다. 현재 실제 프로젝트의 manager_decisions.authorization, proposals=[], real_manager_stopped, TASK-001 승인, TASK-002~004 대기, 3/20을 **읽기 전용**으로 확인하고 상태를 유지한다. 이번 작업에서 OpenRouter/외부 네트워크 요청을 만드는 스크립트·실행 명령을 절대 실행하지 않는다.
4. **실패 원인 계측**: 기존 `RealManagerDecisionProvider.generate`의 응답 구조/finish_reason/content/JSON/strict 검증 경계를 테스트 가능한 형태로 최소 분리하고 오류 코드를 전달하라. 사용자에게 노출하는 메시지는 한국어로 간결하게, 개발 감사 이력은 단계/유형만. 어떤 응답을 왜 거절했는지 다음 실제 실행에서 판단 가능해야 하지만, 원문/기밀을 저장해서는 안 된다.
