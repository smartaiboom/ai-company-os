# 실제 AI 클립 1개 수입 및 9:16 쇼츠 렌더 작업 지시
작성: 2026-11-09 KST

## 반드시 지킬 작업 방식
- **명령과 결과는 파일 기반으로만 전달한다.** 대화창/콘솔에 긴 진행 로그나 결과를 출력하지 않는다.
- 최종 결과는 반드시 로컬 파일 `reports/real_ai_clip_import_result.md`에 저장한다. 이 파일은 실행된 사실, 사용된 실제 입력 파일, 출력 영상 경로, 검증 수치, 오류/한계와 남은 일만 간결히 기재한다.
- 결과 파일이 저장된 후 사용자에게는 `결과 나왔어`라고만 알리거나 완료 여부를 짧게 알린다. 사용자에게 직접 긴 보고서를 붙여 넣도록 요구하지 않는다.
- 작업 도중 반복 질문하지 말고 확인 가능한 파일과 코드를 먼저 확인한다.

## 목표와 입력
- `AGENTS.md`, `docs/FIRST_REAL_AI_CLIP_TRIAL.md`, `companies/video/ai_clip_pipeline.py`, `docs/IMPLEMENTATION_STATUS.md`를 읽고 시작한다.
- 사용자가 Google Flow에서 AI 영상 클립을 생성하여 Codespaces의 `data/video_ai_clip_inbox/`에 넣었다고 확인했다. **폴더에 있는 실제 파일을 직접 확인**하여 MP4/MOV 하나를 scene-1에 수입한다. 파일이 없거나 여러 개라 식별이 어려우면 추정하지 말고 결과 파일에 현황을 기록한다.
- 클립 출처: 사용자 진술에 따르면 Google Flow. 사용자의 진술 외에 공식 권리·워터마크·상업 이용 확인 근거가 없으면 확인된 것으로 표기하지 말 것.
- 원래 확정된 목표: AI 초보자 대상 ChatGPT 활용법 소개, 60초, 9:16 쇼츠, AI 회사가 대본/내레이션 제작.
- 기존 MeloTTS를 재사용하며 이전 생성된 음성 샘플 개선에 시간을 더 쓰지 않는다.

## 실행
1. GitHub 최신 상태와 Codespaces 작업 트리를 안전하게 확인하고 관련 계약/CLI를 읽는다. 이미 있는 모듈을 우선 사용한다. 이전에 렌더한 `data/video_ai_clip_review/20261109T145000_KST/` 및 기존 확정 프로젝트·원장·백업/로컬 아카이브를 수정/삭제하지 않는다. `git clean`·`git reset --hard` 금지.
2. 새로운 `data/video_ai_clip_review/<KST 타임스탬프>/` 작업 폴더를 만든다. 기존 60초 장면 계획을 기반으로 scene-1에 실제 mp4/mov를 수입한다. `source.json`의 정확한 스키마를 사용하고 알 수 없는 사용권/워터마크/상업 이용 사항은 unknown/false/미확인으로 기록, `publish_ready=false` 유지.
3. 나머지 scene-2/scene-3은 기존 fixture 영상을 사용할 수 있다. 단 **전체를 AI 생성 영상이라고 표시하지 않는다**. 결과물은 실제 AI 클립 1개+비AI 테스트 클립 2개를 포함하는 혼합 기술 시안. 기존 코드에서 mixed source를 어떻게 기록하는지 정확히 검토하고 실제 출처를 숨기지 않는다.
4. 기존 `ai_clip_pipeline`의 입력 검사 및 한 작업당 1회 렌더 제한을 지킨다. MeloTTS 내레이션, 한글 자막, 720×1280 세로형, 60초 영상 생성. 입력 클립은 변경하지 않는다.
5. ffprobe와 FFmpeg 전체 디코딩 확인, 9:16/SAR, 실제 길이, 음성 트랙, 실제 AI 클립의 출처·해시와 라이선스/워터마크/상업 이용 상태를 기록한다. 실패했을 경우 해당 job에 자동 재시도하지 말고 실패 원인 기록.
6. 이번 작업에서 새 Google Gemini/영상 AI API 호출 **0회**, 유료 결제/추가 비용/자동 업로드 0회, 기존 동의·비용 원장 불변. 기존 코드의 기능 오류 수정이 불가피하면 최소 변경 후 마지막 통합 검증 1회; 불필요한 새 개발과 테스트 반복 금지.
