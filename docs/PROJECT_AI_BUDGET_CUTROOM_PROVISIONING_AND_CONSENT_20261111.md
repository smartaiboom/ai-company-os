## 범위 및 구현
1. `companies/video/studio_server.py`, `companies/video/studio/studio.js`, `companies/video/budget_video_provider.py`, `companies/video/video_budget.py`, `core/project_budget_ledger.py`를 필요한 부분만 확인한다. 기존 서비스 내부 `enable_budget(pid, provider_job)`와 새 모드 provider grant 준비의 경계를 명확히 하고, 새 사용자 UI에서 필요한 입력/검토/승인 과정을 최소 추가한다.
2. 신규·미운영 컷룸 영상 프로젝트에서만 **예산 모드 opt-in**을 제공한다. 기존 운영 프로젝트, 원장/기획·보고서 생성된 프로젝트, 미션 01, 이미 연결된 프로젝트는 이관·재연결·자동 변환 금지. 등록 전 권한 있는 사용자에게 프로젝트·목표·provider 모델/API·계정 프로젝트 ID·무료 전용·사용 데이터 범위/외부 데이터 정책·유효기간 및 관리 책임을 읽을 수 있게 제공한다.
3. **예산 승인과 외부 데이터 전송 동의는 별개**: 단순 체크박스만으로 기존 provider 서명/키 바인딩/동의 가드를 우회하지 않는다. 기존 유효한 prepare/review_hash/approve 절차를 재사용해 사용자 본인이 정확한 검토 내용/정책을 승인하도록 한다. UI에서 처리할 수 없는 안전한 키 입력/소유자 서명 절차가 있다면 키·서명 프롬프트를 노출하거나 임의 승인하지 말고 검증된 기존 사용자 로컬 절차를 안내하며 그 전에는 등록·실행을 차단한다. 기존 계정·모델/무료 서비스 검증, 동의 철회와 만료 검사도 유지한다.
4. 관리자 초기 견적 제안과 대표 예산 승인은 실행을 허용하는 범위만 결정한다. **초기 승인량 0**이며 미승인 견적만으로 외부 요청 가능해지는 경로 금지. 이미 연결한 승인/거절, 예산 부족/추가 승인, 명시적 계속 버튼과 중복 요청 차단을 그대로 재사용한다.
5. 신뢰된 로컬 서비스와 HTTP 사용자 라우트·컷룸 JS 폼의 최소 통합을 구현하고, 실제 저장 후 새로고침/중복 제출/인증 실패/위조 hash/서명 만료/다른 프로젝트 바인딩/권한 없는 계정·무료 아닌 서비스/거절/동의 철회, 동시 실행 시나리오를 격리 오프라인 테스트한다. UI 모의 상태만 바뀌는 가짜 등록 금지. 기존 실제 provider consent verify 콜백 사용, 무조건 True 연결 금지.
6. 합성 임시 컷룸 프로젝트에서 opt-in 등록→독립 provider 승인→관리자 예산 견적→대표 예산 승인→모의 전송 예약·소모→예산 부족→추가 승인→이어가기의 전체 경로를 증명한다. DNS/외부 네트워크 차단; 실제 API 요청 0회, 실제 운영 프로젝트 등록 0건. 화면/버튼의 HTTP 라우트 수준 검증을 수행하고 브라우저 테스트는 기존 도구가 있을 때만 수행한다. 테스트 결과를 실제 AI 생성 결과로 표시하지 않는다.
7. 기능 범위를 무리하게 확대하지 말 것. 새 사용자 provisioning/동의의 일부가 기존 UI/서명 보안 제약상 불가능하다면 우회하지 않고 **동작하는 안전한 최소 연결**과 미구현 지점을 명시한다. 불필요한 전 분야 자동 전환, 대규모 UI 리디자인, 예산 수치 기본값 하드코딩, 별도 API 실험 금지.
8. 기존 미션 01의 세 stopped 업무/컷룸 `research_planning`, Gemini 누적 6/10, YouTube `search.list` 2/4 및 `videos.list` 2/4, 기존 조사·25초 관리자 선정·서명/실패/active_operation을 **읽기 전용 보존**. 이 작업은 미션 01 재개나 예산 모드 이관 승인으로 해석하지 않는다. 사용자 자료·키·원장·WAV/영상·백업·미추적 파일도 변경/삭제 금지.
