# AI Company OS v1.0 — 실전 운영 시작 합격 기준 및 다음 개발 지시서
기준일: 2026-11-09 KST

## 본 문서의 목적
영상 제작 기술 경로는 실제 Google Flow 출처 클립 3개 → 60초/9:16 쇼츠 합성으로 종단 검증했다. 그러나 AI 관리자·직원의 진짜 자율 판단, 품질 심사·재작업, 사용자 자연어 피드백의 경험화·재사용은 아직 구현/운영 검증되지 않았다. **영상 한 편의 완성도 향상**과 **AI 회사가 지속 개선하는 제품 기능**을 분리한다.

이 문서는 "여기까지 개발하면 실제 영상을 만들며 피드백으로 개선해도 된다"는 운영 전환 기준이다. 사용자와 합의할 **제안 기준**이지, 현재 이미 달성했다는 뜻이 아니다.

## 범위·최상위 원칙
- AI Company OS = 재사용 가능한 공통 회사 엔진 `core/` + 분야별 전문 회사 `companies/video/` 등.
- 첫 도메인은 9:16 초보자 대상 한국어 쇼츠. 중간 대본·음성·클립을 사용자에게 일일이 승인받지 않고, 최종 산출물 중심으로 사용자 평가를 받는다.
- 추가 비용, 새 실제 외부 AI 호출, 외부 게시, 민감정보 외부 전송에는 사용자의 구체적인 별도 승인 필요. 승인 불가 시 오프라인·모의 검증을 제공하되 실제 AI 자율 동작과 혼동하지 않는다.
- 기존 데이터·키·승인/시도/비용 원장, Gemini 단일 인수 1/1 호출 결과, 과거 영상/음성 결과, 백업/아카이브 절대 훼손 금지. KST UTC+9.
- 기능 단위 묶음 개발 후 마지막 통합 검증 1회. 불필요한 API나 TTS 재호출/영상 렌더 반복 금지. 우선 내부 기능·계약 개발, GUI는 나중.
- 정교한 외부 AI 영상 API의 무료 웹 로그인 계정과 API 권한은 별개. 현재 파일 import 기반 제작은 임시 반자동 경로이고 완전 자동 외부 클립 생성이라고 표시하지 않는다.

## 운영 시작 필수 능력 (P0)
### 1. AI 관리자의 목적 판단과 작업 위임
- 최상위 목표와 이전 답변으로 품질/시청자/영상 규격/예산 제약을 구체화한다.
- 정말 필요한 경우에만 사용자에게 질문한다. AI가 자율 판단 가능한 장면 수, 대본 표현, 목소리·편집 스타일은 사용자에게 하나하나 선택하라고 하지 않는다.
- 계획에서 역할·입력·출력·완료 기준·의존성·예산/호출 허용 범위를 명시한다.
- 사용자 승인/권리/호출 게이트를 건너뛰지 않는다.
- 오프라인 테스트의 고정 규칙·모의 AI와 실제 AI 관리자 호출 결과를 구분한다.

### 2. AI 직원 간 실제 인수인계
- 조사/기획 → 대본 → 영상 장면 기획/소스 확보 → 음성/자막/편집 → QA와 같은 역할을 목표에 맞게 배정한다. 역할 목록을 하드코딩한 가짜 고정 파이프라인만 운영 가능하다고 표시하지 않는다.
- 이전 단계의 실제 산출물·버전·출처/근거를 후속 직원이 읽어서 일을 하도록 한다. 입력과 출력의 스키마/상태/해시를 보존한다.
- 입력 부족·외부 수동 업로드 대기·도구 미지원 상태는 명시적으로 대기/차단한다. 가짜 완료/추정 입력 금지.

### 3. 품질 평가 및 재작업
- 기술적 미디어 유효성(해상도/재생/트랙/자막)과 콘텐츠 품질(대본 흥미·정확성·장면-대본 일치·클립 과반복·한국어 음성 자연스러움)은 별도로 평가.
- 평가 항목별 근거, 점수 또는 명확한 pass/fail, 한계, 개선 제안을 구조화해 기록한다.
- 실제로 확인할 수 없는 영상/음성 체감 품질을 AI가 봤다/들었다고 주장하지 말 것. 가능한 도구 기반 검사는 실시하고, 불가능한 항목은 '미평가'로 유지.
- 결함 발견 → 담당 AI 직원 재작업 지시 → 변경 전후 비교 → 개선/악화 판단 최소 1주기. 재작업 최대 횟수/비용 제한. 동일 오류 루프 차단. 외부 비용 미승인 시 자동 재호출 금지.

### 4. 최종 결과물까지의 실행
- 사람의 콘텐츠 선택·중간 승인 없이도 허용된 범위 내에서는 최종 MP4 + 대본 + 장면 구성 + 자막 + QA/비용/출처 보고를 생성한다.
- 실제 AI 영상/음성 소스가 제공되지 않으면 정확하게 `external_clip_pending` 등으로 보류한다. 수동 생성이 필요하면 해당 절차만 사용자에게 요청한다. 부족한 소스를 fixture로 몰래 채우거나 영상이 완성됐다고 표시하지 않는다.
- 미디어 제작 성공과 `publish_ready`를 구분: 상업 이용권·워터마크 등 확인되지 않으면 게시 준비 미완료.

### 5. 사용자 자연어 피드백의 경험 축적·재사용
- 사용자는 최종 영상에 대해 “30~40대 주부 대상이면 좀 더 친근하고 젊은 음성이 좋겠다”, “같은 5초 화면 반복이 심하다” 등 자연어로 평가한다.
- AI 관리자가 피드백의 대상(대본/음성/영상/편집), 적용 범위(해당 프로젝트/특정 시청자군/전체), 선호/문제, 확신도/근거, 다음 행동, 검증 여부를 분리 추출·저장한다.
- **검증된 경험**과 **미검증 가설** 분리. 한번의 주관적 피드백을 영구적인 전역 규칙으로 오해하거나 다른 시청자군에 무분별 적용하지 않는다.
- 새 프로젝트에서 관련 경험만 검색·선택·적용한 근거(참조 ID)를 남긴다. 유사 목표 재생성 시 적용 전후 계획·결과 차이를 테스트로 확인한다.
- 사용자가 피드백을 수정/철회하면 유효 규칙에서 제외하며 이력을 추적한다.

### 6. 안정성/제어
- KST, 상태 전이, 스키마/해시, 오류 진단, 멱등성/중복 호출 방지, 승인·예산·권리 게이트.
- 기존 데이터 비파괴, 실패/중단 후 안전한 재개 또는 명확한 사용자 조치 요청.
- API 호출/결제/업로드/외부 전송은 실사용 승인 없으면 없음. 실제 호출 0회 테스트가 실제 AI 자율 운영의 증명은 아님.

## 제안 운영 전환 인수 시험 (실제 목표)
세 가지 서로 다른 영상 목표로 총 3편을 시험한다.
A. 최초 목표 → 관리자 계획 → 직원 협업 → 최종 MP4와 QA 보고서; 중간 사용자 마이크로 승인 없이 완결(비용/권리 게이트 제외).
B. A의 최종 결과에 사용자가 자연어 피드백 → 경험 기록 → A와 비슷한 새 주제 제작 시 검색/적용/전후 차이 기록.
C. 시청자층/톤이 다른 목표로 한 편 제작하여 B의 특정 세그먼트 경험이 부적절하게 전역 적용되지 않는 것을 확인한다.
피드백 반영 검증 2회 이상(적용할 때와 적용하면 안 될 때 등), 관리자 재작업 지시 및 개선 비교 1회 이상.
- 세 편 모두 실제 MP4 기술 유효성 통과, 사용자 최종 평가 수집 가능, 각 역할·산출물·판단/재작업·사용 경험 적용/비적용 근거 추적.
- 모든 사용권·외부 호출·비용은 실제 승인 수준을 준수. 무단 비용/외부 호출/자료 훼손 0건.
- 허용된 수동 Google Flow 클립 제공은 표기된 반자동 경로로 인정. **자동 외부 생성이 없는데 완전 자동 영상 회사라고 합격 처리하지 않는다.**
- 콘텐츠 미학적으로 완벽한 3편이 필수는 아님. 다만 피드백이 결과에 반영되는 사실을 확인할 수 있어야 한다.
- 이 기준을 충족하면 '영상 제작 기술 시안'에서 '초기 운영/피드백 개선 단계'로 전환. 이후 품질 실측과 도구 교체는 운영 중 지속 개발.

## 현재 상태와 차이
- 현재 통과: 실제 AI 출처 클립 수입 3개·fixture 0, 60초 9:16 MP4, MeloTTS, 자막, ffprobe/전체 디코딩, 비용/원본 보존.
- 미통과: 실제 AI 관리자→직원 전 업무 연결, AI 자체 콘텐츠 판정과 수정, 최종 피드백 경험 검색·반영, 서로 다른 프로젝트에 대한 반복 검증. 원본 영상 라이선스/워터마크/상업 권리 근거도 미확인.
- 기존 Gemini 단일 호출 1/1은 별도 인수 범위로 재사용/재호출하지 않는다.

## 다음 개발 묶음(우선순위와 세부 Codex 지시)
**다음 1회 개발 묶음: P0 공통 판단·검토·경험 재사용 엔진**. 영상 API·TTS 교체/GUI/영상 재렌더가 아니다.
1. AGENTS.md, docs/ARCHITECTURE.md, README.md, core/와 companies/video/의 현재 API/스토어·테스트 코드를 먼저 분석하고 기능 중복 여부를 확인한다. 이미 구현된 역할/상태/원장/스키마는 재사용한다. '예전 phase1 통째 재구축' 금지.
2. 공통 `core/`에 도메인 비종속 관리자 판단(목표→업무 분해→역할 할당→의존성→검토/수정 지시), 직원 산출물 인수인계, 평가 판정, 수정 주기, 자연어 피드백 경험 기록·검색·범위 제한·버전/철회 기능을 기존 구조에 필요한 최소한으로 연결한다. JSON만 기록하는 가짜 판단을 'AI 자율'이라 표시하지 않는다. 실제 모델은 승인된 provider 경계에서만 호출. 무료/무호출 모드에선 mock evaluator와 계약 검증을 명확히 분리.
3. 영상 회사는 공통 엔진을 재사용하는 통합 어댑터를 만들어 `대본/장면/음성/소스/합성/품질` 작업 계약과 현재 클립 렌더 경계를 연결하되 실제 무료 웹 영상 생성은 수동 입력 대기로 유지. 영상 고유 규칙(예: 장면 반복, 자막, 음성 길이)은 `companies/video/`에 둔다.
4. 검증은 오프라인에서 목표 1개를 AI 관리자·직원 역할로 인계→품질 결함 검출→수정 요청→재평가, 사용자 자연어 피드백→경험 저장→유사 목표 재사용, 서로 다른 시청자 대상에서는 선택적 비적용, 실패/제한·예산/승인 차단을 통합해 **한 번** 실행. 실제 AI 모델 추론을 테스트한 것으로 혼동하지 않는다.
5. 기존 프로젝트/실사용 원장/동의/키/백업/지난 영상/미확정 상태 절대 변경 금지. 불필요한 재개발, 전역 파일 구조 변경, 새 API 호출/비용/외부 업로드 금지. 필요 시 새 테스트 fixture 저장소만 사용.
6. 완료 조건: 새 기능의 실제 코드와 통합 검증 결과 및 아직 실제 모델·사용자 운영에 미연결된 부분을 `reports/manager_staff_feedback_engine_result.md`에 기록. 코드는 기능 단위 커밋/푸시. 문서와 보고서도 GitHub에 반영. 로그·결과는 파일 기반, 대화 출력 최소화. 미달 항목은 미달로 기록하고 자체적으로 완료 판정하지 말 것.
