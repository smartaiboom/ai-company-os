# 공급자 장애 대응 및 업무 재개 기능
2026-11-24 KST. 기준 f4501d9. DEVELOPMENT_WORKFLOW.md, AGENTS.md 및 reports/20261124_gemini_transport_stabilization_result.md 참조.

## 목표
공급자 장애에도 완료 자료와 업무 상태를 보존하고 미완료 직원 보고/관리자 검토부터 안전하게 재개한다. 영상 v5는 실제 사례이며 공통 운영 기능을 우선한다. 현재 v5 직원 요청은 HTTP 503 UNAVAILABLE, 예약 1 완료 0, 관리자 미실행이다. 이전 400과 구분한다. 공식 상태 페이지 https://aistudio.google.com/status 는 상세 상태를 독립 확인하지 못했으며 외부 모니터의 정상 표시가 모델/계정 가용성을 보장하지 않는다.

## 기존 구조 검토
- core의 공급자 어댑터, 승인/서명/원장, decision_recovery, Gemini 공통 전송, 기존 OpenRouter 구현 및 Git 이력 확인. 이전 OpenRouter 성공 및 실패 기록과 현재 사용 가능 코드 구분. 기존 구현을 재사용하고 폐기된 실험 코드를 무조건 복원하지 않는다.
- research_workflow의 report_only 및 continuation 상태, 출처 관측, 실패 원장, 직원/관리자 결과 검증과 UI 연결을 확인한다. 이전 성공 및 실패 기록을 불변으로 유지한다.

## 기능 구현
- 장애 분류와 관측 시점, 출처, 모델/계정 범위 및 미확인 상태를 바탕으로 보류/재개 검토/대체 공급자 제안이 가능하도록 한다. 서비스 상태 조회는 공개 상태 정보와 실제 모델 호출을 구분한다. 자동 호출 또는 주기적 API probe를 추가하지 않는다.
- 503의 새 실행은 기존 실패 범위 재활성화가 아니다. 독립 검토 기록, 보존 자료 해시, 새 명시 승인, 유효 무료 범위, 신규 서명/예약, 기존 실패 연결 및 총예산 차감을 검증하는 별도 제한된 재개 경로를 설계/구현한다. 동일 실패 요청 자동 재전송 금지. 명시적 새 승인에 따른 동일 내용 재검증은 기존 중복 차단과 충돌하지 않는 별도 감사 가능한 계약이 필요한 경우에만 구현하고 근거를 기록한다. 결과 미확정/권한/쿼터/청구 오류는 임의 재개 금지.
- v5는 보존 관측과 출처를 사용해 직원 보고 1회 및 검증 통과 후 관리자 1회, 새 YouTube/Tavily 검색 0회인 별도 검증 범위 제안까지만 준비한다. 현재 개발에서는 실제 실행하지 않는다. 기존 승인 잔여 1회를 새 승인과 혼동하거나 초기화하지 않는다.
- 기존 OpenRouter 어댑터의 현재 연결 계약, 모델 고정, 실제 무료 조건과 비용/라우팅 통제, 데이터 전송 범위, 구조화 응답 및 출처 검증 호환성을 검토한다. 검증되지 않은 무료 모델이나 openrouter/free 동적 선택을 확정 모델로 주장하지 않는다. 대체 공급자는 후보 및 준비 상태를 표시하고 공급자/모델 변경은 별도 대표 승인 필수. 현재 코드에 적합한 공통 경계까지만 구현하고 대규모 재작성이나 가짜 가용 상태 금지.
- 컷룸에서 중단 사유, 기존 보존 자료, 가능한 다음 조치, 신규 승인 범위를 명확하게 표시한다. 동일 클릭 중복 실행, 만료/철회/변경된 자료/원장, 승인 없는 호출, 자동 공급자 전환을 차단한다. 보류 상태에서도 보존 자료 확인 가능.
- 결정적 정책 판정과 실제 AI 관리자 판단을 구분한다. 장애 시 AI 판단 호출 자체가 불가능할 수 있으므로 정책 기반 안전 상태 및 제안을 제공하되 AI가 판단했다고 허위 표시하지 않는다.
