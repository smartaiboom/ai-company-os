# 다음 개발 작업: 승인 경계를 지키는 AI 직원 업무 자동 진행 (mock 우선)

## 목적
AI Company OS의 큰 목표는 사용자 목표를 AI 직원들이 분담·협업·검토·수정하여 최종 산출물을 만드는 것이다. 지금까지는 사용자가 업무마다 실행 버튼을 눌렀다. 이번에는 **사용자의 명시적 시작 요청 한 번으로 실행 가능한 다음 업무를 찾아 진행하되, 검토 승인 대기·실패·입력 부족에서는 안전하게 멈추는 최소 자동 조정**을 구현한다. 실제 AI API 자동 호출이나 무한 루프는 이번 범위가 아니다.

## 사전 확인
- `AGENTS.md`, `codex_tasks/README.md`, `reports/ai_company_os_current_state_audit_20261102.md`, `reports/concurrent_task_execution_safety_20261102.md`, 현재 `app.py`, `execution_engine.py`, 관련 테스트와 보고서를 확인한다.
- 현재 git 브랜치, origin/main, status/diff 및 사용자가 남긴 변경·미추적 파일을 확인한다. 기존 업무 데이터·백업은 절대로 삭제/초기화하지 않는다. reset/clean/force push 금지. 모든 로그·기록 시각은 KST.
- 기존 승인 게이트, 명시적 선행 결과 연결, 실패·빈 결과 보존, 중복 실행 보호, openrouter/free 제한을 유지한다.

## 설계·구현
1. 기존 코드의 단일 업무 실행 경로와 승인 검증을 재사용하고, 최소한의 '다음 실행 가능 업무 판정' 및 사용자 요청에 의한 자동 진행 동작을 추가한다. 필요 이상으로 아키텍처를 바꾸지 않는다.
2. **이번 자동 진행은 `AI_ENGINE=mock`에서만 허용한다.** 실제 엔진/불명확한 모드에서는 시작 전에 명확히 거절하며 외부 요청을 절대 보내지 않는다. 향후 실제 AI 연동은 별도 명시적 승인 아래 단계적으로 진행한다.
3. 필수 선행 업무의 완료 결과와 검토 승인 조건이 충족된 업무만 실행한다. 자동 진행 중 검토 대기 상태에 도달하면 멈추고, 사용자가 승인한 뒤 별도 재개 요청을 받아 다음 업무를 처리한다. 실패/빈 결과/수정 요청/실행 가능 업무 없음에서도 이유를 기록하고 중단한다.
4. 한 번의 자동 진행에서 처리 가능한 업무 수에 안전한 상한을 둔다. 같은 업무를 한 요청에서 중복 실행하지 않고, 프로젝트별 동시 실행 보호와 충돌하지 않도록 설계한다. 상태를 최신 저장 값에서 다시 확인하고 사용자 데이터 유실 위험이 없게 한다.
5. 최소 UI에는 시작·재개 조작과 현재 멈춘 이유를 알기 쉬운 한국어로 보여 준다. 기존 UI 기능을 손상시키지 않는다.
6. 자동 진행이 기존 프로젝트의 JSON 형식·이력·개별 수동 실행과 충돌하지 않는지 확인한다. 구현 중 새로운 작업 결과 저장이나 시각은 KST로 처리한다.

## 테스트와 안전 조건
- TemporaryDirectory의 격리 프로젝트와 mock 실행기를 사용해 '계획 승인→업무 1회 실행→승인 대기 정지→사용자 승인→재개→다음 업무'를 검증한다.
- 선행 결과 미승인/누락, 실행 실패, 빈 결과, 중복 요청, 동시 프로젝트 요청, 실제 엔진에서 자동 진행 거절, 최대 실행 횟수 상한을 테스트한다.
- 외부 API 요청·유료 모델 호출·네트워크 접근 금지. 실제 사용자 데이터 경로에 접근할 우려가 있는 테스트는 실행하지 않는다.
- 관련 기존 단위 테스트와 필요하면 격리된 HTTP 테스트를 실행하고 `git diff --check` 확인. 테스트 실패나 충돌이 남으면 푸시 중단.
- 처음에는 최소 mock 흐름을 완성하고 AI 품질 자동 평가·도구 실행·장시간 백그라운드 작업·실제 모델 자율 호출은 후속 단계로 남긴다.
