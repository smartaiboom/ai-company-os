# 다음 작업: 검토 승인 게이트의 격리된 HTTP 통합 검증

**상태:** 준비 완료 — 사용자가 실행을 지시하면 진행한다.

## 목표
최근 구현한 AI 직원 업무 검토 승인 게이트를 실제 HTTP 요청/응답 경로에서 검증한다. 보고서에서 브라우저 사용성 확인과 HTTP 스모크 테스트가 미실행으로 남아 있으므로, 기존 사용자 데이터를 건드리지 않는 격리된 검증을 보완한다. 문제가 발견되면 이 범위 안에서 최소 수정한다.

## 시작 전에 확인할 것
- `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, `reports/review_approval_gate_report.md`를 읽는다.
- 최근 커밋과 `git status`, `git diff`를 확인하고 기존 사용자 변경을 보존한다.
- `app.py`의 검토 상태 표시, 승인/수정 요청 POST 처리, 후속 업무 실행 차단, 저장 경로를 추적한다.
- `tests/test_smoke.py`가 실제 저장소 데이터를 참조하는 지점을 확인한다. 격리 방법을 입증하기 전에는 실행하지 않는다.

## 작업 범위
1. 안전한 임시 디렉터리에서 프로젝트/저장 데이터 경로를 격리할 수 있는지 먼저 확인한다.
2. 필요하면 별도의 HTTP 통합 테스트를 추가한다. 임시 프로젝트 데이터와 모의 실행기를 사용하며 실제 AI API는 호출하지 않는다.
3. HTTP 수준에서 다음을 검증한다.
   - 승인 전 후속 업무 실행은 거절되고 실행 엔진은 호출되지 않는다.
   - 성공 결과가 존재하고 유효한 검토 상태일 때만 승인된다.
   - 빈 수정 의견은 거부되고, 유효한 수정 의견은 저장된다.
   - 수정 실행 성공 후 다시 검토 대기가 되고, 재승인 후에만 후속 실행이 허용된다.
   - 실패 또는 빈 수정 결과는 기존 결과를 덮어쓰지 않는다.
   - HTML 응답에 검토 상태와 승인/수정 요청 폼이 표시되고 대상 업무 ID가 올바르다.
4. 관련 회귀 테스트를 실행한다. 사용자 데이터 경로를 쓰는 테스트는 격리가 입증되지 않으면 실행하지 않고 사유를 기록한다.
5. 실패·빈 결과 보존, 기존 프로젝트 JSON·업무 기록·백업, 모달 중복 제출 방지, 스크롤 복원, `openrouter/free` 제한을 유지한다. 실제 AI API 요청은 하지 않는다.
6. 발견된 문제는 요청 범위 안에서 최소 수정한다. 무관한 리팩터링이나 기능 추가는 하지 않는다.

## 필수 검증
- 관련 테스트 및 HTTP 통합 테스트 통과
- `git diff --check` 통과
- 테스트가 실제 사용자 데이터와 백업을 수정하지 않았음을 확인
- `reports/review_approval_http_integration_report.md`를 작성한 뒤 다시 읽어 확인
- 보고서에 변경 파일, 실행 명령과 실제 결과, 격리 방법, API 호출 여부, 미확인 사항을 기록
- `codex_tasks/task_history.md`에 확인된 완료 사실과 보고서/커밋을 추가
- 통과한 경우에만 관련 파일을 커밋하고 원격 상태 확인 후 push한다. 실패나 미해결 충돌이 있으면 커밋·push하지 않는다.

## 완료 후 보고
검증 내용, 통과한 테스트, 실제 브라우저에서 별도 확인이 여전히 필요한지를 쉬운 한국어로 요약한다. 실제 AI API를 호출했다고 주장하지 않는다.
