# 사용자 협업형 전체 업무 연결: 조사 검토에서 기획·대본으로

## 개발 책임자 판단
현재 v1.0 목표는 완전 무인 회사가 아니라 대표와 AI 관리자·직원이 협업해 실제 산출물을 만들고 피드백/경험을 재사용하는 종단간 회사 운영이다. 기존 실제 조사/재지시 검증은 유지하며, 최근 근거 기반 판단 변경의 실제 검증은 필요한 핵심 검증으로 남긴다. 다만 게임 3종 검증, App Store 추출 추가 고도화, 공급자별 예외 복구 확대, 승인/UI 부가 기능은 당장 전체 흐름을 막는 결함이 아니라면 보류한다. 필요 여부는 기술적 근거로 결정하고 사용자 의견만으로 방향을 바꾸거나 기존 기능을 폐기하지 않는다.
## 이번 핵심 완료 범위
조사 결과 대표 검토 및 수정/선택 → AI 관리자 다음 업무 계획/배정 → 기획·대본 담당 업무 → 대표 검토/수정/승인 → 기존 제작 단계 인계. 실제 전체 사이클의 다음 연결을 하나의 기능 단위로 완성한다. 실제 영상 제작·평가·경험 재사용은 후속 연결 목표이며 이번에 완성했다고 주장하지 않는다.
- general_research_report.py review()/versions(), research_workflow.py, studio_server.py/studio.js, mission_production.py, production_operating.py, quality_workflow.py 및 기존 core 엔진의 업무/산출물/피드백 계약을 확인한다. 현재 보고서 검토에는 approve/revise/reject가 존재하고 handoff 오류 general_report_only가 기존 회귀 기록에 있다. 실제 원인을 확인하고 기존 기능을 재사용하여 최소 연결 수정. 새로운 병렬 회사 엔진/대형 승인 관리 시스템을 만들지 않는다.
- 대표는 기존 조사 보고서와 확인/미확인 근거, 관리자 보류 이유를 보고 후보를 선택하거나 방향·대본 요구사항을 자연어로 입력할 수 있어야 한다. 관리자 보류가 모든 후속 업무를 막지 않도록 사용자가 제한된 근거로 기획을 진행하는 명시적 결정 경로를 제공한다. 이는 조사 사실 검증 완료나 제작/게시 권리 승인이 아니다. 필수 안전·권리·비용·외부 전송 요건은 유지. 부족한 근거를 사실로 승격하거나 관리자 결정을 덮어쓰지 않는다. 목표 변경은 명시적으로 기록한다.
- 대표 결정과 원본 보고서 해시/버전, 선택 후보, 사용자 피드백, 근거 ID와 미확인 조건을 기존 프로젝트 업무 인계에 연결한다. 관리자에게 다음 업무 계획/직원 배정, 실제 기획·대본 산출물, 검토와 수정에 필요한 문맥이 전달되도록 한다. 기존 실제 AI 관리자/직원 실행 경로를 재사용한다. 실제 역할별 업무 수행과 단일 모델이 한 번에 모의로 작성한 결과를 구분한다. 사용자 선택을 하드코딩하지 않는다. 테스트에서는 명시적인 fixture 결정과 운영 대표 결정을 분리하고 운영 v8을 실제 승인/변경하지 않는다.
- 대표는 기획/대본을 확인하고 수정 의견을 전달하고 다음 단계로 승인할 수 있어야 한다. 원래 요구사항, 변경 이력, 산출물 버전, 다음 단계 입력 연결을 보존한다. 기존 제작 계획/음성/클립/렌더 기능을 재사용할 인계 상태까지 검증한다. 실제 클립 권리/생성 도구/비용이 필요하면 별도 미완료로 표시. 업무상 대표 검토를 기술적 반복 승인과 혼동하지 않는다. 피드백은 기존 저장 구조에 남겨 다음 단계 및 이후 경험 재사용에 연결 가능한 형태로 유지한다.
