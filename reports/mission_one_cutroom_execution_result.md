# 미션 01 컷룸 실행 연결 (2026-11-18 KST)

## 원인과 변경

작업 시작 HEAD는 `6e1b79f`였다. 컷룸은 미션 준비와 상태 표시까지만 제공했고, 독립 조사 연결, 승인 범위 검토, 서명 동의, 실행 및 결과 제출은 기존 미션 명령에서만 가능했다.

- `representative_workflow.py`에서 기존 독립 조사 연결 방식으로 현재 프로젝트의 미사용 준비본을 보존하고 새 조사 연결 작업을 붙인다. 화면에서 보던 미션 ID를 검증하며, 호출이나 세션 또는 서명 파일이 남은 준비본은 교체할 수 없다.
- `studio_server.py`와 `studio/studio.js`에서 컷룸 제안·동의·실행을 연결했다. 브라우저에는 키와 키 결합값을 보내지 않으며, 동의 시에는 서버가 보관한 제안의 해시를 확인한다. 제안은 서버 프로세스 메모리에 보관되므로 미서명 제안은 서버 재시작 후 화면에서 다시 준비한다. 저장 완료된 동의와 실행 기록은 기존 서명 및 원장을 사용한다.
- 명시적 실행은 백그라운드에서 기존 미션 엔진으로 진행한다. 고정 설정, 서명·유효 기간·키 결합 및 기존 상태·호출 원장 검증을 그대로 거친다. 완료 시 기존 보고서 제출 경로로 대표 승인 대기에 올린다. 제출만 남은 상태에는 외부 호출 없이 결과를 제출하는 버튼이 표시된다. 실패 또는 결과 미확정 시 새로고침은 상태 조회만 하며, 자동 재호출하지 않는다. `video_mission_one.py`는 화면에서 볼 수 있도록 조회 종류, 상태, HTTP 코드만 제공한다.
- 현재 컷룸 실행 범위는 기존 미션 01의 게임 쇼츠 목표다. 목표와 입력을 유지하고 실제 게임·주제·길이 및 조사 판단은 기존 역할 분담에 맡긴다. Gemini 모델은 `gemini-3.5-flash-lite`이며, Gemini와 YouTube 모두 기존 프로젝트 `gen-lang-client-0938732315`에 대한 소유자 확인을 받는다. 신규 기본 계약은 Gemini 10회, YouTube 검색·영상 조회 각각 4회, 작업당 및 전체 수정 각 1회, 허용 비용 미화 0달러다. 제공자 잔여량은 `unknown`으로 표시하며, 무료 조건 확인은 소유자 확인이다.

## 운영 중인 프로젝트에서 진행하는 방법

1. 업데이트된 코드를 사용하도록 기존 컷룸 서버를 재시작한다. 기존 작업·참조 디렉터리와 기존 환경 설정을 사용한다. 이 모듈은 키를 프로세스 환경에서 읽으므로 기존 실행 방식으로 `.env`의 설정을 내보낸 뒤 서버를 시작한다. 고정 모델·엔드포인트와 실행 활성화 설정도 기존 값을 사용한다. 이번 검증에서는 운영 서버를 재시작하지 않았다.
2. 컷룸에서 이미 준비한 프로젝트를 열고 **독립 웹 조사 연결**을 누른다. `목표 접수` 단계에만 **미션 01 준비**가 필요하다. 기존 미션이 조사 연결 대기라면 바로 연결한다.
3. **외부 전송 동의 제안 준비**에서 두 키의 프로젝트 소속, 결제 미연결·무료 조건, YouTube 정책 확인을 체크하고 **제안 준비**를 누른다.
4. **외부 전송 동의 검토**에서 목표, 전송 데이터, 한도, 유효 기한, Google 무료 서비스 데이터 정책을 확인한다. 동의하는 경우 체크 후 **동의 저장**을 누른다. 이 단계의 실제 요청은 0회다.
5. **미션 01 실행**을 누르고 확인 창에서 **외부 요청 시작**을 선택한다. **상태 새로고침**으로 진행·원장·실패 원인을 확인한다. 작업이 끝나면 **기획 승인 대기**에서 보고서를 열어 대표가 검토한다. 내부 검토만 완료된 경우 화면에 제공되는 **내부 검토 결과 대표 제출**로 로컬 제출을 진행한다.

## 검증 범위

- Python 3.14.4에서 지정된 세 모듈의 통합 테스트 **86개 통과, 실패·오류 0개**였다. 기존 84개에 컷룸의 정상 실행과 실패 차단 시나리오 2개를 추가했다. 실행 시간은 163.685초였다. Node 22.22.1의 JavaScript 문법 검사와 `git diff --check`도 통과했다.
- 추가로 컷룸 및 대표 워크플로 테스트 5개를 실행했다. 4개는 통과했고 실물 MP4·음성 렌더 테스트 1개는 `espeak-ng` 실행 파일이 없어 오류로 끝났다.
- 기존 조사 미연결 준비본부터 모의 Gemini 8회, 모의 YouTube 검색·영상 조회 각 1회를 거쳐 대표 승인 대기에 도달했다. 원본 준비본은 바이트 단위로 일치했다. 별도 모의 HTTP 503은 실패 1회만 차감됐고 재호출과 보고서 제출이 차단됐다.
- 미승인 실행, 잘못된 정책 확인·프로젝트 ID, 변조된 해시와 서명, 만료된 동의, 키·모델 불일치, 실행 비활성화, 중복 동의·실행 차단을 오프라인으로 확인했다.
- 환경을 비운 별도 로컬 프로세스에서 가짜 키와 `GEMINI35_AUTONOMOUS_FREE_ENABLED=0`만 사용했다. 임시 루트의 실제 `127.0.0.1` HTTP 서버에서 정적 리소스, 프로젝트 생성·조회, 미션 준비, 조사 연결, 제안, 동의 및 실행·제출의 차단 응답을 확인하고 종료했다.
- 실제 Gemini·YouTube API 호출과 유료 실행은 **0회**였다. 운영 프로젝트, 기존 데이터, `.env`, 원장 및 백업을 사용하지 않았다. Playwright와 Chromium을 사용할 수 없어 브라우저 클릭 검증은 수행하지 않았다. 실사용 환경 및 실제 AI 동작은 미검증이다.

## 실행 명령

```bash
git pull --ff-only
source .venv/bin/activate
PYTHONPATH=core:companies/video python -B -m unittest -q tests.test_rework_quality_followup_unit tests.test_rework_script_review_defects_unit tests.test_video_mission_one
PYTHONPATH=core:companies/video python -B -m unittest -q tests.test_studio_server tests.test_representative_workflow

```

localhost 검증에서는 빈 환경에 모의 설정만 제공하고 `python -B -m studio_server --host 127.0.0.1 --port 0 --root <임시 작업 경로> --reference <임시 참조 경로>`를 실행했다. `http.client`로 응답을 검사한 뒤 프로세스를 종료했다.
