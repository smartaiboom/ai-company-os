## 명시 승인 범위 (대표가 이 파일을 명시 승인한 경우만)
GroqCloud Personal / Default Project, openai/gpt-oss-20b, https://api.groq.com/openai/v1/chat/completions, 동일 등록 키, 새 서명 후 24시간, Free 전용 USD0. 독립 신규 통신 호환성 진단용 가상 최소 메시지와 신규 격리 협업 업무의 가상 목표·대표 선택·승인된 공개 근거와 한계·기획·대본·장면표·가상 수정 의견·역할 검토만 허용. 개인정보·운영 자료·영상/음성·로컬 실측값 제외. 기존 실패/서명 보존, 임의 전체 호출 총량 없음, 실제 무료 속도/쿼터 준수. 지시서 자체는 승인이 아니며 대표 명시 승인 및 유효 새 서명/선예약 필수.
## 구현 및 실제 검증
- 기존 urllib 실패를 반복하지 않는다. 기존 코드/의존성/공식 Groq 지원 HTTP 클라이언트 계약 및 일반 WSL curl 성공의 차이(환경 프록시 유무, TLS/HTTP 버전, 키 파싱 등)를 비밀 없이 확인. 설치된 requests/httpx 또는 공식 SDK 중 표준 지원 경로를 우선 검토하고 필요한 의존성은 기존 방식으로 명시 관리한다. 로컬 테스트에서 TLS 인증/호스트명 검증, 고정 HTTPS 목적지, no redirect, timeout, no retry, 인증 정보 미노출, 프록시 정책 및 응답 크기/오류 처리, 기존 비용/서명/원장 호환성을 검증한다. 네트워크 제한을 회피할 목적으로 헤더 위장, TLS 지문 변경, 프록시 경유, 다른 프로세스/환경 이용 금지. 원래 curl 성공은 호환성 단서이지 접근 제한 우회 허가가 아니다. 403이 실제 보안/권한 정책 차단이면 지원/정식 권한 해결을 우선하고 우회하지 않는다.
- 허용된 표준 클라이언트의 독립 신규 최소 진단을 기존 서명/예약/원장 경로로 실행. Codex 정식 네트워크 권한 사용. 사전 승인된 진단이라도 권한·보안·공급자 차단/쿼터/청구/전송 미확정 시 실제 실행 중단, 같은 실패 요청 자동 재송신 금지. 클라이언트 결함이 명확하게 입증되고 서비스의 정상 허용 경로가 확인된 경우에만 해당 결함 수정 후 승인 내 새 서명/예약으로 검증. 근거 없이 requests→httpx→curl 순차 실패 재시도 금지. 정상 허용 경로를 입증 못하면 지원 문의에 필요한 비밀 없는 증거 및 구체적 재개 조건을 남기고 멈춘다. 키/원문/인증값 출력 금지.
- 정상 연결이 입증되면 Groq 전용 transport 변경 최소화, 공통 엔진/기존 Gemini 경로 보존. 외부 호출은 반드시 기존 승인/서명/예약/원장/검증 경로를 거친다. 실제 새 업무를 같은 승인 범위에서 이어서 수행: 관리자 기획 및 배정→작가 대본→편집 장면표→관리자 검토→가상 대표 의견 반영→수정 대본→가상 승인→기존 영상 제작 인계 및 가능하면 Heami 음성 MP4 실제 재생 검증. 기존 성공 음성/영상 기능 재개발하지 않는다. 운영 v8 대신 승인 금지. 사용자 최종 평가와 경험 재사용 연결을 기록. 실제와 fixture 명확히 구분.
