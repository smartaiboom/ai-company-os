# AI Company OS v0.1 — M4 사용자 승인 실제 무료 AI 인수 테스트

## 사용자 승인 범위
사용자는 2026-11-02 KST 대화에서 아래 제한된 실제 AI 연결 테스트에 동의했다. 이 동의는 **이 목표와 이 테스트 범위에 한정**된다. Codex가 임의 목표, 기존 사용자 프로젝트 데이터, 다른 API/모델, 추가 호출, 결제 설정을 전송할 권한은 아니다.
- 목표: "소규모 매장의 재고 확인 업무를 개선하는 도구 기획 및 실행 제안서 작성"
- 전송 가능: 이 목표, 새 테스트 프로젝트에서 생성한 업무 지시, 해당 프로젝트 내 사용자가 승인한 선행 결과, 명시 품질 기준 및 수정 피드백. 기존 사용자 프로젝트·비밀·백업 데이터 전송 금지.
- 정확한 모델: openrouter/free, 고정 OpenRouter HTTPS chat/completions 경로. 유료 모델 전환/자동 fallback/자동 재시도 금지.
- 프로젝트 총 최대 7회 실제 API 시도(계획1, 직원 업무/검토/수정/재검토/최종 합계6), 명시 시작/재개당 최대2회. 실패·타임아웃도 소모. 모델 가용성/무과금 보장하지 않음. 키·결제 정보 출력 금지.
- **실제 요청 전 사전 점검**: M2/M3의 서버 활성화/프로젝트 동의/예산/전송 정보 표시를 검토하고, 허용된 새 테스트 프로젝트에만 명시적으로 동의를 적용한다. 동의 설정이 안전하게 지원되지 않거나 환경에 실제 API 키가 없다면 임의 우회/설정 변경/키 생성 없이 중단하여 보고한다. 이미 허용된 범위 내에서 별도 반복 동의 요청 없이 진행 가능하나, 사용자 입력/승인 단계가 필요하면 멈추고 안내한다.

## 작업 원칙
- 기존 M1~M3 코드, 계획·직원 실행·승인·품질/수정·최종 확정/JSON·Markdown 다운로드를 재사용. 처음부터 재구현하거나 별도 실험 앱 생성 금지.
- AGENTS.md와 M1/M2/M3 보고서의 관련 부분 및 현재 안전 코드만 확인. 전체 리포지토리/보고서 무차별 재분석 금지.
- git status/diff/branch, origin/main 동기화 후 시작. 실제 업무 데이터·백업·스냅샷·미추적 파일 보존, reset/clean/force push 금지. KST.
- API 키 존재 여부만 확인(값/길이/앞뒤 글자 출력 금지). 키가 없으면 설정 방법만 보고하고 실제 호출 없이 종료. Codex 사용량 절약을 위해 네트워크 무한 재시도·대규모 브라우저 설치·불필요한 패키지 다운로드 금지.

## 수행 순서 및 완료 기준
1. **사전 안전 검증**: 현재 실제 실행 경로/동의·활성화 수단/무료 모델 고정/호스트/7회 영속 예산·예약 상태를 확인. 기존 프로젝트는 사용하지 않고 격리된 새 테스트 프로젝트만 생성. 테스트 목표/전송 항목/최대 호출을 사용자에게 알기 쉽게 보여준다. 기존 프로젝트 동의/설정 임의 수정 금지.
2. **최소 연결 확인**: 실제 API 연결이 가능한지 허용된 프로젝트의 계획 1회 호출로 확인. 이 호출도 7회 예산에 포함. 인증·계정·무료 라우팅 오류면 원문 비밀/응답을 노출하지 않고 중단, 추가 호출/모델 변경 금지.
3. **실제 종단 흐름**: 계획 사용자 승인→4개 역할에 순차 작업/선행 승인 결과 전달→의미 검토(가능하면 changes_needed 및 사용자 수정 승인)→동일 직원 수정 1회→사용자 재승인→재검토→최종 직원→최종 사용자 승인→JSON/Markdown 확정본. 사용자 승인 없이 자동 승인하지 않는다. 실제 모델 결과가 통과하지 않거나 호출 예산이 부족하면 무리하게 성공을 만들지 않고 정지·보고. 검토가 실제로 pass라면 억지로 changes_needed를 조작하지 않는다. 결과의 실용성/근거/환각·형식 오류를 구분하여 평가한다.
4. **웹 UI 인수**: 현재 환경에 브라우저/Playwright가 있으면 클릭·승인·다운로드까지 실제 브라우저 검증. 없다면 대규모 설치를 강행하지 말고 기존 loopback HTTP/HTML 검증으로 대체하고 미검증이라고 명시.
5. **보존/회귀**: 기존 M1~M3 회귀를 필요한 집중 테스트와 전체 1회로 확인. 실패 수정 때만 집중 재실행. 실제 데이터 경로에 영향을 주는 smoke 테스트 금지. 테스트용 네트워크 mock과 실제 승인된 호출을 구분해 보고한다.
6. **실제 연결 불가능한 경우**: API 키·활성화/동의 UI·계정·환경 문제 등으로 진행할 수 없으면 안전 경계를 우회하거나 거짓 성공을 보고하지 않는다. 필요한 최소 수정만 수행하고 정확한 중단 원인/사용자가 해야 할 1개 다음 단계만 보고한다.

## Codex 사용량 절약
- 파일 탐색/테스트 최소화, M1~M3 재개발 금지, 사전 확인→최소 수정→한 번의 통합 시연/검증→짧은 보고.
- 안전 문제/외부 요청 실패가 반복되면 즉시 정지. 전체 재설계·반복 네트워크 호출 금지.
