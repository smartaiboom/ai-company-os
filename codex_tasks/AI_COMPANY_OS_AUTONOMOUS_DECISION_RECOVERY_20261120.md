# AI Company OS — 공통 AI 판단 검증·복구 개선 (2026-11-20 KST)

## 목표
AI 직원이 도구와 행동을 자율 선택하고, 검증 가능한 판단 오류를 구체적으로 피드백받아 승인된 범위 안에서 수정할 수 있는 공통 계약을 구현한다. 영상 교차 조사 실패를 첫 적용 사례로 사용하되 영상 전용 임시 우회나 고정 검색 순서를 만들지 않는다.

## 구현
1. 현재 단계에서 실제 선택 가능한 도구·옵션·종료 행동을 모델 입력과 구조화 계약에 명확하게 반영한다. 공급자 지원 스키마 부분집합을 확인하고 지원되지 않는 조합을 가정하지 않는다. 선택과 최종 보고의 필수/금지 필드가 일치하도록 한다. 기존 엄격한 의미 검증과 권리·보안 경계를 유지한다. AI의 도구 선택, 조사 종료, 전문 자료 단독 활용 판단을 고정하지 않는다.
2. 공통 엔진에 재사용 가능한 판단 오류 분류 및 제한된 수정 피드백 계약을 구현한다. 구체적 규칙 위반 코드, 허용된 선택지, 수정 지시 및 단계/시도 식별자를 안전하게 전달한다. 신뢰할 수 없는 모델 출력이나 검색 자료를 지시로 취급하지 않는다. 전체 원문·키·인증정보를 무조건 저장하지 말고 안전한 최소 진단 정보와 해시를 기록한다. 모델 오류와 코드 오류, 정책/권한 차단, 공급자 실패, 결과 미확정을 구분한다.
3. 의미 검증 실패가 응답 수신 증거와 함께 확정되고 새 승인 범위에서 수정 판단이 명시 허용되는 경우에만 동일 업무의 수정 판단을 별도 예약으로 수행할 수 있는 구조를 구현한다. 잘못된 응답을 코드에서 임의 보정하거나 성공 처리하지 않는다. 전송 불확실성·429/503·타임아웃·권한/서명 오류는 자동 재호출하지 않는다. 사용된 호출은 실패도 포함해 보존하고 새 시도는 별도 기록한다. 기존 무료 운영 정책과 한도를 우회하지 않는다. 구체적인 복구 예산은 기존 승인 계약에 맞춰 검토 가능한 제안으로 표시하고, 실제 새 승인/호출은 수행하지 않는다. 한도 부족·동일 오류 반복 시 중단 및 관리자/대표 검토로 연결한다. 독립 관리자 검토 몫을 침범하지 않는다.
4. 기존 영상 교차 조사에 공통 계약을 적용한다. 안전한 새 복구 범위 제안(원실패 링크, 기존 사용량, 별도 추가 예산, 변경된 입력/계약, 만료/키 결합)을 기존 서명 정책으로 검토 가능하도록 구현한다. 기존 grant와 실패 원장을 재사용·초기화·덮어쓰지 않는다. 승인 전 실제 전송 차단. 현재 대본 v2, WAV, 영상, 대표 평가, 기존 제작사/Commons 상태 유지. 승인 제안/복구 시작·중단 상태를 컷룸에 한국어로 표시하며 기존 오류 진단을 유지한다. 구조상 안전한 복구 제안 구현이 불가하면 차단 상태와 이유를 보고하고 우회하지 않는다.
5. 기존 실행 구조와 호환되는 공통 모듈을 우선 재사용하고 영상 외 가상 업무 fixture로도 계약 재사용성을 검증한다. 공통 계층과 영상 어댑터의 역할을 명확히 한다.
