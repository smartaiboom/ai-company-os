# 첫 실제 영상 프로젝트 — 계획 보완 및 사용자 승인 대기 (외부 AI 호출 0회)

## 방향 고정
AI Company OS는 범용 가상회사: 사용자 목표 → AI 관리자 가변 계획/역할 배정 → AI 직원 간 승인된 결과 전달/협의/검토/수정 → 최종 결과물. 영상 제작은 첫 실전 사례이지 코어 하드코딩 대상이 아니다. codex_tasks/README_KOREAN_LANGUAGE_RULE.md 준수. 진행·보고·최종 답변 한국어, KST. 기존 코드/업무 데이터/백업 보존. 전체 재설계·반복 전수 조사 금지.

## 사용자 판단과 현재 사실
사용자는 실제 AI 관리자 생성 계획을 보고 품질 검토 추가, MP4 불가능 약속 제거, 최종 대본·스토리보드·편집 지시서 산출물로 보완하는 방향에 '진행하자'고 답했다. **이는 계획 수정 진행에 대한 동의이며, 수정된 계획에 대한 최종 사용자 승인이나 외부 AI 호출 추가 승인은 아니다.**
실제 영상 프로젝트 ID cb44b605b498, 원본 파일 data/video-real-plan-20261103/projects/cb44b605b498.json. 상태 pending_approval, 실제 AI 계획 생성 completed 1/7, 업무 0. 기존 재고 프로젝트 c85d9853906a reserved 1/7과 보존본은 손대지 않는다.
실제 영상 목표: 'AI 초보자에게 유용한 ChatGPT 활용법을 소개하는 1분 영상 제작'.
현재 7회 상한 내 남은 6회이므로 계획 + 직원 5개 + 수정/재검토 2회는 불가능. 사용자 의도인 조사/대본/품질 검토/스토리보드/최종 패키지의 **기능을 유지하면서 업무 4개로 통합하는 초안**을 제시한다. 실제 호출 예산 계산과 semantic_review 계약이 허용하는 구성인지 코드로 확인한다. 가변 역할 설계 유지.

## 이번 Codex 한 번에 할 일
1. git pull --ff-only. 최신 보고서 reports/v01_video_real_plan_one_call_20261103.md, 기존 app.py의 계획 승인·수정 요청 경로, manager_plan.validate_stages, semantic_review 계약 및 해당 테스트의 관련 구간만 확인. **프로젝트 JSON이 실제 존재하고 예상 상태·목표·1/7·업무 0·reserved 0과 일치하는지 먼저 확인**. 없다면 새 프로젝트/가짜 데이터 만들지 말고 0회 호출로 중단 및 보고.
2. 사용자가 합의한 다섯 기능을 가능한 한 4개 작업에 반영한 **수정 계획 초안**:
   TASK-001 ChatGPT 활용법 조사 / AI 도구 조사 전문가 / 선행 없음 / 초보자용 검증 가능한 팁·출처 또는 미확인 표시
   TASK-002 한국어 1분 대본 / 스크립트 작가 / 선행 TASK-001 / 낭독 분량·자막·사실 확인 안내
   TASK-003 의미적 품질 검토 / 품질 검토 담당 / 선행 TASK-002 / 정확성·초보자 이해도·분량·자막 기준별 근거, 수정 제안
   TASK-004 스토리보드 및 최종 제작 패키지 / 콘텐츠 디자이너·편집 기획 담당 / 선행 TASK-002 및 TASK-003 (실제 validator 허용 여부 확인) / 승인된 대본, 0~60초 장면 구성표, 자막, 편집 지시서, 미확인 항목. **실제 MP4 파일 생성/업로드를 약속하지 않음**.
   다만 기존 의미 검토 계약이 정확히 어떤 역할/인접성/의존 관계를 요구하는지 확인해 충족하는 범위 내에서만 조정. 검토·수정·재검토 경로에 필요한 실제 API 횟수를 계산: 계획 1 + 직원 4 + 수정 1 + 재검토 1 = 총 7회가 가능한지, semantic 검토가 별도 추가 API 호출이면 불가능하므로 명확히 보고. **불가능한 흐름을 가능하다고 표시하지 말고, 호출 예산을 확대/초기화하지 말 것.** 불가능하면 실현 가능한 대안 1개만 보고하고 수정 초안은 승인 대기로 유지.
3. 실제 생성된 AI 원본 계획은 잃지 않도록 기존 프로젝트 안의 불변 원본/변경 이력(또는 기존 지원되는 수정 요청 이력)으로 보존하고, 계획 초안 변경은 기존 save_project 원자적 저장 방식과 validate_stages를 사용. 임의로 plan.status='approved', tasks 생성, 사용자 승인 기록 추가 금지. 가능하면 기존 /manager/reject 피드백 흐름을 먼저 사용하고, 외부 AI 재계획 호출이 발생하는 /manager/plan은 절대 호출하지 말 것. 최소 변경으로 실제 계획 내용을 수정할 지원 경로가 없으면 새 범용 '사용자 승인 전 계획 편집' 경로를 안전하게 최소 구현하되 기존 계획 원본·목표 지문·호출 예산 보존 및 승인 전만 허용. 새 UI가 필요 없으면 추가하지 않는다. 사용자에게 실제 수정된 계획을 확인할 방법을 제공한다.
