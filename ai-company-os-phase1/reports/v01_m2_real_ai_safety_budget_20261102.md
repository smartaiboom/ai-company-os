# v0.1 M2 — 실제 무료 AI 안전 경계·영속 예산

작성: 2026-11-02 13:28 KST
기준 커밋: `d0a41eca3f4d5754a0ecd9c875d6cfac3d7ef212` (main/origin/main 동기화)
판정: **M2 구현·모의 통합 검증 완료. 실제 AI API 호출 0회.** 실제 제공자 접속·품질 실증은 M4 별도 승인 전 수행하지 않는다.

## 구현 범위와 재사용

- 신규 `ai_safety.py`의 `request_json`으로 기존 실제 계획/직원 전송을 공통화했다. 요청 직전 모델이 정확히 openrouter/free이고 JSON 본문의 모델도 같은지 검사한다. OpenRouter의 정확한 HTTPS 기본 주소와 고정 /chat/completions만 사용한다. 사용자 정보·query·다른 호스트·HTTP 주소는 거절한다. 기본 전송은 리다이렉트 및 환경 프록시를 사용하지 않는다. 유료 fallback·결제 변경 없음.
- 서버 실제 요청 활성화는 기본 꺼짐이며, 해당 프로젝트의 enabled와 명시적 동의(승인 시각·목표 지문·목표/업무 입력/선행 결과/의견 전송 범위)가 모두 필요하다. 모델 설정만으로 송신하지 않는다. 이번에 실제 동의를 부여하거나 서버 활성화를 변경하지 않았다. 테스트만 가상 동의·활성화를 주입했다. UI/POST에는 동의를 켜거나 예산을 초기화하는 기능이 없다.
- 프로젝트 real_ai에 최대 7회(더 낮게 설정 가능)의 attempts를 저장한다. 실제 전송 전에 KST reserved 기록을 저장하고, 전송/JSON 수신 종료 후 completed 또는 failed로 갱신한다. 실패·타임아웃·형식 오류도 시도 수를 되돌리지 않는다. 미완료 reserved가 있으면 새 전송을 거절한다. 입력/출력 상한이나 모델/주소/동의 오류는 전송 전에 거절한다.
- ContextVar 요청 범위는 저장 콜백·프로젝트 ID·사용 횟수를 묶고 POST 한 번당 최대 2회로 제한한다. 앱의 기존 프로젝트 잠금 안에서 사용한다. 여러 탭의 경합은 기존 409이며, 새 시작/재개와 재시작도 저장된 프로젝트 예산을 초기화하지 않는다. 예약 저장 실패 시 전송 0회다.
- 입력 JSON 최대 128KiB, 프로젝트 누적 입력 최대 7×128KiB, 원시 응답 최대 256KiB, 출력 토큰 최대 4096(계획은 기존 3000), 요청 시간 최대 90초다. 응답 읽기도 상한을 둔다. 상한은 코드에서 검사하며 클라이언트 폼으로 올릴 수 없다.
- 기존 manager_plan.py와 execution_engine.py는 응답 정규화·업무 프롬프트·빈/잘린 결과 거절을 재사용하고 전송 부분만 공통 모듈로 연결했다. 계획 함수에 프로젝트 인자를 추가했다. 생성 뒤 model을 바꾼 엔진도 요청 직전 다시 차단된다. 제공자 HTTP 오류 본문·연결 상세·계획 응답 미리보기는 표시하지 않고, 진단 메타데이터도 허용 항목만 기록한다.
- 기존 `/workflow/run`과 mock 수정은 계속 mock 전용이다. 별도 `/workflow/run-real`은 활성화·목표 동의를 먼저 검사하고 같은 실행 대상 선택/승인 경계/단일 실행/실패 보존을 재사용한다. 최대 2개 처리 후 정지하고, 승인 대기·요청 오류에서 반복하지 않는다. 사용자 승인 없는 실제 경로는 시작 전에 차단된다.
- UI는 외부 전송 자료, 별도 M4 승인 필요, 프로젝트 상한·사용/예약·남은 횟수·정지 이유를 표시한다. 미완료 예약도 읽기 전용으로 안내한다. 일반 수동 계획/직원 경로도 공통 검사와 같은 예산을 사용하며 최종 보관에 예산/인증 메타데이터를 내보내지 않는다.

예약에 completed라고 기록되는 것은 API 응답 JSON 수신 처리 완료이며 **계획·업무 품질의 성공이나 사용자 승인이 아니다.** 이후 업무 응답 검사 실패는 기존 실패 상태·오류 화면·자동 진행 중단으로 처리하고 이미 사용한 API 예산은 유지한다.

```text
python -B -m unittest tests.test_real_ai_safety_budget tests.test_execution_engine tests.test_manager_plan tests.test_manager_plan_persistence tests.test_task_execution_persistence
```

최종 집중 **53개 통과(신규 13개 포함)**. 신규 초기 실행에서는 모의 프로젝트에 승인된 계획 fixture가 없어 2개가 실패했다. 승인된 계획 fixture를 보완한 뒤 52개 통과, 실제 시작당 2개 업무 제한 및 진단 정보 보강 후 53개 통과했다. 실제 전송을 허용해 해결한 것이 아니다.

검증 범위:

1. 동의/활성화 없음·목표 변경·mock 모드 및 폼의 가짜 approved/enabled는 전송 0회. 기존 동의·예산을 자동 변경하지 않음.
2. 비무료/누락 모델, 생성 후 엔진 모델 변조, HTTP·위장 호스트·query·userinfo URL, 입력/출력 상한 초과, 요청 범위 없음은 전송 전 거절.
3. 전송 mock이 호출되는 순간 디스크의 마지막 시도가 reserved임을 확인. 한 요청 최대 2회, 프로젝트 전체 최대 7회. 재요청/재조회에서도 카운터 보존.
4. reserved JSON을 다시 읽으면 재시작 상황에서도 전송 0회. HTTP 429·연결 오류·타임아웃·큰/잘못된 응답은 1회 소비, 민감 sentinel은 오류/저장 메타데이터/진단 로그에 없음. 예약 저장 실패는 전송 0회.
5. 모의 실제 계획 생성 1회→계획 사용자 승인→두 역할 실행/승인 대기/재개가 공통 예산 총 3회를 사용. 후속 요청 본문에 선행 TASK-001 전달 확인.
6. 독립 업무 3개에서도 한 시작은 2개만 처리. 실제 경로의 타임아웃 후 기존 결과 보존·다음 자동 진행에서 재시도 없음. 같은 프로젝트 중복 실제 시작은 409와 전송 1회.
7. 리다이렉트 핸들러가 다른 호스트로의 자동 이동을 허용하지 않음. 테스트 transport와 기본 실제 네트워크 경로 모두 통제됨.

```text
python -B -m unittest discover -s tests
```

최종 전체 안전 회귀 **1회 실행**: **Ran 138 tests, OK (skipped=1)** → **137개 통과, 브라우저 1개 건너뜀**. 종료 코드 0까지 확인했다. 기존 M1 완주·Markdown 다운로드·품질 HTTP·수정 예약·사용자 승인·최종 보관·무료 모델 제한 포함. Playwright 부재로 브라우저 미검증 조건은 M4에 남긴다. 실데이터 경로가 격리되지 않은 함수형 `tests/test_smoke.py`는 별도 실행하지 않았다. 미해결 실패·충돌 없음.

모든 새 저장은 TemporaryDirectory의 projects/artifacts이며 API 응답은 가상 Response/실패 fixture다. 실제 전송 함수를 mock으로 대체하고 build_opener를 금지했다. 전체 회귀의 기존 HTTP는 loopback만 사용했다. 실제 OpenRouter/OpenAI API 요청 **0회**, 실제 키/비밀 설정 파일 접근 **없음**, 유료 서비스/외부 의존성 설치 **없음**. 기존 사용자 JSON·결과·스냅샷·백업·미추적 파일은 보존하고 Git에 포함하지 않는다.

## 안전 한계와 M3 인계

- M2는 안전 경계와 모의 전송으로 실제 실행 준비를 검증했다. 실제 계정·무료 라우팅 가용성·응답 품질·과금 상태를 확인한 것은 아니다. 실제 전송 동의 부여/활성화 관리 화면도 이번에는 만들지 않았으며 M4에서 구체적인 승인 범위를 확인해야 한다.
- 예산·중복 보호는 단일 프로세스의 앱 POST 잠금, 최신 프로젝트 객체, 신뢰할 수 있는 저장 콜백을 전제로 한다. 외부 JSON 편집/직접 카운터 삭제·다중 서버 프로세스·전원 장애 내구성·exactly-once는 보장하지 않는다. 임의 Python 코드가 표준 라이브러리로 직접 네트워크를 여는 것까지 격리하는 샌드박스도 아니다.
- 예약은 전송보다 먼저 저장하므로 중단 때 실제로 요청을 못 보냈어도 1회 소비될 수 있다. 완료 여부가 불명확하면 안전하게 차단하며 예약 확인·해제/예산 증액·새 주기 UI는 없다. 제공자 성공 뒤 저장 오류가 나면 응답이 유실되고 예약이 남을 수 있어 자동 재전송하지 않는다.
- 현재 승인 기록은 프로젝트 목표 지문과 전송 자료 종류를 식별한다. M4 전에는 실제 사용될 목표/자료/횟수를 사용자에게 구체적으로 보여주고 별도 승인해야 한다. 테스트의 가상 동의를 실제 승인으로 전용하지 않는다.
- 형식/구조 파싱 오류가 없는 응답도 실제 의미 품질을 보장하지 않는다. M3는 의미 검토 결과 계약·대상 지문·사용자 수정 확인·수정/재검토 제한을 이 공통 전송과 동일 프로젝트 예산에 연결해야 한다. 기존 mock 수정 권한을 실제 엔진으로 풀거나 별도 비예산 전송 경로를 만들지 않는다.
- 실제 품질 검토/수정 경로·목표별 프롬프트 정리·실제 목표 종단 실증은 M3/M4 범위로 남긴다. 이번 실제 시작은 기존 승인 경계에 정지하며 사용자 승인을 자동화하지 않는다.

`git diff --check` 통과. 보고서 동일 경로가 없음을 확인한 뒤 작성했으며 저장 후 재독하고 의도한 파일만 staged diff로 확인한다. 관련 코드/테스트/README/이력/보고서 **13개 파일만** 커밋·푸시하고 원격 SHA와 보고서 존재를 확인한다.
