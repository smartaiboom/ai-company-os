선행 결과 또는 상태 변경 시 모든 뒤쪽의 진행 중·완료 업무를 재검토 대상으로 바꾼다. 실제 의존 관계만 따라 무효화하는 방식은 아니다. 구형 데이터는 입력명 매칭으로 연결을 추정하며, 연결이 누락된 의미상의 의존성을 코드가 알아낼 수는 없다. 새 계획은 ID 형식을 검증하지만 의존성의 의미적 완전성은 검증하지 않는다.

## 실제 모델 연결과 비용 안전

- 기본 `AI_ENGINE=mock`은 외부 호출 없이 고정된 역할별 텍스트를 생성한다.
- 실제 엔진은 `AI_ENGINE=openai_compatible` 또는 호환 별칭일 때 선택하며, 설정한 기본 주소의 `/chat/completions`에 요청한다. 계획과 업무 실행 모두 `validate_openrouter_free_model`로 모델이 정확히 `openrouter/free`인지 검사한다. 누락·다른 값이면 요청 전에 중단한다. 유료 모델 fallback은 확인되지 않는다.
- 실제 엔진은 생성자에서, 계획기는 요청 구성 전에 검사한다. 엔진 인스턴스의 공개 model 속성을 생성 후 바꾸는 직접 사용까지 방어하는 구조는 아니므로 향후 변경 시 요청 직전 재검증을 검토할 수 있다. 현재 앱의 일반 경로는 요청마다 엔진을 생성한다.
- 모델 ID 제한과 별개로 기본 URL의 호스트는 강제하지 않는다. 이번에는 환경 변수의 실제 값·제공자 연결·계정 과금 상태를 확인하지 않았으므로 이 코드만으로 임의 외부 제공자의 비용까지 보장할 수 없다.
- 빈 응답·잘린 응답·안전 판정 문구만 있는 응답 등을 오류 처리한다. 이는 업무 품질이나 사실 검증을 대신하지 않는다. HTTP 오류의 제공자 응답 일부와 일부 계획 응답 미리보기를 오류에 넣는 경로가 있어 외부 응답의 민감 정보 처리도 후속 검토 대상이다. 이번 조사에서 해당 요청은 실행하지 않았다.
- 관리자 화면의 '모의 관리자/외부 호출 없음' 문구와 README의 초기 설명은 실제 엔진을 설정할 수 있는 현재 코드와 어긋난다. 사용자가 실행 모드와 외부 전송 여부를 정확히 인지하도록 정리할 필요가 있다.

## 위험과 다음 개발 우선순위

1. **우선: 실행 모드와 외부 전송 안내의 정확성.** 실제 요청 경로가 있는데 화면이 항상 외부 호출 없다고 안내한다. 가장 작은 다음 작업으로 관리자 안내를 엔진별로 표시하도록 수정하고 README의 실행 모드 설명을 맞추기를 권고한다. 완료 기준: mock은 외부 요청 없음을, 실제 모드는 `openrouter/free` 사용 및 목표·입력·선행 결과 외부 전송을 명확히 표시한다. 키·인증 값은 표시하지 않는다. 두 모드 HTML을 모의 테스트로 검사하고 기존 무료 모델 제한 테스트가 통과해야 한다. 실제 API 호출 없이 완료할 수 있다. 이번에는 구현하지 않았다.
2. **다음: 서버 중복 실행·동시 저장 보호.** 다중 탭 요청에서도 같은 결과가 두 번 생성되거나 승인 상태가 유실되지 않도록 실행 식별자·동시성 제어 설계가 필요하다. 임시 JSON 및 지연 mock으로 동시 요청과 오류 복구를 검증하는 것이 완료 기준이다. 자동 실행 추가 전에 해결해야 한다.
3. **다음: 승인 경계를 유지하는 최소 실행 조정.** 실행 가능한 업무를 결정하고 승인 대기·실패에서 멈추는 mock 전용 흐름부터 도입한다. 사용자 명시적 실행 요청, 실제 API 자동 호출 금지 원칙을 유지한다. 계획 승인→실행→검토 대기 정지→승인 후 다음 업무, 실패 시 기존 결과 보존을 격리 테스트로 입증해야 한다.
4. **다음: 최종 결과 확정과 보관.** 마지막 결과의 검토/수정 절차 및 보고서의 승인 대기 표시, 확정 시점의 버전·입력 출처 연결이 필요하다. 미승인 결과를 최종 완료로 오인하지 않고 변경 후 재승인이 필요함을 테스트로 입증한다.
5. **후속: 실질적인 직원 도구와 품질 판정.** 조사 출처·수집 시점, 개발 산출물 실행 검증, 구조화된 검토 판정과 제한된 수정 횟수를 단계적으로 추가한다. 자율 조정에 앞서 안전한 실행 경계와 승인·실패 규칙이 전제다. 유료 서비스나 실제 API 검증은 이번 범위가 아니다.

## 확인 명령·변경 범위·미해결 사항

- `git status --short`, `git branch --show-current`, `git diff --stat`, `git diff --cached --stat`, `git rev-parse HEAD`, `git rev-parse origin/main`: main, 위 기준 SHA 일치, 기존 추적 파일 변경 및 staged 변경 없음 확인.
- `git pull --ff-only`: 처음 샌드박스에서 FETCH_HEAD 읽기 전용 오류. 승인된 재실행은 c0ba461→464fea6 fast-forward 성공. 원격 지시 파일 2개 및 next_step 갱신을 받았다. 로컬에서 이 파일들을 작성·수정한 것은 아니다.
- `rg --files`, `rg -n`, `cat`, `sed`: AGENTS, 작업 지침·이력, 운영 코드 3개, 기존 테스트 및 관련 보고서를 읽었다. 환경 비밀 파일·기존 업무 JSON 본문은 읽지 않았다.
- 동일 보고서 경로의 로컬 파일 및 origin/main 파일이 없음을 확인한 뒤 새로 작성했다.
- 신규 산출물: `reports/ai_company_os_current_state_audit_20261102.md` 하나. 운영·테스트 코드, 기존 보고서, next_step, task_history, 사용자 데이터·백업 변경 없음.
- 기존 미추적 파일(상위 폴더 파일·기록 및 로컬 감사 문서 포함)은 보존하고 스테이징 대상에서 제외한다.
- 보고서 재독 및 `git diff --check` 검증 후 보고서 하나만 커밋·푸시한다. 최종 SHA와 원격 파일 일치는 완료 응답에서 확인한다.
- 미해결 사항은 위 위험 및 미검증 범위이다. 이번 실행한 테스트 실패는 없으며 실제 AI API 호출도 없다.
