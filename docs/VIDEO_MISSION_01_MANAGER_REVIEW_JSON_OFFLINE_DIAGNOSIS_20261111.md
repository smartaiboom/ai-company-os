## 이번 작업의 엄격한 범위

1. `AGENTS.md`, 위 결과 보고서, `companies/video/video_mission_one.py`의 `_manager_selection`/검토 계약 및 관련 `core/` 역할 응답 정규화·검증 코드를 중심으로 확인한다.
2. 로컬에 남은 3번째 실제 응답의 **승인 범위 내** 구조/필드, 모델 결과 원장, 실패 단계의 원인 예외를 대조한다. 민감한 원시 대화/키/헤더/전체 메타데이터 또는 개인 자료를 공개 보고서에 복제하지 말 것. 응답 원문이 로컬에 저장되지 않았다면 **없다고 명시**하고 SHA·상태·비밀값 없는 오류 정보로 확인 가능한 범위까지만 진단한다. SHA가 같아도 원문 복원은 불가능하다.
3. `invalid_model_json` 발생 경로를 분리한다: (a) 실제 JSON 문법 오류, (b) 바깥 래퍼/역할 응답 구조 차이, (c) 내부 검토 `feedback`의 기대 형식·필드 불일치, (d) 유효한 모델 출력에 비해 검증 계약이 지나치게 엄격한 경우. 각각 실제 증거를 갖고 단정하거나 확인 불가로 표시한다.
4. 원인과 **필요한 최소한의 수정 범위**를 밝힌다. 기존 검증/서명/소모 원장/실패업무를 임의 완화·수정하지 않는다. 재발 방지용 오프라인 fixture가 실물 자료를 정확히 재현할 수 있다면 추가·수정하고 관련 단위 테스트만 수행한다. 실물 응답을 볼 수 없다면 임의 fixture를 실물 재현으로 주장하지 않는다. 이번 단계는 진단 위주: 제품 코드 변경이 꼭 필요하지 않으면 보고서만 작성.
