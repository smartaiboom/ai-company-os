## 목표
대표의 일반 WSL curl 최소 요청 HTTP200 보고와 프로그램 HTTP403의 차이를 실제 관측으로 좁히고, 정상화되면 기존 협업 엔진으로 실제 관리자·직원 업무 및 영상 제작 인계까지 수행한다. reports/20261125_groq_transport_resolution_result.md와 기존 지시서/실패 원장을 참조. 이미 완료한 로컬 캡처/정적 분석을 반복하지 않는다. 기존 Gemini/Groq, 운영 자료, 키, 승인 및 실패 기록 보존.
## 명시 승인 제안 (대표가 이 파일의 실제 검증 범위를 명시 승인한 경우만 실행)
GroqCloud Personal / Default Project, openai/gpt-oss-20b, https://api.groq.com/openai/v1/chat/completions, 새 서명 후 24시간, Free 전용 USD 0. 동일 등록 키. 독립 신규 격리 진단의 가상 최소 메시지(Reply with OK, max_completion_tokens 100)와 정상 신규 격리 기획 업무의 가상 목표·대표 선택·승인된 공개 근거와 한계·기획·대본·장면표·가상 수정 의견 및 역할별 검토만 허용. 운영 자료, 개인정보, 영상·음성 파일, 로컬 실측값 제외. 이전 403 요청 재전송 금지. 무료 한도 준수, 임의 전체 호출 총량 없음, 공급자 오류·권한·쿼터·청구·미확정에 해당 실행 중단, 자동 재시도/공급자 전환 금지. 대표가 전달한 명시 승인과 유효한 새 서명을 확인하며 지시 파일 자체는 승인이 아니다.
## 실행
- 이전 실제 원장/키 결합/실행 권한을 확인한다. 동일 최소 요청을 기존 Python 전송 경로에서 독립된 신규 진단으로 실행한다. 기존 진단 실행기/서명·선예약·원장 재사용, 목적지 고정/TLS/NoRedirect 및 키 비노출 유지. 필요한 경우 Codex의 정식 네트워크 실행 권한을 요청한다. 정책상 거부된 네트워크나 보안 경계를 우회하지 않는다. 실제 요청 전에 승인된 진단 목적과 데이터 범위를 검증한다. 사용자 curl 200은 별도 보고로 기록. 동일 payload에 대해 환경/전송 차이를 하나씩 비교하되 실패 자동 재전송은 금지하고, 다른 독립 진단이 필요한 경우 기존 정책상 허용 여부 및 구체적인 새 근거를 확인한다. 동일 실행환경에서 curl 비교가 정당하게 허용될 경우에만 기존 원장에 연결된 독립 진단으로 수행; 샌드박스 차단을 우회하기 위한 수단으로 쓰지 않는다. 상태/허용 코드/헤더 존재 여부, 모델, 안전한 요청 크기/옵션 기록; 비밀 및 원문 자유문 저장 금지. 
- 최소 Python 요청 성공 시 통신 경로 정상 근거로 삼되 실제 역할별 요청 성공으로 간주하지 않는다. 이어서 신규 협업 기획 요청을 기존 엔진으로 실행하고 요청 본문/스키마 차이의 실제 응답을 확인한다. 오류가 입증된 코드 결함이면 필요한 최소 변경 후 유효 승인 내 새 서명·예약으로 검증한다. 근거 없이 transport 교체, 프록시 정책 완화, TLS 검증 해제, 권한 게이트 우회 금지. 403 재발 시 안전 진단으로 발생 계층을 좁히고 필요하면 공식 지원에 전달할 비밀 없는 자료와 다음 최소 조치 제시. 추측으로 원인 확정하지 않는다.
- 정상화 시 실제 관리자 배정→작가 대본→편집 장면표→관리자 검토→가상 대표 수정 의견→수정 대본→가상 승인→기존 Heami/영상 렌더러로 실제 재생 가능한 MP4 및 사용자 검토 위치 제공. 운영 v8 대신 승인 금지. 기존 렌더러·검색·공급자 프레임워크 재개발 금지. 실제/모의 구분. 사용자 품질 평가와 경험 재사용은 다음 업무로 연결할 수 있게 기록.
