# 미션 01 편집 인계 진단 및 복구 (2026-11-18 KST)

## 운영 진단

16:05:29 KST에 기존 35초 대본의 관리자 재검토가 완료되고 대본이 수락됐다. 16:05:35 KST의 편집 요청도 HTTP 200과 `json_parsed`까지 기록됐으나 `script_editor_handoff_mismatch`로 중단됐다. 편집 버전과 응답 원문은 저장되지 않았다. 어느 필드가 달랐는지 확인할 수 없다. 기존 대본 검토의 응답 해시와 검토 대상 대본 해시는 저장된 결과와 일치했다.

전송 직전 요청 생성 경로를 읽기 전용 운영 복제본으로 실행했다. 네트워크와 저장을 막은 상태에서 재구성한 47,715바이트 요청의 컨텍스트·요청 해시가 원장과 일치했다. 원래 편집 요청에는 승인 대본 전문과 `handoff_refs[].result_hash`가 있었다. 이 값은 기대 산출물의 `writer_ref.result_hash`와 일치했다.

편집 직원에게는 샷별 내레이션·자막·화면·소스 상태 정리와 자막 규격, 복수 게임 소개, 미검증 주장 검토가 주어졌다. 반환 계약은 `contract`, `writer_ref`, 네 장면의 `shots`를 승인 대본에서 투영한 객체와 **완전히 동일**해야 했다. 창의적으로 장면을 바꾸면 계약을 벗어난다. 이 경로에서 정확한 복사와 해시 구성에 AI 호출을 사용할 이유가 없었다.

## 복구 구조와 역할

- 확인된 중단 작업에 한해 새 작업을 준비할 수 있다. 이전 전송의 완료·HTTP 상태, 단계, 세션, 해시, 중단 이유와 서명을 검증한다. 수락된 대본 및 관리자 검토 기록을 그대로 가져온다. 미확정 전송은 복구 대상에서 제외한다.
- 기존 `script_editor_handoff`로 시스템이 스토리보드와 `writer_ref`를 생성한다. 스토리보드 계약이 요구하는 장면 필드를 변경 없이 투영하며 대본 원문과 사실 상태 등 원본 자료는 보존한다. 산출물 출처는 `deterministic_system`, 생성 주체는 `system`이다. 생성에 API를 쓰거나 AI 직원 작업을 원장에 추가하지 않는다. 기존 전체 객체 일치 검증과 투영 해시 확인을 유지한다.
- 새 서명 동의 범위는 **Gemini 관리자 검토 1회, 수정 0회**다. 실제 판단은 관리자에게 맡긴다. 장면 구성의 편집 가능성, 구체성, 주장에 대한 근거를 검토하고 수락하면 기존 대표 기획 승인 대기로 제출한다. 검토에 실패하면 중단한다. 창의 연출 생성이나 자동 재시도는 이 복구 범위에 포함되지 않는다.
- 이전 복구 흐름은 관리자 대본 검토 → 편집 직원 호출 → 관리자 편집 검토 순으로 수락 경로에 3회가 필요했다. 현재 복구는 이미 완료한 대본·검토를 보존하고, 로컬 투영 → 관리자 편집 검토 1회로 진행한다. 기계적 편집 호출 1회 및 완료된 검토의 반복을 줄인다. 다른 재작업의 기존 승인 범위와 이전 실행 기록은 그대로 유지한다.

## 대표 다음 조작

기존 컷룸 프로젝트를 새로고침한다. **편집 인계 중단 · 스토리보드 검토 → 스토리보드 관리자 검토 준비**에서 무료 조건을 확인하고 제안을 준비한다. 이어 **새 외부 전송 동의 → 이 범위에 동의 → AI 재작업 시작**을 각각 선택한다. 준비와 동의 저장만으로 실행되지 않는다.

## 검증

- 핵심 통합 및 컷룸 테스트 **101개 통과, 실패·오류 0개**였다. JavaScript 문법 검사와 `git diff --check`도 통과했다.
- 실제 승인 대본과 관리자 검토를 메모리 복제본에 보존하고 기존 검증기가 수락하는 동일 투영, 생성 주체, 대본 참조 해시, 관리자 `review` 요청을 전송 직전까지 확인했다.
- 모의 HTTP 통합에서 완료되지 않은 전송과 승인 검토 변조의 복구 차단, 원본 및 기록 보존, 새 동의 전 실행 및 중복 시작 차단, 기계적 산출물의 위장 차단, 관리자 리뷰 1회와 기획 승인 대기 연결을 확인했다. 관리자 수정 요구가 추가 호출 대신 중단되는 분기도 확인했다.
- 실행 중 요청이 없음을 확인하고 기존 환경과 작업 루트로 운영 컷룸을 재시작했다. 실제 로컬 상세 API와 JavaScript가 HTTP 200을 반환했고, 운영 중단 작업에서 복구 준비가 가능한 상태를 확인했다. 운영 프로젝트·원장·동의 JSON은 바이트 단위로 동일했다. 브라우저 클릭과 실제 모델의 판단 품질은 검증하지 않았다.
- 기존 누적 Gemini **19회**, YouTube **4회**를 보존했다. 이번 작업에서 실제 API 호출, 대표 결정 및 외부 전송 동의 생성은 모두 **0회**였다.
