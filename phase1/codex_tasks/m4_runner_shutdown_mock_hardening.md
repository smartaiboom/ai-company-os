# M4 테스트 실행 도구 종료·시간 제한 보강 — 모의 검증만

## 근거
reports/v01_m4_real_free_ai_acceptance_20261102.md의 '예약/타임아웃 진단'에 따르면 기존 프로젝트 c85d9853906a의 plan 예약 1건은 reserved, 1/7 소모이며 외부 처리 완료 여부 미확인. ThreadingHTTPServer의 daemon 요청 스레드가 client timeout 후 종료 대기에서 제외되어 프로세스가 종료될 수 있음. urllib timeout 45초는 전체 wall-clock 마감이 아님. 이전 진단 테스트 3+2 통과.

## 이번 목표
기존 M4 테스트 실행 도구의 **서버 종료·요청 스레드 대기·시간 구간 관측·실패시 예약 보존**을 모의 환경에서 재현 가능하게 보강한다. 신규 실제 API 호출 금지. M1~M3 및 운영 앱 기능 재설계 금지. Codex 사용량 절약.

## 절차
1. git status, 기존 보고서의 최신 진단 섹션, 관련 테스트 실행 코드 및 ai_safety.py 경로만 확인. 임시 /tmp/m4_direct_approval_runner.py가 존재하면 읽되, 원본과 기존 업무 데이터는 보존. Git 제외 JSON 원본/복제본을 변경하지 않는다.
2. 실제 API를 전혀 호출하지 않는 재사용 가능한 **작은 테스트 하네스** 또는 기존 테스트 내 최소 보강을 한다. ThreadingHTTPServer shutdown/close 이후 요청 처리 스레드가 종료되었는지 확인하고, 제한 시간 내 종료하지 않으면 **프로세스 강제 종료나 예약 상태 변경 없이** 안전하게 '완료 불명'으로 표시하는 정책을 명시한다. daemon_threads/블로킹 종료/외부 호출의 wall-clock 제한의 트레이드오프를 설명한다. 단순히 client timeout을 늘리는 것만으로 해결했다고 주장하지 않는다.
3. 요청 단계별 KST 시간·경과 시간 관측은 비밀/프롬프트/응답 본문 없이 상태·구간만 기록. 가능하다면 모의 지연 transport로 정상 완료, transport 실패, 클라이언트 먼저 timeout, 종료 시 미완료 예약의 4가지 시나리오를 검증한다. 네트워크 차단/모의 transport로만 실행한다.
4. 실제 공급자 호출 0회, 기존 reserved 1건 재전송/failed 강제 변경/예산 초기화/새 프로젝트 생성 금지. /tmp 및 data/m4_acceptance_preserved 원본 보존. 기존 승인만으로 새 호출을 시작하지 않는다.
5. reports/v01_m4_real_free_ai_acceptance_20261102.md에 '테스트 실행 도구 보강' 결과·테스트 수·확인된 한계·M4 미완료·다음 한 단계 추가. 테스트 하네스 파일을 만들었다면 안전하고 작은 코드만 선택적 커밋, 기존 미추적 파일·실제 데이터·비밀은 제외. git diff --check, GitHub push.
