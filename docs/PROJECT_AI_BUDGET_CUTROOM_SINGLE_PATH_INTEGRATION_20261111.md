## 사용자 정책
대표가 결정한 새 운영 방식은 임의의 일률적 고정 호출 상한이 아니라, **프로젝트마다 AI 관리자 견적 → 대표 초기 승인 → 승인 범위 내 자유 진행 → 부족 시 중복 없는 추가 승인 요청 → 대표 승인 후 이력 보존형 진행**이다. 승인된 예산만 집행하고, 무료 전용·외부 데이터 전송 동의와 예산 승인은 구별한다. 이 작업에 대한 승인은 **코드 구현 및 네트워크 차단 오프라인 검증**에 한정된다. **실제 Gemini/YouTube API 호출 또는 기존 미션 01 재개 승인 아님**.

## 이번 작업의 하나의 완료 목표
신규 영상 프로젝트 **한 경로**에서 관리자 예산 견적/추가 요청과 컷룸의 대표 승인·거절 동선이 실제 예산 원장의 승인·차감 안전 가드로 이어지는 동작을 **종단 간 오프라인으로 검증**한다. 전 분야 전체 적용, 별도 새로운 컷룸 화면 리디자인, 큰 구조 변경, 토큰·비용 계측, 기존 미션 이관은 하지 않는다.

## 구현
1. 현재 코드의 컷룸 웹 라우팅/기존 대표 승인 동선/기존 실제 provider 호출 진입점과 예산 어댑터의 연결 부분만 확인한다. 이미 존재하는 예산 견적·승인·거절 기능을 복제하지 않는다. 적용 지점은 새 프로젝트에 한정된 **명시적 opt-in**으로 시작해 기존 운영 프로젝트의 동작을 바꾸지 않는다.
2. 컷룸 화면에서 권한이 있는 대표가 새 프로젝트의 자원별 승인량/소모/잔여/불명 상태, 미결 요청의 프로젝트·scope·증액량·사유·작업계획/해시·무료 및 데이터 처리 조건을 확인한 뒤 **승인 또는 거절**할 수 있도록 기존 UI에 최소 연결한다. 승인 버튼은 실제 원장 이벤트와 일치해야 하며 표시만 바뀌는 모의 승인 금지. 중복 제출·위조·만료/해시 불일치 차단. 기존 역할 승인과 예산 승인은 구분한다.
3. 공급자 동의·고정 모델·계정/무료 사용 범위·API 키 바인딩·데이터 처리 scope 검증은 기존 provider의 실제 가드에 연결한다. `verify_consent=lambda: True`와 같은 자리 채우기 금지. 예산 승인만으로 외부 호출이 가능해져서는 안 된다.
4. 관리자는 작업계획을 근거로 최초 필요량/추가량을 **제안**할 수 있고, 전송 전에 예산이 부족하면 실제로 차단되고 요청이 컷룸 대표 검토 목록에 1건만 나타나야 한다. 승인되면 동일 project/operation 범위에서 이전 소모 기록을 보존하며 계속 진행할 수 있어야 한다. 불명·예약/장애 중 중복 재전송은 여전히 차단하고 자동 재시도 불가.
5. 단일 영상 실행 경로에 대해서만 기존 send 진입점 앞에 `BudgetedVideoTransport`를 연결한다. 추론·조사·영상 제작을 실제 API로 수행하지 말고 임시 격리 프로젝트 + 네트워크 차단된 **합성 fixture**를 사용한다. 기본 provider 경로에 연결되지 않은 경우 이 경로를 '운영 배포 완료'로 표시하지 않는다.
6. 표적 오프라인 통합 테스트: 관리자 요청→대표 승인→실제 send **모의** 콜백의 사전 예약·차감→예산 부족/중복 요청→대표 증액→계속 처리, 대표 거절, 기존 provider 동의 철회·범위 변조 차단, 인증되지 않은 승인 요청, 동시성·중복 실행, 불명 요청/실패 소비, 미션 01 불변. 대규모 회귀 반복하지 않는다. UI 버튼 동작을 최소 1개의 실제 HTTP 라우트/폼 테스트로 검증하고, 헤드리스 브라우저가 이미 있으면 해당 경로에 한정해 활용한다. 합성 데이터의 실제 결과 위장 금지.
7. 범위 내에서 기술적으로 구현이 어려운 경우, 제품 기능을 위해 임의로 안전 가드 완화하지 말고 **작동하는 최소 완결 단위**만 구현하고 통합 미완료를 명시한다. 기존 미션 01의 대상·호출 소모·서명/시도·active_operation·컷룸 상태/기획·조사 및 기존 영상·음성·키·백업·미추적 파일을 건드리지 않는다.
