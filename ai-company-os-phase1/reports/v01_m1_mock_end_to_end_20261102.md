## 판정

**M1 구현·통합 검증 완료(지시서가 허용한 HTTP/HTML 대체 적용).** 하나의 임시 프로젝트에서 목표 입력부터 mock 품질 수정 1회, 추가 승인, 최종 확정·보관, Markdown 다운로드까지 실제 loopback HTTP로 완주했다. 브라우저 클릭·모달·다운로드 조작은 환경 부재로 미검증이며 M4 웹 인수 조건으로 남긴다. 실제 모델 v0.1 완료를 의미하지 않는다.

## 구현과 변경 파일

- `app.py`: 기존 확정 검증을 `load_confirmed_snapshot`으로 공유하고 화면/다운로드가 같은 성공·입력 맥락·승인·참조·파일 해시·근거 지문·버전 일치를 확인한다. 보관 경로의 resolve 결과가 artifacts 루트 안인지 검사한다.
- `GET /report/{project_id}/download/v000001.md`: 검증된 ID와 정규 버전만 받는다. 현재 유효한 확정 버전만 제공하며, 미확정/무효/누락/손상/다른 버전/경로 조작을 거절한다. 프로젝트 잠금 아래 조회·검증·렌더링하여 변경 중인 요청과 경합하면 409로 안내한다. 파일 쓰기는 없다.
- `confirmed_markdown`: 저장된 JSON의 목표·관리자 목표(다른 경우)·업무 ID/이름/역할/선행 ID/결과·확정 버전·KST를 사람이 읽는 Markdown으로 만든다. 본문은 길이를 조절한 코드 펜스 안에 원문을 보존하여 업무 내용의 Markdown/HTML을 새 실행 지시나 태그로 사용하지 않는다. 키/환경 변수/불필요한 내부 경로·실행 메타데이터는 추가하지 않는다.
- 상세·보고서 화면에 유효할 때만 'Markdown 확정본 다운로드' 링크를 표시하고, 그렇지 않으면 확정 후 다운로드 가능 안내를 표시한다. 응답은 UTF-8 text/markdown, attachment, Content-Length, no-store, nosniff를 사용한다.
- `tests/test_v01_m1_end_to_end.py`: 신규 HTTP 통합/집중 테스트 6개. 기존 격리 서버/클라이언트를 재사용하고 사용자 프로젝트 생성 POST부터 시작한다.
- `README.md`: mock 협업·사용자 승인·수정 1회 및 확정본 다운로드 사용 안내 추가.
- `codex_tasks/task_history.md`: M1 완료 및 브라우저 한계 기록.
- `reports/v01_m1_mock_end_to_end_20261102.md`: 이 보고서.

AI 엔진·무료 모델 제한·결제·실제 모델 자동 진행은 변경하지 않았다. M2/M3/M4 기능은 구현하지 않았다. 기존 모달·폼 처리 코드는 유지하고 링크/읽기 전용 다운로드만 추가했다.

## 단일 종단 흐름의 실제 증거

새 임시 프로젝트 하나에서 다음을 순서대로 처리했다.

1. POST /create로 목표 '재고 확인 업무 개선 제안'과 프로젝트를 생성하고, /manager/plan 및 /manager/approve로 mock 4단계 계획을 승인했다.
2. /workflow/run으로 TASK-001을 실행해 승인 대기 정지한 뒤 사용자가 승인했다. 재개한 TASK-002의 previous_results에 TASK-001 ID와 승인된 실제 fixture 본문이 전달됨을 확인했다.
3. TASK-002의 제목이 부족한 초안을 /quality/review로 changes_needed 판정했다. /quality/revise-once로 같은 콘텐츠 제작 담당 역할에 누락 항목 피드백을 전달했다.
4. 수정 실행과 재평가가 각각 1회임을 확인하고 새 result_revision=2/pass를 저장했다. 중복 수정 POST는 거절됐다. 사용자 승인 없이 /workflow/run을 다시 요청해도 추가 실행 없이 정지했다.
5. 사용자가 TASK-002를 승인하고 재개하자 TASK-003에 수정된 전체 결과 본문이 전달됐다. TASK-003 사용자 승인 후 TASK-004를 실행했다. 최종 pending에서는 다운로드 409이며 사용자 최종 승인을 별도로 받았다.
6. v000001.json 확정 후 Markdown GET 200, attachment/UTF-8/no-store 헤더, JSON의 프로젝트·목표·업무별 결과·확정 버전·KST가 내려받은 내용과 일치함을 확인했다. 상세/보고서 링크도 확인했다.
7. 화면 및 다운로드 GET 전후 프로젝트 JSON과 보관 파일의 바이트가 같음을 확인했다. 내부 artifacts 경로·환경 변수 이름·execution_context는 다운로드에 포함하지 않았다.

업무 내용의 개선은 테스트가 명시적으로 공급한 초안/수정 fixture다. 일반 mock 엔진이 의미를 이해해 개선한다고 주장하지 않는다. 형식 pass는 사용자 승인이나 사실성 검증을 뜻하지 않는다.

## 실행 명령과 정확한 결과

```text
python -B -m unittest tests.test_final_report_approval tests.test_quality_revision_once tests.test_project_ui
```

검증 helper 추출 직후 tasks 지역 변수 누락으로 29개 중 8개 오류가 발생했다. 해당 누락을 수정한 동일 명령 재실행은 **29개 통과**였다.

```text
python -B -m unittest tests.test_v01_m1_end_to_end
```

초기 6개 중 4개는 테스트가 여러 줄 본문을 리스트 repr 문자열과 비교해 실패했다. 실제 previous_results의 result 값 목록과 비교하도록 테스트를 바로잡았다. 동일 명령 최종 실행은 **6개 통과 (OK)**였다. 실제 전달 본문을 직접 검증하며 기대값을 완화하지 않았다.

```text
python -B -m unittest discover -s tests
```

최종 **Ran 125 tests, OK (skipped=1)** → **124개 통과**, Playwright 부재로 기존 브라우저 테스트 **1개 건너뜀**. 관련 품질 HTTP·최종 확정·수정 예약·자동 진행·동시성·무료 모델 제한의 기존 회귀 포함. 미해결 테스트 실패 없음. `tests/test_smoke.py`는 실제 저장 경로가 격리되지 않은 함수형 테스트이므로 별도 실행하지 않았다.

전체 실행은 장기 프로세스 세션 60787의 종료 코드 0과 최종 결과까지 확인했다. `git diff --check` 통과. 보고서/작업 이력은 저장 후 재독하고 staged diff를 확인한다.

## 데이터 격리와 실제 호출 여부

TemporaryDirectory의 projects/artifacts만 사용하고 loopback 임의 포트 서버를 실행했다. 계획/실행 AI urlopen은 호출 시 실패하는 mock이며 테스트 종료 시 미호출을 확인한다. 역할별 실행 결과도 고정 fixture로 공급했다. 기존 업무 JSON·업무 결과·스냅샷·백업·기존 미추적 파일을 수정·삭제·스테이징하지 않았다. 테스트의 파일 변조는 전부 일회용 임시 fixture다.

실제 AI API 호출 **없음**, 외부 AI 제공자·유료 모델·결제 변경 **없음**, 실제 비밀 키 조회/출력 **없음**. 새 외부 의존성 설치 **없음**. 네트워크는 loopback 검증과 사용자 요청의 Git 원격 동기화/푸시뿐이다.

## 브라우저 환경·한계

Python에서 Playwright 탐색 False, chromium/chromium-browser/google-chrome 경로 None, 과거 /tmp/review_approval_browser_env와 기본 Playwright 캐시가 없음을 확인했다. `python -m pip cache list`도 현재 계정의 기본 pip 캐시 권한/소유 제한으로 사용할 수 없었다. 이는 테스트 실패가 아니라 환경 조사 결과다.

기존 선택 의존성은 playwright==1.64.1이며 과거 무료 환경 설치 기록은 있다. 그러나 현재 바이너리를 재사용할 수 없고, 기존 브라우저 보고서에는 OS 의존성 설치 67개 신규/14개 업데이트·약 299MB 추가 기록이 있다. 현재 설치 성공 가능성·네트워크/OS 의존성 상태를 보장할 수 없으므로 무리한 재다운로드·시스템 변경은 하지 않았다. 지시서가 허용한 HTTP/HTML 대체로 M1을 완료 처리한다.

실제 브라우저 클릭·모달/버튼 상태·409 시각 안내·다운로드 대화상자/파일 저장은 미검증이다. M4 실제 웹 인수의 열린 조건으로 명시하며 별도 독립 소형 작업을 계속 생성하지 않는다. 과거 브라우저 통과 결과를 이번 결과로 사용하지 않았다.

## 남은 M2 과제
