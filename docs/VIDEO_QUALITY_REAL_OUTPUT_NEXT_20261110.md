## 이번 묶음의 산출물 우선순위
### A. 사용자에게 보여줄 실물 MP4 — 최우선
1. 새 작업 폴더(기존 영상 폴더 절대 덮어쓰기 금지)에서 **새 60초, 9:16, 한국어 쇼츠 1편**을 실제 렌더해 `preview.mp4`, 최종 대본`script.md`, 샷플랜`shot_plan.md`, 자막 `captions.srt`, 개선 전후 비교 `evaluation.md`, media verification receipt를 저장한다. 결과 폴더는 `data/video_quality_iteration/<새KST폴더>/`처럼 별도 보존한다.
2. 기존 Flow 클립 3개는 권리 확인 전 새 시안에서 수동 참고만 사용 가능하며, 사용한 정확한 소스/해시/라이선스 미검증/워터마크 미확인/게시불가 상태 유지. 한 클립을 20초 동안 강제 반복해서는 안 된다.
3. **새 Flow 영상 10개가 있다고 가정하지 말라.** 기존 3개의 실제 움직임이 제한적이라면 직접 생성한 **영상의 설명 가치를 높이는 편집 장면**(로컬 텍스트 카드, 키워드 강조, 대화 전/후 비교, 프롬프트 타이핑 시각화, step-by-step UI mock 시연)으로 장면별 의미를 달리 하라. 화면 자체를 실제 ChatGPT 앱 녹화인 척하지 말고 `예시 화면`으로 명확히 표기. 위조된 실제 답변/성과를 꾸미지 말 것. 슬라이드·텍스트 장면의 과도한 반복도 피하고 실제 교육 정보가 읽히도록 시각적 완성도를 높인다. 가능하면 오픈소스 폰트/로컬 렌더 기법을 사용하되 신규 이미지·API·유료 서비스 호출 금지.
4. 한국어 대본은 초반 **3초의 구체적인 후크**, 영상 전체에 **핵심 메시지 한 가지**, 초보자가 그대로 따라할 **전/후 질문 예시와 실제 적용 방법**이 있어야 한다. 첫 20초 인사/공허한 소개 금지. 기존 `QUALITY_REVIEW.md`의 고정 fixture를 최종 대본으로 그대로 복사하는 것은 개선이 아니다. 사용자에게 유익한 내용을 새롭게 기획하고 스스로 비판·수정한다.
5. 음성: 기존 MeloTTS를 로컬에서 재사용할 수 있고 **새 로컬 합성이 비용 없이 허용되는 명백한 환경**이면 필요 최소 새 합성만 수행. 기존 음성을 새 대본에 부정확하게 끼워 맞추지 말 것. 새 음성 합성이 실행 불가한 경우, 기존 대본·음성에 맞는 영상 개선판을 먼저 완성하고 음성 제약/부족을 기록하라. 음성/자막 실제 싱크·발화 길이/재생 여부를 파일 기반으로 검사. 자연스러움의 청취 평가는 미확인으로 남긴다.
6. 기존 영상 합성기와 권리/출처 기록/ffmpeg/ffprobe를 재사용하고 필요 최소 코드만 추가. 소스가 없는 구간에 단순 반복 영상이나 가짜 'AI 출처' 표시하지 말 것. 실제로 완성 못하면 변명으로 mock 결과를 새 MP4라고 표시하지 말고 정확한 중단 원인 및 가장 작은 수동 입력 필요사항을 남긴다.

### B. AI Company OS의 판단 및 개선 능력 강화
- 인공지능을 실제 호출하지 않는 단계라도 **프로덕션에서 재사용할 수 있는** 영상 품질 검사/관리자 품질 피드백/직원 수정 인계/재검토 계약을 실제 제작 과정에 연결한다. 필수 결함: 의미 없는 장시간 인사, 초반 메시지 부재, 중복 source_id/원본길이 초과, 자막 너무 길거나 화면 초과, 미디어 출력 오류, 대본·음성 불일치, 불확실한 권리.
- 정량적 결함과 인간/실AI 의미 판단을 반드시 분리한다. Codex가 전문적 편집 판단을 한 것은 `Codex authored/offline editorial judgement`로 기록하고, AI Company OS의 자체 모델 판단 결과로 **절대 오인시키지 않는다**. 고정 fixture 변경만으로 제품 능력 향상이라고 과장하지 말 것.
- 새 대본 초안/수정안, 개선 지시, 장면계획 초안/수정안, 전후 결함 수와 근거, 여전히 부족한 항목을 각각 **실제 파일**에 보존한다. 개선 전후 새 영상이 없는데 실제 영상이 좋아졌다고 보고하지 않는다.
- 기존 Google 무료 모델 실 API는 실행 금지. 사용자는 무료/0원/단계적 테스트에는 동의했지만 **이 새 스코프의 정확한 호출·Google 무료 데이터 처리·계정 상태에 대한 개별 서명 승인은 아직 없음**. 현재 준비된 `MANAGER_PLAN_EXECUTION_ENABLED=False`, `QUALITY_TRANSPORT_ENABLED=False`를 해제하지 말 것. 외부 API 호출0회/유료 비용0원/외부 업로드0.
- 이미 완료된 provider 안전 개발을 반복·재설계하지 말 것. 진짜 모델 추론이 필요한 후속 1회/다회 승인 제안은 마지막 보고서에 구분한다.

### C. 사용자 가시성 및 결과 저장
- 새 시안의 경로를 `reports/CURRENT_PROGRESS.md`에 단계별로 요약(누가 판단했는가: Codex, deterministic 검사, 실제 모델)하고 사용자 평가 요청 상태 표시.
- `reports/VIDEO_QUALITY_ITERATION_RESULT.md`에 다음을 **반드시** 포함한다:
  - 기존 영상과 새 영상 **정확한 로컬 경로**와 실제 존재·재생/코덱 검사 결과. 시안 간 대본/샷/음성/반복/자막 차이, 측정 가능한 전후 지표(근거 없는 10점 감각 점수 금지), 미확인 사용권
  - 문제→판단 주체→수정 담당→전/후 결과의 인수 경로/증거, 실 AI 추론과 Codex 편집 구분
  - 사용자 Codespaces에서 파일을 쉽게 다운로드하는 절차(기존 폴더 대비 신규 preview 경로)와 평가해 줬으면 하는 2~3가지 핵심 질문
  - 미해결 품질 문제, 실제 AI 관리자·직원 능력에서 아직 부족한 것, 다음 제품 개발 우선순위
  - 테스트 실행/통과/skip, 렌더 횟수, 외부 호출0/비용0/기존 데이터 보존/게시 여부. 영상 미제작 시 필수 경로를 허위로 적지 말고 원인·가장 작은 후속 조치.
- 해당 신규 결과는 GitHub에는 **텍스트 보고서와 필요한 코드/테스트만** 올린다. 사용자 MP4/모델/비밀키/로컬 원본/실제 프로젝트 데이터는 GitHub에 푸시하지 않는다. 확인된 사실만 보고한다.
- GUI/대시보드/웹 화면 작업 금지. 사용자는 실물 영상이 유튜브 게시 수준에 도달한 뒤 GUI를 원한다.
