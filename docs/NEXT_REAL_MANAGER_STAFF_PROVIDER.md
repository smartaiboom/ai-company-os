# 다음 개발: AI 관리자·직원 실제 추론 연결 준비와 품질 평가 계약
작성일: 2026-11-10 KST

## 먼저 상태를 사실대로 인식
직전 결과 `reports/manager_staff_feedback_engine_result.md`: 오프라인/mock 관리자→직원 인계·계획 결함 검사·수정·경험 범위 선택을 구현. 전체 31개 발견, 최초 1실패 수정 후 최종 관련 테스트 통과(기존 전체 24개 통과 포함); 실제 외부 모델 추론0회, 새 영상0편, 10개 항목 감각점수 전부 unassessed. 대본 도입과 샷 계획 개선은 테스트 전용 **고정 fixture**이며 실제 AI가 만든 결과가 아님. 이 차이를 유지한다.

## 다음 묶음의 목적
기존 공통 엔진 `core/autonomous_company.py`, `core/quality_feedback.py`, `companies/video/quality_workflow.py`의 **실제 AI 모델 추론을 연결할 수 있는 안전한 경계**를 우선 완성한다. 특히 “AI 관리자와 AI 직원이 실제 모델을 사용하여 계획/대본/샷플랜/수정 지시를 결정”하는 경로가 필요하다. 개발 과정에서 외부 API를 승인 없이 실제 호출하거나 과거 Gemini 1회 인수 저장소를 재사용하지 않는다.

- 모델·provider 교체 가능한 역할별 스키마/프롬프트, 요청·출력 유효성 검사, 실제 호출 시 데이터 범위·계정 무료 여부·동의 게이트의 필요 변경사항을 문서로 정리한다. 비공개 정보가 모델 요청에 섞이는지 확인.

## 개발 지시
1. 현재 mock 전용 안전한 경로는 유지한다. **별도 실AI 전용 실행 모드/경계** 또는 명확히 분리된 provider contract를 기존 설계와 조화되게 추가하되, 안전하게 검증 가능한 최소 구성만 구현한다.
2. AI 관리자 프롬프트/스키마에는 목표·대상·중요 질문 여부·유용한 한 가지 메시지·60초 구성·장면/실제 소스 수량·대본/음성 요구·업무 분배·QA 완료 기준/재작업 결정을 포함. 모든 요청에 고정 질문·고정 후크·하드코딩된 대본을 강요하지 말 것.
3. AI 직원(writer/editor/voice/QA)은 반드시 이전 직원 결과/해시·관리자 수정 피드백·사용자 타깃에 접근하고 유효한 JSON/아티팩트와 근거를 반환할 수 있는 구조로 한다. 영상 20초에 6초 동일 클립 반복을 QA가 검출하도록 기존 수치 검사와 모델의 의미평가를 분리한다.
4. 자연어 피드백 추출은 지금 `offline_fixture`/수동 구조화 값뿐임. 향후 실제 모델이 출력하는 안전한 구조화 피드백 수신·검증 계약을 연결하되 단순 키워드 추출 결과를 모델 추론이라고 포장하지 않는다. 선호의 '적용 대상 범위'와 철회/수정 기록 유지.
5. 기술적 점수(계획 반복/길이/미디어 메타데이터)와 감각적 점수(실제 영상 청취/시청)는 분리. 데이터 미검증 항목은 `unassessed` 유지. 보고서에 품질 2~3/10을 7/10으로 상승시켰다고 주장하지 말 것.
6. `실제 호출 비활성`이 기본. 모델 키 존재만으로 실행 권한을 부여하지 않는다. 별도 승인 없이 실제 API 호출0회/비용0원/외부 전송0. 과거 Gemini 단일 인수1/1 재전송/재활용 절대 금지. 실 API 사용을 위해 어떤 별도 승인과 무료 계정 확인이 필요한지 보고서에 정리한다.
7. 기존 사용자 데이터·영상/원장·비밀키·백업/아카이브 보존, `git reset --hard`·`git clean` 금지, KST.
8. 코드 구현 후 **모의 네트워크/로컬 fixture로 단일 묶음 통합 검증**: 실제 provider 경계 요청 구성→모델 답변 검증→관리자 판단→직원 인수→QA 재작업→경험선택, 비용/동의 누락/타임아웃/중복실행 차단. API를 호출하지 않은 검증은 '실 AI 검증'으로 표시 금지. 새 모델 추론/영상 생성/GUI/TTS 업그레이드는 이번 범위 아님.
9. 결과를 `reports/manager_staff_provider_readiness_result.md`에 저장: 구현 파일·검증/문제·모의/실제 구분·남은 필수 게이트·실사용에서 가능한 최소 호출 승인 범위·보존 검증. 검증된 코드+테스트+보고서만 GitHub 커밋/푸시. 채팅에는 완료 사실만 짧게. 작업이 너무 크면 안전한 절단면까지 구현하고 미완료를 정직하게 기록.
