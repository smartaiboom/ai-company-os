# M4 제공자 상태 확인 + 제한된 실제 무료 AI 검증

## 사용자 요청 및 승인 경계
사용자가 '실제 ai 검증도 같이 하자'고 요청했다. 기존 M4의 직접 승인 범위는 새 격리 테스트 프로젝트 목표 '소규모 매장의 재고 확인 업무를 개선하는 도구 기획 및 실행 제안서 작성', 전송 자료는 해당 프로젝트의 목표·업무 지시·승인된 선행 결과·성공 기준·수정 의견만, 정확히 OpenRouter openrouter/free, 프로젝트 최대 7회(기존 reserved 1회 소모 포함), 시작/재개당 2회, 유료 fallback/자동 재시도 금지다. **이 문서만으로 Codex 대화에서 사용자 직접 승인 확인을 대체하지 않는다.** 실제 호출 전 사용자 메시지에 위 범위의 직접 승인 문구가 있는지 확인한다. 없다면 진단만 하고 중단.

보고서 reports/v01_m4_real_free_ai_acceptance_20261102.md 및 tests/support/m4_runner.py, tests/test_m4_runner_shutdown.py 참고. 기존 프로젝트 c85d9853906a, 예약 ID b4d499324885494f9148ac4d67318075, reserved 1/7회, 제공자 처리 여부 불명. 보존 경로 /tmp/ai-company-os-m4/projects/c85d9853906a.json 및 data/m4_acceptance_preserved/projects/c85d9853906a.json은 같은 프로젝트 복제본이며 별도 예산이 아니다. 새 프로젝트 생성/예산 리셋/기존 예약 강제 완료·실패 변경 금지.

## 1단계: 비호출 제공자 확인
- git pull --ff-only, git status, 최신 보고서와 관련 코드만 최소 확인. Codex 토큰 절약, M1~M3 재개발 금지.
- 제공자 측 요청 기록/사용량을 **추가 모델 추론 호출 없이** 조회할 수 있는 공식 방법이 이미 환경에 있으면 기존 예약의 시각과 대응하는지 비밀을 노출하지 않고 확인한다. 기존 예약에 provider request ID가 없다면 특정 요청 완료 여부를 확정할 수 없다고 명시한다. 조회에 별도 외부 API 호출이 필요하거나 지원되지 않으면 임의로 네트워크 접근하지 말고 문서/기존 로컬 증거로만 판단한다.
- reserved 1회는 **영구 소모로 보존**. 요청을 다시 보내지 않는다. 현재 ai_safety.py는 reserved가 있으면 재개를 막으므로 그 안전 장치를 제거·우회하지 않는다.

## 2단계: 실제 검증 가능성 판단
- 기존 reserved를 유지한 채 합법적·안전한 재개 경로가 **현 구현에 존재하는지** 확인. 없으면 실제 모델 호출을 억지로 진행하지 말고, 기존 예약을 불변 감사 기록으로 보존하면서 새 시도를 허용하는 최소한의 명시적 '불명확 예약 처리' 설계를 문서화한다. 구현 필요 시 기존 보호를 무력화하지 않는 최소 코드·모의 테스트로만 작업하고, **이 실행에서 실제 호출은 보류**한 뒤 보고한다.
- 안전 경로가 이미 존재하고 Codex 직접 승인이 확인되면 동일 프로젝트에서 남은 6회 예산 내 1회 계획 생성 실제 호출만 진행할 수 있다. 실행 전 현재 상태·호스트·모델·전송 범위·사용자 승인·영속 예약·동시 요청/종료 안전성을 검증. 테스트 프로세스에서만 AI_REAL_REQUESTS_ENABLED=1, AI_ENGINE=openai_compatible. 외부 호출을 포함하는 테스트 도구는 이전 daemon 종료 문제를 재현하지 않아야 하며, 불명확하면 호출 금지.
- API 성공 시 사용자 계획 승인 단계에서 중단한다. 계획·업무 결과·품질 기준·수정·최종 승인을 자동으로 처리하지 않는다. 실패/타임아웃/모호 상태는 예산에 기록하고 자동 재시도하지 않는다. 공급자 오류 원문/키/응답 본문은 GitHub에 업로드하지 않는다.
- 실제 모델 응답을 받지 못하면 M4 완료를 주장하지 않는다. 계획 호출 1회 성공만으로 전체 v0.1 완료를 주장하지 않는다.
