## 목적 및 기술 판단
AI Company OS v1.0은 사용자와 AI 관리자/직원이 협업하여 실제 산출물을 만들고 평가·수정·경험 재사용하는 시스템이다. 직전 실제 검증에서 Heami 한국어 음성/자막/36초 MP4 및 수정 영상 제작에 성공했다. 관리자·작가·편집 업무는 모의 응답이며, 15:47:40 신규 Gemini 기획 요청도 HTTP503으로 실패했다. 따라서 이번 우선순위는 실제 AI 업무 경로 확보다. 음성/검색/App Store/UI/승인 부가 고도화나 전체 공급자 플랫폼 재개발은 범위 외.
## 기존 구현 확인과 선택
- core/ai_provider_adapter.py(OpenRouter), autonomous_free.py, groq_provider.py 및 기존 Groq/대체 연결 관련 코드·Git 이력·결과 보고서, quality_provider.py, autonomous_gemini35.py, companies/video/collaboration_handoff.py 및 quality_workflow.py 확인. 과거 OpenRouter free router는 모델/공급자가 동적으로 달라질 수 있고 Groq adapter는 enabled=False이며 이전 진단 실패 이력이 있다. 과거 연결이 현재 동작한다거나 무료라고 가정하지 않는다.
- 기존 로컬 키/계정 설정 존재만 비노출 확인, 과거 실패 원인과 기존 구조 재사용 가능성, 공식 최신 모델 목록/가격/무료 정책/구조화 출력/한도/데이터 정책 및 한국어 기획 품질 요구를 비교한다. 실제 외부 계정 요청/키 전송은 별도 승인 없이는 하지 않는다. 가능하면 기존 키와 검증된 코드가 있는 고정 무료 모델/공급자 하나를 선택. OpenRouter라면 명시적인 무료 모델/고정 제공자 및 유료 fallback 금지 설정을 확인하고 동적 openrouter/free를 그대로 승인된 고정 모델로 간주하지 않는다. Groq도 실제 무료 프로젝트/모델/권한 확인 필요. 필요시 다른 대안은 근거만 제시. 현재 무료 잔량/청구 미확인 명시.
- 기존 공통 관리자/직원 실행 엔진 및 역할별 구조 검증, 서명/원장/비용 게이트, 기획·대본/편집/대표 수정 승인 흐름을 최대한 재사용. Gemini 전용 고정값과 provider wire 차이는 필요한 최소 어댑터/선택 지점으로 분리한다. 기존 Gemini 경로/서명/실패 기록 보존. 공급자 변경은 명시 선택이며 자동 fallback/재시도 금지. 서로 다른 공급자의 응답/모델 식별을 원장 및 산출물에 실제 기록. provider_model_claim와 fixture 분리. 현재 구현상 publish_plan은 MODEL 상수 고정 검사이므로 승인된 공급자/모델·검증된 실제 응답·역할별 이력과 대조하도록 최소 개선 필요. 기존 권한/역할 검증을 완화하지 않는다. 전송 제한, 무료 요건, 미확정/중복 보호 유지. 임의의 개발 전체 호출 총량 금지. 
## 실제 검증 및 권한
- 이번 '진행해'는 개발/준비 지시이고 새로운 공급자·모델 외부 전송 승인이 아니다. Codex는 기존 로컬 코드 분석과 필요한 최소 연결 구현 및 오프라인 통합 검증을 먼저 수행한다. 선택한 공급자/모델, 정확한 endpoint, 키 등록 여부, 무료 계정 근거, 유효기간, 무료 비용0, 가상 목표/대표 선택/공개 근거 및 제한/기획·대본/가상 수정 의견(실측 메타데이터가 필요하면 별도 명시), 데이터 정책 및 실제 실행 조건을 한 번 명확히 제시하고 대표 명시 승인을 받기 전에는 실제 요청/서명 발급을 하지 않는다. 기존 승인으로 다른 공급자를 호출하거나 유료 전환하지 않는다. 선택 근거가 부족하면 구현을 억지로 확장하지 않고 구체적인 최소 조치 보고.
- 별도 유효 승인 후 Codex가 기존 서명/원장 경로로 격리 프로젝트에서 실제 관리자 배정→작가 대본→편집 장면표→관리자 검토→가상 대표 수정 의견→수정 결과→제작 인계를 수행한다. 이전 Gemini 실패 요청을 재전송하지 않는다. 실제 오류/미확정/쿼터/청구 등 발생 시 중단하고 자동 재시도/공급자 변경 없음. 확인된 코드 계약 오류는 기존 승인 내 새 서명/요청으로 필요한 단계 검증. 운영 v8 선택/승인 금지. 가능하면 승인 대본을 기존 Heami/렌더러로 실제 MP4 제작하여 대표가 볼 수 있게 한다. 기존 음성/영상 기능은 재개발하지 않는다. 대표 품질 평가는 직접 남겨 두고 기술 시안과 게시 가능 완성품 구분.
