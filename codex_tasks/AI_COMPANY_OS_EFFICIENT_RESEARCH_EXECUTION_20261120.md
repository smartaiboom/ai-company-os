## B. 효율적인 공통 직원 실행
- 기존 core/staff_supervision.py, core/web_research.py, research_https.py, task_replanning.py, video/research_supervision.py 및 관련 계약을 분석. 보존된 전문 자료(Commons/YouTube/제작사 관측)는 정확한 기존 출처·시점·범위·해시·권한을 검증하여 해당 목표에 관련된 읽기 전용 관측으로 사전에 제공할 수 있도록 한다. 외부 신규 호출 없이 제공하고 모델의 추론이나 검색 단서가 원문 관측으로 승격되지 않게 한다. 부적격/낡은/상충 자료 표시, 필요한 경우에만 새 조사 선택. 전송 범위·크기 제한과 기존 참조 ID/독립성 유지. 비영상 가상 업무 재사용.
- 조사 행동, 최종 직원 보고, 관리자 독립 검토의 실행 예산을 명시적으로 분리하고 마지막 보고 및 검토 몫을 선예약 또는 동등한 불변조건으로 보존한다. 기존 직원 3회/관리자 2회의 제안 한도 안에서 기본 직원 조사 판단 최대 2회+최종 보고 최소 1회, 관리자는 검토 최대 2회. 중간 보완 여부에 따라 가용 행동을 동적으로 보여주되 최종 보고를 잃지 않는다. 이 배분은 설계 제안이므로 동등하게 안전한 기존 구조를 재사용할 수 있으며 차이를 보고한다. 실제 도구 실행은 각 승인/차감 단위, 한 번의 판단에서 관련 도구/옵션을 제한된 묶음으로 선택할 수 있는 경우 도입 검토(무조건 다중 호출 금지, 전체·개별 상한, 필요성, 선행 의존성, 순차 실패 중단, 각 요청 서명/해시, 미확정 중단). 무리한 병렬 호출/추정 결과/신규 자동 재시도 금지. 최신 관측을 받은 실제 직원 보고와 독립 관리자 의미 검토 없이는 목표 달성 불가. 관리자 보완에 필요한 직원 보고/검토 몫이 부족하면 별도 제안/보류. 현재 예산으로 충분하지 않으면 구체 필요성과 최소 추가 범위를 보고하며 임의 상향 금지.
- 공식 페이지가 Klei로 제한된 문제는 기존 승인된 장면 및 제작사 경로를 읽기 전용 분석하여 다른 장면의 공식 후보/미충족 권리 기준을 제안으로 정리한다. 허용 범위 밖 실제 조회/임의 도메인 접근은 금지. 새 호스트/경로 승인 자동 확대 금지. robots/TLS/DNS/IP/크기/리다이렉트/정확한 URL 제한 유지. 단일 발행사 복수 페이지와 보존 자료/검색 스니펫으로 독립 근거를 허위 충족하지 않는다.
