## 실제 사용 가능한 대표 UI의 최소 기능
1. **프로젝트 목록/대시보드**: 목표·상태·현재 담당 역할·대표에게 필요한 행동·최근 업데이트(KST). 현재 상태는 반드시 저장된 로컬 상태에서 읽는다. 앞서 만든 가상 사례는 '검증/모의'라고 표시. 참고용 주제 3안은 '대표 선택 보류, 승인 없음'으로 표시하고 어떠한 자동 제작/승인도 하지 않는다.
2. **프로젝트 생성**: 대표가 광범위한 목표 입력(스포츠 뉴스 등), 언어/플랫폼/길이/제약은 선택 사항. 새 프로젝트 생성은 기존 `RepresentativeVideoWorkflow` 진입점을 이용, 중복 제출 방지. 생성했다고 AI가 실제 조사했다고 주장하지 않는다.
3. **업무 진행 화면**: "조사·주제선정 → 기획·대본 → 대표 1차 검토 → 제작 → 대표 2차 검토 → 완료"를 실제 프로젝트 상태와 매핑, 대기/실행/반려/오류 상태·담당/근거/버전/SHA/수정이력 명확히 표시. *무작정 버튼 하나로 모의 관리자 응답을 실제 AI 판단으로 가장하지 않기*.
4. **기획안·대본 검토 화면**: 주제 후보 및 조사 출처/시점·불확실성, 기획 요약, 대본 전체, 내레이션/장면 계획, 권리·미확인 항목, 변경 전후를 한 화면에서 확인. 대표는 해당 버전·SHA를 대상으로 `승인` 또는 `수정 요청`(자유 텍스트 피드백). 백엔드에서 최신 상태/버전/SHA 검증. 승인 시 기존 workflow 경유; 수정 요청은 정식 피드백 저장 후 해당 단계 대기, 가짜 자동 수정 금지.
5. **제작·영상 검토 화면**: 기존 로컬 `video.mp4` 파일을 안전한 동일출처 스트리밍으로 브라우저에서 재생. 버전별 결과 비교/미디어 메타데이터/참조음성 표시, 영상 승인 또는 수정 요청. 렌더 파일과 승인된 계획 SHA 결합. 대본 변경 피드백이면 기획 재승인으로 복귀함을 UI에 설명. 승인 후 최종 완료 명확히 표시.
6. **실제 한계의 시각화**: 현재 기획·대본 생성에 실제 AI LLM 호출이 연결돼 있지 않으면 `오프라인 모의 검증`/ `실제 모델 미실행`을 눈에 띄게 표시. 16:9 벡터/eSpeak 참조음성은 '기술 검증용'으로 표기. 기존 실제 Gemini/Puck 사용자 채택 7점은 음성 능력의 근거지만 현재 검증 MP4가 그 음성을 사용한 것처럼 쓰지 말 것.
7. **비용/안전/재진입**: 브라우저에서의 기획 승인과 외부 API·비용 권한 별개. UI는 외부 Gemini, 검색, TTS, 업로드, 게시, 유료 API를 암묵적으로 발동하지 않는다. 상태 변경은 서버에서 현재 버전·SHA+상태 전이 재확인, 새로고침/중복클릭 이중 승인·렌더/피드백 중복 없음. 파일 접근/경로 변조·임의 파일 열람 금지. 브라우저에서 사용자 피드백을 안전히 저장하고 과거 승인/피드백 이력은 불변.
8. **개발 사용성**: GitHub Codespaces 포트 8000 우선 검토(이미 사용하는 서버가 있으면 그 포트를 유지). 실행 명령과 포트 포워딩/접속 방법/화면별 동작을 짧게 README 또는 보고서에 명시. 새 패키지 최소화, 서버 재시작 시 기존 상태 복원, 오류/권한 차단 상황에서 사용자가 원인을 알 수 있는 한국어 메시지.
9. **페이지 우선순위**: 복잡한 디자인보다 실제 조작 가능성. ① 목록·상태, ② 기획/대본 승인 및 반려, ③ 동영상 재생·최종 승인, ④ 피드백 재작업 이력. 모바일 최적화·화려한 CSS·독립 SPA 구축 등은 추가 요구 없으면 보류.

## 현실적 완료 기준
- **동작하는 로컬 HTTP 서버+브라우저 화면** 실제 접근, 프로젝트 생성 및 목록·상태, 기획 승인/수정 요청 및 피드백 기록, MP4 재생과 최종 승인/반려/완료가 기존 워크플로우에 연결된 것이 로그 및 브라우저 실행 증거로 확인돼야 한다.
- 초기 실제 AI/기획 생성이 없어서 승인할 실 보고서가 없는 프로젝트의 경우 버튼이 '준비/실제 AI 연결 대기' 상태인 게 정상이다. 검증용 사례는 `simulation=true` 표시하고 이미 만든 별도 검증 데이터의 스냅샷을 이용해 버튼/상태 전이를 검증하되 원본 검증 기록은 변경하지 않는다. 검증용 신규 격리 프로젝트에서만 실제 승인/반려 UI 동작 테스트.
- 대표 1차 승인 누락 시 제작 불가, 대본 변경 시 재승인, 영상 v1→v2 이력/결과, 최종 승인 전 완료 금지, stale SHA/중복 POST/악성 경로 거부, 새로고침 후 상태 복원 등의 핵심 경로를 로컬 HTTP/브라우저에서 확인.
- **API 외부 호출 0, 비용 0, 재생/스트리밍 외 사용자 자료 외부 업로드 0, 무단 새 Gemini WAV/MP4 제작 0**. 필요시 기존 로컬 오프라인 렌더는 **격리된 UI 테스트 프로젝트와 실제 필요 범위**에서만 허용하며, 그 사실과 결과를 보고.
- 기존 60초 비디오, 실제 Gemini WAV, journal, attempt/guard/사용량/서명 및 backups·환경 키 불변. reset hard/git clean 금지. 모든 시각 KST.
- 보고서: `reports/VIDEO_REPRESENTATIVE_UI_RESULT.md`에 실행 주소/명령, 실제 페이지/조작, 자동화 테스트·스크린샷 경로(존재할 때), 수동 브라우저 검증 근거, 한계(모의 vs 실 AI, 미디어 기술 시안), 남은 오류와 C단계 진입 가능 여부. `reports/CURRENT_PROGRESS.md` 갱신. GitHub main 코드/테스트/짧은 보고서 commit+push.
- 테스트를 끝없이 반복하지 말고 필요한 범위만 실시. 완성 후 대표에게 직접 UI를 열어보고 체험할 수 있게 하라. 실제 화면이 없는 단순 설계 보고서로 완료 처리 금지.
