# 다음 작업: 검토 승인 게이트 브라우저 UI 회귀 검증

**상태:** 실행 지시됨 — 이 문서의 작업을 실제로 수행한다.

## 배경
2026-10-29 HTTP 통합 검증은 완료됐다. 전용 HTTP 통합 테스트 1개와 전체 테스트 59개가 통과했다. 다만 해당 보고서에는 실제 브라우저에서 처리 모달, 중복 제출 방지, 스크롤 복원 및 화면 배치를 확인하지 않았다고 기록되어 있다.

이번 작업은 이미 완료된 HTTP 테스트를 반복하는 것이 아니라, **실제 브라우저 UI 동작 중 아직 검증하지 않은 부분을 자동화된 브라우저 테스트로 확인하는 작업**이다.

## 시작 전 필수 확인
- `ai-company-os-phase1/AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md`, `reports/review_approval_http_integration_report.md`를 읽는다.
- 원격 `origin/main`을 확인하고 로컬 브랜치, 최근 커밋, `git status`, `git diff`를 확인한다.
- 기존 미커밋 변경, 미추적 파일, 프로젝트 JSON, 업무 결과, 백업을 보존한다. 삭제·초기화하지 않는다.
- 현재 브라우저 UI 구조, 모달 처리 코드, 중복 제출 방지, 스크롤 복원 구현과 기존 테스트 도구를 확인한다.

## 목표 및 작업 범위
1. 현재 프로젝트에 이미 설치되어 있거나 사용 가능한 브라우저 자동화 도구(예: Playwright)가 있는지 확인한다. 단순히 도구를 추가하기 위해 유료 서비스나 유료 의존성을 도입하지 않는다.
2. 브라우저 테스트 환경을 기존 사용자 데이터와 분리한다. 임시 프로젝트 데이터·임시 저장 경로와 모의 실행기를 사용한다. 실제 AI API는 호출하지 않는다.
3. 가능한 범위에서 브라우저 테스트를 추가해 다음을 검증한다.
   - 검토 승인/수정 요청 UI가 올바른 업무 ID와 상태로 표시된다.
   - 처리 중 모달과 진행 표시가 나타나고 요청 완료 후 정상 종료된다.
   - 처리 중 중복 제출이 방지된다.
   - 요청 후 페이지 새로고침/응답 갱신 시 기존 스크롤 위치가 복원된다.
   - 승인 및 수정 요청 후 화면의 검토 상태가 서버 저장 상태와 일치한다.
4. 브라우저 자동화 도구가 없거나 설치가 불필요하게 크고 위험하면 무리하게 설치하지 않는다. 현재 프로젝트의 기존 도구로 검증 가능한 대체 방법을 조사하고, 미검증 항목과 이유를 기록한다.
5. 기존 HTTP 통합 테스트 및 관련 회귀 테스트를 실행한다. 실제 사용자 데이터 경로를 사용하는 테스트는 격리가 입증되지 않으면 실행하지 않는다.
6. 실패·빈 결과 보존, 업무 결과 연결, 검토 승인 게이트, `openrouter/free` 제한 등 기존 동작을 유지한다. 무관한 리팩터링은 하지 않는다.

## 필수 완료 조건
- 실제 실행한 브라우저 테스트 명령과 결과를 기록한다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
- 관련 회귀 테스트와 HTTP 통합 테스트 결과를 확인한다.
- `git diff --check` 통과
- 테스트 데이터가 임시 경로에만 기록됐는지 확인한다.
- `reports/review_approval_browser_ui_report.md`를 작성하고 다시 읽어 검증한다.
- `codex_tasks/task_history.md`에 확인된 작업 내용, 테스트 결과, 보고서 및 커밋을 기록한다.
- 통과한 변경만 의도한 파일에 한해 커밋·push한다. 실패, 미해결 충돌, 사용자 변경 포함 위험이 있으면 커밋·push하지 않는다.
- 실제 AI API 호출은 하지 않는다.

## 완료 후 보고
무엇을 브라우저에서 검증했는지, 통과한 테스트 수, 미확인 사항, 실제 AI API 호출 여부를 쉬운 한국어로 요약한다.
