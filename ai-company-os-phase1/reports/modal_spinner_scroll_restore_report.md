# 처리 중 로더 및 화면 위치 복원 보고서

## 조사 결과

- `e6e9703` (`Diagnose truncated AI responses and show request progress`)에서 주요 폼 제출을 브라우저 기본 탐색에서 공통 `fetch` 처리로 바꾸고, 리다이렉트 응답에서 `window.location.assign(response.url)`을 호출한다.
- 그 시점 전후로 폼에 스크롤 위치를 저장하거나 복원하는 코드가 없다. 이후 `c47684c`는 모달과 배경 잠금을 추가했지만 스크롤 복원 코드는 추가하지 않았다.
- 따라서 관찰된 위치 초기화의 직접적인 변화 지점은 `e6e9703`의 비동기 제출 및 명시적 페이지 이동 경로로 판단된다. 이것은 코드 이력에 근거한 원인 분석이며, 당시 각 브라우저의 기본 스크롤 복원 동작을 재현해 확인한 것은 아니다.

## 변경 내용

- 기존 중앙 모달, 배경 어둡게 처리, 화면 잠금 및 전역 중복 제출 방지를 유지했다.
- 모달에 CSS 회전 애니메이션 로더를 추가하고 문구를 `작업 처리 중입니다. 잠시만 기다려 주세요...`로 맞췄다. 기존 성공·오류·네트워크 예외의 `finally` 정리 흐름에서 모달과 화면 잠금은 계속 해제된다.
- 리다이렉트 직전 현재 세로 스크롤 위치와 작업 행 ID를 `sessionStorage`에 저장한다. 같은 경로로 돌아오면 작업 행이 있으면 화면 가운데로 이동하고, 없으면 이전 세로 위치로 복원한다.
- 저장소 사용이 불가능해도 원래 응답 URL로 이동하도록 저장 및 복원 오류를 무시한다. URL, 서버 저장 방식, 업무 결과 및 상태 처리 로직은 변경하지 않았다.

## 미확인 사항

- 복원은 응답 후 같은 경로로 리다이렉트되는 경우에 수행된다. 작업 행은 해당 작업 폼 안에서 제출된 경우 식별할 수 있다.
- 브라우저에서 페이지 콘텐츠의 높이가 복원 시점 이후 동적으로 바뀌는 경우의 픽셀 단위 위치는 실제 브라우저에서 확인되지 않았다.
