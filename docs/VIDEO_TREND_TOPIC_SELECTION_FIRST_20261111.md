## 현재 단계와 사용자 결정
우리는 **이미 60초 영상 제작 경험이 있고**, 현재 **품질 개선 2단계**다. 음성: 실제 Gemini/Puck 8.04초와 21.52초 WAV를 사용자 직접 평가(각각 자연스러움 7/10), 21.52초는 목소리/억양 좋음·속도/쉼 적절·'현재 음성 충분'. **추가 음성 테스트는 보류.**
기존 대본 개선 기능은 모의 관리자·직원 반려→수정 흐름까지 검증됐다. 사용자는 다음 순서가 잘못됐다고 지적했다: **대본보다 먼저 요즘 쇼츠에 맞는 인기 주제 선정**. 그러므로 이번 작업은 '대본 작성'이 아니라 **AI 관리자/조사 직원의 트렌드 기반 주제 발굴, 근거 비교, 후보 선정 및 사용자 검토용 결과물**에 집중한다. 사용자가 말한 타협점은 **AI+사용자 협업**: AI가 조사·판단·추천하고, 사용자가 중요 단계에서 확인해 피드백을 남긴다. 무조건 완전 자율 운영을 강제하느라 계속 모의/게이트만 개발하지 않는다.

## 필수 실행 작업
1. AGENTS.md, reports/CURRENT_PROGRESS.md, reports/VIDEO_SCRIPT_QUALITY_IMPROVEMENT_RESULT.md, 기존 `VideoProductionCompany`, `VideoQualityCompany`, `VideoProviderQualityCompany`, 관련 `core/` provider 및 대본/리서치 도구 코드를 먼저 확인. 새 공통 엔진, 별도 회사 시스템·중복 주제 저장소를 만들지 말 것.
2. **AI 관리자 주제 조사 의사결정 계약**을 해당 전문 회사에 최소 구현/연결. 입력 예: 사용자 채널/대상/형식(한국어 초보자·직장인 AI 활용 / 세로 60초) + 조사 시점/KST + 취득한 실제 자료와 신선도. 출력: 주제 후보 3~5개, `topic, title_hook, who_cares, viewer_problem, one_takeaway, demonstrable_action, available_visuals_or_missing, source_url, source_date, metric_kind, metric_value_or_null, evidence_scope, risk, freshness, selection_reason, confidence, manager_decision, owner_review_required`. 실제 최신 데이터를 확보하지 못하면 **unknown/null** 및 `unverified_candidate`. 조회수/상승률/검색량은 단위를 섞어 순위 매기지 말고 관측기간·지역·영상 수·채널 크기 등의 차이를 명시한다. 타인의 인기 영상 대본/영상을 그대로 복제 금지.
3. 선정 기준: (a) 해당 시청자 관심과 채널 일치 (b) **실측/출처가 확인된 최신 상승 흐름** (c) 첫 3초 궁금증/직관적 문제 제시 (d) 30~60초에 하나의 실제 효용 (e) **화면 녹화나 시연 등 확보 가능한 시각적 행동** (f) 사실 검증 가능/오류·저작권 위험 (g) 영상제작 회사가 현 도구로 제작 가능 (h) 사용자 기존 피드백 '정적 카드·반복 영상은 지루함' 회피. 가중치·결론 근거 기록, 센서리 '흥미도'는 자동 사실 판정 아님.
4. 기존 기본 '가상 약속 문자' 주제를 일방적으로 유지하지 말 것. 그것은 과거 대본 수정 기술 확인에 쓰인 **codex-authored 연습 소재**이지 최신 인기 주제 선발 결과가 아니다. 최근 인기 자료를 근거로 3~5개 다른 후보를 놓고 비교해 사용자에게 **추천 1개 + 대안 2개 + 명백한 불확실성**을 제시. 예시 방향: AI 업무 팁, AI 도구 비교 실사용, 초보자 화면 시연, 생산성 실제 전후 비교. 이 예시를 그대로 인기순위로 정하거나 출처가 있다고 가장하지 않는다.
5. **실제 조사 실행을 우선**: 허용되는 공개 웹/읽기전용 경로가 있다면 기사/랭킹/유튜브 공개 메타데이터를 읽어 **소스 URL, 조회 시각·KST, 지표 종류, 스냅샷 및 사용약관 준수**를 저장. 데이터 접근이 기술적으로 불가능하면 위 참고 자료에서 유효한 공개 사실과 검증 범위를 분리해 작업하고, mock 데이터를 진짜 실시간 트렌드처럼 제시하지 말 것. 외부 실제 AI/Gemini 모델 호출·유료 API·YouTube 계정 연결·영상 다운로드/재생성은 **이번 사용자 승인 범위가 아님**; 실 실행0, 비용0. 기존 공개 데이터 HTTP GET가 가능한 경우만 필요 최소 수행, 앱 권한/유료 검색 API/키 필요하면 별도 승인 요청. 가능하면 코딩툴 Codex가 사용자 대신 '인기 트렌드 분석'을 수행한 결과인지, '실제 AI 관리자 실행'인지 구분.
6. **실제 선택 흐름 검증**: 입력된 후보 중 더 적합한 주제를 정하는 결정적 검증(실제 source freshness, 메트릭 단위 및 URL 누락, 전 채널 인기와 AI 특정 시청자 인기 혼동, 기존 오래된 소재 자동 확정 금지), AI 관리자·조사 직원/대본 직원 인수는 기존 프로젝트 흐름에 연결. 대본 직원은 **선택된 주제와 선정 근거를 인수하는 단계까지만** (새 60초 대본 작성은 다음 단계). 모의 콜백이면 정확하게 simulation/codex-authored. 후보 변화/검토 수정과 결정 SHA/시간 보존. 사용자 검토 전 제작·게시 진행 금지.
7. 결과는 사용자 눈으로 확인 가능한 **간결한 주제 후보 비교**로 내라. `reports/VIDEO_TREND_TOPIC_SELECTION_RESULT.md` 및 `reports/CURRENT_PROGRESS.md` 업데이트. 보고서에 조사 시각/출처/유효범위·후보 비교·추천 주제와 이유·현재 기능의 실제 실행/모의 구분·코드/테스트·다음 한 단계(**사용자의 주제 선택/피드백 → 그 다음 실제 AI 대본**)·모든 미해결 부분을 적어라. 가능한 한 사용자 평가 입력을 후속에 경험으로 기록할 연결 마련.
8. 코드 변경 및 테스트를 관련 범위에서 한 묶음 실행. 파일은 KST. 기존 영상 60초 원본, WAV, feedback ExperienceJournal, 이전 시도/무료 호출/승인·사용량 원장·비밀은 보존. `git clean` / reset hard / 무단 구조 삭제 금지. GitHub main에 코드·테스트·보고서만 커밋/푸시.
