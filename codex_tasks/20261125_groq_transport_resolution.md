## 새 근거와 목표
기존 실제 기획 호출 16:24:42 HTTP403(permission/other) 및 11월4일 Codespaces 403은 보존한다. 대표의 11월25일 관찰: Personal/Default Project Free $0, GPT-OSS-20B 조직 한도 30 RPM/1000 RPD/8000 TPM/200000 TPD, 별도 프로젝트 한도 없음, 모델 선택 창에서 차단 선택 없음(저장 정책 확정 아님), 신규/기존 키 Last Used Never 및 0 calls 당시 표시, Playground 한국어 응답 정상. 이후 대표가 일반 WSL 터미널에서 동일 .env의 GROQ_API_KEY를 읽어 curl로 https://api.groq.com/openai/v1/chat/completions 에 openai/gpt-oss-20b, user "Reply with OK", max_completion_tokens 100, Authorization Bearer 및 Content-Type application/json으로 독립 진단 1회 실행하여 HTTP200을 보고했다. 이는 대표 보고이며 Codex 원장에 기록된 실제 업무 성공이 아니다. 원인 계층, 동일 키/환경, 실제 응답 본문 및 청구는 미확인. 신규 키 재발급이나 다른 공급자 변경 없이 이 차이를 활용해 실제 AI 협업 업무를 정상화한다.
## 작업
- 이전 결과 reports/20261125_alternative_live_workflow_result.md, core/groq_provider.py, core/goal_dialogue_live.py(send_once), core/ai_safety.py(guarded_urlopen), core/autonomous_free.py 및 companies/video/collaboration_handoff.py GroqHandoffCompany 실제 호출 경로를 확인한다. 과거 11월4일 진단 기록도 참조하고 동일 정적 분석만 반복하지 않는다.
- 직접 curl과 프로그램의 차이를 확인: .env 로더와 프로세스 변수 우선순위/키 동일 여부(불리언만), 요청 URL/메서드/헤더 이름과 안전한 공개 헤더 값, User-Agent, JSON schema/토큰/길이/추론 옵션, TLS 및 프록시 설정 존재 여부, Codex 샌드박스와 일반 WSL 네트워크 권한. 키 값/해시/접미사/인증 헤더/프록시 비밀은 출력 또는 커밋 금지. 로컬 캡처/모의 transport로 먼저 비교한다. 현재 send_once는 ProxyHandler({}), NoRedirect를 사용하고 curl은 기본 환경을 사용하므로 이 차이는 가설이지 원인 확정이 아니다.
- Codex 실행 환경의 정식 네트워크 권한 요청 기능이 필요한 경우 사용하고, 정책상 차단이면 우회하지 않는다. TLS 검증, 목적지 고정, no redirect, 키 결합, 무료·서명·예약·원장, 전송 데이터 제한, 오류/중복 방지 모두 유지. 보안 제한을 회피하기 위해 curl/프록시/다른 프로세스 경로를 사용하거나 직접 업무 요청을 전송하지 않는다. 정당한 네트워크 설정/호환성 결함이 입증될 때만 기존 transport를 최소 수정한다. 헤더/오류 진단은 기존 bounded diagnostics 재사용; 실패 원문 및 비밀 저장 금지.
