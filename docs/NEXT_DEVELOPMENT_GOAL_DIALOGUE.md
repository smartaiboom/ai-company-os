# AI Company OS — 목표 구체화 문답 기능 통합 개발 지시
2026-11-09 KST. 개발은 Codex가 수행한다. 이번 작업은 하나의 기능 묶음으로 개발한 뒤 통합 검증한다. 사소한 중간보고서와 테스트를 반복하지 않는다.

## 제품 목적
사용자가 영상 제작 목표를 입력하면 AI 관리자가 부족한 핵심 정보를 판단해 적응형 질문을 만들고, 사용자 답변을 저장하고, 최종 요구사항 명세를 확정한 다음 기존 AI 회사의 계획 입력으로 연결한다. 단순히 질문을 보여주는 데모가 아니라 답변이 실제 관리자 계획에 영향을 준다는 것을 검증한다.

## 기존 코드와 연결
- 공통 실행: core/autonomous_company.py의 Store.create(goal) 및 Company의 plan 단계.
- 기존 실제 AI: core/autonomous_live.py, core/autonomous_gemini.py, core/autonomous_gemini35.py. 기존 권한·비용·상태해시·동의 계약 변경 금지.
- 전문 영상회사: companies/video/video_production_company.py의 VideoProductionStore.create(goal).
- 현재 파일명 import 방식: PYTHONPATH=core:companies/video.
- 기존 tests/test_v1_core.py 테스트 4개는 유지. 구 phase1 소스 복구/복제 금지.

## 이번 개발 범위 (한 번에 구현)
1. core/에 범용 goal_dialogue 모듈: 별도 초안 ID, 원래 목표, 질문/답변/이력, KST 시각, 라운드 한도, 중단 후 재개, 최종 명세와 사용자 확정 상태를 영속적으로 저장한다. 기존 실서비스 원장과 격리, 안전한 파일 쓰기.
2. AI 관리자 인터페이스: 목표·누적 답변을 보고 정말 필요한 질문만 선택해서 1~3개 생성하거나 이미 충분함을 판단. 정형 고정 질문지는 금지. 질문 ID, 필요 근거, 명세 요약, 가정/미확정 사항을 구조화하여 검증. Mock 관리자는 테스트에서만 사용하고 실제 AI 판단인 것처럼 표시하지 않는다.
3. 사용자 답변과 정정, 질문 건너뛰기, 반복 질문/무한 라운드 방지. 같은 질문과 답변을 단순 중복하지 않으며 적응형 추가 질문을 지원한다.
4. 요구사항 명세: 대상 사용자, 산출물 정의, 스타일, 핵심 품질 기준, 필수 제약·예산, 답변 근거 및 미확정 가정. 실제 사용자로부터 확인한 내용과 AI가 추정한 내용을 명확히 구분한다.
5. 사용자가 최종 명세를 확인·확정하면 기존 VideoProductionStore를 통한 실제 회사 프로젝트 초안/계획 입력에 연결한다. 확정 이전에는 자동 제작 금지. 설명만 저장하는 게 아니라 manager plan context에 답변이 반영되는 오프라인 테스트를 포함한다.
6. 간단한 실제 사용 CLI 1개: 목표 생성, 질문 확인/답변, 재개, 명세 확인/수정/확정, 기존 회사 계획 연결. 무거운 웹 UI/영상 렌더러 개선은 이번 범위에서 제외한다.

## 반드시 지킬 안전 조건
- 실제 Gemini 등을 통한 질문도 외부 데이터 전송이다. 전송 범위·모델·무료/유료·호출 제한의 명시적 사용자 승인 전에는 호출하지 않는다. 초기 구현 및 통합 테스트는 mock-only, 실제 AI API 호출 0회, 네트워크 0회. 실 API 연결이 권한 계약 개정 없이는 안전하지 않으면 기본 차단 상태를 유지하고 명확히 보고한다.
- 기존 VideoProductionStore.prepare/approve, 원장, 소진 마커, 상태 해시, 예산, 불확실 호출 정책을 우회/초기화하지 않는다. 새로운 명세로 프로젝트 목표가 바뀌면 예전 동의를 자동 재사용하지 않는다.
- 기존 사용자의 프로젝트 데이터/백업/영상 및 Codespaces 별도 보관 폴더를 수정·삭제·재실행하지 않는다.
- 데이터 디렉터리는 gitignore. KST(UTC+9). 사용자 질문/응답과 실 AI 응답에 비밀키 포함 금지.

## 완료와 검증
- 코드/CLI/핵심 테스트/최소 문서(README.md, docs/ARCHITECTURE.md)를 하나의 작업으로 묶어 구현한다. 사소한 단계마다 테스트하지 말고 끝에 통합 검증 1회(실패 시 필요한 수정 후 재검증).
- 적어도 mock 목표 → 모델 적응형 질문 → 사용자 답변 → 명세 확정 → 실제 기존 manager 계획 반영, 중단 후 재개, 중복 요청 차단, 기존 4개 핵심 테스트를 확인한다.
- 폴더 위치 변경 이후 import/실행도 같은 통합 검증에 포함한다.
- 불필요한 임시 파일/중복 코드/일회성 테스트러너는 Git에 남기지 않는다. 간결한 결과 기록은 docs/IMPLEMENTATION_STATUS.md 하나만 작성.
- 실제 AI 구동은 이번 작업의 합격 기준이 아니다. 실제 Gemini 기반 질문 및 실제 영상 생성이 완료된 것처럼 쓰지 않는다.
- 최종 수정 파일/명령/통합 테스트/실제 API 호출 0회/미완료 항목을 한국어로 보고하고 GitHub main에 커밋·push.

기존 계약을 깨야만 구현 가능한 부분은 위험을 숨겨 억지로 진행하지 말고 해당 변경 범위와 대안을 보고한다.
