# 다음 작업: AI Company OS v0.1 완성 기준 고정 및 통합 개발 계획

## 목적
지금까지 작은 기능의 설계→구현→검증을 여러 번 반복했다. 이제부터는 **사용자가 하나의 목표를 제시하면 AI 직원들이 실제 무료 모델로 계획→분담→실행→결과 전달→검토/수정→최종 산출물까지 완수하는 시제품**이라는 v0.1 종료 조건에 집중한다. 기능별 별도 소형 지시서를 계속 생성하지 말고 검증과 구현을 묶는 통합 마일스톤을 수립한다.

## 착수 전
- AGENTS.md, codex_tasks/README.md, task_history.md, 주요 최근 reports(최종 승인 구현, mock 자동 진행, mock 품질 검토/수정 1회, 전체 현황 조사)와 실제 app.py, manager_plan.py, execution_engine.py, tests를 확인한다.
- origin/main/현재 브랜치/working tree와 기존 미추적 파일, 프로젝트 JSON·스냅샷·백업을 점검하고 모두 보존한다. reset/clean, 기존 데이터 삭제, 무차별 git add, 강제 push 금지. KST 기록.
- 사용자가 실제 AI 호출을 명시적으로 승인한 것은 아니므로 이번 작업 중 **실제 AI API 호출 금지**, 유료 모델 호출/결제 경로 추가 금지.

## 작업 1: v0.1 완료 기준 및 범위 고정
다음 기준을 코드 현황에 맞춰 구체화하고, 달성 여부와 남은 작업을 증거에 기반해 작성한다.
- 사용자의 목표 입력 및 AI 계획 생성/승인.
- 여러 AI 직원 역할의 실제 무료 AI 작업, 승인된 선행 결과를 사용하는 핸드오프, 실패 안전성.
- 사용자 명시적 실행에 따른 실제 무료 모델 기반 연속 협업 경로(안전한 실행 상한, 승인 대기, 호출 횟수/비용 통제). 현재 mock-only 자동 진행과의 차이를 명확히.
- 결과 품질 검토 및 수정 요청·재작업·재검토; mock 형식 검사와 실제 AI의 의미적 품질 평가의 차이를 명확히.
- 최종 결과 검토·확정·버전 보관과 사용자에게 활용 가능한 산출물 제공.
- 한 개의 실제 목표에 대한 시작→끝 통합 시나리오와 수동 개입 지점.
- 클라우드 Codespaces 환경, 무료 우선, KST, 사용자 데이터 보존.
- 제품 아이디어 선정과 실제 매출까지 완전 자율화하는 기능은 v0.1의 필수 종료 조건에서 제외하고 후속 단계로 구분한다. 하지만 가상회사 방향을 협소한 단일 콘텐츠 도구로 바꾸지 않는다.

## 작업 2: 통합 마일스톤
- 구현 완료 / 부분 구현 / 미구현을 근거 함수·테스트·보고서와 함께 표로 작성한다.
- 남은 필수 작업을 **최대 3~4개의 통합 마일스톤**으로 묶고 각각 의존성, 한 번에 구현·검증할 범위, 명확한 완료 기준, 위험을 지정한다.
- 가능한 경우 첫 통합 마일스톤에서 현재 테스트가 검증하지 못하는 핵심 흐름을 임시 데이터 + mock 기반의 종단 통합 테스트로 추가한다. 단, 이번 작업의 주된 목적은 범위 고정과 마일스톤 계획이며 불필요한 코드 확장은 금지한다.
- 브라우저 검증 등 기존 환경 이슈는 한 마일스톤의 일부로 묶고 매번 별도 독립 작업으로 반복하지 않는다.
- 실제 API 호출이 필요할 때는 사용자에게 예상 호출 데이터/보안/한도를 먼저 승인받는 별도 마일스톤으로 명시한다. 승인 전 실제 호출을 수행하지 않는다.
- 앞으로 결과 보고와 관련 테스트를 기능마다 따로 작업으로 떼지 말고 해당 구현 마일스톤에 통합한다.
