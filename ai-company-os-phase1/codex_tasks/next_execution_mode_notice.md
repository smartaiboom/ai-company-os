# 다음 개발 작업: 실행 모드 및 외부 전송 안내 정확화

## 목적
사용자가 AI Company OS 화면에서 mock 모드와 실제 OpenRouter 호출 모드를 명확히 구별하도록 한다. 전체 가상회사 목표를 유지하면서도 비용·데이터 전송에 대한 잘못된 안내를 우선 수정한다.

## 착수 전
- AGENTS.md, codex_tasks/README.md, reports/ai_company_os_current_state_audit_20261102.md와 해당 코드 및 테스트를 읽는다.
- main/origin/main, git status, git diff를 확인하고 기존 변경·미추적 파일·업무 데이터·백업을 보존한다. reset/clean/강제 push 금지.
- 실제 AI API 호출 금지, 유료 모델/결제 변경 금지, 기존 기능 구조 변경 금지.

## 구현
1. 앱에서 현재 AI_ENGINE이 mock일 때는 '외부 AI 요청 없음'을, openai_compatible일 때는 정확히 openrouter/free 모델을 사용하고 목표·업무 입력·선행 결과가 외부 제공자에 전송될 수 있음을 표시한다.
2. 실행 모드 불분명/설정 오류 시 실제 호출이 발생하지 않도록 기존 검사와 오류 동작을 보존한다. 키·토큰·인증 정보는 화면·로그·보고서에 노출하지 않는다.
3. README의 모드 설명을 현재 실제 구현과 일치시킨다.
4. 두 모드 화면 안내에 대한 격리된 모의 테스트를 추가하거나 기존 테스트를 보강한다. 실제 사용자 데이터 경로를 사용하는 테스트는 격리 증명 없으면 실행하지 않는다.
5. 불필요한 리팩터링을 하지 않는다. 모든 시각 기록은 KST.

## 완료 조건과 결과 전달
- mock, 실제 엔진 모드 각각의 안내가 올바르고 유료 모델 우회가 없음을 확인한다.
- 관련 기존 테스트와 신규 테스트 실행 결과를 확인한다. 실제 AI API 호출은 하지 않는다.
- 새 보고서를 reports/execution_mode_notice_fix_20261102.md 에 작성하고 재독해 검증한다. 변경 파일, 테스트 명령/결과, 미확인 항목, API 호출 여부를 기록한다.
- 이번 작업 관련 파일만 선택적으로 스테이징, 테스트 성공·충돌 없음 확인 후 origin/main에 안전하게 커밋·푸시한다. 실패·충돌 시 중단하고 정확한 이유를 보고한다.
- 결과를 대화에만 남기지 말고 보고서 파일과 원격 반영을 필수로 한다. 완료 응답에는 보고서 경로와 커밋 SHA를 짧게 안내한다.
