# 다음 개발 작업: mock 품질 검토 후 수정 1회와 재평가

## 목표
AI Company OS의 AI 직원들이 결과를 생성하고 품질 검사 의견을 받은 뒤 수정·재검토하는 협업 흐름의 **첫 번째 안전한 최소 단계**를 구현한다. 기존 `reports/autonomous_quality_review_design_20261102.md`, `reports/mock_quality_review_implementation_20261102.md`, `reports/mock_quality_review_http_validation_20261102.md`를 바탕으로 한다.

## 착수 전 필수 점검
- `AGENTS.md`, `codex_tasks/README.md`, `codex_tasks/task_history.md` 및 위 보고서, `app.py`, `quality_review.py`, `execution_engine.py`, 승인·최종 보고·자동 진행·동시 실행 관련 테스트를 읽는다.
- Git 브랜치, origin/main, status, diff, staged diff를 확인한다. 기존 추적/미추적 변경, 사용자 프로젝트 JSON, 업무 결과, 백업, 기존 최종 스냅샷을 보존한다. `reset`, `clean`, force push, 무차별 git add 금지. 모든 시각 KST.
- 실제 AI API 호출·유료 모델·외부 의존성 설치 금지. 현재 코드와 기존 경로를 재사용하는 최소 수정 우선.

## 구현 범위
1. mock 모드에서 사용자 명시적 요청을 받았을 때만, 하나의 정확한 대상 업무에 대한 최신 `quality_review` 판정이 `changes_needed`이고 성공 결과/입력 맥락/정책 바인딩이 현재와 일치하는 경우에만 수정 재실행을 허용한다. `pass`, `inconclusive`, `stale`, 실패/빈 결과, 사용자 수정 요청 미해결, 사용자 승인된 최종 확정 등은 무조건 임의 수정하지 않고 거절 또는 사용자 확인을 요구한다.
2. 기존 검토 승인 상태를 가짜로 변경하거나 수동 요청 검사를 우회하지 않는다. 서버 내부에서만 사용하는 좁은 수정 실행 권한 경로를 설계하고, 기존 실행 함수의 선행 결과 검증·후속 재검토·성공/실패 결과 보존·최종 확정 무효화 규칙을 재사용한다.
3. 이전 모의 품질 판정의 구체적인 누락 항목/피드백을 기존 사용자 `review_feedback`과 구분된 입력 항목으로 **같은 업무 담당 역할**에 전달한다. 실제 mock 실행기가 피드백에 따라 결과를 지능적으로 개선한다고 주장하지 않는다. 테스트에서는 명시적인 순차 fixture로 개선 시나리오를 재현한다.
4. 첫 구현은 **한 명시적 요청에서 수정 실행 최대 1회, 이후 재평가 최대 1회**로 제한한다. 동일 품질 주기에서 중복 POST나 재시작/재개로 추가 수정이 발생하지 않도록 수정 시도 예약/카운터/중단 이유를 영속적으로 기록한다. 이번 단계에서 자동 연속 반복은 구현하지 않는다.
5. 수정 성공 시 result revision을 증가시키고 새 결과에 대한 형식 품질 검토를 수행한다. pass/changes_needed/inconclusive를 구조화해 저장하며 사용자 승인은 자동 처리하지 않는다. 수정 실패/빈 결과·평가 예외/저장 오류 시 기존 성공 결과와 사용자 의견을 보존하고 정지한다. 재시도 동작과 남는 한계를 분명히 기록한다.
6. 프로젝트별 기존 잠금 아래 실행/검토 경합을 보호하고, 동시 중복 요청은 409를 반환한다. 다른 프로젝트 동시 작업은 허용한다. 기존 JSON과 구형 데이터 호환, 최종 승인/스냅샷 보존, `openrouter/free` 제한 유지. GET에서 상태/파일 쓰기 금지.
7. UI에는 mock 전용 '수정 1회 및 재검토' 조작, 마지막 판정/중단 이유/남은 횟수와 '형식 검사일 뿐 사실성 검증 아님' 안내를 제공한다. 자동 품질 pass와 사용자 검토 approved를 명확히 구분한다.
8. 구현 범위가 예상보다 커져 저장·승인 무결성을 해칠 위험이 있으면 무리하게 확장하지 말고 안전하게 중단하고 보고한다. 과도한 리팩터링 금지.

## 테스트 완료 조건
- `TemporaryDirectory`로 projects/artifacts 경로를 격리하고 실제 AI 네트워크 호출 금지 mock을 사용한다.
- changes_needed→수정 피드백 전달→mock 결과 1회 재실행→새 revision/재평가→사용자 승인 대기, 개선 없이 여전히 changes_needed, 결과 실패/빈 결과 보존, 중복 POST/재요청 횟수 상한, stale 판정·무효 모드 차단, 평가 오류, 저장 실패/재시작으로 인한 반복 안전성, 동시 실행 409, 다른 프로젝트 독립성, 최종 확정 보존·무효화 경계를 시험한다.
- 기존 품질 HTTP·전체 회귀(최종 승인, 자동 진행, 잠금, 무료 모델 차단)를 실행한다. 실제 업무 데이터 경로를 사용하는 격리되지 않은 smoke 테스트는 실행 금지.
- `git diff --check` 통과. 미해결 테스트 실패/충돌이 있으면 커밋·푸시하지 않는다. 테스트를 실제로 실행하지 않았다면 통과로 보고하지 않는다.
