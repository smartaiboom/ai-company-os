# 미션 01 AI 제작 계획과 실제 자산 인수 (2026-11-19 KST)

## 보존한 기준과 경험

운영 컷룸에는 승인된 35초 기획 v2와 무음 자체 카드 영상 v1이 있다. 영상은 대표 검토 대기 상태이며, v1에서 품질 승인을 기록하지 않았다. v1은 보존하고 **영상 수정 · 실제 제작 준비**로 진입하도록 했다. 이 작업에서 운영 상태와 기존 대본은 바꾸지 않았다.

- 이전 품질 반복 및 사용자 피드백 보고서의 장면 변화, 같은 클립의 반복, 발화 시간에 맞춘 자막, 실제 시청·청취 확인을 제작 검토 항목으로 전달한다. 다른 길이와 장르의 수치 합격선을 이 영상에 강제하지 않았다.
- 3개 실물 클립과 로컬 인수 보고서가 사용한 `ClipJob`의 파일 검증, 소스 영수증, 원본 해시와 중복 차단을 재사용한다. 과거 Flow 클립, MCP로 생성된 파일, Codespaces의 WAV, Melo 모델이나 경험 저널을 새 게임 영상의 자산으로 가져오지 않았다. 현재 WSL에 해당 모델과 재사용 가능한 게임 소스가 없다.
- [이전 Gemini/Puck 7점 평가](VIDEO_VOICE_USER_AB_FEEDBACK_RESULT.md)는 한국어 AI 안내 영상 표본의 대표 평가다. [별도 148자 승인 표본](GEMINI_TTS_148_CHAR_REAL_ONE_SHOT_RESULT.md)에는 실제 합성 기록이 있다. 현재 영상의 음성 점수, 무료 모델 적용 또는 실행 권한을 그 평가와 원장으로 대체하지 않는다.

## AI 판단과 실행

| 단계 | 판단·실행 범위 | 상한 |
| --- | --- | --- |
| 관리자 제작 계획 | 승인된 목표·대상·대본·장면·해시, 대표의 이번 수정 의견, 과거 품질 근거의 범위, 실제 사용 가능한 도구, 관측과 출처 한계를 보낸다. AI가 음성 후보·스타일, 장면별 소스 요청과 연출, 시간 전략, 작업 순서와 검토 기준을 결정한다. | 고정 Gemini 텍스트 **1회**, 직원·추가 검토 요청 0회 |
| 장면 음성 | AI가 골랐을 때 기존 `TTSExecution`의 새 승인 스코프를 사용한다. 승인 장면 원문과 모델·음성·스타일·요청 본문·파일 및 계획 해시가 결합된다. 각 장면을 별도 검토·동의·실행한다. | 승인한 장면마다 **1회**, 현재 **최대 4회**. 실패·미확정도 차감 |
| 영상 자산 | 관리자가 만든 구체적인 요구를 보고 대표가 로컬 인수 경로에 MP4를 둔 뒤 장면 적합성과 사용권을 확인한다. 자동 영상 취득이나 웹 다운로드는 지원하지 않는다. | 자동 영상 생성·YouTube 요청 **0회** |
| 로컬 합성 | 각 장면의 승인 경계와 원문을 보존하고 실측 음성 길이에 맞춰 승인 자막을 표시한다. 파일·해시·음성 길이·전체 디코딩, 반복과 고유 클립 수, 프레임 샘플 차이 및 자막 읽기 속도를 기록한다. | 외부 요청 **0회** |

관리자 요청에는 기존 `ManagerPlanAcceptanceStore`의 정확한 요청 서명과 독립된 한 번의 원장을 사용한다. 시스템이 승인 해시와 씬 ID를 결합하고 구조·순서·지원 범위를 검증한다. 목소리와 장면 연출은 관리자 응답에 속한다. 현재 로컬 실행이 지원하는 인수는 운영자 제공 MP4, 장면 순서 유지, 컷 전환 및 레터박스다. 이 범위 바깥에서 필요한 도구나 영상이 있으면 대기한다.

장면별 WAV는 기존 Gemini 응답 검증을 거쳐 로컬 렌더에 전달한다. 35초 전체 합성은 기존 20초 수락 한도와 장면별 타임라인에 검증된 인수가 없어 이번 실행 범위에서 제외했다. 카드 등록, 유료 전환, 재시도, 게시 경로는 추가하지 않았다. 계정의 현행 무료 적용과 잔량은 소유자가 확인해야 하며 요금은 독립 검증되지 않았다. 모델 자체의 시청·청취 또는 음성 내용 일치는 별도 인간 평가가 필요하다.

## 대표 다음 조작

1. 컷룸을 새로고침한 뒤 **영상 수정 · 실제 제작 준비 → 수정 요청**으로 들어간다. 승인 기획 변경 체크를 비워 둔다.
2. **관리자 제작 계획 준비 → 제작 계획 외부 전송 동의 → 관리자 제작 계획 실행**을 각각 선택한다. 서버에는 기존 키와 별도로 대조한 제작 프로젝트 키 설정 `GEMINI_PRODUCTION_PROJECT_API_KEY`가 필요하다. 현재 무료·결제 비활성화·쿼터를 확인한 뒤 준비한다.
3. 관리자 지시를 확인한다. 기존 영상이 이 장면과 일치하고 사용권을 보유한 경우 화면의 로컬 인수 폴더에 두고 **로컬 클립 인수**를 선택한다. 게임 제목이나 검색 결과는 영상 파일을 갖고 있거나 사용할 수 있다는 의미가 아니다.
4. 관리자가 Gemini 장면 음성을 골랐다면 별도 실행 설정 `GEMINI_PRODUCTION_TTS_ENABLED=1`과 함께 장면마다 **장면 음성 준비 → 장면 음성 동의 → 장면 음성 실행**을 순서대로 선택한다. 이미 설치된 MeloTTS가 선택됐을 경우만 로컬 합성을 사용한다.
5. **인수한 클립과 음성으로 제작**이 표시되면 로컬 제작을 시작한다. 생산된 영상은 별도의 대표 영상 검토로 제출된다. 자산이 부족하면 카드로 자동 대체하지 않는다.

## 검증

- 회귀 테스트 144개 중 142개 통과, 2개 건너뜀. 신규 승인 경로 테스트 2개, `node --check`, `git diff --check`도 통과했다.
- 운영 승인 v2의 복제본에서 영상 v1 승인 차단, v2 유지, 모의 관리자 계획 1회, 장면별 별도 승인과 모의 TTS 응답 4회, 합성 테스트 MP4 4건의 명시적 인수, 실제 FFmpeg 720×1280 음성·자막 합성과 대표 2차 검토 대기까지 확인했다. 운영 원본과 영상 v1을 보존했다. 모의 음원과 클립은 제작 연결 검사용 fixture이며 실제 음질·게임 영상은 미검증이다.
- 기존 환경으로 운영 서버를 재시작했다. localhost의 프로젝트와 JavaScript 응답에서 승인 v2, 영상 v1 검토 대기, 영상 수정 진입점을 확인했다. 브라우저 조작은 미검증이다. 운영 환경에는 독립 제작 프로젝트 키와 장면 TTS 실행 설정이 아직 없다.
- 실제 Gemini 텍스트·TTS·YouTube·영상 생성 요청과 운영 동의·제작 시작은 모두 **0회**였다. 기존 Gemini 텍스트 **20회**, YouTube **4회** 및 별도 과거 TTS 기록은 보존했다.
