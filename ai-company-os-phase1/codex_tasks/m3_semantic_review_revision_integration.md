# AI Company OS v0.1 — M3 통합 개발: 의미 검토·수정·재검토 연결

## 목표와 중복 개발 금지
M1 mock 완주·Markdown 다운로드, M2 실제 무료 AI 전송 안전 경계·영속 예산, 기존 사용자 승인/수정/최종 보관을 **그대로 재사용**한다. 새 회사 OS나 별도 업무 엔진을 만들지 않는다. M3는 실제 모델 기반의 구조화된 의미 검토 계약과 사용자 승인된 수정 1회·재검토 흐름을 기존 직원 협업에 연결하는 **단일 구현+통합검증+보고** 작업이다. 실제 외부 AI API 호출은 이번에 절대 하지 않는다.

## 시작 전 최소 확인
- AGENTS.md, reports/ai_company_os_v01_completion_roadmap_20261102.md의 M3, reports/v01_m2_real_ai_safety_budget_20261102.md, reports/v01_m1_mock_end_to_end_20261102.md의 관련 부분, app.py/manager_plan.py/execution_engine.py/ai_safety.py/quality_review.py, 핵심 테스트만 살핀다. 전체 이전 보고서를 매번 정독하지 않는다.
- git branch/status/diff 및 origin/main 확인. 기존 업무 JSON, 스냅샷, 백업, 추적/미추적 파일 보존. reset/clean/강제 push/무차별 스테이징 금지. 시각 KST.

## 구현 범위
1. **의미 검토 계약**: 특정 target_task_id, 최신 result_revision/hash/입력 맥락, 사용자 승인된 성공 기준에 대해 pass/changes_needed/inconclusive, 기준별 근거·위험·수정 제안의 엄격한 구조화 결과를 수신·검증한다. 모델 주장과 독립적으로 확인된 사실을 구별하고 빈/잘못된 JSON·오래된 지문·오류는 통과시키지 않는다. 기존 제목 기반 mock 형식 검토와 상태를 혼동하지 않는다.
2. **역할별 프롬프트**: 일반 사용자 목표에 맞는 계획/업무/검토 프롬프트. AI Company OS 자체 개발 문구가 무관한 목표를 왜곡하지 않도록 수정한다. 역할·선행 승인 결과·명시 성공 기준을 활용하고 임의의 추가 도구/웹 검색·코드 실행을 구현하지 않는다.
3. **사용자 수정 승인 경계**: 품질 담당자가 이미 승인된 이전 직원 결과를 수정해야 한다고 판정해도 자동으로 승인 취소/수정 실행하지 않는다. 정확한 업무 ID, 기존 승인, 수정 사유, 남은 API 예산을 UI에 표시하고 별도 사용자 '수정 요청 승인' 뒤 기존 changes_requested·결과 보존·후속 무효화 경로를 재사용한다.
4. **실제 수정 1회·재검토 1회**: 같은 업무 담당 역할에 사용자 승인된 의견 전달→새 실행→기존 사용자 재승인→검토자의 최신 revision 재평가. 자동 반복 금지. 동일 프로젝트의 M2 호출 예산(계획/직원/검토/수정 모두)에 포함. 현재 mock 전용 수정 예약을 삭제·초기화하거나 실제 엔진 권한으로 재사용하지 말고 별도 좁은 사용자 승인 경로로 구현한다.
5. M2 공통 무료 모델/HTTPS 호스트/동의/전송 크기/영속 예산/예약 안전과 M1 승인·최종 확정/Markdown 다운로드를 유지한다. 사용자 동의가 실제로 부여되지 않은 상태에서 외부 전송할 수 없게 한다.
6. 사용자 목표는 일반 도메인을 지원해야 한다. 테스트 샘플 목표 '소규모 매장 재고 업무 개선 제안'에 필요한 업무별 내용·검토 근거가 이어지는지 확인하되, 제품을 그 도메인에 고정하지 않는다.
