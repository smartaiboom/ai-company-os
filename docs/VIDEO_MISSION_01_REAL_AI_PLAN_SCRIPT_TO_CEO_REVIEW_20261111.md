# 컷룸 첫 번째 미션 — 실제 AI가 기획안·대본 작성 후 대표 승인 대기까지
작성일: 2026-11-11 KST / `smartaiboom/ai-company-os`

## 대표가 확정한 미션과 절대 범위
사용자의 정확한 목표: **"첫번째 미션은 ai관리자가 첫기획안과 대본을 작성해서 대표에서 승인대기까지 올리는거로 하자"**.

완료 상태는 **컷룸 UI의 새 프로젝트에서 실제 AI 관리자와 대본/조사 직원의 업무 기록을 거쳐, 주제 선정 근거·기획안·대본 전문이 대표 검토 화면에 `awaiting_plan_approval`로 노출되는 것**이다. 대표가 직접 읽고 승인하거나 반려할 수 있어야 한다. 이번 미션에서 **대표의 실제 승인, TTS/WAV, 영상/MP4 생성, 영상 최종 승인, 업로드/게시를 수행하지 않는다**.

기본 예시 목표가 필요하다면 직전 대화에 제안된 **"AI 초보자를 위한 요즘 인기 있는 쇼츠 영상을 만들어 줘"**를 새 실험용 제안 목표로 사용하되, 사용자가 확정한 새 프로젝트 주제인 것처럼 가장하지 않는다. 실제 대표가 컷룸에서 입력한 목표가 있으면 그것을 우선한다. 2026-11-11 조사 후보 3개는 **전부 참고자료이며 미선정/대표승인 없음**. 1위 추천을 자동으로 가져와 기획한 것처럼 꾸미지 말 것. 장기적으로 "스포츠 뉴스" 등 어떤 분야도 수용 가능해야 한다.

## 이미 있는 것과 확인해야 할 핵심 간극
- `reports/VIDEO_REPRESENTATIVE_APPROVAL_FLOW_RESULT.md`: `RepresentativeVideoWorkflow.start_planning`은 **기존 오프라인 `VideoQualityCompany` 작업을 생성/컨텍스트 바인딩**한다. `report_plan`은 accepted writer/editor, `render_spec`, 전체 대본·인수·SHA를 기대한다. 관리자·직원 모의 콜백을 실제 LLM 작업이라고 표시하면 안 된다.
- `reports/VIDEO_REPRESENTATIVE_UI_RESULT.md`: `studio_server` / 포트 8000 / 컷룸 UI는 업무 보기·승인/반려와 MP4 재생을 지원하지만 **실제 LLM 기획 연결 0회**. 디자인(카드, 아이콘, 실제 썸네일, 상태) 보존, 이번 미션은 UI 재디자인 아님.
- `companies/video/quality_workflow.py`의 `VideoProviderQualityCompany`는 실제 Gemini 프로바이더용 검증 경로가 있으나 production transport는 비활성. `companies/video/representative_workflow.py`는 오프라인 흐름. **둘 사이 연결/프로젝트 저장·역할·서명/호출 권한 호환을 먼저 진단**한다.
- 기존 `core/` provider, 승인/호출예약, 비활성 플래그, `companies/video/script_quality.py`, `topic_research.py`, `studio_server.py`, 관련 테스트, `AGENTS.md`와 `reports/CURRENT_PROGRESS.md`를 읽고 **기존 코드를 재사용**. 새 AI 오케스트레이터/웹 앱/승인 원장/유사한 회사 엔진을 만들지 말라.

## 개발 구현 요구
1. **실제 생성 작업 흐름:** 대표 목표 입력 → 컷룸 프로젝트 생성 → 관리자 실제 모델이 사용자 목표/시청자/길이/장르/최신성 필요를 정리하고 적절한 조사·대본 직원 업무를 지정 → 조사 결과/후보·출처·날짜/모르는 점 인수 → 대본 직원이 0–3초 후크, 주제 선정 이유, 한 가지 메시지, 시연할 장면을 갖는 60초 기획안과 **전체 한국어 대본**을 작성 → 관리자 리뷰/결함 지적 및 실제 필요 시 직원 수정 → 최신 수락 버전만 `RepresentativeVideoWorkflow.report_plan`을 통해 대표에게 제출.
2. `report_plan`의 기존 엄격한 `render_spec` 계약과 실제 영상 제작 간극을 진단하라. **대표에게 대본을 보고하는 단계에서 실제 영상·음성 제작/렌더까지 강제하지 않도록** 기존 구조를 최소 변경. 구체적 영상 장면/타임라인 계획은 보고하되 존재하지 않는 소스·영상이나 사용권을 확보했다고 하지 않는다. 향후 실제 제작에서는 대표 승인된 SHA만 사용.
3. **실제 AI vs mock provenance**: 모델·provider·실제 HTTP 결과/시각, 직원 역할, 요청/응답 결과 해시·비용/사용량, 관리자 결함 지적·수정 버전 연결. Codex가 작성한 후보/예시와 실제 API 결과 명백히 구분. 실제 모델 호출이 없다면 대표 승인 대기로 상태를 이동시키지 말 것. 보고서 `awaiting_plan_approval`은 **실제 AI 생성 및 내부 수락/검증 완료한 기획안**에 한정.
4. **쇼츠 최신 동향을 추정하지 말라**: 실시간 인기 뉴스/랭킹은 독립 출처·시점이 필요하다. 이번 요청은 새로운 외부 웹수집 API나 계정/유료 데이터 수집 권한을 부여하지 않는다. 공개 자료가 오래되거나 직접 성과 수치가 없으면 사실과 추정 분리, 검색 불가능하면 `unverified`와 근거 한계를 기획안에 표시. 스포츠 경기 결과, 영상 클립 사용권도 검증 전 단정 금지.
5. **UI 체험 우선:** 컷룸 대시보드에서 '기획 진행 중' → '대표 승인 대기'가 실제 저장 상태와 연결되고, 담당 AI 직원 작업/검토·수정 이력, 추천 주제/근거, 기획안, 대본 전문, 버전/SHA, '실제 AI 결과' 출처를 대표가 볼 수 있어야 한다. 기획안 수락이 안 됐다면 '준비 중/실행 권한 필요/실패' 이유를 정확히 보여주고 가짜 성공 카드 생성 금지. 세련된 기존 UI 스타일 보존.
6. 승인/재시작 경계: 같은 실행을 새로고침/재개해도 기존 호출이 중복되지 않도록 attempt 선예약, 실패·timeout도 소모, 자동 retry/fallback 없음. 기존 Gemini/Puck 음성 실험 가드 1/1과 다른 ledger/사용자 프로젝트 절대 건드리지 말 것. KST 모든 저장 시간.

## 외부 AI 호출은 별도 명시적 범위 승인 필요
**중요: 이 대화의 미션 결정은 아직 특정 Gemini 모델·요청 내용·무료/유료 계정·API 호출 횟수·외부 전송에 대한 새 동의가 아니다.** 실제 AI에게 목표/대본 내용을 전송하기 전에 기존 무료 프로젝트·요금/쿼터/키 경로와 잔여 허용 횟수를 비밀 유출 없이 확인하고, 대표에게 **하나의 구체적인 승인 제안**을 보여주어야 한다. 검증한 텍스트 모델이 예컨대 `gemini-3.5-flash-lite`라면 그 모델과 예상 입력(가상 목표/맥락), 실패 포함 최대 호출수, retry0, Free Tier·$0, Google 무료 API의 데이터 사용 정책, 실제 입력/출력 보존·출처를 보고. 이전 음성 실호출 동의를 재활용하거나, AI 모델과 Codex 직접 집필을 바꾸어 주장하지 말 것.

**이번 Codex 실행 지시는:** 외부 AI 호출 전의 진입점/상태 연결·검증까지 바로 구현하고, 실제 API POST가 필요해지면 위 승인·계정 조건의 확인 결과와 정확한 1회성 실행 범위를 **보고서에 기록하고 멈춘다**. 사용자가 새 범위를 승인하면 **그 다음에만** 실제 AI를 호출해 대표 승인 대기까지 진행한다. 승인 요청만 하느라 연결 구현을 무기한 미루지 말 것. 기본 오프라인 API/브라우저 통합 테스트는 충분히 수행하되 모의 결과를 실제 미션 완료라고 발표하지 말 것.

## 작업 결과와 검증
- 실제 코드를 변경하고 관련 오프라인 테스트를 한 번의 묶음으로 실행: 새 프로젝트 생성→관리자 호출 진입점→writer/editor 산출물 연결→기획 문서 보고→대표 승인 대기 UI, 거절·재시도 차단·SHA/버전 불일치·새로고침을 검증. 텍스트 모델용 mock adapter는 실제 호출하지 않는 오프라인 검증 용도. AI 실제 호출 0인 경우 **실제 미션 결과 = 승인 전 준비 완료**라고 정직하게 기록.
- 결과 보고 `reports/VIDEO_FIRST_REAL_AI_PLAN_SCRIPT_MISSION_RESULT.md`, `reports/CURRENT_PROGRESS.md` 갱신: 실제 구현 변화, 업무 상태·브라우저 검증, mock vs real 명시, 잔여 실제 AI 호출 권한 1건 제안(정확한 모델/요금/호출 상한), 대표가 UI에서 무엇을 볼 수 있는지, 이어서 한 단계로 해야 할 작업을 기록.
- Codespaces에서 실행: `PYTHONPATH=core:companies/video python -B -m studio_server --host 0.0.0.0 --port 8000`; Ports 8000 Private. 기존 UI/원본 MP4/WAV/data/backups/approvals/ledger/키 보존. `git clean`/`git reset --hard` 금지. GitHub main에 코드·테스트·짧은 보고서만 커밋/푸시.

## 최종 목표(계속 유지)
AI 회사는 대표가 큰 목표만 제시하면 주제와 대본을 **실제 AI 직원들이 작성·수정**하고 대표가 **1차 기획 승인**을 하며, 그 후 영상·음성 실제 제작→대표 2차 검토→최종 완료한다. 지금은 그중 **첫 번째 실제 기획안+대본을 대표 승인 대기에 올리는 일**에 집중한다. 처음부터 새 회사를 설계하거나 영상부터 다시 제작하지 마라.
