## 1. v0.1 종료 정의

**사용자가 한 목표를 입력하면 실제 무료 AI 모델이 계획을 만들고, 사용자가 승인한 역할·업무·입력 연결에 따라 여러 직원이 결과를 생성·전달하며, 의미적 검토와 필요한 수정·재검토를 거쳐 사용자가 최종 결과를 확정하고 활용 가능한 파일로 받을 수 있는 Codespaces 시제품**을 v0.1로 정의한다.

사람의 계획 승인·중간 결과 승인·수정 지시·최종 확정은 의도적인 개입 지점이다. 모든 업무를 사용자가 ID를 찾아 개별 실행해야 하는 상태와, 승인 경계를 지키며 '시작·재개'로 다음 실행 가능 업무를 시스템이 선택하는 상태를 구분한다. 승인 없는 무인 운영은 종료 조건이 아니다.

완료는 다음 조건을 **모두** 충족할 때 선언한다. 모의 테스트 개수 증가만으로 완료를 선언하지 않는다.

## 3. 통합 마일스톤: 총 4개

각 마일스톤은 **구현·관련 단위/E2E·HTTP/필요한 UI 검증·보고·원격 반영을 한 작업 단위로 완료**한다. 기능별 설계/검증 지시서를 계속 분리 생성하지 않는다. 아래 순서는 승인 없는 실제 호출을 허용하지 않는다.

### M1. 기존 mock 협업을 하나의 완주 시나리오와 산출물로 묶기

의존성: 현재 main. 실제 API 불필요.

한 번에 할 범위: 목표 입력→계획 승인→mock 직원 실행/승인→형식 평가→수정 1회/재평가→사용자 승인→최종 정리→최종 승인/JSON 보관→Markdown 다운로드를 **단일 통합 시나리오**로 연결한다. 현재 분산된 테스트를 대체 삭제하지 말고 부족한 연결을 보강한다. 새 수정 POST의 실제 loopback 검증, 중단 이유/남은 횟수 UI, 확정본 읽기/다운로드를 함께 처리한다. Markdown은 이미 확정된 JSON에서 생성하고 서버가 검증한 ID/버전만 허용하며 GET이 기존 업무 JSON을 쓰지 않게 한다.

완료 기준: TemporaryDirectory의 projects/artifacts 및 AI 네트워크 금지 mock에서 한 시나리오 완주; 수정·재평가 각 1회, 승인 경계/중복 409/실패/저장 오류 보존/최종 무효화 확인; 내려받은 Markdown과 JSON의 업무 ID·버전·결과 일치. Codespaces 브라우저 검증 환경과 클릭·모달·중단 표시 확인도 이 마일스톤에 포함한다. 브라우저가 끝내 불가능하면 HTTP 완료·브라우저 미완료를 명시하고 v0.1 웹 실증은 M4까지 열린 조건으로 유지한다.

예상 영향: app.py의 다운로드/표시 및 최소 연동, 통합 테스트, 관련 사용법. AI 엔진은 그대로. 위험: 다운로드 경로 탈출·미확정 결과 노출·기존 보관물 덮어쓰기. 확정 스냅샷 검증 및 읽기 전용 경로로 방어한다.

**이번 선택:** 새 테스트를 지금 파일로 추가하지 않았다. 이번 지시의 최종 변경 범위가 '보고서 파일만'이고 로드맵 고정이 주목적이므로, 위 단일 mock 종단 테스트와 실제 HTTP/브라우저 보강을 M1의 구현·검증 산출물로 묶었다. 임시로 테스트 하나만 추가하는 별도 작업을 만들지 않는다.

### M2. 실제 무료 모델 협업 실행기의 안전 경계와 예산을 코드로 완성

의존성: M1의 상태/전달 계약. **구현과 테스트는 네트워크 금지 mock만 사용**하며 실제 호출 활성화는 M4 승인 전 기본 거절이다.

한 번에 할 범위: 기존 mock 진행은 유지하고 별도의 명시적 실제 실행 시작/재개 경로를 추가한다. 계획·일반 업무·의미 검토·수정·재검토가 같은 영속 요청 예산을 사용하도록 설계/구현한다. 실제 네트워크 요청마다 정확한 openrouter/free, 허용된 OpenRouter HTTPS 호스트/경로, 외부 전송 동의·활성화 여부, 입력 크기·출력 상한·잔여 횟수를 검사한다. 엔진 생성 시 검사만 믿지 않고 보내기 직전 재검증한다. 다른 모델/호스트로 fallback, 결제 기능은 없다.

예산은 전송 전 예약하고 실패·타임아웃·형식 오류도 소비한다. 여러 탭·재개·재시작으로 초기화하지 않는다. 계획 호출도 빠뜨리지 않는다. 실행 중단으로 완료 여부가 불명확하면 자동 재전송하지 않는다. 요청당 업무 상한과 프로젝트 전체 API 시도 상한을 별도로 표시하고 승인 대기·사용자 중단·오류·한도에서 멈춘다. 기존 승인 게이트를 제거하지 않는다. 길어진 API 호출로 같은 프로젝트의 다른 변경이 409가 되는 UX를 명시하고 다른 프로젝트는 독립 처리한다.

완료 기준: 계획/직원/검토/수정 모두 예산을 소비하는 모의 전송 E2E, 비무료/누락 모델·다른 호스트·미동의·소진·중복·중단 예약에서 요청 0회 또는 허용 횟수 이내, 실패 결과 보존·KST·비밀 없는 기록. 실제 네트워크 함수는 호출하면 실패하는 mock으로 검증한다. 승인되지 않은 실제 실행 버튼이 요청을 보내지 않아야 한다.

예상 영향: execution_engine.py/manager_plan.py의 공통 전송 검사·예산 연결, app.py 실행 조정·동의 표시, 격리 테스트. 위험: 기존 수동 경로가 예산/동의 검사를 우회하는 것, 무한 재시도, 제공자 오류 본문의 민감 정보. 모든 실제 경로를 하나의 검사에 묶고 오류 기록을 제한한다.

### M3. 의미적 품질 검토·수정·재검토를 실제 역할 계약으로 연결

의존성: M1 전달/보관, M2 예산/전송 안전 경계. 이 단계도 **실제 API 없이 모의 응답으로 구현·검증**한다.

한 번에 할 범위: 명시적 target_task_id와 사용자 승인된 성공 기준을 가진 의미 검토 역할을 추가한다. 결과는 pass/changes_needed/inconclusive, 기준별 관찰 근거, 누락/위험, 수정 제안, 대상 revision/hash를 갖는 엄격한 계약이다. 일반 실행의 포장 문구나 reasoning 텍스트를 합격 JSON으로 오인하지 않도록 명시적 결과 형식 경로와 검증을 둔다. 현재 required-sections-v1은 보조 형식 검사로 남기고 의미 검토와 구분한다.

역할별 실제 프롬프트도 사용자가 승인한 목표·산출물에 맞춘다. 현재 제품 기획 안내의 AI Company OS 자체 개발용 문구를 다른 목표에 강제하지 않도록 분리하고, 재고 도구 목표가 별개의 회사 OS 기획으로 바뀌지 않는 모의 요청 본문/응답 사례를 이 단계에서 검증한다.

검토 역할이 이미 승인된 앞선 결과에 수정을 권고하는 경우 **기계가 사용자 승인을 철회/위조하지 않는다.** 사용자에게 해당 업무 ID·기존 승인·수정 의견·추가 호출 예산을 보여주고 별도 '수정 요청 승인'을 받는다. 이 동작은 정당한 사용자 changes_requested 기록을 남기고, 그 뒤 기존 단일 실행 규칙으로 수정한다. 수정 뒤 선행 결과를 재승인하기 전 품질 업무의 재검토/후속 실행을 막는다. 최종 승인도 별도다. 기존 mock 수정 전용 내부 권한을 실제 엔진용으로 그대로 풀지 않는다.

v0.1 수정은 대상 1개·최대 1회와 재검토 1회로 제한하고 M2의 프로젝트 전역 예산에 포함한다. 오류/빈 판정/지문 불일치/평가 불가/개선 없음은 정지하며 형식 오류를 pass로 간주하지 않는다. 판단 근거를 모델 주장과 확인된 사실로 구별한다.

완료 기준: 목표→실제 경로를 모사한 계획·4역할→의미 검토 changes_needed→사용자 수정 승인→동일 담당 역할 재실행→사용자 재승인→검토 역할 재평가→최종 확정/다운로드까지 한 통합 fixture로 통과. pass·판정 불가·실행/저장 실패·상한·동시 요청·스냅샷 보존도 같은 마일스톤에서 검증한다. 실제 품질이 검증됐다고 표현하지 않는다.

예상 영향: 명시적 의미 검토 계약 모듈 또는 실행 엔진 결과 형식, app.py의 사용자 수정 확인·승인 흐름·최종 근거 연결, 통합 tests. 위험: 자동 승인, 검토 결과 자체가 오래된 입력을 사용함, 수정 후 이전 확정 유지. 대상 지문·사용자 승인·기존 무효화와 불변 보관으로 방어한다.

### M4. 별도 실제 호출 승인 후 한 목표로 v0.1 종단 실증·인수

의존성: M1~M3 구현과 모의/HTTP 회귀 통과, 사용자에게 아래 전송·보안·한도 계획을 제시하고 **실제 AI API 호출을 명시적으로 승인받음**. 현재 이 승인은 없으며 이번에는 요청/호출하지 않는다. 승인할 수 있도록 구현·모의 증거와 사용될 목표·데이터를 먼저 구체화한다.

한 번에 할 범위: Codespaces의 격리된 시연 프로젝트에서 계획부터 실제 역할·핸드오프·의미 검토·수정·재검토·최종 확정·다운로드까지 수행한다. 필요한 브라우저 클릭 검증, 중단 상태/예산 표시, 사용자에게 쓸 수 있는 결과물 확인, 잔여 버그의 최소 수정·회귀와 최종 인수 보고를 이 마일스톤에서 묶는다. 브라우저 검증만 반복하는 별도 기능 작업은 만들지 않는다.

완료 기준: 승인 범위 내 실제 실행 근거·역할별 결과·입력 ID/revision/hash·의미 검토/수정 전후와 사용자 승인·KST·최종 vN/다운로드 일치를 확인. 최소 한 번 실제 수정/재검토 수행. 키/헤더를 기록하지 않고 실제 모델 ID·소비한 호출 수·성공/정지 상태만 필요한 범위로 보고한다. 새 데이터로 다시 열어도 저장 상태 일치. 기존 데이터/이전 보관 파일 불변, 관련 회귀 통과. 모두 충족할 때만 v0.1 완료를 선언한다.

위험: 무료 라우팅 가용성·대기/제한·모델 결과 품질과 JSON 안정성. 실패/판정 불가이면 미완료로 기록하고 남은 예산을 임의 확대하지 않는다. 유료 전환·fallback 없이 안전히 정지한다. 개선은 가능한 한 오프라인 mock으로 먼저 검증한다.

## 4. 대표 목표 1개와 실제 인수 시나리오

목표 제안: **'소규모 매장의 재고 확인 업무를 줄이는 도구를 기획하고, 고객 문제·업무 흐름·첫 구현 범위·검증 계획을 갖춘 실행 가능한 제안서를 작성해 달라.'** 가상회사의 분석·기획·검토·관리 역할을 사용하며 단순 콘텐츠 생성 도구로 제품 방향을 바꾸지 않는다. 최신 시장 자료를 실제 수집하지 않으면 수치·경쟁사·수요 주장을 사실로 꾸미지 않고 가설/미확인으로 표시한다. 제품 아이디어 자동 선정·출시·매출 달성은 이 시나리오의 합격 조건이 아니다.

권장 4업무 흐름:

이는 한 번의 인수용 계획이다. 제품을 고정된 4단계나 위 업종 전용으로 바꾸지 않으며, 현재 목표별 가변 계획 구조를 유지한다. 다른 목표/업무 수의 실제 호출은 그 계획에 맞는 예산과 동의를 별도로 산정한다.

1. 실제 AI 관리자가 목표에서 4단계 계획·역할·선행 ID를 생성. 사용자가 범위·성공 기준·전송 자료·예산을 확인하고 계획 승인. 유효 계획이 아니면 호출을 소모한 오류로 정지하고 임의로 성공 처리하지 않는다.
2. 조사/업무 분석 담당(TASK-001)이 고객 문제·가정·확인 방법을 작성. 사용자 승인 후 기획 담당(TASK-002)에게 승인된 결과를 전달해 범위·업무 흐름·검증 기준을 작성. 사용자 승인.
3. 품질 검토 담당(TASK-003)이 TASK-001/002와 성공 기준을 비교해 구조화된 의미 판정과 구체적 수정 의견을 작성. 기계 평가가 통과여도 사용자가 개선 요청을 제시할 수 있다. 적어도 하나의 의미 있는 수정 요청을 사용자 확인으로 TASK-002에 전달한다.
4. 기획 담당이 같은 승인된 입력과 수정 의견으로 한 번 재작업. 새 결과를 사용자가 재승인한 뒤 품질 담당이 최신 revision을 재검토한다. 이전 검토 결과는 재검토 상태로 취급한다. 아직 부적합/판정 불가이면 한도 내라도 자동 반복하지 않고 인수 미완료로 정지한다.
5. 사용자가 재검토 결과를 승인한 뒤 관리자/최종 정리 담당(TASK-004)이 최신 승인 결과를 정리. 사용자가 최종 승인하여 불변 JSON과 읽기 쉬운 Markdown을 받고, 다시 열어 버전·본문·확정 상태를 확인한다.

중간에 사용자가 승인하는 것은 데이터 전달 경계이며 '작업을 대신 수행'하는 것이 아니다. 시스템은 시작/재개 요청에서 상태에 맞는 다음 업무를 선택하고 승인 전 실행을 차단해야 한다. 모델의 역할별 결과가 실질적인 목표 내용을 담는지는 M4에서 사람이 확인한다.

## 5. 실제 호출 승인 때 제시할 데이터·보안·한도 초안

다음은 **향후 승인안이며 현재 호출 권한이 아니다.** M2~M3 완료 후 실제 전송될 구체적 목표·샘플 입력으로 다시 제시한다.

- 제공자: 허용된 OpenRouter HTTPS API만. 모델은 요청마다 정확히 `openrouter/free`. 비무료·누락·다른 호스트는 전송 전 거절. 결제 설정 변경·유료 대체 없음.
- 데이터: 시연용 비민감 목표와 조건, 승인된 계획의 해당 업무 지시·역할·입력 연결, 필요한 최신 선행 결과 본문, 명시적 사용자 수정 의견, 성공 기준/검토 근거. 기존 업무 JSON 전체·백업·키·환경 변수·다른 프로젝트 결과는 전송하지 않는다. 계획 호출과 후속 실행의 자료 범위도 구분해 표시한다.
- 호출 상한 제안: **프로젝트 전체 최대 7회**, 정상 5회(계획 1+4업무)와 수정 1·재검토 1회. 실패/타임아웃/잘못된 JSON도 1회를 소비한다. 자동 재시도 0회. 기존 수동 경로로 보내는 요청도 같은 예산을 소비한다. 계획이 4단계가 아니거나 예산 안에 완주할 수 없으면 정지해 범위를 다시 검토한다.
- 한 번의 시작/재개에서 실제 모델 요청은 최대 2회, 승인 대기에서는 즉시 정지. 계획/일반 작업/의미 검토의 응답 토큰 상한은 M2에서 각각 고정하고 승인안에 표시한다. 현재 계획 3000·업무 4096 설정은 출력 토큰 제한이지 입력 총량/총 호출 수/제공자 청구를 보장하는 예산 장치가 아니다. 입력 본문 길이와 누적 전송량도 별도 제한한다.
- 예산 추가·다른 목표/기존 실데이터 사용·모델/호스트 변경은 기존 승인에 포함하지 않는다. 한도 소진 또는 무료 경로 이용 불가 시 유료 경로로 진행하지 않는다. '실제 계정에서 비용이 절대 발생하지 않는다'고 지금 확인하지 않은 사실을 보장하지 않는다.
- 비밀 키는 제공자의 인증 헤더로만 사용하고 화면·로그·보고서·보관 결과에 복사하지 않는다. 호출 기록은 모델 ID·상태·업무 ID·시도/결과 revision/hash·KST·잔여 예산 중심으로 제한한다.

## 6. 고정 범위 밖과 위험 관리

v0.1 필수 범위 밖: 제품 아이디어 자동 선정부터 실제 매출까지 완전 자율화, 결제/구독/유료 모델, 무인 승인, 무한 수정, 다중 회사·다중 사용자 권한 시스템, 분산/다중 프로세스 실행, 외부 이메일/슬랙·CRM 대량 연동, 임의 웹 조사·배포·실거래, 범용 코드 실행 샌드박스, 장기 백그라운드 에이전트 플랫폼. 개발 역할의 실제 빌드/실행 도구는 후속 단계이며 계획서 문구만으로 구현 완료라고 주장하지 않는다.

기존 유지 조건: 단일 프로세스 보호의 한계 공개, 예약·불명확한 중단의 보수적 정지, 기존 결과/스냅샷 보존, GET 무쓰기, KST, 승인되지 않은 API 요청 금지, 테스트 데이터 격리. Codespaces 수명·임시 브라우저 환경은 실제 제약이므로 검증 환경을 M1/M4 인수에 묶는다. 호스팅·클라우드 사용료를 새로 승인하거나 변경하는 작업은 포함하지 않는다.

현재 mock 수정 예약은 업무별 하나이며 자동 초기화가 없다. M3의 사용자 승인된 실제 수정은 이 예약을 삭제·리셋하는 방식으로 구현하지 않고 별도 명시적 권한/예산 기록으로 설계한다. 계획을 다시 생성해도 기존 tasks가 자동 교체되지 않는 현재 동작 때문에, v0.1 인수는 새 시연 프로젝트에서 시작한다. 기존 프로젝트의 재계획 마이그레이션은 사용자 데이터 보존 정책을 먼저 정한 후속 범위다.

## 7. 개발 순서와 완료 판정 운영

**M1 → M2 → M3 → 사용자 실제 호출 승인 → M4** 순서로 진행한다. 각 단계가 끝날 때 해당 구현·검증·보고서를 함께 원격 반영한다. 발견한 운영 버그와 그 회귀는 같은 단계에 포함하되, v0.1 기준 밖의 기능을 끼워 넣지 않는다. 단계별 독립 소형 설계서/검증서 생성 자체를 목표로 삼지 않는다.

M1 완료는 '안전한 mock 완주 기반', M2~M3 완료는 '실제 호출을 모의 검증한 구현 준비', M4 완료만 '실제 무료 모델 v0.1 인수 완료'다. 외부 승인/가용성 때문에 M4가 멈추면 앞 단계 완료와 제품 미완료를 구분한다. 진척을 임의 퍼센트로 표현하지 않는다.
