## Codex에게 맡기는 상위 완성 목표
**기존 사용자 중간 결재 없는 자율 회사의 역할별 실제 AI 판단/직원 결과 생성에 승인된 OpenRouter 무료 공급자를 연결할 수 있는 안전한 실행 경로를 구현하고, 실제 API 호출은 하지 않은 채 fake HTTPS transport/응답으로 ‘목표→AI 관리자 실제 모델 형식 계획·기준→AI 직원 수행→관리자 검토/수정→선행 결과 전달→관리자 최종 통합→저장’ 전체를 검증한다.**

'연결 준비'에 그치지 말고, 사용자에게 나중에 **프로젝트 시작 시 전체 운영 범위를 단 한 번 명시적으로 승인**받은 후, 운영 한도 안에서 **추가 업무별 승인 없이** 관리자가 계획/평가하고 AI 직원이 순차적으로 일하도록 하는 실제 실행기/운영 승인 설계를 가능한 범위까지 완성한다. 그렇지만 **이번 Codex 작업 자체는 어떤 실제 AI 호출·운영 승인도 허가하지 않는다.** mock-only 모드와 live-disabled 모드를 확실히 분리하고 **실사용 활성화는 별도 명시 동의와 안전 검증 전까지 차단**한다.

### 반드시 달성할 기능적 요구
1. **역할 분리**: 관리자 계획·업무 기준·평가·수정·최종 통합은 실제 manager 모델 응답, 직원 조사/작성 등은 employee 모델 응답에 근거한다. 기존 mock fixture의 규칙을 live prompt/결정 로직으로 복사하거나 도메인/영상 1분/TASK ID/품질 기준을 하드코딩하지 않는다. 계약(JSON schema/validation, response size, finish_reason stop, 의미 불확실성, 역할별 입력/출력)은 일관되고 검증 가능하게.
2. **기존 보안 경계 재사용**: live 요청은 검증된 `openrouter/free` 고정 HTTPS, 명시적 모델/전송 자료 동의, API 키 비노출, 길이/시간 제한, durable reservation-before-send, 소진·실패·timeout 집계, 불확실 상태 무재전송, 중복 호출/동시 실행 차단, KST 유지. mock 원장을 그냥 live 원장으로 표시하거나 동일 호출을 2번 기록해서는 안 된다. 기존 검증된 인프라를 최대한 재사용하라. 기존 live 사용자 승인/보호 API를 약화시키거나 우회하는 백도어 금지.
3. **운영 범위 한 번의 승인**: 사용자가 프로젝트 시작 전에 목표/전송 자료 유형·범위, 실행 provider/model, 최대 실제 호출 횟수(시작/재개당 상한 포함), 최대 비용/무료-only, 수정·재검토/예상 실패·중단 조건, 운영 권한의 유효 기간/프로젝트 ID 등을 확인·명시 동의할 수 있는 별도 **안전한 승인 계약·감사 모델**을 설계/구현하라. 이것은 **모든 업무 내용 승인**이 아니라 외부 실제 전송·예산에 대한 최초 허가다. 승인 없으면 live 0회, 승인 범위 밖 데이터·모델·호출/비용 증가는 실행 전에 중단. 운영 동의가 있어도 별도의 현재 시스템 제한(예: 2회/시작, 예약 오류, unresolved attempt 등)을 임의 해제하지 않는다. 이미 existing consent/authorization 정책이 별도 건별 승인만 허용한다면, 새 최초 운영 승인 계약의 결합과 보안 검증을 **라이브 차단 상태에서 먼저 설계·구현**하고, 정책 모순이 남으면 실행 불가능 상태로 남기고 보고하라. '사용자가 이전에 동의했을 것'이라고 가정 금지. 실제 동의 레코드 임의 생성 금지.
4. **한 사이클과 재개**: 최종 산출물이 나올 때까지 운영 범위 내에서 관리자가 내부적으로 accept/revise/stop과 직원 다음 작업을 결정하는 자동 루프. 각 요청과 결과의 role, event, dependency/result hash, rationale, version, KST, 원장·사용량 저장. 중단/재시작 시 완료한 단계는 반복 호출하지 않고 정상 체크포인트부터 재개. 실패한 요청·unresolved reservation·ambiguous response에는 허가되지 않은 자동 재시도 금지. 2회/시작 한도가 존재하면 안전한 명시적 재개 절차로 한 사이클을 이어갈 수 있어야 하되, 재개를 가장한 자동 우회 금지.
5. **초보자도 사용할 최소 실행 경로**: 목표 및 운영 동의 준비/확인/실행/상태·최종 파일 조회를 위한 최소 명령형 또는 작은 공개 서비스 기능이면 충분. **대시보드/화면 제작은 이번에 하지 않는다.** 초기 실사용 동의 없이 요청이 송신되는 흐름을 절대 만들지 않는다. 실행 명령 자체가 자동으로 동의를 생성하지 않게 분리한다. 사용자는 업무별 결과를 수락하도록 요구받지 않는다.
6. **명확한 실패 상태**: 실제 AI 응답 불량/finish_reason 미완료/공급자 장애/품질 미달/출처 부족/한도 초과/운영 권한 부족은 실제 업무 완료로 속이지 않는다. API 오류를 성공으로, unknown 사실을 사실검증으로 표시하지 않는다. 필요한 경우 관리자/직원에게 실제 사용 가능한 도구가 없음을 알리고 결과물을 제한된 주장으로 제출하거나 안전 정지. 유료 provider·다른 모델·웹/파일 등의 새 외부 연결은 사용자 승인 없이 추가하지 않는다.

### Codex의 자율 구현 범위
관련 현재 코드 전체를 분석하고 재사용·리팩터링 위치를 스스로 판단하라. Mock 클래스 타입 제한과 live 경계를 경솔히 제거하지 말고 **명시적으로 타입·스토리지·동의·공급자 분리**하라. 테스트에서만 fake transport를 주입하고 실제 OpenRouter API에 접속하지 않을 것. 요구되는 코드 변경·오프라인 테스트·결과 보고서를 한 작업 안에서 완료한다. **제품의 목표 지점은 실제 AI 기반 자율 회사 전체 사이클**이다. 안전 때문에 이번에 실제 송신 검증을 못 하면 ‘연결 준비/모의 전송 검증’까지의 완료와 ‘실제 한 사이클’ 미완료를 분명히 보고하고, 다음에 요청할 1회 초기 운영 동의 내용을 구체적으로 제시한다.

## 구체적 테스트·완료 기준
- **두 가지 이상의 서로 다른 임의 프로젝트 목표**, 한 사례는 정상 완료, 다른 사례는 관리자의 수정 지시→직원 재작성→재검토→최종 파일 성공, 사용자 업무 승인 0회. **live adapter + fake HTTPS 응답**으로 관리자와 직원의 요청 데이터·역할/모델·응답 검증·사용량/중복방지까지 실제 경계에 최대한 가깝게 검증. mock-only fixture 테스트 성공만으로 live 연결 완료 주장 금지.
- 운영 범위 **미승인/부족한 동의/권한 위반**, 무료 이외 모델, HTTPS/도메인 부정, 키 유출 시도, 예산 초과, 2회/시작 제한, 미확정 예약, 재개 중복, timeout/finish_reason 오류/잘못된 JSON/규칙 충돌 등에 대한 무송신 차단 확인.
- 강제 중단 후 재개 테스트: 완료 단계 반복 호출 없음, 불확실 시도 임의 재전송 없음, KST 이벤트·실제 결과 파일·hash 연결 확인.
- 기존 자율 mock 시나리오와 live 수동 프로젝트 회귀를 함께 확인. fake transport 결과를 실제 API 호출이라고 표현 금지. 테스트 실패가 있으면 관련 범위 내에서 자율 수정하고 재실행.
